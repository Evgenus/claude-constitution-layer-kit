# MODULE.md — `const-doc-budgets`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A document a project keeps grows with every change that touches it, and nobody measures what that costs the reader, or the model that loads it in every session. The kit's own tree shows it (the research comparison, E2 and E3): the session guide grew from 15,720 to 20,372 characters in one week, the shared code document from 24,787 to 42,795 in another; the longest decision record holds 30,126 characters, the longest research comparison 71,590. Each change decides its own length, and no one sees the kind's length move until a reader gives up. This module gives the project a number per group of documents — a ceiling in characters, set from what the group was observed to need — holds it in the dials file, and measures every held document against it after each write and in a scan. A ceiling warns while its data are young and blocks only once 30 days of data stand behind it.

<a id="t2"></a>
## 2. Failure class

`self-limiting`: an over-long document is felt by its readers and fixed there; nothing compounds across the repository except a template, whose documents inherit its length. **Entry trigger:** bloat observed, with data — a reader or a session saying a document is too long to use, or a document loaded into every session growing past what its readers want, and the lengths of its group over time at hand to show it. The kit did not pass it: the module was started ahead of the trigger by the decider's choice, with ceilings set from 15 days of data, the objection recorded (decision [dec-0052-doc-budgets-module-rulings](../../docs/decisions/dec-0052-doc-budgets-module-rulings.md), section 1).

## 3. Rows

| row | this module's reading |
|---|---|
| [A11.1](../../docs/requirements.md#a11-1) | A size is a count of characters as [kernel §7](../../kernel/CONVENTIONS.md#k7) defines one; the module counts by that definition and does not restate it. The count covers the whole file — the envelope, code, tables, link targets — since the reader loads the whole file, and any tool that counts the code points of the file read as UTF-8, a CRLF as one and bad bytes as [kernel §7](../../kernel/CONVENTIONS.md#k7) says, repeats the count. |
| [A11.2](../../docs/requirements.md#a11-2) | "A group of documents" is an entry of the dial `ceilings` in the module's own namespace: a name, path patterns in the dials file's dialect, the number, the level, the window of data. A document kind is such a group, its patterns written once as the policy's territory and pointed at by a YAML alias; a group no policy governs — the session guide, the skills, the install notes — is a group all the same. The module reads no policy and no envelope. "One ceiling per document at most" is held: a document two entries hold is a configuration failure, so a number never depends on the order of a list. "Post-hoc" is a `PostToolUse` hook on `Write` and `Edit` that hands an excess back to the model after the write, and a scan over the Markdown files git lists; under the shipped wiring no write is refused, while a consumer who wires the hook before the write makes a finding refuse it. "Warn → block per dial" is the `level` of each ceiling, `warning` or `error`; the shared `severity` keeps its one meaning, how a finding travels after a write. A document that must stand over its ceiling — an accepted record, a frozen comparison — is declared as an entry of the dial `departures`, with its reason. |
| [A11.3](../../docs/requirements.md#a11-3) | "Observed data" is the lengths of the group's documents in the history of the repository's first-parent line, read by the report `--scan --since <date>`, and today's lengths, in the note each ceiling prints on every scan. "30 days" is `window.to` minus `window.from` of the ceiling, two dates the dials declare: a ceiling at level `error` on a shorter window is a configuration failure at every read, hook and scan alike, and no clock is read, so the same tree gets the same verdict on any day. "Blocks" is read as: an excess over a ceiling at level `error` is a finding — red in the scan, and exit 2 after a write under `severity: block` — while at level `warning` it is a note. The number itself is review: the rule of thumb the module teaches and the report prints — the window's longest document plus 10 %, rounded up to a multiple of 1,000 — leaves no document over the ceiling on the day it is set. The window's longest is the longest version of a held document that any commit of the window held, not only the version at its end. |

## 5. Invariant

**No document a ceiling at level error holds is longer, in characters, than that ceiling's `max`, save where an entry of the `departures` dial lifts that ceiling for it; no document is held by two ceilings; and no ceiling at level error rests on a window shorter than 30 days.** "Holds": among the Markdown files git lists, tracked and untracked, ignored ones excepted, the ones the ceiling's `paths` match. "In characters": as [kernel §7](../../kernel/CONVENTIONS.md#k7) counts them, over the whole file. "Lifts": an entry whose `paths` match the document and whose `allow` names the ceiling; the document is measured and passes. A ceiling at level warning holds its documents to a note, never a finding. The invariant holds after every write of a held document through the file tools and at scan time; under the shipped wiring no write is refused ([§9](#t9)). After a write, holding is by pattern alone: the hook measures a written file the patterns match whether or not git ignores it, while the scan lists only what git does not ignore (shared limit 7).

The advisory rules beside it, each `advisory` in its own text, stated in the skill:

- **B-a.** Set a ceiling from the report, never from a wish: the window's longest document plus 10 %, rounded up to a multiple of 1,000, so that no document is over it on the day it is set. *Advisory.*
- **B-b.** A ceiling stays at warning until 30 days of data stand behind it; then it may block. *Advisory; the gate refuses `error` on a shorter window.*
- **B-c.** A document over its ceiling is split or cut, never squeezed: a shorter document that says less clearly is the wrong fix. *Advisory.*
- **B-d.** A ceiling is lowered only from data, in a change of its own with the number and the reason. *Advisory.*
- **B-e.** A document that must stand as written is declared as a departure in the dials file with its reason; nothing is marked in the document, and no pattern hides it from its ceiling. *Advisory.*

<a id="t7"></a>
## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | the hook | As every hook gate's ([template §7](../../module-template/MODULE.md#t7)): `block` hands a finding to the model as a block beside the tool result, exit 2, the write already made; `warn` hands it as context, exit 0. The scan ignores it and is red on any finding. It never turns a note into a finding: that is each ceiling's `level`. |
| `log_dir` | absent | all three | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |
| `ceilings` | `[]` | all three | The groups and their numbers: entries `{name, paths, max, level, window: {from, to}}`. `name` is kebab-case and unique, the handle a departure names. `paths` is gitignore syntax over the Markdown files git lists — a policy's territory by a YAML alias, or patterns of the entry's own; a negated pattern takes files out of this entry alone. `max` is a whole number of characters, 1 or more; a held document longer than it is B1 at level `error` and N2 at `warning`. `window` is the first and the last day of the data the number was set from, each written `YYYY-MM-DD`, quoted or not; `level: error` needs `to` 30 days or more after `from`, and a shorter window is a configuration failure. A document two entries hold is a configuration failure, in the hook for the written file and in the scan for the first in path order. Empty or absent: the gate measures nothing, says so at session start, and the scan counts zero. |
| `departures` | `[]` | the hook and the scan | What stands over its ceiling, where, and why: entries `{paths: [<patterns>], allow: [<ceiling names>], reason: <one line>}`. `paths` is gitignore syntax — a pattern for a kind of document, a number range by a character class such as `docs/records/rec-00[0-3]*.md`, or one file by its path with a leading slash; `allow` names ceilings that exist; `reason` is required and one line. A document an entry matches is measured and passes the ceilings it names; the others still apply. An entry that lifts nothing — it matches no document a ceiling it names holds — is N3 on every scan. A malformed entry, an unknown field, a name no ceiling carries, an empty or multi-line reason, a pattern git would misread: a configuration failure naming the entry. The report reads no departure: its data are every document's. |

A consumer's calibration lives in its own dials file, never here; the kit's, as it was set, is dated in [§10](#t10), item L1.

## 8. Boundary examples

Each pair reads *violates / complies*. The gate's own lines are numbers; the boundaries below are the module's judgment lines and the moments where a number is not the answer.

**A ceiling, or a target** ([A11.2](../../docs/requirements.md#a11-2), [A11.3](../../docs/requirements.md#a11-3)):

1. A ceiling for records set at 20,000 because records "should be short", with five records already over it → a target from no data, red on day one / the report's longest record, 30,126, plus 10 %, rounded up: 34,000, and a later lowering from data in a change of its own.
2. A ceiling moved to `level: error` on its fifteenth day because a document crossed it → refused by the gate, and a block from half the data / left at warning until the window holds 30 days, the excess cut or split meanwhile from the note.
3. A median-based ceiling that half the documents of a kind already break → a percentile, a target for the many / the maximum plus the margin, no document over it when it is set.

**A cut, or a split** ([A11.2](../../docs/requirements.md#a11-2)):

4. A module document over its ceiling squeezed by dropping its examples and its limits → shorter and less true / split along a seam it already has, a long table moved into a document of its own linked from the first, or a restated rule replaced by a link to its home.
5. The session guide over its ceiling, a paragraph moved into a second always-loaded file → the reader loads it all the same / the paragraph moved into a skill that loads when its activity occurs, and the always-loaded text shrinks.
6. A record over its ceiling cut by deleting its options and keeping the ruling → the reasoning lost / the options kept, a long quotation replaced by a link to its source.

**A departure, or a hiding place** ([A11.2](../../docs/requirements.md#a11-2)):

7. An accepted record over a ceiling lowered below it, taken out of the ceiling's `paths` by a negated pattern → hidden with no reason; or cut to meet the number by edits its policy does not allow / first the edits its policy allows, where they reach the number; for what they do not reach, a departure over its path, allowing that ceiling, with the reason that accepted records stand as written.
8. Two ceilings over one folder so that a narrower one gives a sub-group more room → refused by the gate; the verdict would hang on the order of the list / the broad entry's patterns narrowed, or the sub-group taken out of it by a file pattern, each group then under one entry.
9. A departure left in the dials file after its document was deleted → a reason for nothing, reported on every scan / the entry removed in the change that deleted the document.

**Honest limits**, each with its backstop. The shared code's limits — [kit-shared-gate-code §4](../../shared/GATE.md#g4) — apply. This module's own:

1. **The window is declared, not proven.** The gate checks that `to` is 30 days or more after `from`; it cannot check that the data of those days were read, or that the number came from them. Backstop: the report prints the window and the rule of thumb beside the number set; review, at the change that sets it.
2. **A document already over its ceiling is reported after every write to it,** the finding saying the length and not how much this write changed it. Backstop: the first finding says how much to cut; a departure where the document must stand.
3. **The hook sees a write through the file tools and nothing else.** A shell command, a merge, an editor: the shared limit 1. Backstop: the scan, in CI and before a merge.
4. **The report reads the first-parent line of HEAD.** A version that lived only on a merged branch between its commits, and a commit dated by a clock set wrong, are not in its days as they happened; a day is the committer's calendar day. Backstop: the report's lines name the commits and days it read; the branch's own history, reported on the branch.
5. **The report applies today's ceilings to the past.** A path that two of today's ceilings would hold is counted under each in the report, since the report judges nothing; the gate refuses the overlap in today's tree. Backstop: the scan.
6. **A count is of the whole file.** Link targets, the envelope and code count as text does, since the reader loads them; a group heavy in tables or links gets a higher number from its own data. Backstop: the ceiling is set per group from that group's lengths.
7. **A departure lifts a ceiling for a document whole,** with no number of its own, and one by path outlives its document until the scan's note is acted on; the note is not a finding. Backstop: the reason names what stands; N3 on every scan; review.

8. **A configuration failure stops the whole gate.** A malformed entry — a ceiling at error on a short window, a departure naming no ceiling — fails every read, and while it stands no document is measured, in the hook or the scan. Two ceilings over one document fail every scan, and in the hook a write of that document alone. Backstop: the failure is exit 1 with its line, which a hook shows the user and CI turns red; the scan in CI.

**Exit-code contract**: `0` green, a report, or nothing examined (the count line says which); `2` finding — a held document is over a ceiling at level error; `1` configuration failure — the checker could not run: the shared failures, this module's C5 and C12. Nothing exits 0 on error.

## 12. Deferred

1. **A ceiling by meta-type** — an entry filtered by the envelope's `type` beside its paths. Signal: a consumer whose documents of one meta-type are scattered across folders no pattern names.
2. **The change a write made, in the finding** — the difference an `Edit` made, from its `old_string` and `new_string`, so that a finding on an already long document says whether this write made it longer. Signal: a consumer finding the repeated finding of limit 2 noise.
3. **A `PreToolUse` mode that refuses only a write making a document over its ceiling longer.** The shipped hook judges after the write; wired before it, the gate refuses every write that leaves a document over its ceiling, a partial cut included. Signal: a consumer asking to be stopped before the write, at the price of the reconstruction of an `Edit`.
4. **A number derived by the gate** — the ceiling computed from the history at each run instead of declared. Signal: a consumer whose declared numbers drift from the report for want of anyone to set them.
