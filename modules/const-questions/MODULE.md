# MODULE.md — `const-questions`

*Draft at manifest version `0.0.2`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A session asks what it should have decided, and decides what it should have asked. Both poles were observed. Four questions were bundled in one message, each with no options and no recommendation. A question about where a scratch file goes blocked until it was answered. A request with two plausible readings was answered on one of them in silence. A delivered plan carried `TBD: who owns this` inside. And, once corrected, the inverse was seen. Every small uncertainty was escalated as a fixed-price ceremony until the person asked stopped reading the ceremony. In the kit's own authoring sessions the shape of one decision message took six commits in two days before it held. The days were 2026-09-14 and 2026-09-15. Twice the argument was written where the user never saw it. Each such correction is made in a session and lost with it. The next session asks the same way again. On 2026-09-26 the kit's guide handed the shape to this module alone. That day a kit session that never loaded the skill put eight decisions with the pros and cons inline in prose. A second session lost the shape twelve hours after loading the skill. The decider noticed the next day (decision [dec-0047-decision-shape-printed-at-session-start](../../docs/decisions/dec-0047-decision-shape-printed-at-session-start.md)).

<a id="t2"></a>
## 2. Failure class

`self-limiting`: the drag of a badly shaped question is felt at once by the person asked, who corrects it in the session. Nothing compounds in the repository. A delivered document with an open question inside is caught by its reader. **Entry trigger:** the same correction on how the agent asks, or fails to ask, recurs across sessions. It is a session-guide edit or a commit note, made twice or more. Its theme is the question format, the threshold, a silent reading or a deferred question. The kit passed it with six commits on one theme in two days.

## 5. Invariant

**A covered document written through the platform's file tools, and every covered document of a scanned tree, carries on no line outside code a text the `markers` dial lists.** "Covered" is the `territories` dial of [§7](#t7) over the Markdown files git lists in the scan. In hook mode it is that dial over the written file, whether git lists it or not. "Outside code" is outside a fenced block and outside a code span. A marker that begins or ends with a word character counts only at a word boundary there, and the match is case-sensitive.

The advisory rules beside it, each `advisory` in its own text and carried by the skill:

- **Q-a.** A question is asked at recorded stakes or at a genuine blocker. A genuine blocker is a fact only the user holds, without which the work cannot proceed. Below that line the session makes the reasonable call and notes it in the commit. The line is the pairs of [§8](#t8) and the project's own through `boundary_examples`. A decider's `preferences` entry overrides them on its topics. *Advisory.*
- **Q-b.** One decision per message, never bundled, in the fixed shape. Options are lettered `A`, `B`, `C`…, each a bullet with a one-sentence description. Each has indented **Pros:** and **Cons:** sub-bullets of one prose line each, never inline and never a table. There is exactly one recommendation with reasoning, and the decider is named. A simple factual clarification is a plain one-line question. Under five options, and where the decider's `pick` is `tool`, the platform's question tool follows and carries the pick alone. It holds the letter plus short label, at most one clause. Five or more options, a `pick` of `letter`, or a session where the tool is not offered: chat only, the pick by letter. The shape, in short, is also the always-on text of [§6](#t6), printed at every session start. *Advisory.*
- **Q-c.** Questions come from the artifact's open slots, in document order, and name the slot. Such a slot is the next unfilled template section, `[decide: …]` marker, missing dial or unresolved row. "While we are at it" is noted as deferred with its signal, never asked. *Advisory.*
- **Q-d.** Where the slot's vocabulary is closed the options are exactly that set; free text only for a genuinely open value, with the default proposed. *Advisory.*
- **Q-e.** A slot with a sensible default is asked as "default is X — accept or override?". An override carries a one-line reason, kept in the record or the commit note. *Advisory.*
- **Q-f.** Vague or context-foreign input opens the reply with the reading taken. Several plausible readings are named with the one chosen. The choice is a question only above Q-a's line. It is never a silent guess. *Advisory.*
- **Q-g.** A delivered plan or document holds resolved decisions only. An open decision whose decider is absent halts the affected part behind an explicit named blocker, never an open question inside the deliverable. The gate holds the marker half of this rule. The prose half is judgment. *Advisory.*
- **Q-h.** The argument must reach the user. Once the user reports an argument missing, every later decision in the session ends the turn on the chat message. The pick is then collected by letter, without the tool. A decider's standing `pick: letter` makes that the path from the first decision. *Advisory.*
- **Q-i.** A routine answer is one line in the commit message saying what was chosen and why. A recorded answer is the kernel's to record. When module `const-decision-records` is installed its skill writes it down as argued. *Advisory.*

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | gate, hook mode | `block`: a finding exits 2 and the write is blocked. `warn`: the finding is reported to the model and the user in one JSON object and the write proceeds — the adoption path onto a repository whose documents carry markers. The scan ignores it. |
| `log_dir` | absent | gate | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |
| `territories` | `["*.md"]` | gate | The delivered documents: path patterns in the dials file's dialect over the Markdown files git lists, tracked and untracked, ignored ones excepted — in the scan; the hook judges the written file whether git lists it or not; a negated pattern takes files out — a template, a working draft whose own convention keeps inline markers until it is delivered, each by its own path or directory, never by a wildcard that would hide finished documents with it. | `markers` | `['[decide:', 'TODO', 'TBD', 'FIXME']` | gate | The texts that mark an open question, each one line, matched case-sensitively outside code; one that begins or ends with a word character — a letter, a digit or an underscore — counts only at a word boundary there. ## 8. Boundary examples

The test behind every pair: is the call the user's to make — recorded stakes, or a fact only the user holds that the work cannot proceed without? The pairs are the definition and are carried by the skill; the project's own arrive through the preferences dial ([§7](#t7)).

**Q-a and Q-i — ask or decide** (this module's slice of the routine/recorded line of [kernel §4](../../docs/constitution/CONVENTIONS.md#k4), aligned with the pairs of module `const-decision-records` where installed: the two modules share the triage, this one asking the question and that one writing the answer). Pairs 1 to 3 read *decide and note / ask*:

- **1.** Which of two directory names holds a scratch file → decide, one line in the commit / where the project's decision records live and how they are numbered → ask (`process`).
- **2.** The wording of a commit message, the name of a helper nobody else calls → decide / the name of a dial, a trailer key or a command-line flag that others will type → ask.
- **3.** A fact the session can find by reading the tree, the documents or the history → find it, never ask / a fact only the user holds — who decides, which consumer, a date — without which the work cannot proceed → ask, and if the user is absent, halt that part behind a named blocker.
- **3a.** The answer to a routine question → one line in the commit message saying what was chosen and why / the answer to a question asked at recorded stakes → recorded as the kernel asks, written through the record skill of module `const-decision-records` where it is installed, never left as a commit line.

**Q-b — the full shape or a plain question** ([A6.2](../../docs/requirements.md#a6-2), the exemption, and one decision per message):

5. "The pasted file or the one in the repository?" — one fact, answered in a word → a plain question, one line / three mechanisms compared, one to be chosen → the full shape: lettered options, pros and cons, one recommendation, the decider named.
6. Every uncertainty put as a lettered ceremony — the spelling of a variable, the order of two paragraphs → *not* the shape, and not a question: decide and note / a choice that binds a policy, a procedure or a contract → the shape, every time.
7. Two open slots, both at recorded stakes → two messages, the second put after the first is answered / two facts of one slot — a value and its unit → one message.

**Q-c to Q-e — derived, not improvised** ([A6.3](../../docs/requirements.md#a6-3)–[A6.5](../../docs/requirements.md#a6-5)):

8. The next unfilled template section, the next `[decide: …]` marker, the next missing dial → the next question, in that order / "while we are at it, should we also…" → not asked; noted as a deferred item with its signal.
9. A slot whose values are a kernel enum or a dial's listed values → those values are the options, nothing beside them / a genuinely open value — a title, a path the project owns → free text, with the default proposed.
10. A slot with a sensible default → "default is X — accept or override?", the override carrying its one-line reason / a slot with no defensible default → options with one recommendation.

**Q-f — restate, do not guess** ([A6.6](../../docs/requirements.md#a6-6)):

- **4.** A request with two readings that lead to the same work → proceed on the stated reading, restated first / two readings that lead to materially different work → ask: a material assumption is a question, not an assumption.
- **4a.** Context-foreign or vague input → the reply opens with the reading taken, "I read this as: …" / the same input answered on a silent guess → violates.
- **4b.** Several plausible readings whose choice is below the line of Q-a → name them and the one chosen, and proceed / the choice above that line → ask.

**Q-g — resolved, not deferred** ([A6.7](../../docs/requirements.md#a6-7)):

- **11.** `TBD: who owns this` inside a delivered plan → *not* delivered; the part halts behind "blocked: <who> must name the owner" / a draft module document at manifest `0.0.x` carrying `[decide: …]` markers → the draft's own open slots, legitimate until publication.
- **11a.** "To be agreed with the team" written as a sentence in a delivered document → violates, though the gate sees no marker ([§9](#t9), limit 1) / the same part halted behind a named blocker → complies.
- **11b.** A draft taken out of `territories` by its own path, until it is delivered → complies / the same draft taken out by a wildcard that hides finished documents with it → violates.

**Q-h — the argument must reach the user** ([A6.9](../../docs/requirements.md#a6-9)):

12. Under five options, no report of a missing argument, `pick` absent or `tool` → the platform's question tool follows the chat message and carries the letter and a short label alone / the user has reported an argument missing → every later decision of the session ends the turn on the chat message, the pick by letter, without the tool.
13. A decider whose `preferences` entry says `pick: letter` → the letter path from the first decision / an entry with `pick` omitted → `tool`.
14. Four options, the tool offered, no standing `pick: letter` → the question tool follows the chat message / five options, the same session → chat only, the pick by letter.

## 9. Enforcement honesty

| # | artifact | kind |
|---|---|---|
| E1 | the hook on `PreToolUse` and `check-open-questions.sh` (hook mode): Q1 | `gate`, its dial `severity` (`block` default; `warn` reports and lets the write through) |
| E2 | the scan: `check-open-questions --scan`: Q1 | `gate`, always exit 2 on a finding, ignores `severity` |
| E3 | the skill `ask-or-decide`: Q-a to Q-i | `advisory` |
| E4 | the hook on `SessionStart` and `print-decision-shape.sh`: Q-b in short | `advisory` |
| E5 | the effect entry `effect-report.sh`: it informs judgment, gives no finding, never exits 2 and is never red | `advisory` |

Exit codes, both modes: `0` green or nothing examined (the count line says which); `2` a finding — the document, or the tree, carries a marker; `1` a configuration failure — the shared failures, this module's `C5` and `C12`.

**Honest limits.** The limits every gate shares: [kit-shared-gate-code §4](../../shared/GATE.md#g4). This module's own:

1. **A deferred question written in prose is invisible.** "We can settle the numbering later", a heading with nothing under it, a decider named nowhere: no marker, no finding. The gate proves that nobody left a marker, and its message claims no more. Backstop: Q-g in the skill; review of the deliverable.
2. **A marker inside code is a quotation and is never reported** — a code span, a fenced block from its opener to its closer or to the end of the file. An unclosed fence therefore hides everything after it; an indented code block is not code to this check, nor is a fence indented four spaces or more, and a closing fence that carries an info string closes — three readings that differ from CommonMark and each err toward reporting a marker, never toward hiding one; a backtick fence whose info string holds a backtick is no opener, as in CommonMark, so a line of code spans opens nothing. Backstop: the scan lists what it examined; a fence is closed by its author.
3. **Whether a question should have been asked, and the shape of the message, are judgment.** A choice decided in silence, a bundle of four decisions, an argument written where the user never saw it: no file shows any of them. Backstop: the skill; the shape printed at every session start (E4), which a session sees whether or not it loads the skill; the consumer's own pairs and preferences.
4. **The skill-read dials are not validated.** A malformed `preferences` entry is read by the agent as it stands; the gate refuses a key that is none of the six, which is not validating the shape of what stands under a known one. Backstop: `none — accepted`: the skill reads the dials as prose, and validating their shape is deferred ([§12](#t12), item 2).
5. **A draft is a deliverable to the gate.** A document with legitimate inline slots is blocked at every write unless its path is taken out by a negated pattern or `severity` is `warn` — the cost of catching the marker at the keystroke. Backstop: the fix line names the pattern; the kit's own dials file shows the shape.
6. **One finding per line.** Two markers on one line report the first; a line fixed and re-written reports the second then. Backstop: the count line says how many lines, and the scan re-reads the whole document.
7. **Coverage is by path only, and the two modes see different files.** A document a policy governs is no more covered than any other Markdown file. The scan examines the files git lists, so a git-ignored draft is invisible to it; the hook judges the written file whether git lists it or not, so the same draft is blocked at its write — the backstop the shared code names. Backstop: `territories` is the consumer's; the scan says how many files it scanned.

**Depends on:** [kernel §4](../../docs/constitution/CONVENTIONS.md#k4) — the stakes enum, which is the threshold's vocabulary, and the standing signal of recurring commit notes; [kernel §5](../../docs/constitution/CONVENTIONS.md#k5) — the body shape of a record, which the decision message mirrors so that a recorded answer can be written down as argued by whoever records it; [kernel §6](../../docs/constitution/CONVENTIONS.md#k6) — the dials file, where the project's own pairs and preferences arrive. Beside the kernel it needs, preflighted by the gate on each run, git, Python 3.12 as `python3` and PyYAML, and the Python package `constitution-layer-kit`, which pip installs. That package is the kit's shared gate code and no sibling ([law 3 of CLAUDE.md](../../CLAUDE.md#law-3)). Nothing else.

**Without each tool:** without git, `python3`, PyYAML or the package the gate stops with a configuration failure that names the fix, exit 1, and checks nothing; the skill needs none of them, and the session-start printer is a POSIX script that reads nothing, so both run unchanged.

**Kernel alone, with that package installed:** on a bare repository the skill carries the threshold, the message shape, the derivation order and the no-deferred-questions rule with its seed pairs, and a recorded-stakes answer is recorded as the kernel asks, by whatever the project has for it. With a `constitution.yaml` that holds `module_prefix` and no key of this namespace, the gate's defaults cover every Markdown file git lists, and a written one whether git lists it or not; with no `constitution.yaml` the gate is the shared visible skip naming the file, in the hook and in the scan alike, and the skill still carries its rules.

**When module `const-decision-records` is installed,** a recorded-stakes answer is written through its record skill, which prices the stakes with the same triage and knows where records live; the two modules share the routine/recorded line, this one asking the question and that one writing the answer. **When module `const-locations` is installed,** a document the answer creates is born at its home through the command. **When module `const-catalogs` is installed,** the record's number comes from its allocation. Each is an optional enhancement; every rule here runs with the kernel alone.

## 12. Deferred

The deferrals every gate shares stand once in [kit-shared-gate-code §1](../../shared/GATE.md#g1). This module's own:

1. **The weighted-analysis policy** for trade-offs too complex for the lettered shape — the matrix names it "added at first concrete need" ([A6.2](../../docs/requirements.md#a6-2)). Signal: a decision message in a consumer whose options need a scored table to be compared, reported twice.
2. **Validation of the preferences dial's shape.** The skill reads it as prose; nothing checks its shape ([§9](#t9)). Signal: a malformed entry read wrongly by the skill, reported once.
3. **A deferred question written as prose.** The scan, where it ships, sees markers; "to be agreed with the team" in a sentence is invisible to it. Signal: a delivered document found to carry such a sentence past review, twice.
4. **The effect report's other ways.** The report counts no message that bundles two decisions, no pick collected by the question tool where the letter was owed, and no question asked below the line that carries no question mark; a reader reads W8, but only on a message that puts a question. Signal: a session found, by review, to have bundled or skipped the tool with the report counting it applied, twice.
