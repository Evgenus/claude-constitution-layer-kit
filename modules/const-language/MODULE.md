# MODULE.md — `const-language`

*Draft at manifest version `0.0.2`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

The documents a project governs are read by people whose first language is not English. They are also read by a model that reads them in every session. Nobody measures what that reading costs. The kit's own tree was measured on 2026-09-27 before any rule existed (E2 of the comparison). It had a median Flesch–Kincaid grade of 9.33 over 109 documents, 38 of them above grade 10. Of its 9,598 sentences, 2,890 were over 25 words. Each document decides its own density at the moment of writing. The reader who cannot follow a 60-word sentence has no number to point at. This module gives the project the numbers — a grade ceiling, a words-per-sentence limit, two short lists of the constructions plain language avoids. It holds them in the dials file. It checks every covered document against them after each write and in a scan, with Vale doing the counting.

<a id="t2"></a>
## 2. Failure class

`self-limiting`: dense prose is felt by the reader of that document and fixed there. Nothing compounds across the repository except a template's prose. Its documents inherit that prose until the template is fixed. **Entry trigger:** the first prose-complexity complaint, made twice. Such a complaint is a reader, a reviewer or a consumer session saying a document could not be followed. It may also say a sentence had to be read twice, or a term was never defined. The kit did not pass it. The module was started ahead of the trigger by the decider's choice, and the objection was recorded (decision [dec-0046-language-module-rulings](../../docs/decisions/dec-0046-language-module-rulings.md), section 1). The numbers of [§1](#t1) are what the tree showed at the survey, not the trigger.

## 5. Invariant

**No covered document, as Vale reads its prose, is above the grade ceiling or holds a sentence over the word limit. Nor does one hold a phrase of the forbidden or simpler lists. These rules hold at level error, save where an entry of the `departures` dial allows that rule for the document. And none holds a Vale comment outside a fence or a code span.** "Covered": among the Markdown files git lists, tracked and untracked, ignored ones excepted, the ones the dial `territories` names. "As Vale reads its prose": the document with its envelope and every Vale comment outside a fence or a code span blanked, line numbers kept. Vale 3.23.0 or newer reads it with the configuration of [§7](#t7). It reads the grade over the `summary` scope and the words over each sentence. It reads the phrases over the text outside code spans, code blocks and URLs, case-insensitively. "At level error": the rule's level, as the dial `levels` sets it. A rule at warning reports a note and holds nothing, and a rule at off is not written. "Allows": an entry whose `paths` match the document and whose `allow` names the rule. A hit of such a rule in such a document is neither a finding nor a note. The invariant is checked after every write of a covered document through the file tools and at scan time. No write is refused ([§9](#t9)). One case is reported after a write and is not red. A document may be above the grade ceiling with a grade below that of the same document in the last commit. Such a document gets the note N4 of [§6](#t6) in place of L1. So a long document comes down one edit at a time with no red between. The note stands only where L1 would: the grade rule at level error, and no departure allowing it for the document. At level warning the grade keeps its note N2, and `severity` changes neither. The hook gives N4 for a `PreToolUse` payload too, where a consumer wires the hook before the write. The scan reads no commit and holds the ceiling for that document too (limit 12 of [§9](#t9)). After a write, coverage is by pattern alone. The hook judges a written file the patterns hold whether or not git ignores it. The scan lists only what git does not ignore (limit 9 of [§9](#t9)).

The advisory rules beside it, each `advisory` in its own text, stated in the skill:

1. **L-a.** One idea per sentence; a sentence past the limit is split at a clause, never squeezed. *Advisory.*
2. **L-b.** The plain word: the one a reader meets first; the finding names it. *Advisory.*
3. **L-c.** No idiom: a phrase whose meaning is not the meaning of its words is said plainly. *Advisory.*
4. **L-d.** Name who acts; the passive is a register the project sets, not a defect the gate reds. *Advisory.*
5. **L-e.** A term of the project's own or of the trade is defined in one clause at first use. *Advisory.*
6. **L-f.** A phrase the project keeps on purpose is an exception in the dials file. A document that must not be edited is declared as a departure there, with its reason. Nothing is marked in a document. *Advisory.*

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | the hook | `block` hands the findings to the model as a block beside the tool result, exit 2, the write already made; `warn` hands them as context, exit 0. The scan ignores it and is red on any finding. |
| `log_dir` | absent | the hook and the scan | A repository-relative, git-ignored directory for the output log. |
| `territories` | `["*.md"]` | the hook and the scan | The documents the gate reads: path patterns in the dials file's dialect over the Markdown files git lists, tracked and untracked, ignored ones excepted. A negated pattern takes files out, and a written file the patterns do not hold is a visible skip. Empty: refused. |
| `grade_ceiling` | `10` | the hook and the scan | The Flesch–Kincaid grade a document may reach, a finite number, 0 or more. A document whose grade, as Vale computes it over the `summary` scope, is above it is L1. After a write it is the note N4 instead, while that grade is below the document's grade in the last commit. |
| `sentence_words` | `25` | the hook and the scan | The words a sentence may hold, a whole number of 1 or more; a sentence over it is L2, a heading being a sentence. |
| `levels` | `{grade: error, sentence: error, forbidden: error, simpler: error, passive: warning}` | the hook and the scan | The level of each rule, any subset overriding the default. `error` is a finding, red, save the falling grade after a write, which is the note N4. `warning` is a note, never red. `off` is not written — and a bare `off`, which YAML reads as the boolean false, is taken as that level. Every rule off: refused. |
| `forbidden` | `[]` | the hook and the scan | Phrases of the project's own added to the founding forbidden list, one line each, matched case-insensitively at word boundaries. |
| `simpler` | `{}` | the hook and the scan | Pairs of the project's own added to the founding simpler list, the phrase as the key and the plain word as the value. |
| `exceptions` | `[]` | the hook and the scan | Phrases of either list the project keeps on purpose, removed from the rules before Vale runs; a phrase no list holds is refused. |
| `departures` | `[]` | the hook and the scan | What stands as written, where, and why: entries `{paths: [<patterns>], allow: [<rule keys>], reason: <one line>}`. `paths` is gitignore syntax. It takes a pattern for a kind of document, or a number range by a character class such as `docs/records/rec-00[0-3]*.md`. It also takes one file by its path with a leading slash. `allow` names rules by key from the five. `reason` is required and one line. A line break at either end, which a YAML block scalar gives at its end, is trimmed with the other white space there. One inside it is refused. A hit of an allowed rule in a matched document is neither a finding nor a note; the other rules still apply there. An entry matching no covered document is a note on every scan. A malformed entry is a configuration failure naming it. The kit's own: one entry, by path, for the four accepted records and frozen comparisons whose long sentences are lists no wording edit splits. The others meet the thresholds by wording edits (decision [dec-0048-frozen-documents-take-wording-edits](../../docs/decisions/dec-0048-frozen-documents-take-wording-edits.md)). |

The founding lists, the module's own, are in `plugin/scripts/language_gate/rules.py`. There are thirty forbidden phrases. They are idioms of the trade such as `hit the ground running`, `low-hanging fruit`, `circle back` and `silver bullet`, hedges such as `needless to say` and `it is worth noting that`, and formal words with no one-word replacement such as `notwithstanding`, `aforementioned` and `heretofore`. There are also thirty-three simpler pairs, `prior to` → `before`, `in order to` → `to`, `utilize` → `use`, `in the event that` → `if`, `with regard to` → `about`, `a number of` → `some`, and the rest. The two lists are disjoint, held so by fixture T17. The passive pattern is a form of *be* followed by a regular participle of four letters or more ending in `ed`. The participle may also be one of forty-eight irregular participles by name. A phrase of the repository's own that is also a key of the simpler list is reported by both rules. An exception matches a phrase in any case, as the lists do.

What the gate hands to Vale: the document with its envelope replaced. The envelope runs from a first line `---`, a byte-order mark before it allowed, to the next line `---`, trailing whitespace aside on both. It is replaced by one empty line for each line feed it holds. So the text after it keeps the count of line feeds before it. A line of the envelope ends at a line feed, a carriage return and line feed, or a lone carriage return, and nowhere else. Every `<!-- vale … -->` comment outside a fence or a code span, on one line or across lines, is replaced by spaces. That way line numbers are those of the document. One inside a fence or a code span is a mention Vale does not honour, left as it stands. The copies stand flat in a temporary tree, each under a numbered `.md` name (`000000.md`, `000001.md` and on). Beside them stands a configuration of one section, `[*.md]` with the one generated style. It has a `MinAlertLevel` of `suggestion` so that a rule at warning reaches the gate. So Vale reads every covered document as Markdown, whatever the case of its ending (`X.MD`, `Guide.Md`). It does so whatever its name, a leading dash included, which Vale would read as an option. Results map back to the real path, so a finding carries the document's own path and line. Vale runs once over the copies with `--no-exit`, so its exit 1 on a finding is no failure. Any other exit is the configuration failure of [§6](#t6).

**Honest limits**: the limits every gate shares, [kit-shared-gate-code §4](../../shared/GATE.md#g4), apply and are not restated. This module's own, each with its backstop:

1. **The numbers are Vale's.** The grade is Flesch–Kincaid as Vale counts words, sentences and syllables. Other tools give the same text a grade one to three years apart (E5 of the comparison). A ceiling is checkable only as "grade N by Vale's Flesch–Kincaid", which is what the dial means. A later Vale that counts differently moves every document's grade, and the fixtures that type a grade say which version counted. Backstop: the version floor; the fixtures; a consumer's dial.
2. **A sentence is what Vale ends.** A heading is a sentence to the word limit and no prose to the grade. A list item is a sentence. An abbreviation with a period may end one early. A front-matter field is read by the phrase rules and not by the sentence rule, which is why the envelope is blanked. A phrase of the lists broken across a line break inside a paragraph is not found, since Vale matches within a line. Vale cannot place a table cell that ends without a period, or a sentence that opens with a code span. Such a sentence is reported at the first line of the block that holds it or follows it. Its echo is empty or the block's first words. Backstop: the blanking; the echo of the sentence's start in L2, so a reader sees what was counted.
3. **The lists are lists.** A phrase in the forbidden list fires wherever the words stand. It fires in a name, in a quotation in running text, and in a sentence about the phrase. It fires inside a hyphenated word such as `self-sufficient` too, since a hyphen is a word boundary to the pattern. A Vale comment inside an indented code block, four spaces and no fence, is reported as L6. That is because the gate masks fences and code spans alone. The plain word of a pair is right for most sentences and wrong for some. Two words that only look like a passive — "is red", "is indeed" — are reported by the passive pattern. Backstop: code spans for a phrase mentioned rather than used; `exceptions`; the passive at warning by default.
4. **The hook shows the first findings that fit the cap of the cost and budget (item 3)**. It is the shared cap of limit 14 in [kit-shared-gate-code §4](../../shared/GATE.md#g4). The first is always shown. The count line says how many there are. The scan lists them all. A finding renders under the cap when its values are the ones that only point, cut at 80 characters. A path is bounded by the file system. In a fix, `{plain}` stands whole, escaped (the error messages above). It is a dial's text, which nothing here bounds. So a first finding holding a very long one can pass the platform's cap on its own. That is the break of limit 14 of [kit-shared-gate-code §4](../../shared/GATE.md#g4). Backstop: the count line; the scan; a plain word kept as short as it teaches.
5. **The hook sees a write through the file tools and nothing else.** A shell command, a merge, an editor: the shared limit 1. Backstop: the scan, in CI and before a merge.
6. **Nothing in a document switches a rule off,** and a Vale comment outside a fence or a code span is reported. But a consumer's own `.vale.ini` in the tree, and a `StylesPath` of its own, are never read by this gate. It passes `--config` and `--no-global`. So a consumer running Vale by hand beside this gate sees two configurations. Backstop: the install note says so; `exceptions`, `forbidden` and `simpler` for what the project wants the gate to know.
7. **A document that is not UTF-8** is read with its undecodable bytes replaced. So a count near such a byte may be off by a word. Backstop: the shared limit on encodings; review.
8. **The temporary directory** holds a copy of every covered document for the length of a run, in the system's temporary location. Backstop: removed when the run ends, however it ends.
9. **The envelope ends at the next line that is `---`**, its trailing whitespace ignored, wherever it stands. That is how the shared envelope reader reads it (shared limit 8), which the gate asks through `envelope_bounds`. The line meant to close the envelope may be no `---` line, for example because a form feed stands before the dashes. Then the next `---` line further down closes it, even a thematic break. The document is blanked up to that line, so the prose between is not read. An envelope with no later `---` line at all is not blanked (T7). And after a write, coverage is by pattern alone. A written file the patterns hold is judged though git ignores it, which the scan never lists (shared limit 7). Backstop: the sibling envelope gate. It reads an envelope closed by that later line as invalid when the text up to it is no YAML. It reads an envelope with no closer as unterminated. Backstop too: the scan's count, which says what it listed.
10. **A departure allows a rule in a document whole**, not on one line. One by path outlives its document until the scan's note is acted on. The note is not a finding, so a stale entry does not turn the scan red. The note is per entry, so an entry of several patterns with one that matches nothing is not stale. Backstop: the reason names what stands; N3 on every scan; review.
11. **The waits on `vale` are those of the cost and budget (item 2). They are bounded in the hook and in the version probe, and not in the scan's run.** A probe with no answer is the C12 `no answer in 5 s`. A run past its cap in the hook prints the C12 that names the scan, and the write goes on. In a hook each wait takes the smaller of its cap and what is left of the hook's deadline. What is left is asked as the wait begins (limit 16 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)). A wait may be given less than its cap by the deadline and then run out. It is then the shared [C12.14](../../shared/MESSAGES.md#g3) in place of the C12, naming `vale reported its version` or `vale finished its run`. The scan's run has no budget, so a `vale` that hangs there keeps the scan waiting until the CI job's own limit, with no teaching line. Backstop: the C12 lines; fixture T16 and the shared item S165, which hold the caps and the hook's timeout to the budget. Backstop too: the CI job's limit.
12. **The falling note compares with the last commit, not with the edit before.** A grade above the ceiling is the note N4 while it is below the grade of the document as `HEAD` holds it. An equal grade is L1. So an edit that raises the grade, but leaves it below the grade of the last commit, is a note too. A commit moves the baseline: after it, the next write must read below the grade just committed. The copy is the last commit's, never the index's, so a text that is only staged does not move the baseline. The hook reads it by `git cat-file`, as the commit stores it: no filter of the working tree is applied, and its line endings stay as stored. The hook decodes it as UTF-8 with a bad byte replaced. It prepares it as it prepares the written document, the envelope and every Vale comment blanked. A document the last commit does not hold has nothing to fall from. It may be a new document, one written under a new path, or any document in a repository with no commit. It may also be one whose committed copy git does not give under the written path. It is L1 at every write until it is committed, or is at or under the ceiling. A document that the last commit holds at or under the ceiling is L1 as well. The committed copy may be no prose of the document's own: a symbolic link, or the pointer text that a filter of the repository stores. Then the grade of that text is the baseline where Vale gives it one above the ceiling. Where Vale gives it none, the document is L1. Measured 2026-11-11 with Vale 3.23.0: six pointer texts of Git LFS each held another hash. Their grades ran from 6.42 at the lowest to 18.22 at the highest. A link's target of two long words read at 27.27, and a short target got no grade above a ceiling of 0. So a document may have such a text as its committed copy. It may be written at a grade above the ceiling and below the grade of that text. Then it is N4 at every write, whether its grade fell or not. The read is one git call of a hook. A git that gives no answer in 3 s ends the run in the shared C12.12 line. A call that the hook's deadline cut short, or that is asked after the deadline, ends it in the shared C12.14. Either is exit 1, and that write gets no verdict (limit 16 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)). Backstop: the note names both grades; the scan, which reads no commit and is red on every document whose grade is a finding.

**Exit codes**: `0` green, or nothing examined (the count line says which), a run after a write whose only report is the note N4 included. Exit `2` is a finding. A document is over the ceiling or the limit, or holds a phrase of a list at level error. Or it holds a Vale comment outside a fence or a code span. Exit `1` is a configuration failure — the checker could not run: the shared failures, this module's C2, C5 and C12.

## 11. Siblings

**Depends on:** [kernel §6](../../docs/constitution/CONVENTIONS.md#k6) — the dials file, where every threshold and level lives, and the territory dialect. Beside the kernel it needs the Python package `constitution-layer-kit`, which pip installs, as it needs Python and PyYAML. That package is the kit's shared gate code and no sibling ([law 3 of CLAUDE.md](../../CLAUDE.md#law-3)). It also needs two tools. The tool `git` lists the documents and resolves the territories. Without it every run is the shared configuration failure, and the skill and the pointer still load. The tool `vale` 3.23.0 or newer, preflighted after the repository is located, reads the prose. Without it every run is the configuration failure naming the install command, and Markdown writes pass unchecked. The skill and the pointer still load. Nothing else.

**Kernel alone, with that package installed:** the hook and the scan cover every Markdown file at the defaults. That holds on a bare repository with a `constitution.yaml` that holds `module_prefix` and no key of this namespace. The skill carries the six advisory rules. With no `constitution.yaml` at all every run is the shared visible skip naming the file.

**When module `const-interaction` is installed,** its session-start rule carries the chat half of the language aspect — plain chat language for the same reader. No hook can measure it. This module ships the document half alone. **When module `const-styling` is installed,** its scan holds the twelve markup signatures and this gate holds the prose. A rule about words that the styling guide founds may graduate here ([§12](#t12)). **When module `const-meta-types` is installed,** the envelope this gate blanks is checked there. Each is an optional enhancement; every rule here runs with the kernel alone.
