# MODULE.md — `const-referencing`

*Draft at manifest version `0.0.1`, no open slots; published at `0.1.0` in rollout Phase D. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A document is moved, a heading is reworded, a record is deleted — and every link that pointed there still reads as a link and leads nowhere, or to a neighbouring section that happens to carry the old heading's words. Nobody notices at the edit, because the break is in *other* files; it is found weeks later by a reader who can no longer tell what was meant. Beside the broken link stands the reference that never was one: a bare "see section 4", a row number, an id in backticks — forms that resolve only in the head of whoever wrote them, that no tool can follow, and that a rename cannot find. The kit observed both: its largest rename was repaired by hand, link by link, and one reference form ruled in a record was found uncarried a month later because nothing could search for it. This module makes a reference a thing a machine can follow and keep: one written form per kind, an anchor that does not depend on a heading's wording, a check of the whole tree that turns red on any reference that does not resolve, and a move that repairs what it breaks.

<a id="t2"></a>
## 2. Failure class

**Accumulating.** Every bare handle and every heading-derived anchor written today is one more to convert when the first move breaks them, and a broken reference is found only by the reader it fails. **Entry trigger:** the first cross-reference between two documents — in practice day one of any project with more than one governed document.

## 5. Invariant

**In a scanned tree every link of a covered document names a file that exists and, where it carries a fragment into a covered Markdown document, an explicit anchor that exists there; and a covered document written through the platform's file tools cites nothing by a form the lint refuses.** "Covered" is the dials `territories` and `governed_only` of [§7](#t7); territory, `id` and the dials file are the kernel's ([§1](../../kernel/CONVENTIONS.md#k1), [§3](../../kernel/CONVENTIONS.md#k3), [§6](../../kernel/CONVENTIONS.md#k6)); "a scanned tree" and "written through the platform's file tools" are the honest boundaries of [§9](#t9).

The advisory rules beside it, each `advisory` in its own text, are these. (F-a) Cite a governed document by its id as link text wherever it has one. (F-b) Give every citable unit an explicit anchor with a short fixed key, never rely on a heading's generated name, never change a key once cited. (F-c) Cite code by symbol name, file-qualified — a line range only as a pointer that is not meant to last. (F-d) A commit hash belongs in a commit message, a record's body or chat, never in a current-state document; a pull request is cited by its repository-qualified number, `owner/repo#n`, never a bare `#n`. (F-e) Move a document with the module's move act, never by hand, and never rewrite a prose mention without reading it. (F-f) In chat, every reference to a file is a link and a local handle names its scope when it crosses it.

The module's masking, link finding and anchor reading cost about 12 million characters a second (every `.md` under the kit, 549 documents, 9,119,298 characters, in 0.77 s; macOS, Python 3.12.4, probed 2026-10-08), so they alone take the 20 s at about 240 million characters of covered text, lychee's time not counted. **Error messages.** Each row is one function of this module's `messages.py`, under the same key; `{path}` is the document's repository-relative path and `{line}` a line number. Findings are `RED`, three lines each (what failed / why the rule exists / the exact fix), followed by the count line. The texts every gate shares are written out once, in [kit-shared-gate-code §3](../../shared/GATE.md#g3), with `{module}` standing for `const-referencing`. Every value taken from a document, a dial, the link checker, git, the command line or the environment goes through a shared helper, so a line break in it leaves the line one line. What the reader opens, copies, types or acts on is shown whole, its backslashes and line breaks escaped, never cut: every path (`{path}` and the owner, target and moved paths), a document id typed into a fix, an anchor or fragment, the lane's `fix`, and the one-line diagnoses of lychee and git. What only points — a match, the lane's `names`, a link's text, a document id shown as that text, a link's destination or target as written, the checker's words, an argument or a mention's line — is cut at 80 characters with the cut said, then escaped. The plugin's own path inside a pasteable command stays raw.

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | gate, hook mode | How loud a write-time finding is, for both handlers. `block`: exit 2 — the lint blocks the write; the post-write check reports as an error and **blocks nothing**, the write having happened. `warn`: exit 0 with the finding in one JSON object, for both. The scan ignores it. |
| `log_dir` | absent | gate, mover | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |
| `territories` | `["*.md"]` | gate, mover | The covered documents: path patterns in the dials file's dialect over the Markdown files git lists, tracked and untracked, ignored ones excepted; a negated pattern takes files out. |
| `governed_only` | `false` | gate, mover | `true` narrows coverage to documents that also lie in a policy's territory, the policies themselves included; it needs `root_policy`, and without one the run is a configuration failure — C5 for the gate in every mode, V5 for the mover — never a skip that lets a write through with nothing examined. |
| `heading_anchors` | `refuse` | gate | `allow` switches R7 off. |
| `bare_ids` | `refuse` | gate | `allow` switches R2 off — for a project whose ids are everyday words. |
| `local_paths` | `refuse` | gate | `allow` switches R4 off — for a project whose documents must show a container's or a build machine's home directory, in a fence or elsewhere. |
| `lanes` | `[]` | gate | The project's bare forms: a list of `{pattern, names, fix, home}` — a regular expression; what the form cites, in the project's words; the link form to write instead, printed as written; `home`, optional, patterns in the dials file's dialect of the documents where the form is the local alias and the lane is silent. The reason is the module's and no lane can replace it. A pattern is written in single quotes: one holding a control character — what double quotes make of `\b` — is a configuration failure, never a pattern that matches nothing. |
| `mentions` | `[]` | scan | Governed ids named outside Markdown: a list of `{pattern, files}` — a regular expression whose whole match must be a covered document's id, in single quotes as a lane's; `files`, optional, patterns in the dials file's dialect of the files read; absent or `[]`: every file git lists that is no Markdown, no link and not binary. |

Nothing of `lychee`'s configuration is a dial: the module owns the invocation. The gate validates every key it reads at each read, and a key of this namespace that is none of the nine above is a configuration failure: a misspelt `heading_anchor: allow` would otherwise be a setting ignored in silence.

## 8. Boundary examples

The lint, resolution and R7 are deterministic; the fixtures are their pairs. The judgment is the skill's.

**An id or a path (F-a):**

1. The target opens with an envelope → `[its-id](path)` / *not* `[the policy on records](path)`: the id as text is what the id repair works from.
2. The target is a script → a bare relative path in a link / *not* an invented id.
2a. The same document is cited five times in one page → the id as the text each time / *not* "ibid." or "the policy above": each link is found and repaired alone.
2b. A reference definition at the foot of the page → `[the-id][label]` reads as well as an inline link and is judged the same / *not* a label that opens another document than the id it shows.

**An anchor's key (F-b):**

3. `<a id="t7"></a>` before "7. Dials" → survives the heading becoming "7. Calibration" / *not* `#7-dials`.
4. A key is wrong but cited from six documents → it stays / *not* renamed to something prettier: a key is for machines.
5. A table row is cited → the anchor inside its first cell / *not* before the table: that cites the table.

**Code and hashes (F-c, F-d):**

6. "`read_event` in `events.py`" → survives edits above it / *not* "lines 19–50", unless the sentence is about today's diff.
6a. "`Parser.error` in `cli.py`" → qualified by class and file / *not* "the error method": three classes have one.
6b. A stack trace pasted into a record of what happened → its line numbers stay, it is evidence of that day / in a guide → *not*: cite the symbol.
7. "Fixed in 70b7c39" in a commit message → fine / in a policy → *not*: a rebuilt history leaves it pointing at nothing.
7a. A record of a decision says "applied in the commit that creates this record" → fine, it is a record's body / a current-state page says "since 70b7c39 the gate reads code" → *not*: say what the gate does.
7b. Chat: "that is 1de11cd on the branch" → fine / the same sentence copied into the install note → *not*.

**Moving (F-e):**

8. "Move the policies into `docs/policies/`" → the move act per file, then its list of mentions read one by one / *not* `git mv` and a search-and-replace: that rewrites code samples and sentences about the old place.
9. The act lists "`old/path.md` was where this lived until March" → left as it is: it means the old place / *not* rewritten because a tool found it.
9a. The act lists a script that opens the old path → the script gets the new path, by hand, and is run / *not* left because "the scan is green": the scan reads no script's paths.
9b. A file was already moved with `git mv` by someone else → the repair after a move made by hand, with both paths / *not* a second move back and forth to let the act see it.

**In chat (F-f):**

10. "see [MODULE.md](MODULE.md), section 7" → clickable / *not* "see the module doc".
11. "option B of the decision on coverage" in a later message → the scope named / *not* a bare "B" three messages on.
12. A file that does not exist yet is promised → plain words, "a new `notes.md`" / *not* a link that opens nothing.
13. "finding 3" inside the message that lists the findings → fine, the number is local there / in the commit message written an hour later → "finding 3 of the first validation".

## 9. Enforcement honesty

| # | artifact | kind |
|---|---|---|
| E1 | `PreToolUse` hook + `check-references` (hook mode): R1–R4 | `gate`, severity dial `severity` |
| E2 | `check-references --scan`: R1–R8 | `gate`, always exit 2 on a finding, ignores `severity` |
| E3 | `PostToolUse` hook + `check-references` (hook mode): R5–R7 for the written file | `gate` in kind — deterministic, red means fix — **at a moment that cannot block**: the write has happened. Under `block` it exits 2 so the finding reaches the model as an error, under `warn` it is a note; either way nothing is stopped, and the blocking moment for these findings is E2. Not `advisory`: nothing here shapes judgment, the check is the scan's own |
| E4 | `move-document`: the rewrites | `advisory` — a generator; its closing verdict is E2's check, which is the proof |
| E5 | `SessionStart` hook, skill `referencing` | `advisory` |

**Honest limits**, each with its backstop. The shared code's limits — [kit-shared-gate-code §4](../../shared/GATE.md#g4) — apply. This module's own:

1. **`block` blocks nothing after the write.** Backstop: the scan in CI.
2. **No `lychee`, no resolution check** — X1 on every write, exit 1, which the platform lets through. Backstop: the message is loud and names the install; the lint still blocks; CI's scan fails closed, since exit 1 fails a workflow.
3. **A move or deletion through the shell reaches no hook.** Backstop: the scan; the skill's last step; the move act itself.
4. **The post-write report is about the written file only**, so a break elsewhere, older than this write, is not repeated at every write. Backstop: the scan reports everything.
5. **Links inside code and inside HTML comments are neither checked nor repaired**, and neither is a link assembled by a template or a script. **A usage of a reference definition is judged but never rewritten**: its definition is the link, shared by every usage of the label, so the id repair leaves `[the-id][label]` alone even when the label opens another document — R3 reports it. Backstop: the mover lists mentions of the old path, code included.
6. **R7 judges only targets that are covered Markdown.** A fragment into an uncovered or non-Markdown file is the link checker's alone. An anchor made by a `{#id}` heading attribute is no explicit anchor here, because a forge renders it as text.
7. **File-name case follows the file system** the check runs on: a link in the wrong case passes on a case-insensitive disk and fails on CI's. Backstop: CI is the gate.
8. **Remote links are not checked**: the check is offline. **Masking is line-based**: an unclosed fence masks to the end of the file, code inside an HTML block is not seen as code, an indented block is taken for code only outside a list — under a list item it continues the item, while a fence indented under one is code — and a fence closes at its opener's depth, a tab counting four columns; a deeper fence shown inside it is content. **A footnote is no link**: a bare form in one is judged, a path in one is neither resolved nor rewritten, only listed by the mover. **R4 knows three layouts of a home directory and `file:`**; any other absolute path passes, and a container's own `/home/<user>/…` inside a fence is a finding until `local_paths: allow`, which switches R4 off whole.
9. **A lane is as good as its pattern**; a `fix` text that teaches badly is the project's. Backstop: the reason is fixed, and the install note shows a worked lane.
10. **R2 and R3 know only the ids of covered documents.** `mentions` matches examples in fixtures and comments too; its `files` patterns keep them out.
11. **Prose is never rewritten**, so a move leaves sentences naming the old place. Backstop: V3 lists each, in every text file git lists — a covered document, a Markdown file outside coverage, any other file — by the old path from the repository's top and from the file itself; a symbolic link outside coverage is not read. **Only covered documents are repaired — and the moved document itself, wherever it went**: a territory that leaves a tree out leaves its links as they are, and an id two documents carry is left alone by the id repair, since the envelopes do not say which is meant.
12. **A case-only rename is a move** where the file system ignores case, since the new name is the file itself. **The mover keeps every other character**: a file's line endings and its byte order mark survive a rewrite, and a document moved out of coverage still has its own links and the links to it repaired, since they were written where it lay. **Under `governed_only` with no root policy the gate and the mover both fail, exit 1**: the gate with C5 — non-blocking in hook mode as every configuration failure is (item 2 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)), red in the scan — and the mover with V5, before anything moves; neither skips, since a skip would let a write through with nothing examined. **A file git ignores is judged before its write and not after it**: the list of covered documents is git's, without what git ignores, so the skip line after the write names `territories` for a file the lint has just judged. **The mover can stop midway**: what can refuse is asked first, but a link checker that dies after the move, or a file that cannot be written, leaves a moved file and some rewrites; the closing line says so and names the scan. **The mover needs a work tree git can move in**; it refuses, changing nothing, when the target exists. It does not stage its rewrites, and a short moved file whose links were rewritten may show in git as a deletion and an addition.
13. **The fix lines of R3 and R5 print the plugin's path resolved**, `sh "<plugin root>/scripts/move-document.sh" …`, so that the line can be pasted into a shell — the model's Bash tool has no `${CLAUDE_PLUGIN_ROOT}` in its environment, observed 2026-09-22 on Claude Code 2.1.251, breaks: a Bash tool that exports the variable would let the fix line print it; quoted into a document, that path is a finding of R4 like any path on one machine. Backstop: the line is for the shell, and items 62 and 63 paste it there as printed.
14. **A line feed in the path of a covered Markdown document stops the scan, and the check after every write, with X3**, not with a finding on that file — probed 2026-10-04 with lychee 0.24.2 in a scratch repository: one covered document named with a line feed, the scan and the after-write run on another document both printed the X3 line, `Cannot parse inputs from arguments`, then the closing line `the check could not run — 0 documents examined`, exit 1, so the failure is loud and no reference is checked. A tracked Markdown file the territories leave out does not cause it: in the same probe, with the file left out, the run was green. The mover, whose last step is that scan, moves the file and then stops with X3 and its own midway line, as limit 12 says; this part is read from the code, not probed. The link checker takes its inputs one to a line and refuses the list, and the fix X3 prints, which blames the invocation or the installed checker and says the defect is not of the repository, is then wrong; the path is the cause. Since exit 1 in hook mode never blocks, the write stands. Backstop: git lists the path, so the file is renamed by hand and the scan run again. A path with a lone carriage return is read and judged like any other, and shown escaped (`\r`); item 39 holds it.
15. **A check after a write judges the tree only within one budget**: `HOOK_SECONDS`, 20 s, begins once the file list and the territory matching are done — their git calls have the shared budget of limit 16 of [kit-shared-gate-code §4](../../shared/GATE.md#g4) — and the read of the covered texts, their masking and lychee's run draw on it together. The clock is read after each document is read and after each is masked, never inside one, so one very large document still runs to its end; lychee's run is given what is left, but not under 0.01 s. The version probe's time counts against the budget, and the probe keeps its own 5 s, so it may use the remainder and leave the run 0.01 s. A budget spent before the version probe starts prints the third form of X3, which says the tree's reading and masking took it; a lychee run cut by its timeout, which is 0.01 s when the probe used the remainder, prints the second form; both name the whole 20 s and the scan, and block nothing. Backstop: the scan, which has no budget and waits for the reads, the masking and the run as long as they take. The other side of the same limit: a `lychee` whose run never answers keeps the scan waiting until the CI job's own limit, with no teaching line, while one that never answers `--version` fails in 5 s with X3 in every mode. **The mover's closing scan waits the same way**: it prints its MOVED and REWROTE lines, then passes no budget to lychee's run, and a `lychee` that never answers keeps it waiting until the Bash tool's timeout or the user stops it, without the midway line of limit 12 and with no teaching line; the mover's own git calls, `git mv` among them, have no clock either, as every call of an act has none (limit 16 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)).

**Exit-code contract** (gate and mover): `0` green, nothing examined (the count line says so), or a move whose closing check is green; `2` a finding — for the mover, the closing check's; `1` configuration failure: the shared ones, X1–X3, C5, V5. Nothing exits 0 on error. The `SessionStart` script is advisory and fails open by printing nothing.
