# MODULE.md — `const-referencing`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A document is moved, a heading is reworded, a record is deleted. Every link that pointed there still reads as a link. It leads nowhere, or to a neighbouring section that happens to carry the old heading's words. Nobody notices at the edit, because the break is in *other* files. It is found weeks later by a reader who can no longer tell what was meant. Beside the broken link stands the reference that never was one: a bare "see section 4", a row number, an id in backticks. These forms resolve only in the head of whoever wrote them. No tool can follow them, and a rename cannot find them. The kit observed both. Its largest rename was repaired by hand, link by link. One reference form ruled in a record was found uncarried a month later, because nothing could search for it. This module makes a reference a thing a machine can follow and keep. It gives one written form per kind, and an anchor that does not depend on a heading's wording. It gives a check of the whole tree that turns red on any reference that does not resolve. It gives a move that repairs what it breaks.

<a id="t2"></a>
## 2. Failure class

**Accumulating.** Every bare handle and every heading-derived anchor written today is one more to convert when the first move breaks them. A broken reference is found only by the reader it fails. **Entry trigger:** the first cross-reference between two documents — in practice day one of any project with more than one governed document.

## 5. Invariant

**In a scanned tree every link of a covered document names a file that exists. Where such a link carries a fragment into a covered Markdown document, it names an explicit anchor that exists there. And a covered document written through the platform's file tools cites nothing by a form the lint refuses.** "Covered" is the dials `territories` and `governed_only` of [§7](#t7). Territory, `id` and the dials file are the kernel's ([§1](../../docs/constitution/CONVENTIONS.md#k1), [§3](../../docs/constitution/CONVENTIONS.md#k3), [§6](../../docs/constitution/CONVENTIONS.md#k6)). The phrases "a scanned tree" and "written through the platform's file tools" are the honest boundaries of [§9](#t9).

The advisory rules beside it:

1. **F-a** — advisory. Cite a governed document by its id as link text wherever it has one.
2. **F-b** — advisory. Give every citable unit an explicit anchor with a short fixed key, never rely on a heading's generated name, never change a key once cited.
3. **F-c** — advisory. Cite code by symbol name, file-qualified — a line range only as a pointer that is not meant to last.
4. **F-d** — advisory. A commit hash belongs in a commit message, a record's body, a dated comparison, a dated statement of evidence or of done work, or chat. It never belongs in a sentence that states how things are. A pull request is cited by its repository-qualified number, `owner/repo#n`, never a bare `#n`.
5. **F-e** — advisory. Move a document with the module's move act, never by hand, and never rewrite a prose mention without reading it.
6. **F-f** — advisory. In chat, every reference to a file is a link and a local handle names its scope when it crosses it.

|---|---|---|---|
| `severity` | `block` | gate, hook mode | How loud a write-time finding is, for both handlers. `block`: exit 2 — the lint blocks the write; the post-write check reports as an error and **blocks nothing**, the write having happened. `warn`: exit 0 with the finding in one JSON object, for both. The scan ignores it. |
| `log_dir` | absent | gate, mover | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |

| `governed_only` | `false` | gate, mover | `true` narrows coverage to documents that also lie in a policy's territory, the policies themselves included. | `bare_ids` | `refuse` | gate | `allow` switches R2 off — for a project whose ids are everyday words. |

| `mentions` | `[]` | scan | Governed ids named outside Markdown: a list of `{pattern, files}`. ## 8. Boundary examples

The lint, resolution and R7 are deterministic; the fixtures are their pairs. The judgment is the skill's.

**F-a** — an id or a path:

- **1.** The target opens with an envelope → `[its-id](path)` / *not* `[the policy on records](path)`: the id as text is what the id repair works from.
- **2.** The target is a script → a bare relative path in a link / *not* an invented id.
- **2a.** The same document is cited five times in one page → the id as the text each time / *not* "ibid." or "the policy above". Each link is found and repaired alone.
- **2b.** A reference definition at the foot of the page → `[the-id][label]` reads as well as an inline link. It is judged the same / *not* a label that opens another document than the id it shows.

**F-b** — an anchor's key:

3. `<a id="t7"></a>` before "7. Dials" → survives the heading becoming "7. Calibration" / *not* `#7-dials`.
4. A key is wrong but cited from six documents → it stays / *not* renamed to something prettier: a key is for machines.
5. A table row is cited → the anchor inside its first cell / *not* before the table: that cites the table.

**F-c** — code:

- **6.** "`read_event` in `events.py`" → survives edits above it / *not* "lines 19–50", unless the sentence is about today's diff.
- **6a.** "`Parser.error` in `cli.py`" → qualified by class and file / *not* "the error method": three classes have one.
- **6b.** A stack trace pasted into a record of what happened → its line numbers stay. It is evidence of that day / in a guide → *not*: cite the symbol.

**F-d** — hashes:

- **7.** "Fixed in 3a9e2f1" in a commit message → fine / in a policy → *not*: a rebuilt history leaves it pointing at nothing.
- **7a.** A record of a decision says "applied in the commit that creates this record" → fine. It is a record's body / a current-state page says "since 3a9e2f1 the gate reads code" → *not*: say what the gate does.
- **7b.** Chat: "that is c4d8b07 on the branch" → fine / the same sentence copied into the install note → *not*.
- **7c.** A dated proof says "the workflow cloned the repository at 4f2c9d1" → fine. It is evidence of that day. So is a dated comparison that names the tree it read. So is a dated line of done work that names the commit a tag was made on. / A sentence of the same page that states how things are says "the scan runs in CI since 4f2c9d1" → *not*: say what runs.

**F-e** — moving:

- **8.** "Move the policies into `docs/policies/`" → the move act per file, then its list of mentions read one by one / *not* `git mv` and a search-and-replace. That rewrites code samples and sentences about the old place.
- **9.** The act lists "`old/path.md` was where this lived until March" → left as it is: it means the old place / *not* rewritten because a tool found it.
- **9a.** The act lists a script that opens the old path → the script gets the new path, by hand, and is run. / *not* left because "the scan is green". The scan reads no script's paths.
- **9b.** A file was already moved with `git mv` by someone else → the repair after a move made by hand, with both paths. / *not* a second move back and forth to let the act see it.

**F-f** — in chat:

10. "see [MODULE.md](MODULE.md), section 7" → clickable / *not* "see the module doc".
11. "option B of the decision on coverage" in a later message → the scope named / *not* a bare "B" three messages on.
12. A file that does not exist yet is promised → plain words, "a new `notes.md`" / *not* a link that opens nothing.
13. "finding 3" inside the message that lists the findings → fine. The number is local there / in the commit message written an hour later → "finding 3 of the first validation".

**Honest limits.** The limits every gate shares: [kit-shared-gate-code §4](../../shared/GATE.md#g4). This module's own, each with its backstop or `none — accepted` and the reason:

1. **`block` blocks nothing after the write.** Backstop: the scan in CI.
2. **No `lychee`, no resolution check** — X1 on every write, exit 1, which the platform lets through. Backstop: the message is loud and names the install; the lint still blocks; CI's scan fails closed, since exit 1 fails a workflow.
3. **A move or deletion through the shell reaches no hook.** Backstop: the scan; the skill's last step; the move act itself.
4. **The post-write report is about the written file only**, so a break elsewhere, older than this write, is not repeated at every write. Backstop: the scan reports everything.
5. **Links inside code and inside HTML comments are neither checked nor repaired**, and neither is a link assembled by a template or a script. **A usage of a reference definition is judged but never rewritten**. Its definition is the link, shared by every usage of the label. So the id repair leaves `[the-id][label]` alone even when the label opens another document; R3 reports it. Backstop: the mover lists mentions of the old path, code included.
6. **R7 judges only targets that are covered Markdown.** A fragment into an uncovered or non-Markdown file is the link checker's alone. An anchor made by a `{#id}` heading attribute is no explicit anchor here, because a forge renders it as text. Backstop: none — accepted. R7 is the rule for the documents the project covers, and a file outside coverage is not the project's to anchor. The link checker still resolves a fragment into an uncovered Markdown file, through its headings too. It passes one into a file that is no Markdown or HTML unchecked (comparison, a4).
7. **File-name case follows the file system** the check runs on. A link in the wrong case passes on a case-insensitive disk and fails on CI's. Backstop: CI is the gate.
8. **Remote links are not checked**: the check is offline. **Masking is line-based**: a line ends at a line feed, a carriage return or both, and nowhere else. So a form feed inside a fenced line closes no fence. An unclosed fence masks to the end of the file, and code inside an HTML block is not seen as code. An indented block is taken for code only outside a list. Under a list item it continues the item, while a fence indented under one is code. A fence closes at its opener's depth, a tab counting four columns; a deeper fence shown inside it is content. **A footnote is no link**: a bare form in one is judged. A path in one is neither resolved nor rewritten, only listed by the mover. **R4 knows three layouts of a home directory and `file:`**. Any other absolute path passes. A container's own `/home/<user>/…` inside a fence is a finding until `local_paths: allow`, which switches R4 off whole. Backstop: the mover lists a footnote's path. For the rest none — accepted. The check resolves the repository's files and goes to no network. The masking is a line-based reading because no surveyed Python parser gives an inline link's position (comparison, h2, E13). The one that does is a compiled wheel that warns against itself (h3). And R4 judges the three layouts it names.
9. **A lane is as good as its pattern**; a `fix` text that teaches badly is the project's. Backstop: the reason is fixed, and the install note shows a worked lane.
10. **R2 and R3 know only the ids of covered documents.** `mentions` matches examples in fixtures and comments too. Backstop: its `files` patterns keep them out.
11. **Prose is never rewritten**, so a move leaves sentences naming the old place. Backstop: V3 lists each, in every text file git lists: a covered document, a Markdown file outside coverage, any other file. It finds each by the old path from the repository's top and from the file itself. A symbolic link outside coverage is not read. **Only covered documents are repaired — and the moved document itself, wherever it went**. A territory that leaves a tree out leaves its links as they are. An id two documents carry is left alone by the id repair, since the envelopes do not say which is meant.
12. **A case-only rename is a move** where the file system ignores case, since the new name is the file itself. **The mover keeps every other character**: a file's line endings and its byte order mark survive a rewrite. A document moved out of coverage still has its own links and the links to it repaired, since they were written where it lay. **Under `governed_only` with no root policy the gate and the mover both fail, exit 1**. The gate fails with C5, red in the scan. In hook mode C5 is non-blocking, as every configuration failure is (item 2 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)). The mover fails with V5, before anything moves. Neither skips, since a skip would let a write through with nothing examined. **A new file git ignores is skipped before its write and after it**. The covered documents are the Markdown files git lists, without what git ignores. The check before a write asks git, by one `git check-ignore`, about a written file that its territories hold and git does not list. So both skip lines name `territories`. A file git lists stays covered, whatever the ignore rules say of it. **The mover can move a file back, or stop midway.** What can refuse without moving is asked first. A move is then made with git, and the act plans on the tree as git lists it. It reads every covered document, and the moved one wherever its new path is Markdown. It opens each one it will rewrite for writing, before it writes anything. The moved document is refused when nobody can read it, even outside coverage, where no scan would see its broken links. A file that is not UTF-8 is left alone, as V1 to V4 say. A failure of that plan moves the file back and removes the folders the move made. Git's status, the index, every folder and every file are then as they were, save the edges below. A folder's time and the moved file's change time may differ. `--moved` and `--ids` plan on the tree as it stands. The check cannot hold what follows. A file's permissions or text may change between the check and the write, and a text edit made there is lost without a word. A disk may fill, and since a rewrite empties a file first, a document may be left cut short or empty. As root a mode bit denies nothing, so no read-only mode is refused. A move back that fails is said, with where the file is. The shared entry catches no interrupt, so after one no closing line is printed, only a traceback. An interrupt during the plan still moves the file back. If git then refuses the move back, the file stays at its new path, and no line says where. One during the writes leaves the rewrites made so far, with no midway line. One during the move itself may leave the file moved and the made folders standing. 5. **Changing an id as an act.** The kernel allows three changes of an id. The first is the renumbering of an item not yet landed that meets, at a pull request, a landed item under its number. The second is that of the landed item that came second where two items of one catalog share a number. The third is the one rename of each document of a kind that becomes numbered, or of a numbered kind whose form changes. A kind's form changes, for one, when its width is widened. When module `const-catalogs` is installed, its skill has the procedure for the two renumberings. That module's install guide has the one for the adoption rename, and [§11](#t11) says what the move act does for a renumbering. That module's rule C-c and its skill have the procedure for a widening too; limit 8 of that module settles it with the project. Any other change of an id stays a recorded migration made by hand. Signal: a consumer reports links by an old id left unrepaired after a renumbering or a rename of one of those three kinds.
6. **Effect rules for the move act and the start text.** The effect report counts no rule for a move made by the shell instead of the mover. It counts none for the two sentences printed at session start besides the chat rule W6. Signal: breaks that reach CI after a move by `git mv` in sessions, or a consumer who asks what the pointer line changes.
7. **A reader rule.** No rule of [§13](#t13) needs a reader: each one has a pattern that sees it. W6 judges a link by form and cannot tell whether the file exists. So a name that is no file, such as an example, counts as missed. Signal: a consumer reports many such names in the count of W6.
