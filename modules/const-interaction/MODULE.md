# MODULE.md — `const-interaction`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A short, vague request is answered by a page: a yes/no question opens with three paragraphs and the word comes last; a request for a value comes back as an explanation; the assumption that made the answer possible is never said, so the user cannot correct it; a list of findings has no handles, so the user quotes a sentence to point at one; a wrong request is carried out with a softened note, or a failure is reported as done because it was not verified. Observed in the kit's own sessions: four guide bullets, each written after such a session, and "Lead with the answer" from the first day — five rules carried by hand — and a sixth, "Refuse destructive moves without a spoken confirmation", after an unasked history rewrite; `git reset`, `git checkout -- .` and `rm -rf` remain one keystroke from an unwarned session. This module states the answer shape as rules a session carries always, and puts one deterministic gate in front of the enumerated destructive commands.

<a id="t2"></a>
## 2. Failure class

`self-limiting`: a long answer, a missing assumption line, an unnumbered list are each felt by the reader at once and corrected in the session — nothing compounds in the repository. The one exception is the destructive act, whose damage is immediate and sometimes final; that slice is the gate. **Entry trigger:** the same correction on the shape of a reply recurs across sessions — a guide edit or a commit note on answer length, a silent assumption, an unaddressable list or a softened finding, made twice or more; the kit passed it with five guide bullets on one theme. A single unconfirmed destructive command is trigger enough for the gate alone.

## 5. Invariant

**No command of the platform's `Bash` tool whose reading matches an entry of the `destructive` dial runs without the platform having asked the user; wherever the `PowerShell` tool is the shell, the gate examines nothing and says nothing ([§9](#t9), limit 9).** "Reading": the command split as the platform splits it for its own rules — on `&&`, `||`, `;`, `|`, `|&`, `&` and newlines outside quotes — a redirection's `&` is none — a bare subshell's parentheses as separators, the contents of every `$(…)` and backtick pair, a backslash-newline joined, a heredoc body dropped where its operator stands outside quotes and its terminator line exists. Two kinds of string are split in turn: the strings a shell is told to run — every command flag it is given yields one, `bash -c`, `sh -lc`, fish's `-C` and `-c` both, the value of an option that takes one skipped, a `--` after the flag too — and the string a wrapper's command option names (`env -S`, `flock -c`) with the words after it. Each piece's words split by shell quoting, a leading assignment, a shell word (`if`, `then`, `else`, `elif`, `fi`, `while`, `until`, `do`, `done`, `{`, `}`, `!`) and a wrapper, by name or by path, with its own options and their values stripped, the program reduced to its base name. The wrappers and the shells are those of the dials `wrappers` and `shells` — the defaults of [§7](#t7), merged with what the dials file gives, a default dropped only by `drop: true` — and one option rule reads both: a word that starts with `-`, for a shell `+` too, is an option; `--` ends the options; `--name=value` is one word; a wrapper's short cluster is read a letter at a time, and the first letter that takes a value ends it, its value the rest of the word or else the next word. A shell's cluster is read two ways and the strings of either are read, each once: bash's, each valued letter taking the next word whatever its place, and zsh's and ksh's, the cluster's command-flag letters taken out first and the first valued letter of those left taking the letters after it, else the next word; a command-flag letter anywhere in the cluster is a command flag in both; the command flag then takes the next word, else the first operand. After a wrapper's options come its plain positional words, then up to its count of words that are numbers, then a command option; a command option's value and the words after it are the command. A shell's command flag takes its attached value (`--command=x`), else the next word when that is no option and no other option's value, else the first operand after the options; a word taken as a string is read once, and the words after the strings are arguments, not read. `exec` is a wrapper with a valued `-a`, no longer a shell word. No program's options are skipped by name, git's included: they stay in the words and the matching steps over them. "Matches": the entry's first word is the piece's program, and each later word follows it in order with only options between — words that start with `-`, a lone `-` excepted — and the one value after an option written without `=`; any other word between, or `--`, is no match, and a word equal to the wanted one is read as it, even where it could be an option's value. Where the entry lists flags, one of them stands after the entry's last word and before any `--` — a short flag anywhere inside a cluster, a long flag as the whole token. "Asked": the gate answers the platform's `ask` decision with the entry's teaching text, and the platform prompts the user, or denies the call with that text where no prompt can be shown. A second gate, scan-only, holds the list-handles rule of [§3](#t3): **no top-level bullet list of two or more items in a covered document, outside a fenced block, has an item that opens with no form of the `handles` dial**.

The advisory rules beside it, each `advisory` in its own text and carried always-on, each the reading of one row of [§3](#t3); `plugin/scripts/rules.txt` holds the words the hook prints:

The default entries of `destructive` — fourteen, each as `entry`: "the text D1 teaches" → "the alternative it names", as the code has them word for word (decision [dec-0042-interaction-module-rulings](../../docs/decisions/dec-0042-interaction-module-rulings.md#r8), R8):

1. `git push` with `--force` or `-f`: "a forced push rewrites the branch on the remote: every other clone of it diverges, and the commits it replaced are unreachable there" → "push with --force-with-lease, which refuses when the remote moved, or push a new branch and open a pull request"
2. `git reset` with `--hard`: "a hard reset discards every uncommitted change in the working tree and the index; nothing brings them back" → "run git stash first, or reset with --keep, which stops when a change would be lost"
3. `git checkout` with `-f` or `--force`: "a forced checkout throws away local changes to the files it switches; nothing brings them back" → "run git stash first, then check out; or commit the changes on a branch"
4. `git restore`, the words alone: "git restore discards the working-tree changes of the paths it names; nothing brings them back" → "run git stash first, or git diff to see what would be lost, then restore one path at a time"
5. `git clean` with `-f` or `--force`: "git clean deletes untracked files, which no commit holds; nothing brings them back" → "run git clean -n first to see what would go, then move what matters out of the tree"
6. `git branch` with `-D` or `-f` or `--force`: "-D deletes a branch whether or not it is merged, and -f moves one to another commit: the commits left behind become unreachable" → "delete with -d, which refuses an unmerged branch, or tag the tip first (git tag keep/<name>)"
7. `git stash drop`, the words alone: "a dropped stash is unreachable; nothing lists it again" → "apply it with git stash branch <name>, or leave it in the list"
8. `git stash clear`, the words alone: "clear drops every stash at once; nothing lists them again" → "drop one at a time after applying it with git stash branch <name>"
9. `git rebase`, the words alone: "a rebase rewrites the commits of the branch: their hashes change, and a branch others hold diverges from theirs" → "tag the tip first (git tag keep/<name>), or make the change on a new branch and merge"
10. `git filter-branch`, the words alone: "filter-branch rewrites history across every commit it touches" → "clone the repository first, and rewrite the clone"
11. `git filter-repo`, the words alone: "filter-repo rewrites history across every commit it touches" → "clone the repository first, and rewrite the clone"
12. `git reflog expire`, the words alone: "expiring the reflog removes the record that lets a lost commit be found again" → "leave the reflog; disk is cheaper than a lost commit"
13. `git gc` with `--prune=now`: "pruning now deletes every unreachable object at once, including those the reflog would have let you recover" → "run git gc without --prune=now, which keeps recent unreachable objects"
14. `rm` with `-r` or `-R` or `--recursive`: "a recursive rm deletes a directory tree outside git; nothing brings it back" → "use git rm for tracked files, or move the directory to a scratch location first"

**Honest limits.** The limits every gate shares: [kit-shared-gate-code §4](../../shared/GATE.md#g4). This module's own, each with its backstop:

1. **The list is the gate; the class is not.** An interpreter one-liner, a script file that deletes, a shell function or an alias, a deletion through a file tool, an API call, a database client's `DROP` inside a quoted argument: none matches an entry, and the gate says of every unlisted command only that it did not match. Backstop: rule I-h on the carrier; the consumer's own entries.
2. **The argument form is not expressible.** `git checkout -- .`, `git branch -D main` against any branch and a refspec with a leading `+` need a value the entries cannot name; `git restore` and `git rebase` are therefore gated whole, which prompts on recoverable acts too. Backstop: the consumer tunes the list; the deferred form of [§12](#t12).
3. **Headless, the ask is a block.** Where no prompt can be shown the platform denies the call with the teaching text, and the model reports the block and waits. Backstop: the user's yes in chat, then the command run again — which prompts again, one yes per command by construction.
4. **The reading is best-effort where the shell is cleverer than the reader.** Where the reader cannot split a text cleanly it errs toward examining more. Backstop: the explain, `--scan --command`, shows the reading of any command.
   - **Not seen, and passes:** a command built from a variable (`$CMD`, `git ${x:-push}`), an `eval`, a verb with an escaped space (`git\ push`, one word), a here-string, a heredoc body that feeds `sh`, an interpreter's `-c` string, `find -delete`, and a heredoc operator inside a quote opened on an earlier line, which is read as outside it and drops its body. A wrapper or a shell no list names: `watch`, `script`, `nix-shell --run`, `pwsh -c`, and a runner such as `uv run` until an entry of `wrappers` names it. An option no list holds, whose value is then read as the program: a flag a man page leaves out or a later version adds, a long option abbreviated, which GNU accepts, a long shell option the reader does not know takes a value, an abbreviated command flag (fish's `--init-cmd` for `--init-command`). An option between the words of a multi-word wrapper, `uv --quiet run rm -rf b` for `[uv, run]`. A string that fish takes with its value attached to the short flag, `fish -c'rm -rf b'`.
   - **Read though it runs less, so it asks without need:** a comment, since it is read as text: one that holds a separator and a listed command asks. An option's value that equals the next word of an entry: `kubectl -n delete get pods` asks for the entry `[kubectl, delete]`. A POSIX shell given `-c` twice: `bash -c a -c b` reads the later string too.
5. **The list scan reads a grammar, not the rule.** A bold label, a link or a code span that the rule accepts as a key is invisible to it unless the `handles` dial names the form; an item keyed by prose alone is a finding the rule would not make; nested items are their parent's; a numbered list is handled by construction; an unclosed fence hides everything after it. Backstop: the dial; the kit's own calibration in `constitution.yaml`.
6. **The rules are context, not enforcement.** An essay, a silent assumption, a softened finding: no file shows any of them, and the carrier only makes the rules present. Backstop: the seed pairs and the project's own; the friction signal of [§12](#t12).
7. **A `SessionStart` that fails prints its failure to stderr,** which the user sees and the model does not; the rules, printed by the POSIX wrapper before Python runs, still reach the model. Backstop: the log; the exit code 1.
8. **A hook on every shell call costs a process each time** (the cost sub-slot of [§6](#t6)). Backstop: the hooks file's timeout; `severity` cannot switch the process off, only the plugin can.
9. **The gate is silent wherever the `PowerShell` tool is the shell.** The hook's matcher is `Bash` ([§6](#t6), platform fact 9): a command of the `PowerShell` tool reaches no hook of this module, and neither the gate nor the session start says so. Backstop: rule I-h on the carrier; the `PowerShell(...)` permission rules of the platform; the deferred widening of [§12](#t12).

This module's exit codes: `0` green, nothing examined, or — the shell gate at `block` — a match answered with the `ask` decision; `2` a finding in a scan; `1` a configuration failure, the shared failures and this module's C5 and C12.
