# MODULE.md — `const-interaction`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*


<a id="t1"></a>
## 1. Purpose

A short, vague request is answered by a page: a yes/no question opens with three paragraphs of context and the word arrives at the end, if at all; a request for a value comes back as an explanation; the assumption that made the answer possible is never said, so the user cannot correct it; a list of findings has no handles, so the user quotes a sentence to point at one; a request that is wrong is carried out with a softened note, or a failure is reported as done because it was not verified. Observed in the kit's own sessions: the "Restate before acting", "Assumptions are always explicit", "Every list item is addressable" and "Honesty over agreement" bullets of the kit's session guide were each written after such a session, and "Lead with the answer" was there from the first day — five rules carried by hand in a guide the module exists to replace. On the escalation side, the same sessions produced the "Refuse destructive moves without a spoken confirmation" bullet after an unasked history rewrite, and `git reset`, `git checkout -- .` and `rm -rf` on a scratch tree remain one keystroke from a session that never learned the rule. This module states the answer shape as rules a session carries always, and puts one deterministic gate in front of the enumerated destructive commands.

<a id="t2"></a>
## 2. Failure class

`self-limiting`: a long answer, a missing assumption line, an unnumbered list are each felt by the reader at once and corrected in the session — nothing compounds in the repository. The one exception is the destructive act, whose damage is immediate and sometimes final; that slice is the gate, and it is still self-limiting in the sense that each event is one, never a growing debt. **Entry trigger:** the same correction on the shape of a reply recurs across sessions — a session-guide edit or a commit note on answer length, a silent assumption, an unaddressable list or a softened finding, made twice or more; the kit passed it with five guide bullets on one theme. A single unconfirmed destructive command is trigger enough for the gate alone.

## 5. Invariant

**No command of the platform's shell tool whose reading matches an entry of the `destructive` dial runs without the platform having asked the user.** "Reading": the command split as the platform splits it for its own rules — on `&&`, `||`, `;`, `|`, `|&`, `&` and newlines outside quotes — a redirection's `&` is none — a bare subshell's parentheses as separators, the contents of every `$(…)` and backtick pair, the string after a shell's `-c` (`bash -c`, `sh -lc`, an `-o`, `-O`, `--rcfile` or `--init-file` option's value skipped, a `--` after the `-c` too) and the string `env -S` names — the flag as a token, attached, in a cluster or long — with the words after it, split in turn, a backslash-newline joined, a heredoc body dropped where its operator stands outside quotes and its terminator line exists; each piece's words by shell quoting, a leading assignment, a shell word (`exec`, `if`, `then`, `else`, `elif`, `fi`, `while`, `until`, `do`, `done`, `{`, `}`, `!`) and a wrapper (`sudo`, `doas`, `env`, `nohup`, `timeout`, `nice`, `time`, `xargs`, `command`, `builtin`, `stdbuf`, `noglob`, by name or by path) with its own flags and their values stripped, the program reduced to its base name, git's global options before the verb skipped. "Matches": the entry's words are the piece's first words, and, where the entry lists flags, one of them stands after those words and before any `--` — a short flag anywhere inside a cluster, a long flag as the whole token. "Asked": the gate answers the platform's `ask` decision with the entry's teaching text, and the platform prompts the user, or denies the call with that text where no prompt can be shown. A second gate, scan-only, holds the list-handles rule of [§3](#t3): **no top-level bullet list of two or more items in a covered document, outside a fenced block, has an item that opens with no form of the `handles` dial**, after an optional anchor and, for a form that is not itself bold, an optional bold marker.

The advisory rules beside it, each `advisory` in its own text and carried always-on:

- **I-a.** The expected shape of the answer is classified from the question — yes/no, a value, a short list, an explanation, a deliverable — and the reply matches it: a yes/no question is answered with the word first, the qualification after; a value with the value; a "why" with the reason; a deliverable with the thing itself. *Advisory.*
- **I-b.** The answer stands first. Elaboration follows only when asked for, or when the answer cannot be trusted without one clause of it. *Advisory.*
- **I-c.** Every assumption made while reading the request or doing the work is listed in the reply that delivers the work, one line each, under a heading of its own; when none was made, no such block appears. An assumption that would change the work materially is a question, priced by the stakes triage of the constitution's conventions page the project adopted. *Advisory.*
- **I-d.** A request that is wrong, unreasonable or in conflict with the governing rules is said to be so, with the reason, even after the user has decided and the work proceeds. A finding is never softened, a failure never hidden, and work that was not verified is never reported as done: the reply says what was run and what was not. *Advisory.*
- **I-e.** Every list, table and option set carries a stable per-item handle — a number, a letter or a short key — so that one item can be cited without quoting it; table rows carry a key column or numbers; a handle is scoped to its message, decision or document, and is named with that scope across the boundary. *Advisory.*
- **I-f.** A procedural gap met at routine stakes is closed by a reasonable call and one line in the commit note; one met at recorded stakes stops the work and is put to the decider, and the answer is recorded as the conventions page asks. *Advisory.*
- **I-g.** A procedure at recorded stakes that the project has not written — a numbering scheme, a review flow, a merge rule — is never invented on the spot: the gap is named and the procedure proposed as a decision. *Advisory.*
- **I-h.** Before any hard-to-reverse act — a deletion, a history rewrite, a force push, dropping a definition others rely on, breaking a published contract — the consequence and the reversible alternative are stated and an explicit yes in chat is waited for; one yes covers one act; a request repeated after the warning is the user's decision, done with the objection noted in the commit. The gate holds the enumerated command patterns; everything else in the class is this rule. *Advisory.*
- **I-i.** Chat is written in plain language for a reader whose first language is not English: short sentences, common words, no idiom, a term defined at its first use. *Advisory.*

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | shell gate, hook mode | `block`: a matching command is answered with the `ask` decision and the platform prompts the user, or denies the call with the teaching text where no prompt can be shown. `warn`: the match is reported to the model and the user in one JSON object and the command runs — the adoption path onto a repository whose scripts the list would stop at every turn. The explain ignores it. |
| `log_dir` | absent | every entry point | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |
| `destructive` | the fourteen entries below | shell gate, printer | A list of entries `{command: [<words>], flags: [<flags>], teach: <text>, alternative: <text>}`, matched as [§5](#t5) states; `flags` optional, any one of them matching; an empty list gates nothing and the printer says so at every session start; a malformed entry is a configuration failure naming it. What the list leaves out is named in [§9](#t9). |
| `territories` | `["*.md"]` | list scan | The documents the scan reads: path patterns in the dials file's dialect over the Markdown files git lists, tracked and untracked, ignored ones excepted; a negated pattern takes files out — an accepted record or a frozen comparison that a later rule may not edit, by its number range, never a wildcard that would hide finished documents with it. Empty: refused. |

The default entries of `destructive` — fourteen, each with the text D1 teaches and the alternative it names, as the code has them word for word (decision [dec-0042-interaction-module-rulings](../../docs/decisions/dec-0042-interaction-module-rulings.md), R8):

1. `git push` with `--force` or `-f` — teaches: "a forced push rewrites the branch on the remote: every other clone of it diverges, and the commits it replaced are unreachable there" — alternative: "push with --force-with-lease, which refuses when the remote moved, or push a new branch and open a pull request"
2. `git reset` with `--hard` — teaches: "a hard reset discards every uncommitted change in the working tree and the index; nothing brings them back" — alternative: "run git stash first, or reset with --keep, which stops when a change would be lost"
3. `git checkout` with `-f` or `--force` — teaches: "a forced checkout throws away local changes to the files it switches; nothing brings them back" — alternative: "run git stash first, then check out; or commit the changes on a branch"
4. `git restore`, the words alone — teaches: "git restore discards the working-tree changes of the paths it names; nothing brings them back" — alternative: "run git stash first, or git diff to see what would be lost, then restore one path at a time"
5. `git clean` with `-f` or `--force` — teaches: "git clean deletes untracked files, which no commit holds; nothing brings them back" — alternative: "run git clean -n first to see what would go, then move what matters out of the tree"
6. `git branch` with `-D` or `-f` or `--force` — teaches: "-D deletes a branch whether or not it is merged, and -f moves one to another commit: the commits left behind become unreachable" — alternative: "delete with -d, which refuses an unmerged branch, or tag the tip first (git tag keep/<name>)"
7. `git stash drop`, the words alone — teaches: "a dropped stash is unreachable; nothing lists it again" — alternative: "apply it with git stash branch <name>, or leave it in the list"
8. `git stash clear`, the words alone — teaches: "clear drops every stash at once; nothing lists them again" — alternative: "drop one at a time after applying it with git stash branch <name>"
9. `git rebase`, the words alone — teaches: "a rebase rewrites the commits of the branch: their hashes change, and a branch others hold diverges from theirs" — alternative: "tag the tip first (git tag keep/<name>), or make the change on a new branch and merge"
10. `git filter-branch`, the words alone — teaches: "filter-branch rewrites history across every commit it touches" — alternative: "clone the repository first, and rewrite the clone"
11. `git filter-repo`, the words alone — teaches: "filter-repo rewrites history across every commit it touches" — alternative: "clone the repository first, and rewrite the clone"
12. `git reflog expire`, the words alone — teaches: "expiring the reflog removes the record that lets a lost commit be found again" — alternative: "leave the reflog; disk is cheaper than a lost commit"
13. `git gc` with `--prune=now` — teaches: "pruning now deletes every unreachable object at once, including those the reflog would have let you recover" — alternative: "run git gc without --prune=now, which keeps recent unreachable objects"
14. `rm` with `-r` or `-R` or `--recursive` — teaches: "a recursive rm deletes a directory tree outside git; nothing brings it back" — alternative: "use git rm for tracked files, or move the directory to a scratch location first"

Every entry point validates the whole namespace at each read, and a key of this namespace that is none of the seven above is a configuration failure: a misspelt `destructiv:` would otherwise read as the dial unset, and the default list would gate in silence what the consumer meant to change.

## 8. Boundary examples

Each pair reads *violates / complies*; the pairs are the definition and are carried by this document — no session sees them; the project's own arrive through the dial `boundary_examples` ([§7](#t7)) and are printed at every session start.

**Answer shape** ([A7.1](../../docs/requirements.md#a7-1), [A7.3](../../docs/requirements.md#a7-3)):

1. "Is the branch merged?" → three paragraphs on the branch's history ending in "so, not yet" / "No. The range check is still red on one commit; the fix is one trailer."
2. "Which version is on main?" → the release process explained, the number in the last line / "1.4.2, since Tuesday's merge."
3. "Why does the hook refuse the commit?" → "It refuses it." / the one reason, then the fix — an explanation was asked for, and one is the shape.
4. A deliverable asked for — a plan, a document — → a summary of what it would contain / the deliverable itself, its notes after it.

**Assumptions** ([A7.2](../../docs/requirements.md#a7-2)):

5. A request with no ambiguity answered with "Assumptions: none" every time → the empty ritual / no assumption line at all when none was made.
6. "Use the usual layout" done on the layout the last module used, unsaid → a silent assumption / the same work with one line: "assumed the layout of the previous module".
7. A reading that changes which files are written listed as an assumption after the fact → a material assumption taken instead of asked / the choice put as a question before the work, priced by the stakes triage.

**Honesty over agreement** ([A7.4](../../docs/requirements.md#a7-4)):

8. The tests were not run and the reply says "should pass" → unverified work reported as done / "the tests were not run: the runner needs a library this machine lacks".
9. A request that breaks a published contract carried out with "note: this may affect consumers" in the last line → a softened finding / "this breaks the contract of version 0.1.0 for every consumer; the reversible alternative is a new key beside the old one" first, then, on a repeated request, the work with the objection noted in the commit.
10. A finding the user will not like left out of the review → hidden / stated, with its severity, whatever the reception.

**Addressable lists** ([A7.5](../../docs/requirements.md#a7-5)):

11. Findings as bullets with no handle → the user quotes a sentence to point at one / findings numbered, and the number cited in the fix commit.
12. A table of dials with no key column → unaddressable rows / the dial's name in the first column, the handle.
13. Options numbered 1, 2, 3 beside numbered findings → the two confused / options lettered, findings numbered, steps numbered in their own list.

**Escalation, stakes-triaged** ([A8.1](../../docs/requirements.md#a8-1), [A8.2](../../docs/requirements.md#a8-2)):

14. No rule says where a scratch file goes → the session stops to ask / a reasonable call, one line in the commit note.
15. No rule says how a record is numbered → a scheme invented on the spot and used / the work stops there; the scheme is put as a decision at process stakes, and recorded once chosen.
16. A review flow the project has not written → the session performs one it made up and reports the change reviewed / "the project has no review flow; this change is unreviewed until one is decided" — the gap named, never filled by improvisation.

**Irreversibility** ([A8.3](../../docs/requirements.md#a8-3)):

17. `git push --force` to a shared branch on the user's "just push it" → done / the consequence — every collaborator's clone diverges — and the alternative — `--force-with-lease`, or a new branch — stated, then the wait for a yes.
18. Deleting a directory of generated files that one command rebuilds → a warning ceremony / done and noted: it is reversible, the class does not apply.
19. One yes given for a history rewrite, then a second rewrite done under it → an approval stretched over two acts / the second asked for on its own.
20. The user repeats "delete it" after the warning → refused again / done, the objection in the commit note: the decision is theirs.

**Plain language** ([A10.2](../../docs/requirements.md#a10-2)):

21. "We'll circle back once the dust settles on the upstream churn" → idiom on idiom / "We return to this after the upstream changes stop."
22. A term of the kit used without definition in a reply to a newcomer → undefined jargon / the term defined at its first use in that reply.

**Honest limits**, each with its backstop. The shared code's limits — [kit-shared-gate-code §4](../../shared/GATE.md#g4) — apply. This module's own:

1. **The list is the gate; the class is not.** An interpreter one-liner (`python3 -c "shutil.rmtree(...)"`), a script file that deletes, a shell function or an alias, a deletion through a file tool, an API call, a database client's `DROP` inside a quoted argument: none matches an entry, and the gate says of every unlisted command only that it did not match. Backstop: rule I-h on the carrier; the consumer's own entries.
2. **The argument form is not expressible.** `git checkout -- .`, `git branch -D main` against any branch and a refspec with a leading `+` (`git push origin +main`, a forced push by another spelling) need a value the entries cannot name at this version; `git restore` and `git rebase` are therefore gated whole, which prompts on recoverable acts too. Backstop: the consumer tunes the list; the deferred form of [§12](#t12).
3. **Headless, the ask is a block.** Where no prompt can be shown the platform denies the call with the teaching text; nobody can confirm, and the model reports the block and waits. The unattended session is the one where a destructive act should wait anyway. Backstop: the user's yes in chat, then the command run again — which prompts again, one yes per command by construction.
4. **The reading is best-effort where the shell is cleverer than the reader.** What hides the verb, and passes: a command built from a variable (`$CMD`, `git ${x:-push}`), an `eval`, a verb with an escaped space (`git\ push`, one word), a here-string, a heredoc body that feeds `sh`, an interpreter's `-c` string, `find -delete`; a heredoc operator inside a quote opened on an earlier line, which is read as outside it and drops its body; a wrapper flag the lists omit — a flag a man page leaves out or a later version adds, an abbreviation of a long flag, which GNU accepts, a long shell option the reader does not know takes a value — whose value is then read as the program. What does not: a wrapper by path, a shell's `-lc`, `-o pipefail -c`, `--rcfile f -c` or `-c --`, `env -S` as a token, attached, in a cluster or long, a wrapper's valued flag short, long or clustered as its man page spells it, `exec`, a keyword, a substitution however deep, with a quoted `)` inside, in or outside a double-quoted string, a redirection, a continuation line, an unbalanced quote, which is read as whitespace-separated words, a heredoc operator inside a quote opened on its own line or without its terminator. Where the reader cannot split a text cleanly it errs toward examining more; the first list is what it does not see at all. Backstop: the explain, `--scan --command`, shows the reading of any command.
5. **The list scan reads a grammar, not the rule.** A bold label, a link or a code span that the rule accepts as a key is invisible to it unless the `handles` dial names the form; an item keyed by prose alone is a finding the rule would not make; nested items are their parent's; a numbered list is handled by construction; an unclosed fence hides everything after it, as the sibling's marker scan reads fences. Backstop: the dial; the kit's own calibration in `constitution.yaml` as an example.
6. **The rules are context, not enforcement.** A reply that opens with an essay, a silent assumption, a softened finding: no file shows any of them, and the carrier only makes the rules present. Backstop: the seed pairs and the project's own; the friction signal of [§12](#t12).
7. **A `SessionStart` that fails prints its failure to stderr,** which the user sees and the model does not; the rules, printed by the POSIX wrapper before Python runs, still reach the model. Backstop: the log; the exit code 1.
8. **A hook on every shell call costs a process each time** — Python's start and the preflight, tens of milliseconds. Backstop: the timeout in the hooks file; `severity` cannot switch the process off, only the plugin can.

**Exit-code contract** (every entry point): `0` green, nothing examined (the count line says which), or — the shell gate at `block` — a match answered with the `ask` decision, the verdict being the platform's prompt; `2` finding in a scan — the command matches, or a list has an item without a handle; `1` configuration failure — the checker could not run: the shared failures, this module's C5 and C12. Nothing exits 0 on error.
