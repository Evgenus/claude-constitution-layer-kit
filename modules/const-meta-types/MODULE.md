# MODULE.md — `const-meta-types`

*Draft at manifest version `0.0.2`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A session opens a research note, a stale structure description, or a half-migrated remnant and treats it as binding truth because nothing on the document says otherwise — the retroactive-canonization problem. In the same repository, a document sits in a folder two policies claim, or in one that none claims, and the rules that apply to it are whatever the reader assumes. Both compound silently: every unguarded document raises the cost of the eventual repair. This module makes a Markdown document in claimed territory *governable* at the moment it is written: its authority is declared in its envelope and exactly one policy governs it, or the write is blocked with a message that teaches the fix.

<a id="t2"></a>
## 2. Failure class

`accumulating`: each document written without a valid envelope, or into ambiguous territory, is one more file whose authority a later session must reconstruct by archaeology, and the reconstruction cost grows with every such file. **Entry trigger:** day-one install set of every project that claims territory; the first document written into a territory is the moment the guard must already be there.

## 5. Invariant

**Every Markdown document in claimed territory carries a valid envelope and resolves, path first, to exactly one governing policy at the moment it is written through the platform's file tools.** Claimed territory, envelope, policy, and resolution are the kernel's ([§1](../../docs/constitution/CONVENTIONS.md#k1), [§3](../../docs/constitution/CONVENTIONS.md#k3), [§6](../../docs/constitution/CONVENTIONS.md#k6)); "valid" is the kernel's frontmatter schema plus id uniqueness in the present tree; "written through the platform's file tools" is the honest boundary of [§9](#t9).

Two advisory rules stand beside it, under the handles `R-a` and `R-b`, the letter `R` being one that no message key of this module uses:

1. **R-a.** *Advisory.* A session chooses the meta-type of a governed document by the contrastive pairs of [§8](#t8), and splits a document that mixes how things are with where they should go ([A1.5](../../docs/requirements.md#a1-5)). The skill `choose-meta-type` carries the pairs and the split rule; the gate checks only that the type is one of the three and cannot tell a wrong choice from a right one.
2. **R-b.** *Advisory.* A session that writes a governed document is told, once per session, repository and policy, which policy governs it and where that policy's Enforcement rule stands, and reads it before it edits further ([A2.7](../../docs/requirements.md#a2-7)). The gate prints the line `N3` on a green write; whether the policy is then read, and followed, is the session's.

- **Cost and budget:**
  - Handler timeouts, in `plugin/hooks/hooks.json`: the `PreToolUse` gate 30 s; the `SessionStart` and `SubagentStart` printers 5 s each. Nothing at 30 s is spent while git is quick, unless a repository holds tens of thousands of Markdown files.
  - The hook budget: the identity's `hook_seconds`, 25 s, the one deadline of limit 16 of [kit-shared-gate-code §4](../../shared/GATE.md#g4). Each wait of the gate, the git calls of the run, takes the smaller of its own cap and what is left; a wait asked after the 25 s is not started, and the run ends in the shared C12.14 before the platform's cut at 30 s (platform fact 7). The module makes no wait of its own beyond those git calls. The scan has no clock.

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | the gate in hook mode; the scan ignores it | `block`: a finding exits 2 and the write is blocked. `warn`: the finding is reported to Claude and to the user and the write proceeds — the adoption path onto a repository with legacy documents. |
| `log_dir` | absent | the gate, in both modes, for its output log; the pointer to the governing policy (`N3`), for the memo beside the log | A repository-relative directory for the output log. The shared code validates the two at each read, and a key of this namespace that is neither is a configuration failure: a misspelt `severty: warn` would otherwise leave the default in force unseen. Territory, the root policy, the dialect and the module prefix are the kernel-owned keys and the policy namespaces of [kernel §6](../../docs/constitution/CONVENTIONS.md#k6), not dials of this module. ## 8. Boundary examples

The one judgment boundary is the meta-type choice, the advisory rule `R-a` of [§5](#t5) ([A1.5](../../docs/requirements.md#a1-5)). The pairs are the definition and are carried verbatim by the skill:

**R-a**

1. **Architecture of what should be, written mid-task** → `task-record` (rides with the delta, closes with it) / *not* `current-state` (unrealized intent never sits in a standing document).
2. **The standing specification** — what a subsystem is and must stay, invariants and why → `current-state` / *not* `task-record` (it has no close).
3. **How the code is organised today** — a module map, a dependency listing → `non-authoritative`, dated, generated-preferred / *not* `current-state` (no obligation; a stale copy read as truth is the failure).
4. **A document mixing as-is with direction** → split: normative half `current-state` (or `task-record` if a bounded change), descriptive half `non-authoritative`; or classify by the normative content and cut the rest to a dated pointer / *not* left mixed.
5. **Notes from an investigation** → `non-authoritative` / *not* `task-record` (a record carries a ruling or a delta, not an account).

**R-b** holds no judgment boundary of its own: the line and its time are fixed by the gate, and whether the session then reads the policy is judgment that no example defines. The resolution and envelope boundaries are deterministic and need no examples; the fixtures of [§10](#t10) are their contrastive pairs.

**Honest limits.** The limits every gate shares are [kit-shared-gate-code §4](../../shared/GATE.md#g4). This module's own:

1. **The declaration's condition is not checked.** Whether "an active task-record covers the move" holds is judgment; the gate accepts any declaration that names a matching or existing policy. Backstop: review.
2. **Duplicate ids across history** ("never reused") are not checked; only the present tree is. Backstop: review; the friction signal of [§12](#t12), item 3.
3. **Negation cannot carve a subtree out of a `**` territory.** It is the shared limit 13 of [kit-shared-gate-code §4](../../shared/GATE.md#g4) met in this module's own example: `["docs/notes/**", "!docs/notes/private/**"]` still claims `docs/notes/private/p.md`. Backstop: write the territory without the parent match instead.
4. **An ungoverned twin id is not seen.** A file outside every territory that carries no declaration is never consulted, at write time or in the scan, so a governed document's id may stand in it unseen; a file outside every territory that carries a declaration is bound by it and is consulted like any governed document. Backstop: the generator of module `const-locations`, when installed, refuses such a twin before writing; review otherwise.
5. **The pointer to the governing policy is advice with a memo, not a gate.** It is said once per session, per repository and policy, and the memo that remembers it lives beside the output log, under the log's name with the suffix `.pointed`, one line per pointer: the session's id, the repository root and the policy's path, tab-separated. Where the log goes nowhere — no `log_dir`, no per-plugin data directory — nothing is pointed, and an event that names no session is pointed nowhere either. A memo that cannot be read or written counts as empty, so the line is said again rather than lost, and never changes a verdict (shared limit 10 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)). The memo keeps its last 200 lines, so a session that outlives them is pointed again. Two writes the platform runs at once may each say it, since the memo is not locked; a line said twice costs its characters and nothing else. Whether the session opens the policy, and whether it then follows the policy's rules, is judgment. Backstop: the policy's own Enforcement rule, which the line names, says what review holds.

## 11. Siblings

**Depends on:** [kernel §1](../../docs/constitution/CONVENTIONS.md#k1) (envelope), [§2](../../docs/constitution/CONVENTIONS.md#k2) (the type enum), [§3](../../docs/constitution/CONVENTIONS.md#k3) (territory, policy, resolution, the three defects), [§6](../../docs/constitution/CONVENTIONS.md#k6) (dials file, kernel-owned keys, dialect, portability), [§7](../../docs/constitution/CONVENTIONS.md#k7) (naming). Beside the kernel it needs the Python package `constitution-layer-kit`, which pip installs, as it needs Python and PyYAML, and one external tool, git, which the gate preflights on every run and which gives it the repository's root, its file list and its territory verdicts. That package is the kit's shared gate code and no sibling ([law 3 of CLAUDE.md](../../CLAUDE.md#law-3)). Nothing else.

**Kernel alone, with that package installed:** on a bare repository with no `constitution.yaml`, every write passes with a visible zero count; with a dials file naming `module_prefix` and a root policy, every Markdown write into claimed territory is checked and the scan runs. Policies are the consumer's documents; the module ships none. Without git the gate stops with the shared `C3`, which blocks nothing in hook mode, and checks nothing; the skill and the two pointer printers need neither git nor Python, and run.

**Optional enhancements:** when module `const-locations` is installed, documents are born in their canonical home from the policy's template, so this gate sees fewer findings — it stays the guard either way. When module `const-catalogs` is installed, the name and id form of a numbered kind (`<prefix>-<nnnn>-<slug>`) is checked there, from that module's own dial; this module reads nothing of it. When module `const-decision-records` is installed, the body shape of a decision record is its concern; this module checks the envelope only.

## 12. Deferred

The deferrals every gate shares stand in [kit-shared-gate-code §1](../../shared/GATE.md#g1). This module's own:

1. **A `Bash` matcher inspecting commands for Markdown writes.** Signal: consumer commit notes recurring on shell edits that escaped the hook and were caught late by the scan. The platform calls Bash matching best-effort and points to permissions for a hard deny (documentation read 2026-09-18; breaks: an exact Bash match would make such a hook a gate), so the scan is the honest backstop until then.
2. **`pathspec` as a fallback matcher.** Signal: a consumer reports a territory verdict where git and the kernel's dialect description disagree.
3. **Id reuse across history.** Signal: a retired id resurfacing in a consumer and breaking references; the check needs git history and a definition of "retired".
4. **Checking the declaration's condition** (an active task-record covering the move). Signal: declarations left in place after moves complete; the check needs the record catalog of module `const-decision-records`, which would be a kernel candidate.
5. **An Edit of a governed document as a moment of W5**, which the skill's "changing its type" also covers. The report counts the Write that creates or replaces a document only, since a skill loaded once stays in context and an edit is mostly a body change. Signal: an Edit that changes the `type` field with no skill loaded, found in review of the report.
