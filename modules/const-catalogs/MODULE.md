# MODULE.md — `const-catalogs`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

People cite decisions, tasks and escalations by number — "see D41". The numbers live wherever they were first typed: a flat register file, a heading, a chat. The register may be migrated, or an entry renumbered, split or deleted. Then every citation of the old number points at nothing, or worse, at something else, and nobody can tell which. The failure was observed as 74 dangling `D<n>` references left by one migration of one register. It compounds: every citation written under a loose numbering scheme is one more to repair when the scheme finally breaks. This module makes a number mean one document for good. The number stands in the file's name, and the document's `id` is that name. No two items of a catalog share a number, and a number once held is not handed out again. There is no register file to keep in step, because the catalog is the set of files.

<a id="t2"></a>
## 2. Failure class

**Accumulating.** Every item created outside the form, and every citation of it, is retrofit debt. Numbering a kind later means renaming each document once, with every link to it. The kit paid that for sixteen records. **Entry trigger:** the first numbered kind — typically the first decision record. So the module enters beside module `const-decision-records`, on day one of any project that will cite documents by number.

## 5. Invariant

One rule — *within a catalog a number names exactly one document, and the document's one name carries it* — in its three deterministic facets, each with its finding: **every Markdown document in the territory of a listed catalog carries, at the moment it is written through the platform's file tools, one name — its file name without `.md` is `<prefix>-<number of exactly width digits>-<kebab-slug>` and its `id` is that name — a document that does not exist yet takes a number no other item of its catalog carries in the working tree, and in a scanned tree no two items of one catalog share a number.** Territory, `id` and the dials file are the kernel's ([§1](../../docs/constitution/CONVENTIONS.md#k1), [§6](../../docs/constitution/CONVENTIONS.md#k6), [§7](../../docs/constitution/CONVENTIONS.md#k7)). Here "listed" is the dial `catalogs` of [§7](#t7); "written through the platform's file tools" and "a scanned tree" are the honest boundaries of [§9](#t9).

The advisory rules beside it, under the handles `C-a` to `C-f`:

1. **C-a** — advisory. A new item takes one more than the highest number its catalog has held, deleted items included.
2. **C-b** — advisory. A number is provisional until its branch lands on the main branch, and frozen from then. The one exception is the collision of two landed items (C-c). An item is cited outside its branch only after it has landed.
3. **C-c** — advisory. At a collision the item on the main branch keeps its number. The other renumbers its file, its `id` and the references made on its own branch. Where both items have landed on the main branch, the one landed second renumbers its file and its `id`. In that case every reference to it in the tree is rewritten. In that case, where the project accepts items by a trailer naming the id, that item is accepted again in the change that renumbers it.
4. **C-d** — advisory. A catalog is listed on demand and never into a file.
5. **C-e** — advisory. A gap is never filled and never explained by a placeholder.
6. **C-f** — advisory. The full name on machine surfaces, the bare form in prose.

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | gate | `block`: a finding exits 2 and the write is blocked. `warn`: the finding is reported to Claude and to the user and the write proceeds — the adoption path onto a kind that already has documents. The scan ignores it. |
| `log_dir` | absent | gate, session-start printer | A repository-relative directory for the output log. The gate verifies with git that the directory is ignored and reports a configuration failure otherwise. Absent: the log goes to the platform's per-plugin data directory; where that is absent too (CI), nowhere, and stdout is the record. |
| `catalogs` | `[]` | gate, session-start printer, skill | The numbered kinds: a list of `{prefix, territory, width}`. `prefix` lowercase letters and digits, unique in the list; `territory` a non-empty list of path patterns in the dials file's dialect; `width` a whole number from 1 to 9, default 4. Empty: nothing is examined and every run says so. |

The gate validates every key it reads at each read, and a key of this namespace that is none of the three above is a configuration failure: a misspelt `catalog:` would otherwise read as no catalog listed. Nothing else of the dials file is this module's: it reads no policy's namespace and needs no `root_policy` — though the file as a whole is still validated as every gate validates it ([kernel §6](../../docs/constitution/CONVENTIONS.md#k6)), so a malformed territory under a policy's id is a configuration failure here too.

## 8. Boundary examples

The name, the id and uniqueness are deterministic and need no examples; the fixtures of [§10](#t10) are their contrastive pairs. The judgment the module introduces is the skill's, in six advisory rules, each with its pairs.

**C-a — which number:**

1. The scan says `dec up to dec-0028` → the new item is 29 / *not* 12, though 12 is free: a gap is somebody's deleted or renumbered item.
2. The scan says `dec up to dec-0028, dec-0031 in history` → 32 / *not* 29: 29 to 31 were held once, and somebody may still cite them.
3. A write was blocked and the message names `dec-0030` → 30 / *not* the number first thought of, tried again under another slug.

**C-b — provisional or frozen:**

4. An item written on a branch an hour ago, cited in the same branch's other documents → fine / cited in a message to another team, or in another repository → *not yet*: the number may still change at the pull request.
5. An item that landed on the main branch last week → its number is frozen; a collision with an item still on a branch is that item's to repair / *not* "mine is older by commit date, so the one on main moves".
6. A commit message on the branch says "see DEC-0030" before the branch has landed → fine, it travels with the branch / a ticket in another system says the same → *not yet*.

**C-c — who renumbers, and what is rewritten:**

7. The scan at a pull request reports two items under one number, one of them already on the main branch → the branch's own item takes the next number, its file, its `id` and the references made on that branch change / *not* a search-and-replace across the repository: a reference outside the branch means the other item.
8. Both colliding items are on branches, neither has landed → whoever lands second renumbers; until then neither is wrong / *not* a negotiation over who was first by commit date.
9. Both colliding items have landed on the main branch → the one that landed second renumbers its file and its `id`, and every reference to it in the whole tree is rewritten, since a reference anywhere may mean it / *not* only the references of one branch, and not the item that landed first.
10. A legacy item named `DEC-7-old-ruling.md` is brought into the form → `dec-0007-old-ruling.md`, its number kept, its links rewritten / *not* the next free number: it is already cited as 7.

**C-d — listing:**

- **11.** "What decisions do we have?" → the listing command, read and answered in the dialog / *not* an `INDEX.md` written into the territory: it drifts from the files on the next write, and the gate would block its name anyway.
- **11a.** A file carries the prefix but lies outside the catalog's territory → the listing shows it, the gate does not see it, and review takes it in (limit 4 of [§9](#t9)) / *not* "the gate passed it, so it is an item".
- **11b.** An item in the territory has a name without the form → the scan reports it, and the listing leaves it out / *not* "the listing lacks it, so the catalog has no such item".

**C-e — gaps:**

- **12.** Number 14 is missing → `git log` says what it was / *not* a placeholder `dec-0014-deleted.md`, and not a new item under 14.
- **13.** A README explaining the kind is wanted inside the territory → take it out of the territory with a negated pattern, or keep it one level up / *not* `dec-0000-readme.md`: that is a placeholder with a number.
- **13a.** A write under free number 12 passes the gate while the highest is 28 → the gate lets it through, since a gap is legitimate (limit 3 of [§9](#t9)), and the advice still names 29 / *not* a reading of the pass as leave to fill the gap.

**C-f — citing:**

14. A link target or an envelope field → the full name, `<prefix>-0007-<slug>` / a sentence in a review comment → the bare `<PREFIX>-0007` is fine.
15. An item still on its branch is cited in that branch's own documents → by its full name, which the renumbering step will find and rewrite / *not* by a bare number in a file the branch does not touch.
16. A sentence says "decision 7" → resolve it with the case-insensitive glob before relying on it / *not* by opening the seventh file of the listing: gaps shift positions.

**Honest limits:** the limits every gate shares are those of [kit-shared-gate-code §4](../../shared/GATE.md#g4). This module's own:

1. **Off until listed.** With `catalogs` empty the gate examines nothing. Backstop: every run prints `0 documents examined` with the entry to write, and every session start prints the one line of [§6](#t6) while the dial stays so; a profile can prewrite the dial.
2. **A rename is not a write.** `git mv` and a rename through the shell never reach the hook, so an item can lose its form, or take a carried number, unseen. Backstop: the scan; the skill's last step, which tells the agent to run it after a shell edit.
3. **A silently deleted item is not detected, and a gap may be filled.** Gaps are legitimate ([kernel §1](../../docs/constitution/CONVENTIONS.md#k1): a document nothing should reference is deleted), so no continuity is checked, and the gate lets a free number below the highest through — it cannot tell a deleted item's number from one renumbered away before it landed. Backstop: the advice never names such a number; branch review and `git log`.
4. **A file carrying a prefix outside its catalog's territory is invisible to the gate** and is listed by the skill's prefix glob; an item whose name lacks the form is in the territory and not in that listing. Backstop: the scan reports the second; review catches the first.
5. **Collisions across branches are seen only where both branches meet:** in the scan of a merged tree. Two pull requests green apart can both land where the forge does not require a branch to be up to date. Backstop: the scan on the main branch after every merge; a protected branch that requires up-to-date checks.
6. **A reference to a provisional number from another branch breaks at renumbering.** Backstop: rule C-b; K3 names every file of the collision, so the renumbered name is one `git log` away.
7. **History is read where it exists, and only as long as the hook can wait.** A shallow clone, a repository with no commit yet, a history too long to read, and one rewritten or squashed give the working tree's answer. In a hook, too long means more than the smaller of five seconds and what the hook's deadline has left (platform fact 5 in [§6](#t6)), and a read asked when nothing is left starts no git. The hook gathers history, and the rivals of a malformed name that exists, only once a finding that names a number is certain, and nothing the history reader meets, a failing or a vanished git included, raises. The scan reads history with no clock. A name of the catalog's form added anywhere in the repository counts, which can only skip a number. Backstop: the fix text and the count line say when history is incomplete or was not read — a repository with no commit has a complete, empty one — except for a rewritten history, which nothing can see; skipping is harmless, since gaps are legitimate.
8. **The width is a ceiling.** Past the last number `width` digits can write, the fix says the catalog is full and names no file; widening a catalog renames every item. `width` itself stops at 9. Backstop: none — accepted: width 4 holds 9,999 items, and the choice is made once, with the prefix.
9. **An existing item is never judged on its number at write time,** so two items that already collide can both be edited until the scan is run. Backstop: K3.
10. **The rest of the envelope, and which policy governs an item, are not judged.** Backstop: module `const-meta-types`; alone, this module lets them through, and the install note says so.
11. **Everything in a territory is an item:** a README there is blocked for its name. Backstop: a negated pattern takes the file out — directly under the top directory of a territory written `<dir>/**` or `<dir>/*`, not `<dir>/`; deeper down only from a territory of file patterns ([kit-shared-gate-code §4](../../shared/GATE.md#g4), item 13) — and the install note says how.
12. **A git-ignored item holds no number,** for the scan and for K4 alike: the file list is git's, without what git ignores. Backstop: numbered documents are not ignored files; the hook still judges such a file's name and id when it is written.
13. **Where the file system ignores case, a write to the lowercase name of a file that exists in another case passes and renames nothing:** the hook judges the path it is given. Backstop: the fix says `git mv`; the scan sees the name git records ([kit-shared-gate-code §4](../../shared/GATE.md#g4), item 9).
14. **Under width 4 a date-shaped name is an item.** `<prefix>-2026-09-22-<slug>` has the form (number 2026, slug `09-22-<slug>`), so a legacy convention of dated names makes every such file an item numbered by its year, and once a name of the form is committed, the advice names the year plus one for as long as the branch's history holds it; a rename does not undo it, nor does declaring the catalog later. No verdict follows: a lower free number passes (limit 3, [A13.3](../../docs/requirements.md#a13-3)). Backstop: rename before the name's first commit; or choose a prefix the dated names never carried, since history is read for the catalog's own prefix; or take the number by the skill's rule and let the advice stand. Under another width the name is not of the form and is a K1 finding on the adoption path.

The exit codes of both modes: `0` green or nothing examined (the count line says which); `2` a finding; `1` a configuration failure — the checker could not run (missing or too-old interpreter, missing library, malformed dials file, a key of the namespace that is no dial, a malformed `catalogs` entry or a prefix listed twice, the shared package missing or of a release that does not serve the module, git absent, a log directory git does not ignore, unparseable hook input, a bad argument, or an unexpected exception, whose traceback is printed). A git that cannot list history, or not in time, or that vanishes while history is read, is none of these: history is advice, its absence is the working tree's answer, and the text says so.

## 11. Siblings

**Depends on:** [kernel §1](../../docs/constitution/CONVENTIONS.md#k1) (the envelope's `id`, never reused; the exceptions to the `id` rule for the items of a numbered kind, under which an item takes a new number or a new form; the deletion rule that makes gaps legitimate), [§6](../../docs/constitution/CONVENTIONS.md#k6) (the dials file, the module's own namespace, the territory dialect, portability), [§7](../../docs/constitution/CONVENTIONS.md#k7) (naming: kebab-case ids and file names). Beside the kernel it needs Python 3.12, PyYAML, and the Python package `constitution-layer-kit`, which pip installs. That package is the kit's shared gate code and no sibling ([law 3 of CLAUDE.md](../../CLAUDE.md#law-3)). The one external tool the gate and the printer preflight is `git`. Nothing else — not [§3](../../docs/constitution/CONVENTIONS.md#k3): a catalog's territory says where numbering applies and binds no document to a policy.

**Kernel alone, with that package installed:** on a bare repository with no `constitution.yaml` every write passes with a visible zero count, the session starts with the line naming the missing file, and the skill explains how a kind becomes numbered; with a dials file that lists a catalog — and nothing else but `module_prefix` — every Markdown write into that territory is checked for its name, its id and its number, and the scan runs. Without `git` the gate and the printer report the shared C3 and examine nothing; the pointer line, which reads nothing, still prints, and the skill still loads.

**Optional enhancements:**

1. When module `const-meta-types` is installed, the rest of an item's envelope and its governing policy are guarded there; this gate and that one both report an envelope that cannot be read, each for its own field.
2. When module `const-decision-records` is installed and a catalog's territory holds the records, its skill takes a record's number from this module's procedure.
3. When module `const-locations` is installed, its creation command hands the kind's home and template to the writing step of this module's skill.
4. When module `const-referencing` is installed, an item's full name in backticks must be a link and a link showing it must open the item — its checks of a governed id in backticks that is no link, and of a link whose text is an id opening another document (R2 and R3 of that module's document), know every covered envelope's id, and an item's id is its name — with nothing wired between the modules; the bare form in prose is tolerated by [A13.6](../../docs/requirements.md#a13-6) and linted nowhere unless the consumer writes a `lanes` entry for the prefix in that module's dial.

## 12. Deferred

The deferrals every gate shares — Windows without a POSIX shell, a clone of the kit without symbolic links, a run past the handler's timeout, a governed document with another extension — are those of [kit-shared-gate-code §1](../../shared/GATE.md#g1). This module's own:

1. **A catalog declared by naming a policy** — an entry with `policy: <id>` in place of `territory`, the territory then being the policy's. Signal: a consumer commit note about a catalog's territory that drifted from its kind's policy despite the YAML alias.
2. **`--list` and `--next` modes of the script.** Signal: consumers report the prefix glob as too loose — stray files listed, malformed items missed — or the count line as too awkward to read a number from; it needs module-defined modes in the shared command line.
3. **Refusing, at write time, a number that history held.** It would make one write red in a full clone and green in a shallow one. Signal: re-issued numbers landing despite the advice.
4. **A `--base <ref>` option naming which item of a collision is frozen.** Signal: renumbering disputes the skill's rule does not settle.
5. **Non-Markdown items, and a continuity report.** The first needs an id outside an envelope; the second contradicts the deletion rule. Signal: a consumer numbering files of another type; none foreseen for the second.
6. **The effect report's other ways.** The report counts no choice of a number against the skill's advice (a free number below the highest passes the gate, limit 3 of [§9](#t9)), no file that carries a prefix outside every territory (limit 4), and no collision of two branches before they meet; W6 sees a collision only on a commit of the main branch. The module has no visible shape to miss, so no rule is judged by B6, and no reader rule. Signal: a re-issued number or a stray prefixed file found by review while the report counts every moment applied, twice.
