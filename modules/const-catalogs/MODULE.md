# MODULE.md — `const-catalogs`

*Draft at manifest version `0.0.1`, no open slots; published at `0.1.0` in rollout Phase D. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

People cite decisions, tasks and escalations by number — "see D41" — and the numbers live wherever they were first typed: a flat register file, a heading, a chat. When the register is migrated, or an entry is renumbered, split or deleted, every citation of the old number points at nothing, or worse, at something else, and nobody can tell which; the failure was observed as 74 dangling `D<n>` references left by one migration of one register. It compounds: every citation written under a loose numbering scheme is one more to repair when the scheme finally breaks. This module makes a number mean one document for good: the number stands in the file's name, the name is the document's `id`, no two items of a catalog share a number, and a number once held is not handed out again — with no register file to keep in step, because the catalog is the set of files.

<a id="t2"></a>
## 2. Failure class

**Accumulating.** Every item created outside the form, and every citation of it, is retrofit debt: numbering a kind later means renaming each document once, with every link to it — the kit paid that for sixteen records. **Entry trigger:** the first numbered kind — typically the first decision record, so the module enters beside `const-decision-records`, on day one of any project that will cite documents by number.

## 5. Invariant

One rule — *within a catalog a number names exactly one document, and the document's one name carries it* — in its three deterministic facets, each with its finding: **every Markdown document in the territory of a listed catalog carries, at the moment it is written through the platform's file tools, one name — its file name without `.md` is `<prefix>-<number of exactly width digits>-<kebab-slug>` and its `id` is that name — a document that does not exist yet takes a number no other item of its catalog carries in the working tree, and in a scanned tree no two items of one catalog share a number.** Territory, `id` and the dials file are the kernel's ([§1](../../kernel/CONVENTIONS.md#k1), [§6](../../kernel/CONVENTIONS.md#k6), [§7](../../kernel/CONVENTIONS.md#k7)); "listed" is the dial `catalogs` of [§7](#t7); "written through the platform's file tools" and "a scanned tree" are the honest boundaries of [§9](#t9).

The advisory rules beside it, each `advisory` in its own text, are these. (C-a) A new item takes one more than the highest number its catalog has held, deleted items included. (C-b) A number is provisional until its branch lands on the main branch and frozen from then, and an item is cited outside its branch only after it has landed. (C-c) At a collision the item on the main branch keeps its number, the other renumbers its file, its `id` and the references made on its own branch. (C-d) A catalog is listed on demand and never into a file. (C-e) A gap is never filled and never explained by a placeholder. (C-f) The full name on machine surfaces, the bare form in prose.

- **Platform facts relied on** (all verified 2026-09-20 against the official documentation; sources in the research comparison, section 7):
  1. A `PreToolUse` command hook exiting 2 blocks the tool call and Claude sees stderr as the reason; exit 2 blocks whether or not JSON is printed. Breaks: the gate stops blocking.
  2. `Write` input is `file_path` + `content`; `Edit` input is `file_path`, `old_string`, `new_string`, `replace_all`; `file_path` is absolute for the file tools; `Write|Edit` is an exact-string list. Breaks: locating or reconstructing the document; a Markdown write through an unmatched tool.
  3. On exit 0, JSON on stdout is parsed: `hookSpecificOutput.additionalContext` reaches Claude, top-level `systemMessage` reaches the user; stdout that looks like JSON and fails to parse is an error notice on every exit code other than 2, so the `warn` channel prints exactly one valid object and stdout stays free of JSON otherwise. Without valid JSON, exit 1 is a non-blocking error and the action proceeds. Breaks: the `warn` channel; the visibility of a configuration failure.
  4. All matching hooks run in parallel and every one runs to completion; the most restrictive answer applies. With the two sibling gates installed this module is a third process per matched write — observed 2026-09-20 on Claude Code 2.1.251: a record under a malformed name was blocked by this gate alone while both siblings logged green, and the corrected write was green in all three. Cost on a clone of this repository with the final code, medians of nine in one run (macOS, Python 3.12.4, 29 items): a new item that passes 259 ms; a new item that is blocked 328 ms, the difference being history, which only a blocked write reads; an existing item 217 ms; a Markdown write outside every catalog 214 ms; any other write 152 ms; the scan 331 ms. Breaks: the both-installed behaviour of [§11](#t11).

  6. Hook output strings are capped at 10,000 characters each; a value echoed from a document is cut at 80 characters and K3 names file paths only, so one verdict stays far below it short of hundreds of items under one number. Breaks: a `warn` payload past the cap.
  7. Hook input carries `cwd`, `tool_name`, `tool_input`, `session_id`, and fields this gate does not read; `cwd` follows the session, so the repository root is derived from the written file's path. Breaks: root discovery.

The reasoning lives here and in [§4](#t4).

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | gate | `block`: a finding exits 2 and the write is blocked. `warn`: the finding is reported to Claude and to the user and the write proceeds — the adoption path onto a kind that already has documents. The scan ignores it. |
| `log_dir` | absent | gate | A repository-relative directory for the output log. The gate verifies with git that the directory is ignored and reports a configuration failure otherwise. Absent: the log goes to the platform's per-plugin data directory; where that is absent too (CI), nowhere, and stdout is the record. |
| `catalogs` | `[]` | gate, skill | The numbered kinds: a list of `{prefix, territory, width}`. `prefix` lowercase letters and digits, unique in the list; `territory` a non-empty list of path patterns in the dials file's dialect; `width` a whole number from 1 to 9, default 4. Empty: nothing is examined and every run says so. |

The gate validates every key it reads at each read, and a key of this namespace that is none of the three above is a configuration failure: a misspelt `catalog:` would otherwise read as no catalog listed. Nothing else of the dials file is this module's: it reads no policy's namespace and needs no `root_policy` — though the file as a whole is still validated as every gate validates it ([kernel §6](../../kernel/CONVENTIONS.md#k6)), so a malformed territory under a policy's id is a configuration failure here too.

## 8. Boundary examples

The name, the id and uniqueness are deterministic and need no examples; the fixtures of [§10](#t10) are their contrastive pairs. The judgment the module introduces is the skill's.

**Which number (C-a):**

1. The scan says `dec up to dec-0028` → the new item is 29 / *not* 12, though 12 is free: a gap is somebody's deleted or renumbered item.
2. The scan says `dec up to dec-0028, dec-0031 in history` → 32 / *not* 29: 29 to 31 were held once, and somebody may still cite them.
3. A write was blocked and the message names `dec-0030` → 30 / *not* the number first thought of, tried again under another slug.

**Provisional or frozen (C-b):**

4. An item written on a branch an hour ago, cited in the same branch's other documents → fine / cited in a message to another team, or in another repository → *not yet*: the number may still change at the pull request.
5. An item that landed on the main branch last week → its number is frozen; a collision is the other item's to repair / *not* "mine is older by commit date, so the one on main moves".

6. A commit message on the branch says "see DEC-0030" before the branch has landed → fine, it travels with the branch / a ticket in another system says the same → *not yet*.

**Who renumbers, and what is rewritten (C-c):**

7. The scan at a pull request reports two items under one number, one of them already on the main branch → the branch's own item takes the next number, its file, its `id` and the references made on that branch change / *not* a search-and-replace across the repository: a reference outside the branch means the other item.

8. Both colliding items are on branches, neither has landed → whoever lands second renumbers; until then neither is wrong / *not* a negotiation over who was first by commit date.
9. A legacy item named `DEC-7-old-ruling.md` is brought into the form → `dec-0007-old-ruling.md`, its number kept, its links rewritten / *not* the next free number: it is already cited as 7.

**Listing (C-d) and gaps (C-e):**

10. "What decisions do we have?" → the listing command, read and answered in the dialog / *not* an `INDEX.md` written into the territory: it drifts from the files on the next write, and the gate would block its name anyway.
11. Number 14 is missing → `git log` says what it was / *not* a placeholder `dec-0014-deleted.md`, and not a new item under 14.

12. A README explaining the kind is wanted inside the territory → take it out of the territory with a negated pattern, or keep it one level up / *not* `dec-0000-readme.md`: that is a placeholder with a number.

**Citing (C-f):**

13. A link target or an envelope field → the full name, `<prefix>-0007-<slug>` / a sentence in a review comment → the bare `<PREFIX>-0007` is fine.
14. An item still on its branch is cited in that branch's own documents → by its full name, which the renumbering step will find and rewrite / *not* by a bare number in a file the branch does not touch.
15. A sentence says "decision 7" → resolve it with the case-insensitive glob before relying on it / *not* by opening the seventh file of the listing: gaps shift positions.

## 9. Enforcement honesty

| # | artifact | kind |
|---|---|---|
| E1 | hook + `check-catalog-item.sh` + `check-catalog-item.py` (hook mode): K1, K2, K4 | `gate`, severity dial `severity` (`block` default; `warn` reports and lets the write through) |
| E2 | `check-catalog-item.py --scan`: K1, K2, K3 | `gate`, always blocking (exit 2), ignores `severity` |
| E3 | the number named in K1's and K4's fix and in the scan's count line | `advisory` — deterministic arithmetic over the working tree and the history at hand, carried inside a gate's message; no verdict depends on it or waits for it, a number other than the one named passes when it is free, and where history could not be read the text says so instead of claiming it |
| E4 | skill `catalog-item` | `advisory` |

**Honest limits**, each with its backstop. The limits of the shared code — shell writes and other actors, non-blocking configuration failures and timeouts, a dropped link to the shared code, the reconstructed `Edit`, symbolic links, a key given twice, `.md` only and git-ignored files, where the envelope ends, case-sensitive patterns, the best-effort log, no `--help`, one block message at a time when several gates block, a negated pattern under an excluded directory — are [kit-shared-gate-code §4](../../shared/GATE.md#g4), items 1–13, and apply here; the skill tells the agent to run the scan after a shell edit. This module's own:

1. **Off until listed.** With `catalogs` empty the gate examines nothing. Backstop: every run prints `0 documents examined` with the entry to write, and every session start prints the one line of [§6](#t6) while the dial stays so; a profile can prewrite the dial.
2. **A rename is not a write.** `git mv` and a rename through the shell never reach the hook, so an item can lose its form, or take a carried number, unseen. Backstop: the scan; the skill's last step.
3. **A silently deleted item is not detected, and a gap may be filled.** Gaps are legitimate ([kernel §1](../../kernel/CONVENTIONS.md#k1): a document nothing should reference is deleted), so no continuity is checked, and the gate lets a free number below the highest through — it cannot tell a deleted item's number from one renumbered away before it landed. Backstop: the advice never names such a number; branch review and `git log`.
4. **A file carrying a prefix outside its catalog's territory is invisible to the gate** and is listed by the skill's prefix glob; an item whose name lacks the form is in the territory and not in that listing. Backstop: the scan reports the second; review catches the first.
5. **Collisions across branches are seen only where both branches meet:** in the scan of a merged tree. Two pull requests that are each green apart can both land where the forge does not require a branch to be up to date. Backstop: the scan on the main branch after every merge; a protected branch that requires up-to-date checks.
6. **A reference to a provisional number from another branch breaks at renumbering.** Backstop: rule C-b; K3 names every file of the collision, so the renumbered name is one `git log` away.
7. **History is read where it exists, and only as long as the hook can wait.** A shallow clone, a repository with no commit yet, a history too long to read in five seconds, and one rewritten or squashed give the working tree's answer; a name of the catalog's form added anywhere in the repository counts, which can only skip a number. Backstop: the fix text and the count line say when history is incomplete or was not read — a repository with no commit has a complete, empty one — except for a rewritten history, which nothing can see; skipping is harmless, since gaps are legitimate.
8. **The width is a ceiling.** Past the last number `width` digits can write, the fix says the catalog is full and names no file; widening a catalog renames every item. `width` itself stops at 9. Backstop: width 4 holds 9,999 items; the choice is made once, with the prefix.
9. **An existing item is never judged on its number at write time,** so two items that already collide can both be edited until the scan is run. Backstop: K3.
10. **The rest of the envelope, and which policy governs an item, are not judged.** Backstop: module `const-meta-types`; alone, this module lets them through, and the install note says so.
11. **Everything in a territory is an item:** a README there is blocked for its name. Backstop: a negated pattern takes the file out — directly under the top directory of a territory written `<dir>/**` or `<dir>/*`, not `<dir>/`; deeper down only from a territory of file patterns ([kit-shared-gate-code §4](../../shared/GATE.md#g4), item 13) — and the install note says how.
12. **A git-ignored item holds no number,** for the scan and for K4 alike: the file list is git's, without what git ignores. Backstop: numbered documents are not ignored files; the hook still judges such a file's name and id when it is written.
13. **Where the file system ignores case, a write to the lowercase name of a file that exists in another case passes and renames nothing:** the hook judges the path it is given. Backstop: the fix says `git mv`; the scan sees the name git records ([kit-shared-gate-code §4](../../shared/GATE.md#g4), item 9).
14. **Under width 4 a date-shaped name is an item.** `<prefix>-2026-09-22-<slug>` has the form — number 2026, slug `09-22-<slug>` — so a legacy convention of dated names makes every such file an item numbered by its year, and once a name of the form is committed, the advice names the year plus one for as long as the branch's history holds it: a rename does not undo it, nor does declaring the catalog later. No verdict follows — a lower free number passes (limit 3, [A13.3](../../docs/requirements.md#a13-3)). Backstop: rename before the name's first commit; or choose a prefix the dated names never carried, since history is read for the catalog's own prefix; or take the number by the skill's rule and let the advice stand. Under another width the name is not of the form and is a K1 finding on the adoption path.

**Exit-code contract** (both modes): `0` green or nothing examined (the count line says which); `2` finding — the repository is wrong; `1` configuration failure — the checker could not run (missing or too-old interpreter, missing library, malformed dials file, a key of the namespace that is no dial, a malformed `catalogs` entry or a prefix listed twice, the shared code missing from the install, git absent, a log directory git does not ignore, unparseable hook input, a bad argument, or an unexpected exception, whose traceback is printed). Nothing exits 0 on error. A git that cannot list history, or not in time, or that vanishes while history is read, is none of these: history is advice, its absence is the working tree's answer, and the text says so.

## 11. Siblings

**Depends on:** [kernel §1](../../kernel/CONVENTIONS.md#k1) (the envelope's `id`, never reused, and the deletion rule that makes gaps legitimate), [§6](../../kernel/CONVENTIONS.md#k6) (the dials file, the module's own namespace, the territory dialect, portability), [§7](../../kernel/CONVENTIONS.md#k7) (naming: kebab-case ids and file names). **Optional enhancements:**

1. When module `const-meta-types` is installed, the rest of an item's envelope and its governing policy are guarded there; this gate and that one both report an envelope that cannot be read, each for its own field.
2. When module `const-decision-records` is installed and a catalog's territory holds the records, its skill takes a record's number from this module's procedure.
3. When module `const-locations` is installed, its creation command hands the kind's home and template to the writing step of this module's skill.
4. When module `const-referencing` is installed, an item's full name in backticks must be a link and a link showing it must open the item — its checks of a governed id in backticks that is no link, and of a link whose text is an id opening another document (R2 and R3 of that module's document), know every covered envelope's id, and an item's id is its name — with nothing wired between the modules; the bare form in prose is tolerated by [A13.6](../../docs/requirements.md#a13-6) and linted nowhere unless the consumer writes a `lanes` entry for the prefix in that module's dial.

## 12. Deferred

1. **A catalog declared by naming a policy** — an entry with `policy: <id>` in place of `territory`, the territory then being the policy's. Signal: a consumer commit note about a catalog's territory that drifted from its kind's policy despite the YAML alias.
2. **`--list` and `--next` modes of the script.** Signal: consumers report the prefix glob as too loose — stray files listed, malformed items missed — or the count line as too awkward to read a number from; it needs module-defined modes in the shared command line.
3. **Refusing, at write time, a number that history held.** It would make one write red in a full clone and green in a shallow one. Signal: re-issued numbers landing despite the advice.
4. **A `--base <ref>` option naming which item of a collision is frozen.** Signal: renumbering disputes the skill's rule does not settle.
5. **Non-Markdown items, and a continuity report.** The first needs an id outside an envelope; the second contradicts the deletion rule. Signal: a consumer numbering files of another type; none foreseen for the second.
6. **Windows without a POSIX shell or without symlink support; performance past the 30 s timeout; other Markdown extensions** — deferred for every gate alike; the signal is a consumer on Windows, the timeout hit, a governed document with another extension.
