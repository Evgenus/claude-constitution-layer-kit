# MODULE.md — `const-change-cost`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A person asks what a change cost in tokens. Claude Code writes each reply of the model into the session's transcript with its token counts, and gives no count per commit. Three things defeat a count made after the fact. First, sessions copy each other's records. A forked session copies its parent's replies with the same ids and times. On 2026-10-28, 3,699 of the 18,607 replies in the kit's own transcripts stood in two sessions or more. No field says which session made them. A tool that reads every transcript at once can then give a parent's work to its fork. Second, nothing records which session made a commit, or when a session started, unless a hook writes it at that moment. Once the moment has passed, it is lost for good. Third, Claude Code deletes a command-line session's transcript after 30 days by default, without a message. This module logs each session's start and each commit as they happen. It counts the tokens of each commit's window with a pinned ccusage, over a folder that holds that one session alone. It keeps the count in the clone. It shares it, when a person starts it, by the merge commit's trailers, the pull request's description and git notes.

<a id="t2"></a>
## 2. Failure class

**Accumulating**, the whole module (R13 of [dec-0116-tokens-per-commit-counted-by-ccusage](../../docs/decisions/dec-0116-tokens-per-commit-counted-by-ccusage.md#r13)). A session's start and the session behind each commit are lost for good when no hook records them as they happen. The transcript a count reads expires with the platform's cleanup, so each session not logged is a count that can never be made. **Entry trigger:** the project's first session that commits. The module belongs in every project's day-one install set, and with it Node and npm on the first day. The day-one set also runs `setup-commit-log.sh` once in each clone, before that clone's first session that commits. Without it that clone's commits are not logged, for good (R2 of [dec-0117-change-cost-module-rulings](../../docs/decisions/dec-0117-change-cost-module-rulings.md#r2)). No other module carries any part of the count.

## 5. Invariant

None. Every artifact of the module is advisory ([§9](#t9)), and an advisory-only module claims no invariant. What its deterministic parts do — the logs, the windows, the count and the report — stands in the readings of [§3](#t3) and in [§6](#t6). Each commit of a session whose start is logged, made at or after that start, gets once its window is complete one kept line. The line is made from that session's records alone. The report names every commit of a range that has none, with the reason. In place of an invariant stand the module's rules:

1. **J-a** (advisory) When the start line says this clone logs no commit, tell the person, and run `setup-commit-log.sh` only when they ask. Git's configuration changes only at a person's word.
2. **J-b** (advisory) When the person asks you to open a pull request or to make a merge, do two things. Run `cost-report.sh --pr <range>` before the pull request is opened and again before it is merged, and let its block stand in the description. Put the lines of `cost-report.sh --trailer <range>` into the last paragraph of the merge commit's message. An export is started by a person, or by a session at the person's word, and never by a hook.
3. **J-c** (advisory) Write the counts as git notes with `cost-report.sh --notes <range>`, and push the notes ref, only on the person's word. A pushed ref publishes every count and cost.
4. **J-d** (advisory) Read every cost as the list price, a named compaction as uncounted work, and an unpriced model's cost as a lower bound. Never give a count as all of a session's work or as what was paid.

## 7. Dials

None. The module has no dials of its own (R11 of [dec-0117-change-cost-module-rulings](../../docs/decisions/dec-0117-change-cost-module-rulings.md#r11)). Nothing in its rows asks a project to calibrate anything. A dial on any rule of the count would make two projects' counts mean different things. It has no gate, so its `severity` changes nothing. Its output log is `${CLAUDE_PLUGIN_DATA}`, else nowhere ([rule 12 of kit-gate-script-rules](../../module-template/gate-script-rules.md#r12)), save for the effect report below. Only the effect entry reads the dials file. In the shared runner, `gather` of `effect.py` calls `load_dials` of `dials.py` and `route_log` of `pipeline.py`. The reader parses the whole file: the kernel keys, the territory of every namespace, and in `const-change-cost` the two keys every namespace may hold. They are `severity`, a bad value of which it refuses with the shared `C5` line, and `log_dir`. A malformed file stops the effect report. With `log_dir` set and git ignoring that folder, the report reads its output log from there. A folder git does not ignore stops it with the shared `C13` line. Without `log_dir` it reads the log under `${CLAUDE_PLUGIN_DATA}`, else none. No other entry writes to a `log_dir` folder, so with the key set the report finds no session through its log (limit 22 of [§9](#t9)). Leave it unset. No other entry reads the file, so a fault in it never stops a log that cannot be made later. Any other key under `const-change-cost` is read by nothing. Every cost is the list price of ccusage's table at the pinned version. The report says so. The candidates of that ruling stand in [§12](#t12), items 1 to 3. Item 4 is the deferred dial of R14 of [dec-0116-tokens-per-commit-counted-by-ccusage](../../docs/decisions/dec-0116-tokens-per-commit-counted-by-ccusage.md#r14). That dial is earned only by a project that needs compactions counted. Its reports would then name that their counts include compactions, so two projects' counts are never read as one measure.

## 8. Boundary examples

The logs, the count and the report are deterministic; the fixtures are their pairs. The judgment is the skill's.

**Git's configuration changes only at a person's word (J-a):**

1. The start line names the missing hooks. The person asked for a typo fix → say once that this clone logs no commit and how to set it up. Then fix the typo / *not* run `setup-commit-log.sh` unasked.
2. The person answers "set it up" → run `setup-commit-log.sh`, then `--check` / *not* write the keys with `git config` by hand.
3. The person says this clone should not log commits → leave it and do not raise it again in the session / *not* repeat it every turn.
4. A headless session that no person watches meets the line → name it in the final reply / *not* run the command because nobody can be asked.

**Share at the pull request and the merge (J-b):**

5. The session is to merge a branch on the person's yes → `cost-report.sh --trailer <base>..<branch>`, its lines in the merge message's last paragraph / *not* a merge message without them.
6. The session is to open a pull request → `cost-report.sh --pr <base>..<branch>`, the printed block in the description given to the forge / *not* a cost typed by hand.
7. The report names two commits not counted → the trailers as printed. The total says how many were counted / *not* the trailers held back until every commit is counted.
8. The person will merge on the forge's page → give them the trailer lines to paste / *not* nothing, since no local hook sees that merge.

**Notes on the person's word (J-c):**

9. The person asks to share each commit's count with the team → `cost-report.sh --notes <range>`, then name the push command / *not* push the notes ref unasked.
10. Notes were written and a rebase is planned → say that the notes stay on the old commits unless `notes.rewriteRef` names their ref / *not* rebase in silence.
11. The repository is public and the person asked only for the pull request's block → the block alone / *not* notes as well.

**Read a figure for what it is (J-d):**

12. The report names a window's compaction → "at least this many tokens; the compaction's work is not counted" / *not* the number as the window's whole cost.
13. A cost reads "at least $0.40" with an unpriced model → say "at least" and name the model / *not* "$0.40".
14. The person asks what the branch cost them → the list price, said as such / *not* given as the bill.

Exit codes of every entry: `0` done, nothing to do included, its closing or head line saying how many. `1` a configuration failure, the shared ones and J6. Never `2`, since no entry has a finding.

**Honest limits.** The limits every gate shares: [kit-shared-gate-code §4](../../shared/GATE.md#g4); those that concern this module are 2, 3, 10, 11, 16, 17 and 18. This module's own, each with its backstop:

1. **Commits made before the setup command runs are never logged.** Only a person, or a session when the person asks, writes the hooks, so a clone's first commits can be lost. Backstop: J1 at every session start while a hook is missing; the report names each such commit (J11.1); W1 of [§13](#t13) counts them.
2. **A session with no logged start gets no count, nor a commit made before the session's first logged start:** one started before enabling the plugin. Or one started in another folder, or with `git -C` from outside the clone. Backstop: the report names its commits (J11.3); the day-one install keeps the case narrow.
3. **A compaction's tokens are not counted.** They reach no transcript (platform fact 12). Backstop: each compaction is named in its window. Every figure of that window is a lower bound by rule J-d.
4. **Every cost is a list price.** A project that pays another price sees the wrong cost. A model newer than the pin has no price. Backstop: every output says "list price"; an unpriced model is named and its cost shown as "at least" (J10).
5. **A transcript swept before its window is counted is lost to the count.** Backstop: the count runs after each turn and at each start, long before the 30 days of platform fact 7. The report names the commit (J11.5).
6. **A commit that no git hook of this clone sees is not logged:** one made by a tool that runs no git hook. Or one made on a forge's page. A forge's merge brought in by a fast-forward is no new commit here. The `post-merge` command logs only a merge commit whose reflog entry is no fast-forward. Backstop: the report names every commit of a range with no line (J11.1). The reflog's text is git's own and no promise. A git that changes it would log a fast-forward with the session that ran the pull.
7. **A process that inherits `CLAUDE_CODE_SESSION_ID`,** such as a background launcher a session started, keeps it. So a commit typed later in it is logged with that session (the comparison's d5, read, not run). Backstop: none — accepted; the commit's window holds only that session's own replies.
8. **A nested session that keeps no transcript** names a session whose records stand nowhere (the comparison's d6, read, not run). Backstop: the report names its commits (J11.5).
9. **An async count can be killed:** in a `-p` session at teardown (platform fact 4), or by a crash. A kept line is appended whole after its window's count, so a killed count writes none. Backstop: the next pass counts the window; `count-costs.sh` by hand.
10. **The windows run over the whole session.** While one agent works and another commits, the first agent's tokens until then go to that commit. Backstop: none — accepted, as R6 of [dec-0117-change-cost-module-rulings](../../docs/decisions/dec-0117-change-cost-module-rulings.md#r6) rules; the session's total is exact.
11. **A rewritten commit is a new commit.** After a rebase or an amend, the new commit's window runs from the session's previous logged commit, the old one keeping its count. So a range that holds only the new commits sums less than the work. Backstop: the report with no range lists every kept line, the old commits included.
12. **A session that ends with no record after its last commit** leaves that window waiting until the session is resumed. Backstop: the report names it (J11.4).
13. **The transcript's format is the platform's and undocumented.** The cutter reads six fields of a record, its time, `sessionId`, `message.id`, `requestId`, `type` and `subtype`; a field that moves shows as replies missing from a window. Backstop: the known-count fixture at the pin; the comparison of a window with a count made apart in the fixtures.
14. **The counts stay in the clone** and are lost with it; other clones never see them. Backstop: the trailers, the block and the notes, each started by a person.
15. **`--pr` knows one forge's command line, `gh`.** Elsewhere it prints the block. It tells a missing pull request from another `gh` failure by `gh`'s words `no pull requests found`, which are no promise: other words give J15.3 with its first line. Backstop: the printed block, for a person to paste (J15.2 to J15.4).
16. **A count that fails in an async hook is seen by no session.** Its J6 line reaches only the output log in the data folder. An async hook's results reach the session at most on its next turn. Backstop: the report names each such commit with J11.4, whose fix, `count-costs.sh --all` by hand, prints the failure.
17. **A run by hand finds the data folder only through the record a hook left.** A clone where no start hook ran under this plugin, or whose recorded folder no longer stands, has none. The run gives J6.3. Backstop: J6.3's fix, a session started in the project.
18. **A git hook needs `python3` on git's own `PATH`.** A git client that starts git with another `PATH`, such as some desktop clients, runs the hook without it. The hook fails, and the commit is not logged. Backstop: J11.1 names each such commit; `setup-commit-log.sh --check` shows that the keys stand, not that `python3` runs.
19. **The module is POSIX only.** Its two locks, of the file of counts and of the install, use `fcntl`, which Windows lacks, so the count stops there with a traceback. Backstop: none; accepted while no consumer runs on Windows.
20. **W2 counts every `git merge`,** a merge of the main branch into a work branch included, as a moment of opening or merging a pull request. So its B5 count can be too high. Backstop: the rule's counts are advisory. Its moments are listed by the effect report.
21. **A window is taken as complete on one record dated after the commit, in any of the session's files.** A file is written in order, so such a record proves the earlier records of its own file written. A parallel agent's file is written on its own. So a record of it dated before the commit and written after the count is in no window. This can happen only to an agent still running when its session commits. Backstop: none.
22. **With `log_dir` set for `const-change-cost`, the effect report finds no session through its log.** It reads the output log from that folder, where no other entry writes: they log to `${CLAUDE_PLUGIN_DATA}`. Backstop: leave `log_dir` unset ([§7](#t7)); `--transcripts` still works.
23. **The data folder is one per plugin, shared by every project (platform fact 15), so two versions of the plugin with different lockfiles reinstall each other's copy.** Each install and each ccusage run stands under the install lock, so a count never runs a half-installed launcher or another version. A pass that cannot take the lock counts nothing (J5.4). Backstop: the cost is a repeated install and passes that wait; a later pass counts the windows.
