# MODULE.md — `const-task-close`

*Draft at manifest version `0.0.1`, no open slots. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A change lands in the code and the page that describes the code stays as it was. Nobody notices at the commit, because the page is in another file and still reads well. It is found later by a reader who follows the page into code that no longer does what it says. Or the author of the next change finds it, and now has to work out which of the two is true. The kit saw this on itself while authoring five modules, whose scripts, documents and rules it kept in step by hand. Nineteen of fifty accepted commits touched a module's scripts without its document, and one landed change touched no document at all and declared nothing. Beside it stands the smaller failure of the same shape inside one session. Work done through the shell, a script or a subagent is left uncommitted at the end of a turn. There the chat's rewind cannot see it, and a later edit cannot be rolled back to it. This module makes task close a single, checkable act. Under it, a change that touches code a current-state document describes also changes that document, or says in a searchable line why not. Under it, a task's working files are deleted and its record set `inactive` at its close. And under it, a turn never ends with a dirty tree unremarked.

<a id="t2"></a>
## 2. Failure class

**Accumulating.** Every undocumented change is one more page a reader cannot trust. The divergence compounds silently until the page is rewritten from the code — the retrofit the kernel's defect rule exists to forbid. **Entry trigger:** the first change that touches code described by a current-state document. In practice it is the first commit after a project writes its first design page. So the module belongs in the day-one install set; the kit passed the trigger at its first module.

## 5. Invariant

**In an examined range, every coverage pair whose code the range touches is either updated or declared. A pair is updated when one of the pair's documents is among the range's paths. It is declared by a no-impact line naming the pair, in a commit of the range or in the body given to the check. And at the end of a turn in a session that loads the plugin, a dirty working tree is reported once before the turn ends. While the turn-end event lists an agent of the session that still runs, that report waits. It waits for the first turn end with no such agent.** "Range", "pair", "declared" and "dirty" are this module's definitions ([§6](#t6), [§7](#t7)). An agent that still runs is what limit 15 of [§9](#t9) says. Task close, the defect rule and the lifecycle are the kernel's ([kernel §1](../../docs/constitution/CONVENTIONS.md#k1), [§2](../../docs/constitution/CONVENTIONS.md#k2)). The words "examined" and "a session that loads the plugin" are the honest boundaries of [§9](#t9).

The advisory rules beside it:

1. **T-a** (advisory) Close a task as one act. Merge the deltas into the documents the map names and run the range check. Delete the working files, set the record `inactive`, and commit as one change whose message names the close.
2. **T-b** (advisory) An active task-record whose scope sees no commits is stalled drift. Commit it back or roll it back, never leave the halfway state as truth. An `inactive` record is kept while something should still reference it, and deleted once nothing should, git history its archive. Whether anything should is judgment.
3. **T-c** (advisory) Commit a dirty tree before the first edit of any change, and commit again after each coherent change. Never end a turn dirty — git is the rollback layer, the chat's rewind is not.
4. **T-d** (advisory) A no-impact declaration is a judgment written for the reviewer. Name the pair and say why its documents stand, and never declare what an update would have fixed.
5. **T-e** (advisory) A task's working files are deleted at its close and git remembers them; a file kept is kept with a reason.

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | hook | How loud a dirty tree at turn end is. `block`: exit 2 on the turn's first stop — the model receives T1 and the turn continues once. `warn`: exit 0 with T1 in a `systemMessage`, shown to the user, unseen by the model. The second stop of a turn is exit 0 under both. A dirty tree at a turn end while an agent of the session still runs is exit 0 under both too. The hook then prints the held line of G1. The scan ignores it. |
| `log_dir` | absent | hook, scan | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |
| `coverage` | `[]` | scan | The map: a list of pairs `{name, code, docs}`. The name is kebab-case and unique in the list. `code` holds gitignore patterns of the code the documents describe, matched against the range's paths whether or not they still exist. `docs` holds repository-relative paths of the current-state documents, read by the shared `relative_path` — trimmed, `./` and `//` normalised, a path leaving the repository refused. Each is an existing file at HEAD unless the range itself deleted or renamed it. A path with a trailing slash is refused at the read (C5), one that is a directory at HEAD by the scan (X2). A `docs` path that also matches the pair's `code` is left out of the pair's code side. Pairs may overlap; order carries no meaning. A negated pattern takes a path out only where git can: `src/*` then `!src/vendor/` works, `src/**` then `!src/vendor/**` does not. That is because git re-includes nothing under a directory an earlier pattern excluded. A backslash in a `docs` path separates only where the platform says so (limit 15 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)). `..\x.md` is one file name on macOS and Linux, while on Windows it leaves the repository and is refused. Empty: zero pairs examined, said so. With an empty map no range is examined, so no base is found and the trunk is not looked up. With an empty map, a repository whose only branch is not the trunk is green. With an empty map, a `--since` or `--change` given is still resolved, an unknown ref the C12 it is with a map. |
| `trunk` | `main` | scan | The branch changes land on: the base of a scan given neither `--since` nor `--change` is the merge-base of the trunk and the head. The trunk is the local branch `<trunk>` or the remote's tracking branch `<trunk_remote>/<trunk>`. Where only one exists, it is that one. Where both do, it is the tracked one if the local one is its ancestor or equal to it. Otherwise — the local one ahead, the two split, or an ancestry git cannot answer — it is the local one. A head that *is* the trunk — the branch of that name, or a detached HEAD at either tip — examines its last landed change, as `--change HEAD` would. Looked up only where a range is to be examined: with an empty `coverage`, never. |
| `trunk_remote` | `origin` | scan | The remote whose tracking branch of the trunk is looked up beside the local one. A non-empty string with no white space and no control character, not beginning with a dash, kept as written. A `/` is allowed, as git allows one in a remote's name. Anything else is C5, at every entry point, the hook included. Whether git knows the remote is learned at the lookup, where a trunk found nowhere is the C12 naming `<remote>/<trunk>`. |
| `declaration_key` | `No-Doc-Impact` | scan | The trailer key of the no-impact declaration, matched case-insensitively as git matches it; the same line is read from a `--body` file. The value is a pair's name, a dash and the reason. The dash is an em or en dash, spaced or not, or one or two hyphens spaced on both sides. No wildcard: a value naming no pair, `*` included, is T3, and a change touching several pairs writes one line per pair. |
| `working_files` | `[]` | scan | Gitignore patterns of a task's working files; a tracked file that matches earns note N3. Empty: no note. |

The gate validates every key it reads at each read. A key of this namespace that is none of the seven above is a configuration failure. A misspelt `coverage:` would otherwise be an empty map in silence.

## 8. Boundary examples

The range check and the tree check are deterministic; the fixtures are their pairs. The judgment is the skills'.

**Close as one act (T-a):**

15. The documents, the deletions and the status change → one change, its message naming the close / *not* the status change left for a later commit.
16. A document edited to say what the code now does → the state as it is / *not* a changelog, "as of this task".
17. Intent that is not yet real → the task's record / *not* a current-state page.

**Stalled or paused (T-b):**

- **8.** A task-record has stood `active` for a month, its files untouched. Its author is gone → commit back what is real and set it `inactive`, or roll it back / *not* left as the write-head.
- **9.** A plan whose next step waits on a decision named as the blocker → paused, the blocker written in the record / *not* rolled back.
- **9a.** An `inactive` record a current-state page still cites for its reasoning → kept / *not* deleted for being old.

**Commit before you edit (T-c):**

10. The first edit of any change is about to start on a dirty tree → commit first, then edit / *not* "the rewind will cover it". The rewind covers nothing done through the shell.
11. A turn ends with one coherent change done → commit / *not* "next turn".
12. A turn ends mid-change, a test still red → commit as work in progress, the message saying so / *not* a clean-looking silence. Or stash, and say so.
13. The hook blocks a turn that was a question with no edits → impossible: a clean tree is silent. A dirty one was left by earlier work, and that is what it names.
14. A turn ends while a `process` record waits for its yes → commit the change on its own branch. The yes is named in the merge that lands it / *not* left dirty to wait, and *not* committed onto the trunk before the yes.

**Declare, or update (T-d):**

- **1.** A gate's message text changes → its module document's error-message table is updated / *not* declared: the document states the text.
- **2.** A comment reworded in a script, no behaviour changed → `No-Doc-Impact: <pair> — comments only, no rule or message changed` / *not* an edit to the document to make the gate green.
- **3.** A dial's default changes → the document's dial table / *not* `No-Doc-Impact: … — small change`.
- **4.** A file moved inside the code territory, the document naming it by path → the document / *not* a declaration. The path in the page is now wrong.
- **4a.** A formatter pass over a script tree → a declaration naming the pass / *not* silence. The change is real and the reviewer should see it was judged.

**What is a working file (T-e):**

5. A scratch script written to try a fixture → deleted at close / *not* kept "in case".
6. A note that became the record's reasoning → the record / *not* the note beside it.
7. A fixture the gate runs → code, not a working file / *not* deleted because it was written during the task.

Exit codes: `0` green, or nothing to examine, the count line saying so; `2` a finding; `1` a configuration failure — the shared ones, X1, X2, C5 and C12.

**Honest limits.** The limits every gate shares: [kit-shared-gate-code §4](../../shared/GATE.md#g4). This module's own, each with its backstop:

1. **A block on `Stop` is a request the model weighs, not a wall.** The model may refuse, as it did in the research when its prompt told it not to commit. The second firing lets the turn end either way, and a committed tree can carry a poor message. In a session that cannot ask — `claude -p`, `dontAsk`, `--permission-prompts none` — a block costs that one continuation. In such a session the block leaves the tree dirty unless the commit T1 teaches is allowed. That commit is the compound `git add -A && git commit …`, and a rule must match each part on its own (fact 13 of the platform facts in [§6](#t6)). So the consumer allows both `Bash(git add *)` and `Bash(git commit *)`, or sets `warn`. Backstop: the message teaches the commit's shape; the user sees the notice; the scan judges the commits.
2. **The hook does not fire on a user interrupt,** nor in a session that has not loaded the plugin, nor for a subagent's own stop. Backstop: the scan; the session rule in the consumer's own instructions.
3. **A declaration's truth is review.** The gate holds its presence, shape and target, never whether the documents really stand. Backstop: N2 prints every declaration used, each reason cut at its first 80 characters. So the reviewer reads the whole reason where the note says it was declared, in that commit or in the body; rule T-d.
4. **The unit is the change.** A commit inside the range may touch code without its document. The range is green when a later commit of the same range updates it — by design. And a change merged by hand into the trunk without the scan is examined only by the next scan of the trunk. There, on a trunk that fast-forwards, "the last landed change" is the last commit alone. Backstop: the scan on the trunk, `--change HEAD`, in CI.
5. **Git's trailer rules are unforgiving:** one colon-less line in a message's last paragraph hides every trailer there. And a squash merge keeps a trailer only when its message lands last. Backstop: T2's fix states the paragraph's rule; the body line is the second form.
6. **The body is trusted text.** Whatever file `--body` names is read as the description. Nothing checks that it came from the forge, and the gate never fetches one: no client, no network. Backstop: CI writes it from the event payload; a local run has no body and reads the trailers. **The body form has no live proof in the kit**: the kit's CI passes no body to the scan. Its fixtures are against text (items 3, 19), and the kit's own use is the trailer.
7. **A shallow clone whose history stops before the base cannot see the range**. Git's refusal is relayed as the configuration failure whose fix names the fetch. A shallow clone whose history reaches the base is examined like any other, unremarked. Backstop: CI fetches the whole history.
8. **The map covers what it lists.** Code no pair names is never a finding, and a document no pair names is never asked to move. Backstop: the map grows with the project; N3 and the close skill.
9. **Dirty means what `git status --porcelain` lists** — tracked changes and untracked files git does not ignore. An ignored scratch directory is invisible, which is where working files should live until close. Backstop: `working_files` for tracked ones.
10. **The scan compares commits,** so an update sitting uncommitted in the working tree does not count. Backstop: the hook; T2's fix says "in this change".
11. **`stop_hook_active` is set by any Stop hook's continuation.** When a sibling's Stop hook continued the turn first and the tree was dirtied afterwards, this hook meets the second stop. It lets the turn end with its second-stop line, having reported nothing. Backstop: the next turn's first stop; the line says what it saw.
12. **Every configuration failure ends in a count of documents**. That line is `BROKEN: the check could not run — 0 documents examined`, written for the write-time gates and printed unchanged by the shared guard and by this gate's entry files. Read it here as: nothing was examined. Backstop: the first line names the fix either way.
13. **A git too old for the trailer options is told by one placeholder.** Such a git prints the format's `%(trailers` back as text, with exit 0. The gate reads that text at the start of a commit's whole trailer field as the old git's. It is the C12 naming git's version line, never a red for a declaration nobody wrote. No git version is declared or checked. A reason that quotes the placeholder further in, or a later declaration of the same commit that begins with it, is read as ever. But a commit whose first declaration begins with it gets the same failure. Backstop: the failure names the fix, `install a newer git`.
14. **Shared limit 1 holds here in its own way:** a commit made through the shell is exactly what the scan examines. And the turn-end hook reports the tree such a change leaves. Backstop: none — accepted, since this is the object of both checks, not a gap in them.
15. **The hook knows that agents run, never whose the dirty files are.** While the `Stop` event lists a task of type `subagent`, `teammate` or `workflow` with the status `running`, a dirty tree is not reported, under either severity. So the session's own uncommitted work waits with the agents' files, and an agent that only reads holds the report too. A shell task and a monitor hold nothing. A clean tree keeps the clean line and the second stop of a turn keeps its own line, whoever runs. The held line goes to standard output alone: the model does not receive it (platform fact 10 of [§6](#t6)), and the user gets no notice. The hold needs the platform's list (platform fact 14 of [§6](#t6)). An event without it, a list the hook cannot read, and an entry of another shape leave the report as it was. An entry whose `type` or `status` is no text is one of another shape. An agent whose status is not `running` leaves the report as it was too. None of these is a configuration failure, so the hook fails towards the report. The report comes at the first turn end with no agent running, where that turn end is the turn's first stop. At a second stop, limit 11 holds. A session that is closed while its agents run gets no report. Backstop: that first turn end; the held line gives both counts, and the output log keeps it where `log_dir` is set; the scan judges the commits.

## 11. Siblings

**Depends on:** [kernel §1](../../docs/constitution/CONVENTIONS.md#k1) (the lifecycle rule; `status`) and [§2](../../docs/constitution/CONVENTIONS.md#k2) (task close as a single act, the defect rule, stalled drift). It depends also on [§6](../../docs/constitution/CONVENTIONS.md#k6) (the dials file, the dialect, portability). Beside the kernel it needs git, and Python 3.12 or newer with PyYAML and the Python package `constitution-layer-kit`, which pip installs. That package is the kit's shared gate code and no sibling ([law 3 of CLAUDE.md](../../CLAUDE.md#law-3)). Nothing else. **Kernel alone, with that package installed:** on a bare repository with no `constitution.yaml` the hook is a visible skip and the scan too. With a dials file that holds only `module_prefix: const-`, the hook judges the tree and the scan examines zero pairs and says so. With a map, the scan judges every change. No policy is read, no envelope is judged: a task-record's `status` is set by the skill, in words. **Without git,** the hook and the scan stop at their first call to it, in the shared configuration failure `C3`, and examine nothing. The pointer line, which a POSIX shell prints and no Python reads, and the two skills, which are prose, still work. Without Python or PyYAML the hook and the scan stop in the shared failures `C1` and `C2`, with this gate's own closing clause.

1. When module `const-decision-records` is installed, its record skill defines when a record is `inactive` and this module's close skill performs it at close. Neither reads the other's dial.
2. When module `const-locations` is installed, a document a pair names that does not exist yet is created through its command, at the home its policy implies.
3. When module `const-referencing` is installed, its scan runs beside this one before a merge, and the two verdicts are read together. And the close skill says to repair the links a deletion leaves before the closing commit. The skill says to remove each, or redirect it to where the content went. That scan lists the ones left dangling.
4. When module `const-meta-types` is installed, the documents the map names carry valid envelopes; this module never reads one.

## 12. Deferred

The deferrals every gate shares stand once in [kit-shared-gate-code §1](../../shared/GATE.md#g1). This module's own:

1. **The pull-request body read from the forge** by the module itself, through a client and the network. Today the body is text given with `--body`. Signal: a consumer whose closers cannot get the body into a file.
2. **Drift by timestamp** — the newest commit of a pair's code newer than the newest of its documents with no declaration since. It compares commits, not content, resets on a typo fix, and blames nobody. Signal: a consumer commit note reporting drift no range had shown.
3. **The active-age assist** of [A4.3](../../docs/requirements.md#a4-3): a note of the scan, `<record> is active and its file saw no commit in <n> days`. Its scope is the commits touching the record's file, under a dial `active_age_days` absent by default. The note is skipped in a shallow clone. Signal: a consumer commit note about a task-record left active, or a stretch of the kit's own plan with no commits.
4. **`--history <n>`**, auditing the last *n* landed changes of the trunk in one run. Signal: a consumer adopting the module over a history it wants judged.
5. **A pair with no documents,** meaning "this code is described nowhere and every change to it is a finding". Signal: a consumer asking for the sharper form.
6. **`SubagentStop`.** Signal: subagents leaving dirty trees the main agent's turn end does not reach.
7. **Per-commit strictness as a dial.** The kit's history rejected it; a consumer with one-commit changes may want it. Signal: that consumer.
8. **Ways of the effect report that [§13](#t13) leaves out.** B1, a path bypass: the turn-end hook and the scan name no file, so there is no path to go around them. The shell route to the same end is W2's. B6, a shape missed: the module's advisory rules have no visible form in a reply. A reader rule: no rule of the module needs a judge that a pattern cannot be. Signal: a consumer commit note that names a way around the module in one of these.
9. **The task list read by the shared event reader.** Today this module reads `background_tasks` from the event's text itself, and no shared code carries the list. Signal: a second module whose hook needs the session's tasks in flight.
