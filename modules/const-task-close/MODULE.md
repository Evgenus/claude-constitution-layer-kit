# MODULE.md — `const-task-close`

*Draft at manifest version `0.0.1`, no open slots; published at `0.1.0` in rollout Phase D. This document is the module's description ([template](../../module-template/MODULE.md)). Every list and table row carries a handle.*

<a id="t1"></a>
## 1. Purpose

A change lands in the code and the page that describes the code stays as it was. Nobody notices at the commit, because the page is in another file and still reads well; it is found later by a reader who follows the page into code that no longer does what it says, or by the author of the next change, who now has to work out which of the two is true. The kit observed this on itself while authoring five modules: each module's scripts and its own document, the shared gate code and its page, the git hooks and the session rules, were kept in step by hand, and its history shows the cost — nineteen of fifty accepted commits touched a module's scripts without its document, and one landed change, a linter pass over two script trees, touched no document at all and declared nothing. Beside it stands the smaller failure of the same shape inside one session: work done through the shell, a script or a subagent, left uncommitted at the end of a turn, where the chat's rewind cannot see it and a later edit cannot be rolled back to it — the kit's rule "commit before you edit" exists because that loss happened. This module makes task close a single, checkable act: a change that touches code a current-state document describes also changes that document, or says in a searchable line why not; a task's working files are deleted and its record set `inactive` at its close; and a turn never ends with a dirty tree unremarked.

<a id="t2"></a>
## 2. Failure class

**Accumulating.** Every undocumented change is one more page a reader cannot trust, and the divergence compounds silently until the page is rewritten from the code — the retrofit the kernel's defect rule exists to forbid. **Entry trigger:** the first change that touches code described by a current-state document — in practice the first commit after a project writes its first design page, so the module belongs in the day-one install set; the kit passed the trigger at its first module.

## 5. Invariant

**In an examined range, every coverage pair whose code the range touches is either updated — one of the pair's documents is among the range's paths — or declared, by a no-impact line naming the pair in a commit of the range or in the body given to the check; and at the end of a turn in a session that loads the plugin, a dirty working tree is reported once before the turn ends.** "Range", "pair", "declared" and "dirty" are this module's definitions ([§6](#t6), [§7](#t7)); task close, the defect rule and the lifecycle are the kernel's ([kernel §1](../../kernel/CONVENTIONS.md#k1), [§2](../../kernel/CONVENTIONS.md#k2)); "examined" and "a session that loads the plugin" are the honest boundaries of [§9](#t9).

The advisory rules beside it, each `advisory` in its own text, are these. (T-a) Close a task as one act — merge the deltas into the documents the map names, run the range check, delete the working files, set the record `inactive`, commit as one change whose message names the close. (T-b) An active task-record whose scope sees no commits is stalled drift: commit it back or roll it back, never leave the halfway state as truth; an `inactive` record is kept while something should still reference it, and deleted once nothing should, git history its archive — whether anything should is judgment. (T-c) Commit a dirty tree before a batch of edits, commit again after each coherent change, never end a turn dirty — git is the rollback layer, the chat's rewind is not. (T-d) A no-impact declaration is a judgment written for the reviewer: name the pair and say why its documents stand, and never declare what an update would have fixed. (T-e) A task's working files are deleted at its close and git remembers them; a file kept is kept with a reason.

## 7. Dials

| dial | default | read by | meaning |
|---|---|---|---|
| `severity` | `block` | hook | How loud a dirty tree at turn end is. `block`: exit 2 on the turn's first stop — the model receives T1 and the turn continues once; `warn`: exit 0 with T1 in a `systemMessage`, shown to the user, unseen by the model. The second stop of a turn is exit 0 under both. The scan ignores it. |
| `log_dir` | absent | hook, scan | As every gate's ([template §7](../../module-template/MODULE.md#t7)). |
| `coverage` | `[]` | scan | The map: a list of pairs `{name, code, docs}` — a kebab-case name, unique in the list; `code`, gitignore patterns of the code the documents describe, matched against the range's paths whether or not they still exist; `docs`, repository-relative paths of the current-state documents, read by the shared `relative_path` — trimmed, `./` and `//` normalised, a path leaving the repository refused — and each an existing file at HEAD unless the range itself deleted or renamed it — a path with a trailing slash is refused at the read (C5), one that is a directory at HEAD by the scan (X2). A `docs` path that also matches the pair's `code` is left out of the pair's code side. Pairs may overlap; order carries no meaning. A negated pattern takes a path out only where git can: `src/*` then `!src/vendor/` works, `src/**` then `!src/vendor/**` does not, since git re-includes nothing under a directory an earlier pattern excluded. A backslash in a `docs` path separates only where the platform says so (limit 15 of [kit-shared-gate-code §4](../../shared/GATE.md#g4)): `..\x.md` is one file name on macOS and Linux, while on Windows it leaves the repository and is refused. Empty: zero pairs examined, said so — no range is examined, so no base is found and the trunk is not looked up, and a repository whose only branch is not the trunk is green; a `--since` or `--change` given is still resolved, an unknown ref the C12 it is with a map. |
| `trunk` | `main` | scan | The branch changes land on: the base of a scan given neither `--since` nor `--change` is the merge-base of the trunk and the head. The trunk is the local branch `<trunk>` or the remote's tracking branch `<trunk_remote>/<trunk>`: where only one exists, that one; where both do, the tracked one if the local one is its ancestor or equal to it, otherwise — the local one ahead, the two split, or an ancestry git cannot answer — the local one. A head that *is* the trunk — the branch of that name, or a detached HEAD at either tip — examines its last landed change, as `--change HEAD` would. Looked up only where a range is to be examined: with an empty `coverage`, never. |
| `trunk_remote` | `origin` | scan | The remote whose tracking branch of the trunk is looked up beside the local one. A non-empty string with no white space and no control character, not beginning with a dash, kept as written; a `/` is allowed, as git allows one in a remote's name. Anything else is C5, at every entry point, the hook included. Whether git knows the remote is learned at the lookup, where a trunk found nowhere is the C12 naming `<remote>/<trunk>`. |
| `declaration_key` | `No-Doc-Impact` | scan | The trailer key of the no-impact declaration, matched case-insensitively as git matches it; the same line is read from a `--body` file. The value is a pair's name, a dash — an em or en dash, spaced or not, or one or two hyphens spaced on both sides — and the reason. No wildcard: a value naming no pair, `*` included, is T3, and a change touching several pairs writes one line per pair. |
| `working_files` | `[]` | scan | Gitignore patterns of a task's working files; a tracked file that matches earns note N3. Empty: no note. |

The gate validates every key it reads at each read, and a key of this namespace that is none of the seven above is a configuration failure: a misspelt `coverage:` would otherwise be an empty map in silence.

## 8. Boundary examples

The range check and the tree check are deterministic; the fixtures are their pairs. The judgment is the skills'.

**Declare, or update (T-d):**

1. A gate's message text changes → its module document's error-message table is updated / *not* declared: the document states the text.
2. A comment reworded in a script, no behaviour changed → `No-Doc-Impact: <pair> — comments only, no rule or message changed` / *not* an edit to the document to make the gate green.
3. A dial's default changes → the document's dial table / *not* `No-Doc-Impact: … — small change`.
4. A file moved inside the code territory, the document naming it by path → the document / *not* a declaration: the path in the page is now wrong.
4a. A formatter pass over a script tree → a declaration naming the pass / *not* silence: the change is real and the reviewer should see it was judged.

**What is a working file (T-e):**

5. A scratch script written to try a fixture → deleted at close / *not* kept "in case".
6. A note that became the record's reasoning → the record / *not* the note beside it.
7. A fixture the gate runs → code, not a working file / *not* deleted because it was written during the task.

**Stalled or paused (T-b):**

8. A task-record `active` for a month, its files untouched, its author gone → commit back what is real and set it `inactive`, or roll it back / *not* left as the write-head.
9. A plan whose next step waits on a decision named as the blocker → paused, the blocker written in the record / *not* rolled back.

**Commit before you edit (T-c):**

10. A batch of edits is about to start on a dirty tree → commit first, then edit / *not* "the rewind will cover it": it covers nothing done through the shell.
11. A turn ends with one coherent change done → commit / *not* "next turn".
12. A turn ends mid-change, a test still red → commit as work in progress, the message saying so / *not* a clean-looking silence; or stash, and say so.
13. The hook blocks a turn that was a question with no edits → impossible: a clean tree is silent; a dirty one was left by earlier work, and that is what it names.

## 9. Enforcement honesty

| # | artifact | kind |
|---|---|---|
| E1 | `Stop` hook + `check-task-close` (hook mode): T1 | `gate`, severity dial `severity` — deterministic; under `block` red means commit, and the turn continues once |
| E2 | `check-task-close --scan`: T2–T4, with notes N2–N3 | `gate`, always exit 2 on a finding, ignores `severity` |
| E3 | skills `close-task`, `commit-before-edit` | `advisory` |
| E4 | `SessionStart` and `SubagentStart` hooks + `print-skill-pointer.sh`: the pointer to the skills | `advisory` |

**Honest limits**, each with its backstop. The shared code's limits — [kit-shared-gate-code §4](../../shared/GATE.md#g4) — apply, shared limit 1 in its own way: a commit made through the shell is exactly what the scan examines. This module's own:

1. **A block on `Stop` is a request the model weighs, not a wall.** The model may refuse, as it did in the research when its prompt told it not to commit; the second firing lets the turn end either way, and a committed tree can carry a poor message. In a session that cannot ask — `claude -p`, `dontAsk`, `--permission-prompts none` — a block costs that one continuation and leaves the tree dirty unless the commit T1 teaches is allowed: it is the compound `git add -A && git commit …`, and a rule must match each part on its own (documentation read 2026-09-23, Claude Code 2.1.251; breaks: a rule matching the whole line would allow the commit alone), so the consumer allows both `Bash(git add *)` and `Bash(git commit *)`, or sets `warn`. Backstop: the message teaches the commit's shape; the user sees the notice; the scan judges the commits.
2. **The hook does not fire on a user interrupt,** nor in a session that has not loaded the plugin, nor for a subagent's own stop. Backstop: the scan; the session rule in the consumer's own instructions.
3. **A declaration's truth is review.** The gate holds its presence, shape and target, never whether the documents really stand. Backstop: N2 prints every declaration used, each reason cut at its first 80 characters, so the reviewer reads the whole reason where the note says it was declared, in that commit or in the body; rule T-d.
4. **The unit is the change.** A commit inside the range may touch code without its document, and the range is green when a later commit of the same range updates it — by design; and a change merged by hand into the trunk without the scan is examined only by the next scan of the trunk, where on a trunk that fast-forwards "the last landed change" is the last commit alone. Backstop: the scan on the trunk, `--change HEAD`, in CI.
5. **Git's trailer rules are unforgiving:** one colon-less line in a message's last paragraph hides every trailer there, and a squash merge keeps a trailer only when its message lands last. Backstop: T2's fix states the paragraph's rule; the body line is the second form.
6. **The body is trusted text.** Whatever file `--body` names is read as the description; nothing checks that it came from the forge, and the gate never fetches one: no client, no network. Backstop: CI writes it from the event payload; a local run has no body and reads the trailers. **The body form has no live proof in the kit**: the kit's CI passes no body to the scan, its fixtures are against text (items 3, 19), and the kit's own use is the trailer.
7. **A shallow clone whose history stops before the base cannot see the range**, and git's refusal is relayed as the configuration failure whose fix names the fetch; a shallow clone whose history reaches the base is examined like any other, unremarked. Backstop: CI fetches the whole history.
8. **The map covers what it lists.** Code no pair names is never a finding, and a document no pair names is never asked to move. Backstop: the map grows with the project; N3 and the close skill.
9. **Dirty means what `git status --porcelain` lists** — tracked changes and untracked files git does not ignore; an ignored scratch directory is invisible, which is where working files should live until close. Backstop: `working_files` for tracked ones.
10. **The scan compares commits,** so an update sitting uncommitted in the working tree does not count. Backstop: the hook; T2's fix says "in this change".
11. **`stop_hook_active` is set by any Stop hook's continuation.** When a sibling's Stop hook continued the turn first and the tree was dirtied afterwards, this hook meets the second stop and lets the turn end with its second-stop line, having reported nothing. Backstop: the next turn's first stop; the line says what it saw.
12. **Every configuration failure ends in a count of documents** — `BROKEN: the check could not run — 0 documents examined`, written for the write-time gates and printed unchanged by the shared guard and by this gate's entry files. Read it here as: nothing was examined. Backstop: the first line names the fix either way.
13. **A git too old for the trailer options is told by one placeholder.** Such a git prints the format's `%(trailers` back as text, with exit 0, and the gate reads that text at the start of a commit's whole trailer field as the old git's: it is the C12 naming git's version line, never a red for a declaration nobody wrote. No git version is declared or checked. A reason that quotes the placeholder further in, or a later declaration of the same commit that begins with it, is read as ever, while a commit whose first declaration begins with it gets the same failure. Backstop: the failure names the fix, `install a newer git`.

**Exit-code contract**: `0` green, or nothing to examine (the count line says so); `2` a finding; `1` configuration failure: the shared ones, X1, X2, C5, C12. Nothing exits 0 on error.

## 11. Siblings

**Depends on:** [kernel §1](../../kernel/CONVENTIONS.md#k1) (the lifecycle rule; `status`), [§2](../../kernel/CONVENTIONS.md#k2) (task close as a single act, the defect rule, stalled drift), [§6](../../kernel/CONVENTIONS.md#k6) (the dials file, the dialect, portability). No policy is read, no envelope is judged: a task-record's `status` is set by the skill, in words.

1. When module `const-decision-records` is installed, its record skill defines when a record is `inactive` and this module's close skill performs it at close; neither reads the other's dial.
2. When module `const-locations` is installed, a document a pair names that does not exist yet is created through its command, at the home its policy implies.
3. When module `const-referencing` is installed, its scan runs beside this one before a merge, and the two verdicts are read together; and the close skill says to repair the links a deletion leaves — remove each, or redirect it to where the content went — before the closing commit, that scan listing the ones left dangling.
4. When module `const-meta-types` is installed, the documents the map names carry valid envelopes; this module never reads one.

## 12. Deferred

1. **The pull-request body read from the forge** by the module itself, through a client and the network. Today the body is text given with `--body`. Signal: a consumer whose closers cannot get the body into a file.
2. **Drift by timestamp** — the newest commit of a pair's code newer than the newest of its documents with no declaration since. It compares commits, not content, resets on a typo fix, and blames nobody. Signal: a consumer commit note reporting drift no range had shown.
3. **The active-age assist** of [A4.3](../../docs/requirements.md#a4-3): a note of the scan, `<record> is active and its file saw no commit in <n> days`, its scope the commits touching the record's file, under a dial `active_age_days` absent by default, skipped in a shallow clone. Signal: a consumer commit note about a task-record left active, or a stretch of the kit's own plan with no commits.
4. **`--history <n>`**, auditing the last *n* landed changes of the trunk in one run. Signal: a consumer adopting the module over a history it wants judged.
5. **A pair with no documents,** meaning "this code is described nowhere and every change to it is a finding". Signal: a consumer asking for the sharper form.
6. **`SubagentStop`.** Signal: subagents leaving dirty trees the main agent's turn end does not reach.
7. **Per-commit strictness as a dial.** The kit's history rejected it; a consumer with one-commit changes may want it. Signal: that consumer.
