# The code every gate shares

*One source for what every gate of the kit must have: `constitution_layer_kit/` for the gates, and its subpackage `constitution_layer_kit/testing/` for their fixtures. A plugin holds none of it. Its entry files import the Python package that pip installed for `python3`, in every project, the kit's own sessions included; [§1](#g1) tells how the package is built and released. A module's `tests/` reach the working tree's copy through one relative symbolic link to the package, the shared test files inside it, beside its links to its own packages, and the harness puts `shared/` on the `PYTHONPATH` of every gate it starts, so that a fixture tests the module and the shared code of one commit together and never an installed release (R7 and R8 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r7), and R2 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r2) for the one link). This page is the home of every shared text. A module's document writes out its own messages and links here for the rest. Every list and table row carries a handle.*

## 1. What is shared, and why it may be

What may be admitted here, and when a part already admitted may be widened for one module, is [rule 2 of plc-0009-shared-code](../docs/policies/plc-0009-shared-code.md#r2). The table's class says which kind of code each part is: K, it implements a kernel section literally; R, it implements a gate-script rule of [template §6](../module-template/MODULE.md#t6).

| part | class | carries |
|---|---|---|
| `identity` | R | which gate this run is — namespace, gate name, plugin root, the name of the dials file the gate reads, any library the module needs beyond the shared ones, the two clauses that close `C2` and `C12.11`, what stands until the failure is fixed, a gate's by default, and, by mode, the skill of the plugin that teaches the rule and its fix. The dials file's name is the required field `dials_file`, relative to the repository's top, with no default (R1 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r1)). The top-level keys of that file that are no namespace, the kernel-owned keys of its layer, are the required field `kernel_keys`, with no default either: `KERNEL_KEYS`, the constitution's three, in every gate of this kit, and its own layer's list, `module_prefix` always among them, in a gate of another layer. A list without `module_prefix` is a defect of the entry point, a `RuntimeError` raised as the scope opens, which declares nothing (R3 of [dec-0106-two-dials-files-and-kernel-keys](../docs/decisions/dec-0106-two-dials-files-and-kernel-keys.md#r3)). The constitution's own calibration stays in the one file [kernel §6](../docs/constitution/CONVENTIONS.md#k6) names; another layer's file holds that layer's keys and modules alone. A gate of another layer reads the constitution part of a second file in a scope of `reading(dials_file, kernel_keys)`, opened inside its run's scope: it shadows the file's name and its kernel keys and nothing else, so that every message names the file being read, while the identity's other fields, the mode and the hook's deadline stay the run's. Outside every scope, with a name that is empty or empty once stripped, or with a list without `module_prefix`, it is the caller's defect, raised as it opens (R1 of [dec-0106-two-dials-files-and-kernel-keys](../docs/decisions/dec-0106-two-dials-files-and-kernel-keys.md#r1)). The identity is declared for the length of one guarded run, and with it the mode of the run, hook, scan or act, which the git budget of `repository` and the hook's deadline read (limit 16 of [§4](#g4)). It also carries `hook_seconds`, the seconds one hook run of the gate may take in all: `HOOK_SECONDS`, 25 s, unless the module sets another. In hook mode the opening of the run's scope starts the run's one deadline, `hook_seconds` from that moment. `remaining`, `ran_out` and `left_of`, which never raises, serve the waits of the run, as limit 16 of [§4](#g4) says. `LEFT_FOR_THE_REST`, 5 s, is the margin that a handler's timeout keeps over `hook_seconds`. The declaration is held in one context variable of the package, with no default. Only a scope sets that variable: no other module-level name holds the declaration, and no code assigns or patches it otherwise (R2 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r2)). The context manager `declared(identity, mode)` sets the variable when the scope opens and resets it when the scope closes, normally or by an exception (R3 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r3)). Outside every scope, a read of the identity or of the dials file's name is a defect of the caller, a `RuntimeError` and never a failure of the repository. The mode then reads as none, and no wait has a deadline. So does a scope opened with no mode, as a test runner opens one. An identity whose `dials_file` is empty, or empty once stripped of whitespace, names no file. That is the same kind of defect, raised as the scope opens, and it declares nothing. A scope opened inside another shadows the outer declaration until it closes, and the outer one holds again after it. A second declaration is no defect, whether it differs or not (R5 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r5)). Every module of this kit names `constitution.yaml` in `dials_file`, the file [kernel §6](../docs/constitution/CONVENTIONS.md#k6) names, and a module of another layer names its layer's own file (R10 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r10)) |
| `model` | K, R | the kernel's closed vocabularies (meta-type, status), the template's (severity, mode — hook, scan, and act for a second entry point — stream) and the platform's file tools, the typed structures that cross function boundaries, `Finding` and `Broken`, the kinds of a skip, the keys of the shared configuration failures, the exit codes |
| `messages` | R | every shared text of [§3](#g3), as typed functions under their keys; `shown`, which cuts a value at 80 characters; `escaped`, which shows a value's backslashes and line breaks escaped and never cuts it; and `echoed`, which is `escaped(shown(value))`, so that a failure stays on one line — in hook mode only its first line reaches the user. `escaped` is class R like the others: every module needs it, since each has a path in a headline |
| `errors`, `preflight`, `cli` | R | the configuration-failure exception; the import check of each declared library, and `FLOOR`, the interpreter floor's one source, read by no gate at run time; `argparse` with its exit 2 turned into 1, the single guard — offered as `guarded` to the other kinds of entry point, an act that changes files and a session-start printer, with a closing line of its own — no fail-open; and `cli.version_failure`, which every entry file calls right after it imports `cli`: it returns nothing when the installed package serves the module, and otherwise `C16` or `C17`. Its signature never changes (R5 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r5)) |
| `output` | R | everything printed also appended to a log, one record per print, on the standard library's `logging` |
| `repository`, `territory` | K | git for the root and the file list, and `is_markdown`, the one test of what Markdown is, by the name's ending, in any case, a file named just `.md` included (limit 7 of [§4](#g4)), which the hook and the scan both use; territory patterns evaluated by `git check-ignore` in a fresh null repository ([kernel §6](../docs/constitution/CONVENTIONS.md#k6)). One function, `git`, runs every git call of the shared code and every one a module makes through it, with the clock that limit 16 of [§4](#g4) gives by mode. A module's own clock for a git call it makes outside that function stays its own |
| `envelope` | K | the frontmatter block parsed once, every field kept as YAML read it ([kernel §1](../docs/constitution/CONVENTIONS.md#k1)); which fields matter is the module's. `envelope_bounds` says where it stands, in character offsets of the text as given; `envelope_lines` is the line splitter: a line ends at `\n`, `\r\n` or a lone `\r` and nowhere else |
| `dials` | K, R | the dials file, the one the declared identity names, read and validated for the keys every gate reads: the kernel-owned keys the identity lists in `kernel_keys` — for a gate of this kit the constitution's three, `root_policy`, `territory_dialect` and `module_prefix` —, `territory` of every policy namespace, `severity`, `log_dir` — by a hand-written mirror of the kernel's schema, never a validator library, since a module ships without the kit; `scripts/check-schema-mirror.py` holds the mirror no more lenient than the schema; the rest of the module's namespace handed over as read ([kernel §6](../docs/constitution/CONVENTIONS.md#k6)). A gate of this kit reads all of its dials from that one file, the kernel keys included. `root_policy` is read, and `territory_dialect` checked, only where the identity lists them; a constitution kernel key the list leaves out is `C5.13`, since a copy of it there would be ignored or contradict the one that counts; a key the list names beyond the constitution's three is passed over and handed on as YAML read it in `Dials.layer`, for its layer to validate, and is otherwise empty (R3 and R4 of [dec-0106-two-dials-files-and-kernel-keys](../docs/decisions/dec-0106-two-dials-files-and-kernel-keys.md#r3)). `load_kernel_part` reads the constitution part of the file the declared identity names — `root_policy`, `territory_dialect`, the file's own `module_prefix`, held to its form, `C5.14`, and never to the reading module's namespace, so never `C5.12`, and the policy namespaces as below — and no namespace of the reading module: a gate of another layer calls it in a scope of `reading` with `KERNEL_KEYS`, and joins it to the read of its own file itself. It reads the constitution's three keys whatever the scope lists, so the scope is opened with `KERNEL_KEYS`, for its messages to name them too. It gives None where the file is absent, and what a gate of another layer does then is that layer's to decide. In another layer's own file a key outside the prefix that holds a mapping is still read as a candidate policy namespace, and one that holds none is `C5.4`, whose fix writes a policy's: the shared reader knows no layer's rules, and the layer refuses a policy there by its own (R1 and R2 of [dec-0106-two-dials-files-and-kernel-keys](../docs/decisions/dec-0106-two-dials-files-and-kernel-keys.md#r1)). `module_prefix` is required and read from the file, never built into the code: a kebab-case word that ends in `-`, else `C5.11`, which the reading module's namespace starts with, else `C5.12`, another layer's file. A top-level key that starts with it is a module's namespace by its name (R12 and R13 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r12)): one that holds no mapping is passed over, save the reading module's own, which is `C5.5`, and one that holds a mapping is read as the last read of this row says. Any other top-level key, the kernel-owned ones aside, must hold a mapping, else `C5.4`, and is read as a candidate policy namespace, its `territory` strictly (`C5.6`). Two refusals serve a module's own dials. The first is of a pattern git would misread (`C5.7`): a module that declares territories in its own dials calls it for them too, naming the dial by its whole path. The second is of a key of the module's namespace that the module does not read (`C5.10`), which every module calls — class R, rule 8 of [template §6](../module-template/MODULE.md#t6): a dial ignored in silence is a silent pass. Three small readers serve both: `GATE_KEYS`, the two dials every gate has, which a module's key list opens with — a module that blocks nothing lists `LOG_DIR_KEY` alone; `texts`, the non-empty strings of a list; and `relative_path`, a repository-relative path as the file system reads it, used for `root_policy` and `log_dir` and by the modules that read paths (limit 15 of [§4](#g4)). One read crosses the kernel's "reads no other module's namespace": a prefixed key that holds a mapping is also kept as a candidate policy namespace — its `territory` is kept when it is a list of non-empty strings and is silently empty otherwise, a well-formed list still going through `C5.7`; it is consulted only for the id of a document in the root policy's territory, so with no such document it changes no verdict |
| `events` | R | the hook payload parsed into a typed event that keeps the event's name; the document as it will be after a `Write` or an `Edit` — for an event after the write the document is the file on disk, and the pipeline reads it there; a `Stop`, which names no file, keeps its loop guard `stop_hook_active`; a `PreToolUse` of the shell tool, `Bash`, which names no file either, keeps its `tool_input.command`, and one without a string command is the shared failure `C12.4` |
| `index`, `resolution` | K | the policies found in the root policy's territory, what each claims, and the documents of a scan; which policy governs a document, path first, as a typed result — the policy, or one of the four defects — with no message ([kernel §3](../docs/constitution/CONVENTIONS.md#k3)). What one module alone needs — the first module's id owners and void namespaces — lives in that module. Classification reads the root's territory only; whether an id is unique in the tree is a module's own read of every envelope, never part of resolving a document to its policy |
| `pipeline` | R | from the event — a write, or a `Stop` or a shell event located from its `cwd`, the `EventTarget` carrying the tool's name and the command — or the scan's directory, to the repository and its dials. Whether the dials name a root policy is left to the module, since a gate that reads only its own dials needs none. From findings to the verdict the platform understands: `report_hook` (block; warn as one JSON object, on `Stop` the user's notice alone; `ask` for a gate whose block is the user's yes), `report_scan`, `green_hook`, the green of a hook run on a write, as one JSON object where it has notes, `green_event` for an event without a document; the routing of the log to `log_dir`, public for a second entry point; `within_the_cap`, the first findings of a write that fit the platform's cap on a hook's text, the first always shown, with an optional count limit of a module's own (limit 14 of [§4](#g4)) |
| `testing.harness`, `testing.consumer`, `testing.acceptance`, `testing.items` | R | the case runner driving a module's real entry point; the throwaway three-policy consumer; the pytest marker, the one-number rule and the asserting checks; the acceptance items of [§5](#g5). They ship in the distribution as the subpackage `constitution_layer_kit.testing`, which no gate imports, as review holds, so that a module of another kit runs the same items at the release of the code they prove; pytest is the distribution's extra `testing` (R1 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r1)). Each holds for a gate of another layer as for one of this kit: the items read the gate's own dials file, its kernel keys and its prefix from the identity the session declares, and a line about the policies names the constitution's file; the consumer writes that file and the gate's own beside it, and the harness takes the gate's file, kernel keys and the folders of its own kit's packages (R3 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r3)). `scripts/check-portability.py` reads these files with two of its forms switched off, the relative path and the kit's document folder, since the consumer must be given paths; a kit id or a kit file name there is still a finding (R6 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r6)) |

Delivery: the code reaches a project as the Python distribution `constitution-layer-kit`, which pip builds from the kit's repository at a release tag, `constitution-layer-kit-v<version>`. The tag's form never clashes with a module's version. The command stands in prerequisite 3 of [the install guide](../INSTALL.md#s1). `shared/pyproject.toml` describes the distribution, built by `setuptools`: its version is read from `__version__` in `constitution_layer_kit/__init__.py`, the version's one source; its `requires-python` is the floor `FLOOR` names, which `scripts/check-copies.py` holds with the other copies of it; PyYAML is its one dependency, and pytest that of its extra `testing`; it holds the one package, `constitution_layer_kit`, with a `py.typed` marker, and its subpackage `testing` (R1 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r1)). `scripts/check-shared-package.py` builds it, installs it with its extra `testing` into a fresh virtual environment and imports it there, every submodule included (R1, R2 and R19 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r1)). What a release promises to the modules, and what raises `__version__`, is [rule 11 of plc-0009-shared-code](../docs/policies/plc-0009-shared-code.md#r11).

Deferred, each with its signal (R20 and R22 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r20); its R11 and R21, the two-file read and the shared test files in the distribution, were built by [dec-0106-two-dials-files-and-kernel-keys](../docs/decisions/dec-0106-two-dials-files-and-kernel-keys.md) and [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md)). Publication on PyPI, the git tag staying the package's one source; signal: a consumer asks for it, or the name `constitution-layer-kit` is taken there (R4 of [dec-0112-email-forks-and-pypi-before-the-switch](../docs/decisions/dec-0112-email-forks-and-pypi-before-the-switch.md#r4)). A check that `__version__` rose after a change to the shared code since the last tag, which review holds; signal: a release that missed its raise. Deferred for every gate alike, each module citing this and restating none: Windows without a POSIX shell, where an entry point would become a `.cmd` beside its `.sh`, and a clone of the kit without symbolic links, which a module's `tests/` need and the plugin does not; signal: a consumer on Windows. A gate run past its handler's 30-second timeout; signal: the timeout hit. A governed document with another extension than `.md`; signal: such a document in a consumer project.

## 2. The interface a module fills

1. **Identity.** The module's `start` builds one `Identity(namespace, gate, plugin_root, dials_file, kernel_keys, libraries, until_installed, until_fixed, skills, hook_seconds)` and calls `cli.run(argv, identity, load_modes)`. Its `dials_file` is `"constitution.yaml"`, the file [kernel §6](../docs/constitution/CONVENTIONS.md#k6) names, and its `kernel_keys` `KERNEL_KEYS`, in every module of this kit and in each of its entry points, which review holds; a module of another layer names its layer's own file and that file's kernel keys (the `identity` row of [§1](#g1)). There is no separate declaration. That call, and `cli.guarded` below, open one scope of `identity.declared` that declares the identity and the mode of the run together, before anything else (limit 16 of [§4](#g4)). The scope covers all the guard does: the output, the parse of the arguments, the preflight, the import of the module's modes, the run, the failure lines and the flush. It closes before the guard returns the exit code (R4 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r4)). The `namespace` contains a `-`: the fix of `C5.11` writes the part of it up to and including its first `-` as the file's `module_prefix`, and a namespace without one would get a fix that is no valid prefix. The identity carries the hook's budget, `hook_seconds`, so the opening of a hook run's scope also starts its deadline. `until_installed` and `until_fixed`, the clauses that close `C2` and `C12.11`, default to a write gate's — writes pass unchecked, the check does not run — which fit a gate whose hook runs on a Markdown write, and `until_fixed`'s fits every gate. Any other gate — a scan alone, a hook on the shell, a hook at a turn's end — names `until_installed` with what its failure leaves unchecked, since no Markdown write passes through it; its entry files carry the same clause in `C1`, `C14`, `C15`, `C16` and `C17`, its module's document writes it out, and an item of its runner holds it in `C2` and in the entry files. A second entry point of a module — a generator that changes files, with a command line of its own, never a gate — builds an identity of its own and calls `cli.guarded(identity, Mode.ACT, body, could_not_run)`, whose second argument is the mode of its scope: an act, so its git calls have no clock. That is the same single guard, exit codes and log, around a body that parses its own arguments with a parser whose usage error is a configuration failure, runs `preflight.check`, and only then imports what needs the declared libraries; `could_not_run` is its own closing line, since "0 documents examined" is a gate's. Its two clauses say what it leaves undone or what not to do with it — nothing is created, do not move documents with it — true in every state the failure can find, since no write passes through a generator. A session-start printer — an advisory hook that reads the dials and prints to the model's context, blocking nothing — is a third kind. It builds its own identity and calls `cli.guarded(identity, Mode.HOOK, body, could_not_run)`, so that its git calls have the hook's clock and its deadline, around a body that takes no arguments, turning any into the shared misinvocation by hand, runs `preflight.check`, and only then imports the pipeline and its dials. Its closing line says that the gate's state is not said. Its `until_installed` is `until then the gate's state is not said at session start`. Its module's document writes it out, and an item of its runner holds it in `C2` and `C1`. The shared code never imports a module. A library beyond PyYAML goes into `libraries` and `requirements.txt`; S137 holds the two lists equal. `skills` maps a mode to the skill of the plugin that teaches that mode's rule and its fix, by the skill's own name; the pipeline names it in the line after a red verdict of that mode, `F10`, and a mode the map leaves out gets no line. A gate whose module has no skill, a generator and a session-start printer give none.
2. **Two modes.** `load_modes` returns `cli.Modes(hook, scan)`, each returning an exit code. A module whose scan takes flags of its own hands `cli.run` a list of `cli.Argument` and gives `Modes` a `scan_with`, called in `scan`'s place with the values by flag. A flag given without `--scan` is a misinvocation, and the usage line names the flags. `load_modes` is called after the preflight, because the module's code needs the declared libraries. This makes the import inside `load_modes` — and, in an entry point of another kind, the import of a generator's acts or of a printer's pipeline and dials after its preflight — the explicitly necessary exceptions to gate-script rule 16 of [template §6](../module-template/MODULE.md#t6), marked and reasoned where each stands.
3. **The middle of a run is the module's.** A mode calls `pipeline.locate_write` or `locate_scan` and gets a target or a `Skip`, which carries `reason`, the shared text, and `kind` and `where`, the same facts typed; a module that says a skip in its own words switches on `kind` and takes `where` whole, and never parses `reason`. A gate that resolves policies then returns `pipeline.no_root_policy(output)` when `target.dials.root_policy` is absent — the type of `build_index` does not let it forget. A gate that resolves policies only under a dial of its own raises its own `C5` there instead, since a skip would let a write through with nothing examined. A gate that reads only its own dials matches its own territories with the `Matcher` and builds no index. The first kind builds the index by `build_index` inside `with Matcher() as matcher`, with the pending document in hook mode only. Building it raises the shared failure `C12.10` in both modes for a file in the root policy's territory nobody can read — a policy by the kernel's rule whose own territory nobody can know, never a policy with no id. It then examines documents with its own checks, in a scan through `index.documents()`, which raises the same failure. It hands findings and notes to `pipeline.report_hook`, `report_scan`, `green_hook` or `skip`. `report_hook` takes the event's name, which the `warn` channel must repeat, a count line of the module's own where "1 document examined" would not be true, and `ask`, true for a gate whose block is the user's yes at the platform's prompt — the shell gate — all three defaulting to what a gate before the write needs. `WriteTarget.event_name` tells a module wired to both events which one it is answering. `green_hook` takes what the examined document is — `messages.governed_by(policy)`, or the module's own words where no policy is involved — and the event's name, which a run with notes must repeat (`G2`). `skip` takes the event's name in a hook run that has notes to hand on, and none in a scan. A gate wired to an event that names no file — `Stop` — calls `pipeline.locate_event` for an `EventTarget` or a `Skip`. A clean examination ends in `green_event`. Its findings go through `report_hook` with `event_name=STOP` and a `count` of its own, and the warn there is the `systemMessage` alone. Nothing in the pipeline calls back into the module.
4. **Own dials.** `Dials.own` is the module's namespace as YAML read it; the module parses it once into its own dataclass and raises the shared `ConfigurationFailure` with its own `C5` text when it is malformed. It first calls `dials.refuse_unknown_keys(own, known)`, `known` being the keys it reads in the order its failure lists them: the first key outside them, in sorted order, is the shared `C5.10`. A pattern it reads from a dial goes through `dials.refuse_unreadable_patterns(where, patterns)`, `where` being the dial's whole path as a person writes it — `{module}.{dial}`.
5. **Own messages.** A module's findings, skip reasons, notes and dial failures live in the module's `messages`, written like the shared ones. Its finding keys are its own enum. A value a message takes from a document, a dial, the envelope, the command line, the hook payload, the environment or a tool goes through one of two shared functions of `messages` ([§1](#g1)), never raw and never through `shown` alone. `escaped` shows the backslash, the line feed and the carriage return escaped and never cuts. It is for a value the reader must open, copy or type into a fix, or that a later step reads: a repository path, an id or an anchor typed into a fix, the text of a dial that teaches, a tool's one-line diagnosis, a generator's output line. `echoed` is `escaped(shown(value))`: cut at 80 characters, then escaped. It is for a value that only points at something the reader can already see in the file or the command: a dial key, a pattern, a phrase, a command word, a match from a document, an event or tool name. A value is left alone in three cases only. The code or a check has fixed its shape before the message: a name matched whole by a kebab pattern, an integer, a hash, an enum, a code literal. Or the system's own error text already escapes it: an OS error that quotes the path with `repr`. Or it stands inside a command the reader pastes. A pattern that checks an id is applied with `fullmatch`, so that no id ends in a line break. A field read as a string goes through the shared `envelope.string_field`. A message that names the dials file asks `identity.dials_file()` and holds the name in no string of its own (S178).
6. **The entry files.** The POSIX one prints `C1` and `C11` itself when `python3` is missing. The Python one, parseable by any Python 3, checks the interpreter floor and prints `C14` and `C11`. It states `REQUIRES`, the release of the package that it needs, as `major.minor.patch`, and imports `constitution_layer_kit.cli` from the package pip installed for `python3`, inside a guard that prints `C15` and `C11` when the import fails — an empty directory fails there too. Right after that import, before it builds anything else and before it imports a package of its own, it calls `cli.version_failure(namespace, REQUIRES, guide, until)`, `guide` being the path of the plugin's own `INSTALL.md`; a line it returns, `C16` or `C17`, is printed with `C11`, and the entry file exits 1. Then it runs the module's `start`. These exits, before the single guard can run, are the only ones outside it. The guard opens the scope of the declaration (item 1), so the entry file's own lines run before any scope and read no declaration: `C1`, `C14` and `C15` are the entry file's own text, and `C16` and `C17` come from `cli.version_failure`, which takes the namespace and the clause as parameters (R4 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r4)). A second entry point's files do the same with the closing line of their own in `C11`'s place. Their `C1`, `C14`, `C15`, `C16` and `C17` carry their identity's clause, a generator's or a grant's none. The entry files of a gate that names its own `until_installed` (item 1) carry it in all five, the one its identity gives `C2`. A module requires the first release of the package's major, `2.0.0` today, the major that made `kernel_keys` required, until it uses a name that a later release of that major added; a new major raises every module's `REQUIRES` to its first release in the change that makes it (R5 of [dec-0106-two-dials-files-and-kernel-keys](../docs/decisions/dec-0106-two-dials-files-and-kernel-keys.md#r5)). The change that makes it use one raises `REQUIRES` to that release, which review holds, and `scripts/check-copies.py` holds every `REQUIRES` at or below `__version__`, in the same major. The plugin's `INSTALL.md` gives the command of prerequisite 3 of [the install guide](../INSTALL.md#s1) at the tag of `REQUIRES`, which the same check holds (R5, R6, R14 and R15 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r5)). The package is the one library whose failure points at that note and not at a command, since one command that installs an exact tag could replace a newer release that another module needs; the failure of every other library gives its install command, as `C2` does (R16 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r16)).
7. **Links.** Only the tests have them: `tests/constitution_layer_kit` → `shared/constitution_layer_kit`, which holds the shared test files in its subpackage `testing`; for the tests, `tests/<package>` → the module's own `plugin/scripts/<package>` for each folder at the top of its `plugin/scripts/`, itself no link, that holds an `__init__.py`, whose name starts with neither `.` nor `_`, save `constitution_layer_kit` (today one per module, named `<x>_gate`); all relative, each straight to its source, never through another link. Beside them stands one plain file, `tests/test_shared_items.py`, which brings the shared items into the module's run, `from constitution_layer_kit.testing.items import *` (R2 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r2)). The kit gate is `scripts/check-shared-links.py`, which reads the list from those folders and fails to run when `shared/constitution_layer_kit/` is gone or its `testing/` lacks one of `harness.py`, `consumer.py`, `acceptance.py` and `items.py`: red for each fault K1 of [§5](#g5) lists in the links of `tests/`, a link to the module's own package included; a finding on that link says why in its own words: the runner must import the code the gate runs. A link of `tests/` into `shared/` that is none of those, such as one left to a shared test file of the old layout, is red, its fix `git rm` of it and the import from `constitution_layer_kit.testing`. It is red too for anything at `plugin/scripts/constitution_layer_kit` — a link, a copy, a plain file, a dangling link: a plugin holds no shared code, and whatever stood there would shadow the installed package, since a script's folder comes first on Python's path; its finding teaches `git rm -r` of the path (R7 and R8 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r7)). Its `--self-test` is its red→green fixture. A module owes the links by `plugin/hooks/hooks.json`, by an import line of the shared code in a `.py` under its `plugin/scripts/` — a scan or a generator — or by a link it has; a folder of `modules/` whose name starts with `.` or `_` is no module.
8. **The tests.** A module's `tests/test_<name>.py`, run by pytest, imports the shared package, the module's own packages and the shared test files, `constitution_layer_kit.testing`, from its own folder, which pytest puts first on the import path, through the links of item 7. No Python file of a module edits the import path of its own process, the tests included. The rule binds that process alone: any child process a test starts may be given a path of its own, by `sys.path` in the program it runs or by `PYTHONPATH` in its environment. Today: shared item 112's shim puts the entry's folder first as Python does for a script; a case sets `PYTHONPATH` to a folder that hides or replaces a library for the gate, in the shared items and in the tests of several modules. The list is not closed. The one path every gate gets is `shared/`, the folder that holds the shared package: the harness puts it on the `PYTHONPATH` of every gate it starts, after any folder a test puts there, so that the gate under test imports the shared code of its own commit and never a release installed for the developer's `python3`, and an item that proves the gate without the package leaves it out (R8 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r8)). The test file names the module's identity at its top in `IDENTITY`, the same name in every module, and declares nothing (R2 of [dec-0091-module-fixtures-run-as-pytest](../docs/decisions/dec-0091-module-fixtures-run-as-pytest.md#r2), narrowed by R6 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r6)). The module's `tests/conftest.py` holds the scope the tests run in. An autouse session fixture opens `identity.declared(IDENTITY)`, with no mode, for the test session. An item that needs another declaration opens its own scope inside it. An item that needs none runs in a fresh context, `contextvars.Context().run`. The test file builds its expected messages as it is imported, by the functions the gate uses, so the conftest imports the file inside a scope of that gate, the one the file then names in `IDENTITY`. The test file then builds one `Harness(scripts, wrapper, entry, namespace)` and one `Subject`, which the session fixture `subject` of the conftest returns to the shared items. The `Subject` holds: the harness, a function that runs the gate on a prepared consumer, a patch of its own namespace, a write it passes and one it blocks with the finding that teaches, what the green line says the passed document is, the territory that holds both and the dials patch that declares that territory with other patterns. Its fields `outside`, `long_value`, `pattern_dial`, `noted` and `note` serve the items about a negated pattern, a long echoed value, a path-pattern dial and a note, each described in the `Subject`'s comments; `outside`, the module's skip reason once a negated pattern takes the file out, is typed by hand and required wherever the item about negation runs, so it is never passed on an empty default. It also holds whether the gate resolves policies. Each red→green `Case` names in `green_what`, typed by hand, what its green line says the document is; the case runner holds the exact `RED` lines (the harness's docstring), so a second finding or a stray line fails it. A harness built with `scan_only=True` runs a case the scan's way: each half is written into a fresh consumer and `--scan` run there. The red half's count line is typed by hand in the case's `count`, its `green_what` the whole tail of the green line, the verdict read on stdout and no `RED` line allowed on stderr. A gate on the shell tool gives `event="Bash"`, its `valid` and `red` the commands as the text of a Write, and `ask=True` where its block is the `ask` verdict. For a gate that differs from the first three, the `Subject` also gives what the count line says of a README with no envelope at the repository's top — `0 documents examined` unless the gate covers every Markdown file — and whether the gate judges envelopes. A module that is only a generator — no hook event, no verdict, no scan — says so with `event_driven=False`, gives its own closing line in `closing` and, in `act_args`, the arguments of a run that completes from inside a fresh consumer. Its `gate_on` turns the `Write` the remaining items hand it into the generator's command line, run inside the consumer through the harness's `cwd`, and a refused run counts where a gate's finding would. A gate driven by `Stop` says so with `event="Stop"`: its `gate_on` turns `valid` into a clean tree and `red` into a dirty one, and the items that build a payload use the harness's `stop_json`. A gate whose hook never asks git for the file list says so with `hook_lists_files=False`. A gate without a hook mode — a scan alone, which run as a hook is its own configuration failure — says so with `scan_only=True`. Its `gate_on` writes the action's document into the consumer and runs `--scan` there. Its `green` is the whole green line of a scan over the consumer holding `valid` alone, `bare_readme` that line with a README at the top. The items about a red run read stdout, where a scan prints its verdict, the finding and the count line two records of the log, and `F10` a third where the module names a skill. Each test is one item, `@item(<number>, <title>)` of `acceptance`; the module's red→green `Case` records, where it has them, are the rows of one parametrized `test_case`, each marked with its case's number and title. A shared item the `Subject` leaves out is collected and skipped, its reason naming the flag, and its number stays free; the last paragraph of [§5](#g5) lists what each flag leaves out. The conftest's hooks call `acceptance.configure` and `acceptance.collected`, which stops the run before any test on a test without a number or a number two tests carry; the conftest names no plugin in `pytest_plugins`. One run collects one module's folder: a second module's folder stops the run at collection, since the shared items carry the same numbers in every module and `acceptance.collected` refuses a number two tests carry (H5). `fake_program` starts a fake once before any clock; a gate `run_gate` starts asks git with no clock, save where a test's own `sitecustomize` keeps one. No item depends on the order the items run in, or on another's process: each builds its own consumer and leaves nothing behind, so a module's tests run in any order and side by side, though CI runs them one by one; a run with the collected tests shuffled by a seed, through a `pytest_collection_modifyitems` hook of the run's own, serial and with `-n auto`, three times each, is the proof a change to the fixtures keeps, held by review. The kit's gate list and CI run a module's tests only through `scripts/check-aspects.py`, never pytest itself, so they never select; `scripts/check-gate-lists.py` holds that their code lines, comments aside, name pytest only in an exact pin, pass no `--item` and name no `PYTEST_ADDOPTS`, and that no pytest configuration file at the kit root, in `modules/`, in a module's folder or its `tests/` sets `addopts`. A gate of another layer fills the same interface: its identity names its own dials file and that file's kernel keys, its `Harness` takes the same `dials_file`, `kernel_keys` and the folders of its own kit's `packages`, which go on the gate's `PYTHONPATH` before `shared/`, and its `gate_on` writes the dials with `Consumer.write_dials`, which sends a key its kernel keys list, or one that starts with its prefix, to its own file and the rest to the constitution's. Such a gate reads the policies and resolves them in a scope of `reading` the constitution's file, so that every failure about a policy, a root policy or the constitution's kernel keys names that file, and the items expect it there. The kit's `scripts/check-layered-items.py` holds that every shared item holds for one such gate, `know-check`, kit tooling under `scripts/layered-fixture/` (K2 of [§5](#g5); R3 and R4 of [dec-0107-shared-test-files-in-the-distribution](../docs/decisions/dec-0107-shared-test-files-in-the-distribution.md#r3)).
9. **The envelope's place.** A module that blanks, masks or rewrites the envelope asks `envelope_bounds` where it stands and cuts its lines with `envelope_lines`. It keeps no reading of its own of where the envelope opens or closes, or of where one of the envelope's lines ends.

## 4. Shared honest limits

Every module has these limits and states its own beside them.

1. **Shell writes and other actors.** The gates judge `Write` and `Edit`, the members of `FileTool`. Survey of 2026-10-11, Claude Code 2.1.286: the tools reference lists `NotebookEdit` and the shells `Bash` and `PowerShell` beside them, and `MultiEdit` is in neither page. A matcher of only letters, digits, `_`, `-`, spaces, `,` and `|` is read as an exact string or a list of them, so the matcher `Write|Edit` of a gate that judges writes sends it no other tool. An event for another tool that does reach such a gate is a visible skip, `G1.1`. A shell, `Bash` or `PowerShell`, a heredoc, `sed -i`, a human's editor, a merge, another server's file tool: none is a `Write` or `Edit`, and the hook never sees it. The hooks documentation adds `tool_response.bashEditDiff` to a `PostToolUse` of `Bash` (Claude Code 2.1.269 or later) and calls the list best effort and in public beta. Backstop: the module's scan, on demand and in CI.
2. **A configuration failure, a timeout, and a hook that cannot start are non-blocking in hook mode.** Exit 1 shows the user the first stderr line and the write proceeds. The platform treats a hook past its timeout, or one whose script is missing, the same way (Claude Code 2.1.251, read 2026-09-18 to 2026-09-23). Backstop: the scan exits 1 with the same line, so CI turns red. The line lands in the output log.
3. **The package may be missing, too old or too new.** A plugin holds no shared code, so a project that has not installed the package for the `python3` its hooks run, or has a release the plugin was not written for, gets a gate that cannot run: `C15` when the package cannot be imported, `C16` when the release is below the one the plugin requires, `C17` when the plugin is older than the installed major. Each is an exit 1 that names the plugin's own `INSTALL.md`, where the command stands, and none blocks in hook mode (limit 2). In the kit's own sessions the plugins run from the working tree with the release the developer installed, so a module that requires a later release stops with `C16` until that release is installed, or the developer installs `shared/` from the clone with pip. Between the merge of a change that raises `REQUIRES` and the push of its release's tag, the install notes name a tag not yet made, and installing `shared/` from the clone is the way (R9 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r9)). Backstop: those lines, loud like a missing library's, with an absence fixture in every module (S115, S184–S186); the scan, which exits 1 with the same line. `scripts/check-copies.py` holds each `REQUIRES`, the text of `C15` whole, the code of each entry that prints `C16` and `C17`, but not their texts, which come from the shared code and which S184 and S185 run, and the install note's command. Beside it stand `scripts/check-bare-install.py`, red for anything at `plugin/scripts/constitution_layer_kit` in the copy it installs; the install, session and guide checks, which run every hook and scan in a throwaway virtual environment whose `.pth` file names the change's `shared/`; and `scripts/check-shared-package.py` (R17 and R19 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r17)). Fallback: none. The earlier one, links replaced by copies, has no object, since no plugin holds a link or a copy (R7 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r7)). Platform facts, seen while plugins carried a link and kept because the install check rests on them. A marketplace install that copies a plugin into the plugin cache dereferences a link whose target lies elsewhere within the same marketplace — "the target's content is copied into the cache in its place" — and skips one leading outside it (re-read 2026-09-23 against the documentation, Claude Code 2.1.251); the marketplace root is the directory holding `.claude-plugin/`. A plugin loaded in place — `--plugin-dir`, or a relative-path entry of a marketplace added from a local directory — runs from its source, its hook processes receiving a plugin root that points there (observed on 2.1.282, 2026-10-01). Installing such an entry writes a copy into the cache all the same, which the session does not run (research [res-0008-const-interaction](../docs/research/res-0008-const-interaction.md), p14). In that copy, on 2.1.282, a link to the shared code arrived as a real directory: file links were recorded dereferenced on 2026-09-25, a directory link seen on 2026-10-01, and one a level deeper in `plugin/scripts/` on 2026-10-21. An install from the marketplace's git remote, the copy a consumer's install writes, carries it the same way. A link that stays inside the plugin stays a link, seen on 2026-10-07 in the kit's CI on 2.1.282 and in an install from the working folder on 2.1.286; no plugin holds one, since a module's runner links stand in `tests/`, outside the plugin, and no install copies them. A project that registers a clone as its marketplace runs that clone in place, as a relative-path entry of a local folder does, seen on 2.1.286 on 2026-10-07; one registered from the kit's GitHub repository runs the cache copy, which the install guide's check holds on every run of the kit's CI. The documentation's sentence that under `--plugin-dir` only symlinks that resolve within the plugin's own directory are preserved describes what a copy into the cache keeps; the kit reads it as a rule for a component path, and a script's own import through a link is none (on 2.1.251 a plugin loaded with `--plugin-dir` resolved it, observed 2026-09-19).
4. **`Edit` is reconstructed, not observed.** The edit is applied to the file on disk and the result judged. An absent `old_string` is a visible skip. An `old_string` occurring twice without `replace_all` is judged on its first occurrence though the tool will refuse the edit. An `Edit` of a missing file with an empty `old_string` is judged on what it creates, and one with an empty `old_string` on a file that exists is a visible skip, since it matches everywhere. Backstop: the tool's own refusal comes after the hook (Claude Code 2.1.251, read 2026-09-18 to 2026-09-23), and the next real write is judged again.
5. **Symbolic links in the consumer.** The written path is resolved before it is matched, so a territory that names only a link does not claim what is written through it. Backstop: territories over real paths; the scan lists files under the paths git records.
6. **A key given twice in an envelope.** YAML keeps the last one. Backstop: review.
7. **Markdown means `.md` — the name's ending, in any case, a file named just `.md` included, in the hook and in the scan alike; git-ignored files are invisible to the scan,** which lists tracked files and untracked ones git does not ignore. A tracked file deleted from the working tree is left out. A path holding a line break is examined, and every message shows the break escaped, `\n`, so each line stays one line. Backstop: the hook still judges such a file when it is written through the file tools. A module whose hook follows its dial skips a new file git ignores before the write too, as [`const-referencing`](../docs/requirements.md#const-referencing) does. A file git lists stays covered, whatever the ignore rules say of it.
8. **The envelope opens when the first line, leading byte-order marks aside, is `---`, and ends at the first later line that is `---`, trailing whitespace ignored on both**; a line ends only at `\n`, `\r\n` or a lone `\r`. Whitespace is what Python's `str.rstrip` strips, so a form feed or another break character after `---` is whitespace, while one before `---`, or one after it with text, makes no delimiter. A block scalar containing such a line truncates it. Backstop: the module reports the truncated envelope as invalid.
9. **Patterns match case-sensitively on every platform,** so one repository gets one verdict everywhere. Backstop: the scan sees a file under the case git records.
10. **The output log is best-effort evidence, not a gate.** A logging failure never changes a verdict, and neither does a failure of an advisory memo a module keeps beside the log: the module swallows that memo's read and write errors the same way, each said so at its place (gate-script rule 12 of [template §6](../module-template/MODULE.md#t6)). A configuration failure is two records — its BROKEN line and the closing line — and an unexpected one three, the traceback last, because the guard prints each apart. Should that trouble a reader, the remedy is a guard that prints once, never another unit of record. `C1`, `C14`, `C15`, `C16` and `C17` are printed and not logged, since the entry file prints them before the shared code that logs has run. Backstop: stdout and stderr remain the record.
11. **No `--help`,** and no abbreviated flags: `argparse`'s own help exits past the guard and the log. Backstop: any unknown argument is a misinvocation whose fix line is the usage.
12. **With two gates installed, the model sees one block message at a time** when both exit 2 (observed on Claude Code 2.1.251, 2026-09-19; the documentation is silent). Backstop: the next write is judged again; both findings are in the output logs.
13. **A negated pattern takes a file out of a territory only where git can re-include it:** not under a directory an earlier pattern excluded. `<dir>/**` followed by `!<dir>/README.md` works, since the file lies directly in the named directory. `!<dir>/sub/README.md` does not, and the file stays inside. Backstop: a territory of file patterns — `<dir>/**/*.md` — from which any file can be taken out. The shared item S148 shows the half that works, and the third module's own fixture shows both.
14. **A hook's text over 10,000 characters is replaced by a preview.** Read 2026-10-03 on the platform's hooks documentation, Claude Code 2.1.286 installed: the `additionalContext`, `systemMessage` and `initialUserMessage` strings of a hook, and its plain stdout, are capped at 10,000 characters, each string measured alone; over it the platform saves the whole text to a file and shows its path and a preview of the first 2,000 characters, and the cap has no setting. The two modules that can print many findings after a write, [`const-language`](../docs/requirements.md#const-language) and [`const-referencing`](../docs/requirements.md#const-referencing), show those that fit in `SHOWN_CHARACTERS`, 8,000, through `pipeline.within_the_cap`, so that the whole text stays under the platform's 10,000 and is not replaced by a preview; the count line and the closing note stand last and would be lost with it. The findings shown fit the 8,000, except the first, which is always shown; the notes and the count line are not counted in the 8,000. A value that only points is cut at 80 characters ([`echoed`](#g1)), but a value escaped whole — a path, an id typed into a fix, the text of a dial that teaches — is bounded by its source, not by 80: a dial's text or a document's text by nothing the gate holds, such as the plain word of [`const-language`](../docs/requirements.md#const-language) kept whole in the fix of its pair rule, or a link's fragment in R6 of [`const-referencing`](../docs/requirements.md#const-referencing). Such values reach `within_the_cap`, which runs after a write only. **Breaks:** one such first finding can alone pass the platform's 10,000, and `within_the_cap` still shows it, since it shows the first; the platform then replaces the whole text with a file path and a preview of its first 2,000 characters, and the count line and the closing note are lost with it. Before a write, [`const-referencing`](../docs/requirements.md#const-referencing) prints its R1 to R4 findings with no cut at all, so many of them, or a lane's `fix` kept whole, can pass the 10,000 there as well. Backstop: the count line says how many findings there are; the scan lists them all; a dial's text stays as short as it teaches, which covers a dial's text and not a link's fragment, whose length is the document's. Fallback: none needed.
15. **A dial's path is read with the platform's separator.** `root_policy`, `log_dir` and the paths a module reads — the `docs` paths of the `coverage` dial of [`const-task-close`](../docs/requirements.md#const-task-close), which trims each first, and the `template` paths of [`const-locations`](../docs/requirements.md#const-locations) — go through `dials.relative_path`: blank, absolute and leaving the repository by `..` are refused, `./` and `//` normalised, and `.` is accepted, the repository itself; a leading or trailing space is kept as part of the name for `root_policy`, `log_dir` and a `template` path of [`const-locations`](../docs/requirements.md#const-locations). A backslash separates only where the platform says so, so `..\x` leaves the repository on Windows and is one file name on macOS and Linux: one dials file, two verdicts on two machines — unlike a pattern, limit 9, which is read the same everywhere. Backstop: a path written with `/` reads alike everywhere.
16. **A hook run has one deadline, and every wait in it takes the smaller of its own cap and what is left.** The identity carries `hook_seconds`, 25 s by default (`HOOK_SECONDS`), which each module's gate, session-start printer or generator names in its identity. In hook mode the guard starts one deadline for the run when it opens its scope (item 1 of [§2](#g2); R3 of [dec-0100-gate-declaration-scoped-to-one-guarded-run](../docs/decisions/dec-0100-gate-declaration-scoped-to-one-guarded-run.md#r3)). A scan, an act and a scope opened with no mode have none, and neither has a wait made outside every scope. Every shared git call and every wait a module makes takes the smaller of its cap and what is left of the deadline. The shared git calls have a cap of `GIT_SECONDS`, 3 s each: `rev-parse --show-toplevel`, `ls-files`, `check-ignore`, the `Matcher`'s `init` and `check-ignore --no-index`, and every call a module makes through the function. The modules' own caps are the history read of [`const-catalogs`](../docs/requirements.md#const-catalogs), 5 s; the version probe, 5 s, and the run, 10 s, of the prose linter of [`const-language`](../docs/requirements.md#const-language); the version probe, 5 s, and the one budget for the reading, the masking and the run of the link checker of [`const-referencing`](../docs/requirements.md#const-referencing), 20 s. Where nothing is left when a wait is asked, the wait does not start. The run ends in the configuration failure `C12.14`, which names the budget and the wait it ended. It is non-blocking, as limit 2 says, and the count line follows it, so the user reads the gate's line and not the platform's notice for a hook cut at its timeout. A call that runs past its own 3 s is still `C12.12` for a call in the person's repository and `C12.13` for one in the `Matcher`'s scratch repository. A wait that the deadline shortened, given less than its cap, and that then runs out ends in `C12.14` too: a shared git call, the version probe and the run of the prose linter and of the link checker, and the link checker's budget. The tool's own line stands only for a wait given its whole cap. The history read of [`const-catalogs`](../docs/requirements.md#const-catalogs) is the exception: it is a git call outside the function, and an advisory wait, asked only after a verdict. It takes the smaller of its 5 s and what is left, by `left_of`, which never raises, with a clock of its own inside that number. A read that clock cuts ends in the working tree's answer, and so does a read asked when nothing is left, which starts no git, and neither is a failure, so that no verdict falls with its advice. In scan mode and in act mode the function gives git no clock, so a slow scan or a slow move is waited for as long as it takes, and the scan checks the tree a hook gave up on. The version probes of the two tools keep their cap of 5 s in every mode, and their runs have no limit in a scan. A scope opened with no mode, as a test runner opens one, has no clock and no deadline. **What the deadline does not hold:** the interpreter's start and the reads before the scope opens, the reading of the event on standard input, and a wait that takes no number from the clock, of which there is none in hook mode today. A healthy git slower than 3 s in a hook, as on a very large repository, gives the `C12.12` line in place of a late verdict. A process git started, a `core.fsmonitor` hook, may outlive the git the timeout kills. Two ties hold the numbers. Every handler of a module's hooks file — a gate's or a session-start printer's — whose `command` names `python3`, or whose script names it, has a timeout of at least `hook_seconds` plus `LEFT_FOR_THE_REST`, 5 s: the margin for the interpreter's start, which the deadline does not count, and for the reads after the last wait. So a run that spends its deadline ends with the shared line before the platform cuts the hook. S165 holds it, reading the budget the gate's scope is opened with. A handler's script is each `args` entry that is no option, an option being an entry that starts with `-`, and each word of its `command` that lies under the plugin's folder or is an existing file. A script that cannot be read counts as one that names `python3`. A handler that names no `python3` is not held to the timeout. The other tie: each module's own waits in one hook run fit its `hook_seconds`, held by the module's own item: item 77 of [`const-catalogs`](../docs/requirements.md#const-catalogs), item 16 of [`const-language`](../docs/requirements.md#const-language) and item 70 of [`const-referencing`](../docs/requirements.md#const-referencing). Facts, read 2026-10-08 with git 2.54.0, Python 3.12.4 and Python 3.14.8. A `core.fsmonitor` hook ran on `ls-files`, `check-ignore -q` and `status --porcelain`, never on `rev-parse --show-toplevel` or on the `Matcher`'s `init` and `check-ignore --no-index`. A hung hook of that kind, set in a repository's or a person's configuration, therefore hangs the call that lists the files, and a stalled file system can hang any call. A `subprocess.run` timeout of 1 s raised `TimeoutExpired` at 1.01 s on both interpreters while the hook still ran; the hook ended by itself and no process was left. Backstop: the scan; the lines name the scan, the setting to find and, for `C12.12`, the call to run by hand; S165 and S167.
