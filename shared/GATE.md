# The code every gate shares

*One source for what every write-time gate of the kit must have: `const_gate/` for the gates, `tests/` for their fixtures. A module reaches both through relative symbolic links — `scripts/const_gate` and three files in its `tests/` — so the kit holds one copy to read, fix and review, and the platform copies what a link points at into an installed plugin (decision [dec-0025-shared-gate-code-linked](../docs/decisions/dec-0025-shared-gate-code-linked.md)). This page is the home of every shared text; a module's document writes out its own messages and links here for the rest. Every list and table row carries a handle.*

<a id="g1"></a>
## 1. What is shared, and why it may be

Code is admitted here only when it implements a kernel section literally (class K) or a gate-script rule of [template §6](../module-template/MODULE.md#t6) (class R), and two or more modules need it. A part already admitted may be widened for one module where the widening keeps a rule the part carries for all — the one guard around a second entry point, the one pipeline under a second event, the one fixture subject for a gate shaped differently — and the widening defaults to what the other modules pass, so they change nothing (rule 2 of [plc-0009-shared-code](../docs/policies/plc-0009-shared-code.md)).

| part | class | carries |
|---|---|---|
| `identity` | R | which gate this process is — namespace, gate name, plugin root, any library the module needs beyond the shared ones — declared once by the entry point, before anything is printed; the package's one global of its own |
| `model` | K, R | the kernel's closed vocabularies (meta-type, status), the template's (severity, mode — hook, scan, and act for a second entry point — stream) and the platform's file tools, the typed structures that cross function boundaries, `Finding` and `Broken`, the keys of the shared configuration failures, the exit codes |
| `messages` | R | every shared text of [§3](#g3), as typed functions under their keys |
| `errors`, `preflight`, `cli` | R | the configuration-failure exception; the import check of each declared library; `argparse` with its exit 2 turned into 1, the single guard — offered as `guarded` to a second entry point, an act that changes files, with a closing line of its own — no fail-open; a module's own value flags on the one parser, scan mode only, the usage line naming them |
| `output` | R | every printed line also appended to a log, on the standard library's `logging` |
| `repository`, `territory` | K | git for the root and the file list; territory patterns evaluated by `git check-ignore` in a fresh null repository ([kernel §6](../kernel/CONVENTIONS.md#k6)) |
| `envelope` | K | the frontmatter block parsed once, every field kept as YAML read it ([kernel §1](../kernel/CONVENTIONS.md#k1)); which fields matter is the module's |
| `dials` | K | the dials file read and validated for the keys every gate reads: the two kernel-owned keys, `territory` of every policy namespace, `severity`, `log_dir`; the rest of the module's namespace handed over as read ([kernel §6](../kernel/CONVENTIONS.md#k6)); the refusal of a pattern git would misread (`C5.7`), which a module that declares territories in its own dials calls for them too |
| `events` | R | the hook payload parsed into a typed event that keeps the event's name; the document as it will be after a `Write` or an `Edit` — for an event after the write the document is the file on disk, and the pipeline reads it there; a `Stop`, which names no file, keeps its loop guard `stop_hook_active` |
| `index`, `resolution` | K | the policies found in the root policy's territory, what each claims, and the documents of a scan; which policy governs a document, path first, as a typed result — the policy, or one of the four defects — with no message ([kernel §3](../kernel/CONVENTIONS.md#k3)). What one module alone needs — the first module's id owners and void namespaces — lives in that module. Classification reads the root's territory only; whether an id is unique in the tree is a module's own read of every envelope, never part of resolving a document to its policy |
| `pipeline` | R | from the event — a write, or a `Stop` located from its `cwd` — or the scan's directory, to the repository and its dials — whether the dials name a root policy is left to the module, since a gate that reads only its own dials needs none; from findings to the verdict the platform understands — block, warn as one JSON object, on `Stop` the user's notice alone, scan; a whole-line green for an event without a document; the routing of the log to `log_dir`, public for a second entry point |
| `tests/harness`, `tests/consumer`, `tests/shared_items` | R | the case runner driving a module's real entry point; the throwaway three-policy consumer; the acceptance items of [§5](#g5) |

Deferred: delivery of this code through a package index is not built — inside a plugin the link delivers it. Signal: a reader of this code outside plugins appears.

## 2. The interface a module fills

1. **Identity.** The module's `start` builds one `Identity(namespace, gate, plugin_root, libraries)` and calls `cli.run(argv, identity, load_modes)`. A second entry point of a module — a generator that changes files, with a command line of its own, never a gate — declares an identity of its own and calls `cli.guarded(identity, Mode.ACT, body, could_not_run)`: the same single guard, exit codes and log, around a body that parses its own arguments with a parser whose usage error is a configuration failure, runs `preflight.check`, and only then imports what needs the declared libraries; `could_not_run` is its own closing line, since "0 documents examined" is a gate's. The shared code never imports a module. A library the module needs beyond PyYAML goes into `libraries` and into the plugin's `requirements.txt`; the preflight imports each, and the shared item S137 holds the two lists equal.
2. **Two modes.** `load_modes` returns `cli.Modes(hook, scan)` — `hook(output, stdin) -> int` and `scan(output, start_directory) -> int`, each returning an exit code. A module whose scan takes flags of its own hands `cli.run` a list of `cli.Argument(flag, metavar)`, one value each, and gives `Modes` a `scan_with(output, start_directory, values) -> int`, called in `scan`'s place with the values by flag; a flag given without `--scan` is a misinvocation, and the usage line names the flags. `load_modes` is called after the preflight, because the module's code needs the declared libraries — which makes the import inside `load_modes` — and, in a second entry point, the import of its acts after its preflight — the explicitly necessary exceptions to gate-script rule 16 of [template §6](../module-template/MODULE.md#t6), marked and reasoned where each stands.
3. **The middle of a run is the module's.** A mode calls `pipeline.locate_write` or `pipeline.locate_scan`, which returns a target or a `Skip`. A gate that resolves policies then returns `pipeline.no_root_policy(output)` when `target.dials.root_policy` is absent — the type of `build_index` does not let it forget — and a gate that reads only its own dials matches its own territories with the `Matcher` and builds no index. The first kind opens `with Matcher() as matcher` and builds the index inside it — `build_index(root, dials, root_policy, matcher, pending)`, the pending document only in hook mode; examines documents with its own checks — in a scan by iterating `index.documents()`, which raises the shared failure for a file nobody can read; and hands findings and notes to `pipeline.report_hook`, `report_scan`, `green_hook` or `skip` — `report_hook` takes the event's name, which the `warn` channel must repeat, and a count line of the module's own where "1 document examined" would not be true, both defaulting to what a gate before the write needs; `WriteTarget.event_name` tells a module wired to both events which one it is answering; `green_hook` takes what the examined document is — `messages.governed_by(policy)`, or the module's own words where no policy is involved. A gate wired to an event that names no file — `Stop` — calls `pipeline.locate_event`, which returns an `EventTarget` — the repository the event's `cwd` lies in, its dials, the event's name and `stop_hook_active` — or a `Skip`; a clean examination ends in `pipeline.green_event`, whose line is the module's whole account; its findings go through `report_hook` with `event_name=STOP` and a `count` of its own, and the warn there is the `systemMessage` alone. Nothing in the pipeline calls back into the module.
4. **Own dials.** `Dials.own` is the module's namespace as YAML read it; the module parses it once into its own dataclass and raises the shared `ConfigurationFailure` with its own `C5` text when it is malformed.
5. **Own messages.** A module's findings, skip reasons, notes and dial failures live in the module's `messages`, written like the shared ones; its finding keys are its own enum; a value echoed from a document goes through the shared `shown`; a field read as a string goes through the shared `envelope.string_field`.
6. **The entry files.** The POSIX one prints `C1` and `C11` itself when `python3` is missing. The Python one, parseable by any Python 3, checks the interpreter floor and prints `C14` and `C11`; imports `const_gate.cli` inside a guard that prints `C15` and `C11` — an empty directory fails there too; then runs the module's `start`. These two exits, before any package can be imported, are the only ones outside the single guard. A second entry point's files do the same with the closing line of their own in `C11`'s place, and their `C1`, `C14` and `C15` variants drop the clause about unchecked writes.
7. **Links.** `scripts/const_gate` → `shared/const_gate`; `tests/harness.py`, `tests/consumer.py`, `tests/shared_items.py` → their sources in `shared/tests/`; all relative. The kit gate is `scripts/check-shared-links.py`: red for a missing link, a copy, a plain file, a dangling, absolute or misdirected link, in `scripts/` or in `tests/`; `--self-test` is its red→green fixture. A module whose scripts import the shared code — a hook's gate or a generator alone — owes the links.
8. **The runner.** A module's `tests/run.py` puts its own `scripts/` directory on the import path — the runner only, never gate code — declares the module's identity before any expected message is built, builds one `Harness(scripts, wrapper, entry, namespace)`, and hands the shared items one `Subject`: the harness, a function that runs the gate on a prepared consumer, a patch of its own namespace, a write it passes and one it blocks with the finding that teaches, what the green line says the passed document is, the territory that holds both and the dials patch that declares that territory with other patterns, and whether the gate resolves policies; and, for a gate that differs from the first three, what the count line says of a README with no envelope at the repository's top — `0 documents examined` unless the gate covers every Markdown file — and whether the gate judges envelopes: one that does not leaves the item about an unreadable envelope out and proves in its own items that such an envelope is no crash. A module that is only a generator — no hook event, no verdict, no scan — says so with `event_driven=False`, gives its own closing line in `closing` and, in `act_args`, the arguments of a run that completes from inside a fresh consumer: the items about hook input, paths and skips, the warn channel and the scan are then left out with their numbers kept free, its `gate_on` turns the `Write` the remaining items hand it into the generator's command line, run inside the consumer through the harness's `cwd`, and a refused run counts where a gate's finding would. A gate driven by `Stop` says so with `event="Stop"`: the items about a written file are left out with their numbers kept free, `gate_on` turns `valid` into a clean tree and `red` into a dirty one, the items that build a payload themselves build a `Stop` one from the consumer's root with the harness's `stop_json`, and the warn item expects the user's notice alone.

## 4. Shared honest limits

Every module that links this code has these limits and states its own beside them.

1. **Shell writes and other actors.** A heredoc, `sed -i`, a human's editor, a merge, another server's file tool: none is a `Write` or `Edit`, and the hook never sees it. Backstop: the module's scan, on demand and in CI.
2. **A configuration failure, a timeout, and a hook that cannot start are non-blocking in hook mode.** Exit 1 shows the user the first stderr line and the write proceeds; the platform treats a hook past its timeout, or one whose script is missing, the same way. Backstop: the scan exits 1 with the same line, so CI turns red; the line lands in the output log.
3. **The link to this code may be dropped by an install.** The platform documents that a link leading outside a plugin is copied into a marketplace install, and skipped when a plugin is loaded from a local path in copy mode; on Claude Code 2.1.251 a plugin loaded with `--plugin-dir` runs in place and the link resolves (observed 2026-09-19). Backstop: `C15` — loud, exit 1, the same class as a missing library — with an absence fixture in every module; the kit gate on the links; `cp -RL` for a copy of a module's folder. Fallback: when the consumer-live proof or a platform update shows the link skipped, the links are replaced by copies and the kit's link gate by a gate on copy equality — no module code changes.
4. **`Edit` is reconstructed, not observed.** The edit is applied to the file on disk and the result judged; an absent `old_string` is a visible skip; an `old_string` occurring twice without `replace_all` is judged on its first occurrence though the tool will refuse the edit; an `Edit` of a missing file with an empty `old_string` is judged on what it creates, and one with an empty `old_string` on a file that exists is a visible skip, since it matches everywhere. Backstop: the tool's own refusal comes after the hook, and the next real write is judged again.
5. **Symbolic links in the consumer.** The written path is resolved before it is matched, so a territory that names only a link does not claim what is written through it. Backstop: territories over real paths; the scan lists files under the paths git records.
6. **A key given twice in an envelope.** YAML keeps the last one. Backstop: review.
7. **Markdown means `.md`; git-ignored files are invisible to the scan,** which lists tracked files and untracked ones git does not ignore; a tracked file deleted from the working tree is left out; a path holding a line break is examined, and its finding's headline then spans two lines. Backstop: the hook still judges such a file when it is written through the file tools.
8. **The envelope ends at the first line holding only `---`**; a block scalar containing such a line truncates it. Backstop: the module reports the truncated envelope as invalid.
9. **Patterns match case-sensitively on every platform,** so one repository gets one verdict everywhere. Backstop: the scan sees a file under the case git records.
10. **The output log is best-effort evidence, not a gate.** A logging failure never changes a verdict; `C1`, `C14` and `C15` are printed and not logged, since no shared code runs to log them. Backstop: stdout and stderr remain the record.
11. **No `--help`,** and no abbreviated flags: `argparse`'s own help exits past the guard and the log. Backstop: any unknown argument is a misinvocation whose fix line is the usage.
12. **With two gates installed, the model sees one block message at a time** when both exit 2 (observed on Claude Code 2.1.251, 2026-09-19; the documentation is silent). Backstop: the next write is judged again; both findings are in the output logs.
13. **A negated pattern takes a file out of a territory only where git can re-include it:** not under a directory an earlier pattern excluded. `<dir>/**` followed by `!<dir>/README.md` works, since the file lies directly in the named directory; `!<dir>/sub/README.md` does not, and the file stays inside. Backstop: a territory of file patterns — `<dir>/**/*.md` — from which any file can be taken out; the shared item S148 shows the half that works, and the third module's own fixture shows both.
