# The code every gate shares

*One source for what every gate of the kit must have: `const_gate/` for the gates, `tests/` for their fixtures. A module reaches both through relative symbolic links — `scripts/const_gate` and three files in its `tests/` — so the kit holds one copy to read, fix and review. An install that copies the plugin into the platform's plugin cache copies what such a link points at within the marketplace. One that loads the plugin in place reads through the link (limit 3 of [§4](#g4); decision [dec-0025-shared-gate-code-linked](../docs/decisions/dec-0025-shared-gate-code-linked.md)). This page is the home of every shared text. A module's document writes out its own messages and links here for the rest. Every list and table row carries a handle.*

<a id="g1"></a>
## 1. What is shared, and why it may be

What may be admitted here, and when a part already admitted may be widened for one module, is [rule 2 of plc-0009-shared-code](../docs/policies/plc-0009-shared-code.md#r2). The table's class says which kind of code each part is: K, it implements a kernel section literally; R, it implements a gate-script rule of [template §6](../module-template/MODULE.md#t6).

| part | class | carries |
|---|---|---|
| `identity` | R | which gate this process is — namespace, gate name, plugin root, any library the module needs beyond the shared ones, and the two clauses that close `C2` and `C12.11`, what stands until the failure is fixed, a gate's by default — declared once by the entry point, before anything is printed; the package's one global of its own |
| `model` | K, R | the kernel's closed vocabularies (meta-type, status), the template's (severity, mode — hook, scan, and act for a second entry point — stream) and the platform's file tools, the typed structures that cross function boundaries, `Finding` and `Broken`, the kinds of a skip, the keys of the shared configuration failures, the exit codes |
| `messages` | R | every shared text of [§3](#g3), as typed functions under their keys; `shown`, which cuts a value at 80 characters; `escaped`, which shows a value's backslashes and line breaks escaped and never cuts it; and `echoed`, which is `escaped(shown(value))`, so that a failure stays on one line — in hook mode only its first line reaches the user. `escaped` is class R like the others: all eleven modules need it, since each has a path in a headline |
| `errors`, `preflight`, `cli` | R | the configuration-failure exception; the import check of each declared library; `argparse` with its exit 2 turned into 1, the single guard — offered as `guarded` to the other kinds of entry point, an act that changes files and a session-start printer, with a closing line of its own — no fail-open; a module's own value flags on the one parser, scan mode only, the usage line naming them |
| `output` | R | everything printed also appended to a log, one record per print, on the standard library's `logging` |
| `repository`, `territory` | K | git for the root and the file list, and `is_markdown`, the one test of what Markdown is, by the name's ending, in any case, a file named just `.md` included (limit 7 of [§4](#g4)), which the hook and the scan both use; territory patterns evaluated by `git check-ignore` in a fresh null repository ([kernel §6](../kernel/CONVENTIONS.md#k6)) |
| `envelope` | K | the frontmatter block parsed once, every field kept as YAML read it ([kernel §1](../kernel/CONVENTIONS.md#k1)); which fields matter is the module's. `envelope_bounds` says where it stands, in character offsets of the text as given; `envelope_lines` is the line splitter: a line ends at `\n`, `\r\n` or a lone `\r` and nowhere else |
| `dials` | K, R | the dials file read and validated for the keys every gate reads: the two kernel-owned keys, `territory` of every policy namespace, `severity`, `log_dir` — by a hand-written mirror of the kernel's schema, never a validator library, since a module ships without the kit; `scripts/check-schema-mirror.py` holds the mirror no more lenient than the schema; the rest of the module's namespace handed over as read ([kernel §6](../kernel/CONVENTIONS.md#k6)). Two refusals serve a module's own dials. The first is of a pattern git would misread (`C5.7`): a module that declares territories in its own dials calls it for them too, naming the dial by its whole path. The second is of a key of the module's namespace that the module does not read (`C5.10`), which every module calls — class R, rule 8 of [template §6](../module-template/MODULE.md#t6): a dial ignored in silence is a silent pass. Three small readers serve both: `GATE_KEYS`, the two dials every gate has, which a module's key list opens with — a module that blocks nothing lists `LOG_DIR_KEY` alone; `texts`, the non-empty strings of a list; and `relative_path`, a repository-relative path as the file system reads it, used for `root_policy` and `log_dir` and by the modules that read paths (limit 15 of [§4](#g4)). One read crosses the kernel's "reads no other module's namespace": a `const-*` key whose value is a mapping is a candidate policy namespace, since the kernel names a policy by where its document lies and forbids no id of that form — its `territory` is kept when it is a list of non-empty strings and is silently empty otherwise, a well-formed list still going through `C5.7`; it is consulted only for the id of a document in the root policy's territory, so with no such document it changes no verdict |
| `events` | R | the hook payload parsed into a typed event that keeps the event's name; the document as it will be after a `Write` or an `Edit` — for an event after the write the document is the file on disk, and the pipeline reads it there; a `Stop`, which names no file, keeps its loop guard `stop_hook_active`; a `PreToolUse` of the shell tool, `Bash`, which names no file either, keeps its `tool_input.command`, and one without a string command is the shared failure `C12.4` |
| `index`, `resolution` | K | the policies found in the root policy's territory, what each claims, and the documents of a scan; which policy governs a document, path first, as a typed result — the policy, or one of the four defects — with no message ([kernel §3](../kernel/CONVENTIONS.md#k3)). What one module alone needs — the first module's id owners and void namespaces — lives in that module. Classification reads the root's territory only; whether an id is unique in the tree is a module's own read of every envelope, never part of resolving a document to its policy |
| `pipeline` | R | from the event — a write, or a `Stop` or a shell event located from its `cwd`, the `EventTarget` carrying the tool's name and the command — or the scan's directory, to the repository and its dials. Whether the dials name a root policy is left to the module, since a gate that reads only its own dials needs none. From findings to the verdict the platform understands — block, warn as one JSON object, on `Stop` the user's notice alone, `ask` for a gate whose block is the user's yes, scan; the green of a hook run on a write, as one JSON object where it has notes; a whole-line green for an event without a document; the routing of the log to `log_dir`, public for a second entry point; `within_the_cap`, the first findings of a write that fit the platform's cap on a hook's text, the first always shown, with an optional count limit of a module's own (limit 14 of [§4](#g4)) |
| `tests/harness`, `tests/consumer`, `tests/shared_items` | R | the case runner driving a module's real entry point; the throwaway three-policy consumer; the acceptance items of [§5](#g5) |

Deferred: delivery of this code through a package index is not built — inside a plugin the link delivers it. Signal: a reader of this code outside plugins appears.

## 2. The interface a module fills

1. **Identity.** The module's `start` builds one `Identity(namespace, gate, plugin_root, libraries, until_installed, until_fixed)` and calls `cli.run(argv, identity, load_modes)`. The last two, the clauses that close `C2` and `C12.11`, default to a gate's — writes pass unchecked, the check does not run — so a gate with a hook mode never names the last two. A gate without one, a scan alone, names `until_installed` with what its scan leaves undone, since no write passes through it, and its module's document writes the clause out. A second entry point of a module — a generator that changes files, with a command line of its own, never a gate — declares an identity of its own and calls `cli.guarded(identity, Mode.ACT, body, could_not_run)`. That is the same single guard, exit codes and log, around a body that parses its own arguments with a parser whose usage error is a configuration failure, runs `preflight.check`, and only then imports what needs the declared libraries; `could_not_run` is its own closing line, since "0 documents examined" is a gate's. Its two clauses say what it leaves undone or what not to do with it — nothing is created, do not move documents with it — true in every state the failure can find, since no write passes through a generator. A session-start printer — an advisory hook that reads the dials and prints to the model's context, blocking nothing — is a third kind. It declares its own identity and calls `cli.guarded(identity, Mode.HOOK, body, could_not_run)` around a body that takes no arguments, turning any into the shared misinvocation by hand, runs `preflight.check`, and only then imports the pipeline and its dials. Its closing line says that the gate's state is not said. The shared code never imports a module. A library the module needs beyond PyYAML goes into `libraries` and into the plugin's `requirements.txt`. The preflight imports each, and the shared item S137 holds the two lists equal.
2. **Two modes.** `load_modes` returns `cli.Modes(hook, scan)` — `hook(output, stdin) -> int` and `scan(output, start_directory) -> int`, each returning an exit code. A module whose scan takes flags of its own hands `cli.run` a list of `cli.Argument(flag, metavar)`, one value each, and gives `Modes` a `scan_with(output, start_directory, values) -> int`, called in `scan`'s place with the values by flag. A flag given without `--scan` is a misinvocation, and the usage line names the flags. `load_modes` is called after the preflight, because the module's code needs the declared libraries. This makes the import inside `load_modes` — and, in an entry point of another kind, the import of a generator's acts or of a printer's pipeline and dials after its preflight — the explicitly necessary exceptions to gate-script rule 16 of [template §6](../module-template/MODULE.md#t6), marked and reasoned where each stands.
3. **The middle of a run is the module's.** A mode calls `pipeline.locate_write` or `pipeline.locate_scan`, which returns a target or a `Skip`. A `Skip` carries `reason`, the shared text, and `kind` and `where`, the same facts typed; a module that says a skip in its own words switches on `kind` and takes `where` whole, and never parses `reason`. A gate that resolves policies then returns `pipeline.no_root_policy(output)` when `target.dials.root_policy` is absent — the type of `build_index` does not let it forget. A gate that resolves policies only under a dial of its own raises its own `C5` there instead, since a skip would let a write through with nothing examined. A gate that reads only its own dials matches its own territories with the `Matcher` and builds no index. The first kind opens `with Matcher() as matcher` and builds the index inside it — `build_index(root, dials, root_policy, matcher, pending)`, the pending document only in hook mode. Building it raises the shared failure `C12.10` in both modes for a file in the root policy's territory nobody can read — a policy by the kernel's rule whose own territory nobody can know, never a policy with no id. The first kind then examines documents with its own checks — in a scan by iterating `index.documents()`, which raises the shared failure for a file nobody can read. It hands findings and notes to `pipeline.report_hook`, `report_scan`, `green_hook` or `skip`. `report_hook` takes the event's name, which the `warn` channel must repeat, a count line of the module's own where "1 document examined" would not be true, and `ask`, true for a gate whose block is the user's yes at the platform's prompt — the shell gate — all three defaulting to what a gate before the write needs. `WriteTarget.event_name` tells a module wired to both events which one it is answering. `green_hook` takes what the examined document is — `messages.governed_by(policy)`, or the module's own words where no policy is involved — and the event's name, which a run with notes must repeat (`G2`). `skip` takes the event's name in a hook run that has notes to hand on, and none in a scan. A gate wired to an event that names no file — `Stop` — calls `pipeline.locate_event`, which returns an `EventTarget` — the repository the event's `cwd` lies in, its dials, the event's name and `stop_hook_active` — or a `Skip`. A clean examination ends in `pipeline.green_event`, whose line is the module's whole account. Its findings go through `report_hook` with `event_name=STOP` and a `count` of its own, and the warn there is the `systemMessage` alone. Nothing in the pipeline calls back into the module.
4. **Own dials.** `Dials.own` is the module's namespace as YAML read it; the module parses it once into its own dataclass and raises the shared `ConfigurationFailure` with its own `C5` text when it is malformed. It first calls `dials.refuse_unknown_keys(own, known)`, `known` being the keys it reads in the order its failure lists them: the first key outside them, in sorted order, is the shared `C5.10`. A pattern it reads from a dial goes through `dials.refuse_unreadable_patterns(where, patterns)`, `where` being the dial's whole path as a person writes it — `{module}.{dial}`.
5. **Own messages.** A module's findings, skip reasons, notes and dial failures live in the module's `messages`, written like the shared ones. Its finding keys are its own enum. A value a message takes from a document, a dial, the envelope, the command line, the hook payload, the environment or a tool goes through one of two shared functions of `messages` ([§1](#g1)), never raw and never through `shown` alone. `escaped` shows the backslash, the line feed and the carriage return escaped and never cuts. It is for a value the reader must open, copy or type into a fix, or that a later step reads: a repository path, an id or an anchor typed into a fix, the text of a dial that teaches, a tool's one-line diagnosis, a generator's output line. `echoed` is `escaped(shown(value))`: cut at 80 characters, then escaped. It is for a value that only points at something the reader can already see in the file or the command: a dial key, a pattern, a phrase, a command word, a match from a document, an event or tool name. A value is left alone in three cases only. The code or a check has fixed its shape before the message: a name matched whole by a kebab pattern, an integer, a hash, an enum, a code literal. Or the system's own error text already escapes it: an OS error that quotes the path with `repr`. Or it stands inside a command the reader pastes. A pattern that checks an id is applied with `fullmatch`, so that no id ends in a line break. A field read as a string goes through the shared `envelope.string_field`.
6. **The entry files.** The POSIX one prints `C1` and `C11` itself when `python3` is missing. The Python one, parseable by any Python 3, checks the interpreter floor and prints `C14` and `C11`. It imports `const_gate.cli` inside a guard that prints `C15` and `C11` — an empty directory fails there too. Then it runs the module's `start`. These two exits, before any package can be imported, are the only ones outside the single guard. A second entry point's files do the same with the closing line of their own in `C11`'s place. Their `C1`, `C14` and `C15` variants drop the clause about unchecked writes, as the identity's two clauses do for `C2` and `C12.11` once the package runs. The entry files of a gate without a hook mode carry its own clause in `C1`, `C14` and `C15`, the one its identity gives `C2`.
7. **Links.** `scripts/const_gate` → `shared/const_gate`; `tests/harness.py`, `tests/consumer.py`, `tests/shared_items.py` → their sources in `shared/tests/`; all relative. The kit gate is `scripts/check-shared-links.py`: red for a missing link, a copy, a plain file, a dangling, absolute or misdirected link, in `scripts/` or in `tests/`. Its `--self-test` is its red→green fixture. A module whose scripts import the shared code — a hook's gate, a scan or a generator — owes the links.
8. **The runner.** A module's `tests/run.py` puts its own `scripts/` directory on the import path — the runner only, never gate code. It declares the module's identity before any expected message is built, builds one `Harness(scripts, wrapper, entry, namespace)`, and hands the shared items one `Subject`. The `Subject` holds: the harness, a function that runs the gate on a prepared consumer, a patch of its own namespace, a write it passes and one it blocks with the finding that teaches, what the green line says the passed document is, the territory that holds both and the dials patch that declares that territory with other patterns. In `outside` it holds the module's skip reason for the blocked write's file once a negated pattern takes it out of that territory — typed by hand, and required wherever the item about negation runs, so it is never passed on an empty default. In `long_value`, for a gate whose finding echoes a value from a document, it holds a write it blocks with one finding echoing a value of 12,000 characters `x`. In `pattern_dial`, for a gate that reads path patterns from a dial of its own, it holds the dial's name as a person finds it under the namespace and the dials patch that puts a given pattern there. In `noted`, for a gate that can pass a write with one note, it holds that write, and in `note` the note, typed by hand. It also holds whether the gate resolves policies. Each red→green `Case` names in `green_what` what its green half's line says the document is, typed by hand. The case runner requires that whole green line, and of the red half exactly the finding's headline and the count line among the `RED` lines of stderr, with no `RED` line on stdout nor anywhere in the green half, so a second finding or a stray line fails it. A harness built with `scan_only=True` runs a case the scan's way: each half is written into a fresh consumer and `--scan` run there. The red half's count line is typed by hand in the case's `count`, its `green_what` the whole tail of the green line, the verdict read on stdout and no `RED` line allowed on stderr. A gate on the shell tool gives `event="Bash"`, its `valid` and `red` the commands as the text of a Write, and `ask=True` where its block is the `ask` verdict, so the items about a red run read that verdict's reason. For a gate that differs from the first three, the `Subject` also gives what the count line says of a README with no envelope at the repository's top — `0 documents examined` unless the gate covers every Markdown file — and whether the gate judges envelopes. One that does not leaves the items about an envelope out and proves in its own items that an unreadable one is no crash. A module that is only a generator — no hook event, no verdict, no scan — says so with `event_driven=False`, gives its own closing line in `closing` and, in `act_args`, the arguments of a run that completes from inside a fresh consumer. The items about hook input, paths and skips, the warn channel and the scan are then left out with their numbers kept free. Its `gate_on` turns the `Write` the remaining items hand it into the generator's command line, run inside the consumer through the harness's `cwd`, and a refused run counts where a gate's finding would. A gate driven by `Stop` says so with `event="Stop"`: the items about a written file are left out with their numbers kept free. Its `gate_on` turns `valid` into a clean tree and `red` into a dirty one. The items that build a payload themselves build a `Stop` one from the consumer's root with the harness's `stop_json`, and the warn item expects the user's notice alone. A gate whose hook never asks git for the file list — one that matches the written file against its own territories by pattern alone — says so with `hook_lists_files=False`. The item about git failing to list the files then meets the failing git through the scan on the prepared consumer, where the gate does ask. A gate without a hook mode — a scan alone, which run as a hook is its own configuration failure — says so with `scan_only=True`: the items about hook input, a written file, the warn channel and a negated pattern's skip are left out with their numbers kept free. Its `gate_on` writes the action's document into the consumer and runs `--scan` there. Its `green` is the whole green line of a scan over the consumer holding `valid` alone, `bare_readme` that line with a README at the top. The items about a red run read stdout, where a scan prints its verdict, the finding and the count line two records of the log. The runner's command line is empty for a full run, whose last line is `N/T acceptance items green — …`. With `--item <n>[,<n>…]` it runs only the items named, for one proof by hand, and its last line is `k/k selected items green — k of N items run, not a full pass`, never the full one. An unknown number, a list that is not numbers, or any other argument is a configuration failure: exit 1, no item run. The kit's gate list and CI never filter; `scripts/check-gate-lists.py` refuses `--item` in either.

## 3. Shared messages

Each row is the text of `const_gate/messages.py` under that key, word for word — one function per sub-key (`c5_…`, `c12_…`, `g1_skip_…`), the row's handle being the table's, not the function's name. `{module}` is the namespace the entry point declared, other `{…}` are parameters. A configuration failure is one line that stands on its own — in hook mode only the first stderr line reaches the user (the platform's hooks documentation, read on the survey dates of the six linking modules, 2026-09-18 to 2026-09-23, Claude Code 2.1.251) — followed by the count line `C11`.

## 4. Shared honest limits

Every module that links this code has these limits and states its own beside them.

1. **Shell writes and other actors.** A heredoc, `sed -i`, a human's editor, a merge, another server's file tool: none is a `Write` or `Edit`. The hook never sees it (the platform's hooks documentation, read on the survey dates of the six linking modules, 2026-09-18 to 2026-09-23, Claude Code 2.1.251). Backstop: the module's scan, on demand and in CI.
2. **A configuration failure, a timeout, and a hook that cannot start are non-blocking in hook mode.** Exit 1 shows the user the first stderr line and the write proceeds. The platform treats a hook past its timeout, or one whose script is missing, the same way (the platform's hooks documentation, read on the survey dates of the six linking modules, 2026-09-18 to 2026-09-23, Claude Code 2.1.251). Backstop: the scan exits 1 with the same line, so CI turns red. The line lands in the output log.
3. **The link to this code may be dropped by an install.** Re-read 2026-09-23 against the platform's documentation, Claude Code 2.1.251. A marketplace install that copies the plugin into the plugin cache dereferences a link whose target lies elsewhere within the same marketplace — "the target's content is copied into the cache in its place" — while one leading outside the marketplace is skipped. The marketplace root is the directory holding `.claude-plugin/`, so `.claude-plugin/marketplace.json` at the kit root puts this code inside it. A plugin loaded in place — `--plugin-dir`, or a relative-path entry of a marketplace added from a local directory — is run from its source: its hook processes receive a plugin root that points at the source directory and read through the link there. A session showed it on Claude Code 2.1.282 on 2026-10-01: with the kit's folder added as a marketplace to an empty configuration and a module installed, the session's startup event gave the source folder as the plugin's path, it read the module's hooks file from there, and the module's hook ran green with the cache copy's `scripts/` removed. Installing such an entry writes a copy into the plugin cache all the same, which the session does not run (research [res-0008-const-interaction](../docs/research/res-0008-const-interaction.md), p14). In that copy, on Claude Code 2.1.282, the link to this code arrives as a real directory — file links were recorded dereferenced there on 2026-09-25, this directory link observed 2026-10-01. An install from the marketplace's git remote, the copy a consumer's install writes, carries it the same way: held on every run of the kit's CI by `scripts/check-bare-install.py`, which installs each module from the change's GitHub repository and branch and is red where a link of a module's source leads inside the module, or is left a link, is missing or arrives with other files or bytes than its target in its installed copy. The documentation's sentence that under `--plugin-dir` "only symlinks that resolve within the plugin's own directory are preserved" stands in its section on sharing files within a marketplace, which describes what a copy into the cache keeps. The page never says a `--plugin-dir` plugin is copied, and its path-traversal limitation rejects as a component path a link leading outside the plugin. The kit reads the sentence as that rule — a script's own import through the link is no component path. On Claude Code 2.1.251 a plugin loaded with `--plugin-dir` resolves it (observed 2026-09-19 and in every live proof since). Backstop: `C15` — loud, exit 1, the same class as a missing library — with an absence fixture in every module; the kit gate on the links; `cp -RL` for a copy of a module's folder. Fallback: when the consumer-live proof, the two-install proof of the marketplace (step 10 of the [rollout plan](../docs/rollout-plan.md)), the kit's install check or a platform update shows the link skipped, kept as a link, or arrived with other files or bytes than its target in an installed copy, the links are replaced by copies and the kit's link gate by a gate on copy equality. No module code changes.
4. **`Edit` is reconstructed, not observed.** The edit is applied to the file on disk and the result judged. An absent `old_string` is a visible skip. An `old_string` occurring twice without `replace_all` is judged on its first occurrence though the tool will refuse the edit. An `Edit` of a missing file with an empty `old_string` is judged on what it creates, and one with an empty `old_string` on a file that exists is a visible skip, since it matches everywhere. Backstop: the tool's own refusal comes after the hook (the platform's hooks documentation, read on the survey dates of the six linking modules, 2026-09-18 to 2026-09-23, Claude Code 2.1.251), and the next real write is judged again.
5. **Symbolic links in the consumer.** The written path is resolved before it is matched, so a territory that names only a link does not claim what is written through it. Backstop: territories over real paths; the scan lists files under the paths git records.
6. **A key given twice in an envelope.** YAML keeps the last one. Backstop: review.
7. **Markdown means `.md` — the name's ending, in any case, a file named just `.md` included, in the hook and in the scan alike; git-ignored files are invisible to the scan,** which lists tracked files and untracked ones git does not ignore. A tracked file deleted from the working tree is left out. A path holding a line break is examined, and every message shows the break escaped, `\n`, so each line stays one line. Backstop: the hook still judges such a file when it is written through the file tools.
8. **The envelope ends at the first later line that is `---`, its trailing whitespace ignored**; a line ends only at `\n`, `\r\n` or a lone `\r`. A block scalar containing such a line truncates it. Backstop: the module reports the truncated envelope as invalid.
9. **Patterns match case-sensitively on every platform,** so one repository gets one verdict everywhere. Backstop: the scan sees a file under the case git records.
10. **The output log is best-effort evidence, not a gate.** A logging failure never changes a verdict. A configuration failure is two records — its BROKEN line and the closing line — and an unexpected one three, the traceback last, because the guard prints each apart. Should that trouble a reader, the remedy is a guard that prints once, never another unit of record. `C1`, `C14` and `C15` are printed and not logged, since no shared code runs to log them. Backstop: stdout and stderr remain the record.
11. **No `--help`,** and no abbreviated flags: `argparse`'s own help exits past the guard and the log. Backstop: any unknown argument is a misinvocation whose fix line is the usage.
12. **With two gates installed, the model sees one block message at a time** when both exit 2 (observed on Claude Code 2.1.251, 2026-09-19; the documentation is silent). Backstop: the next write is judged again; both findings are in the output logs.
13. **A negated pattern takes a file out of a territory only where git can re-include it:** not under a directory an earlier pattern excluded. `<dir>/**` followed by `!<dir>/README.md` works, since the file lies directly in the named directory. `!<dir>/sub/README.md` does not, and the file stays inside. Backstop: a territory of file patterns — `<dir>/**/*.md` — from which any file can be taken out. The shared item S148 shows the half that works, and the third module's own fixture shows both.
14. **A hook's text over 10,000 characters is replaced by a preview.** Read 2026-10-03 on the platform's hooks documentation, Claude Code 2.1.286 installed: the `additionalContext`, `systemMessage` and `initialUserMessage` strings of a hook, and its plain stdout, are capped at 10,000 characters, each string measured alone; over it the platform saves the whole text to a file and shows its path and a preview of the first 2,000 characters, and the cap has no setting. The two modules that can print many findings after a write, [`const-language`](../docs/requirements.md#const-language) and [`const-referencing`](../docs/requirements.md#const-referencing), show those that fit in `SHOWN_CHARACTERS`, 8,000, through `pipeline.within_the_cap`, so that the whole text stays under the platform's 10,000 and is not replaced by a preview; the count line and the closing note stand last and would be lost with it. The findings shown fit the 8,000, except the first, which is always shown; the notes and the count line are not counted in the 8,000. A value that only points is cut at 80 characters ([`echoed`](#g1)), but a value escaped whole — a path, an id typed into a fix, the text of a dial that teaches — is bounded by its source, not by 80: a repository path by the system, and a dial's text or a document's text by nothing the gate holds, such as the plain word of [`const-language`](../docs/requirements.md#const-language) kept whole in the fix of its pair rule. Another is a link's fragment in R6 of [`const-referencing`](../docs/requirements.md#const-referencing), document text escaped whole in the headline and in the `<a id="…">` fix. Both reach `within_the_cap`, which runs after a write only. **Breaks:** one such first finding can alone pass the platform's 10,000, and `within_the_cap` still shows it, since it shows the first; the platform then replaces the whole text with a file path and a preview of its first 2,000 characters, and the count line and the closing note are lost with it. Before a write, [`const-referencing`](../docs/requirements.md#const-referencing) prints its R1 to R4 findings with no cut at all, so many of them, or a lane's `fix` kept whole, can pass the 10,000 there as well. Under the 10,000 the text is shown whole, on stdout and stderr alike and on the context fields, since the findings are cut before any of them is written. Backstop: the count line says how many findings there are; the scan lists them all; a dial's text stays as short as it teaches, which covers a dial's text and not a link's fragment, whose length is the document's. Fallback: none needed.
15. **A dial's path is read with the platform's separator.** `root_policy`, `log_dir` and the paths a module reads — the `docs` paths of the `coverage` dial of [`const-task-close`](../docs/requirements.md#const-task-close), which trims each first, and the `template` paths of [`const-locations`](../docs/requirements.md#const-locations) — go through `dials.relative_path`: blank, absolute and leaving the repository by `..` are refused, `./` and `//` normalised, and `.` is accepted, the repository itself; a leading or trailing space is kept as part of the name for `root_policy`, `log_dir` and a `template` path of [`const-locations`](../docs/requirements.md#const-locations). A backslash separates only where the platform says so, so `..\x` leaves the repository on Windows and is one file name on macOS and Linux: one dials file, two verdicts on two machines — unlike a pattern, limit 9, which is read the same everywhere. Backstop: a path written with `/` reads alike everywhere.
