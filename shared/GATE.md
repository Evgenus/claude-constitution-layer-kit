# The code every gate shares

*One source for what every gate of the kit must have: `constitution_layer_kit/` for the gates, `tests/` for their fixtures. A module reaches both through relative symbolic links — `scripts/constitution_layer_kit`, and in its `tests/` the same package and the shared test files, beside its links to its own packages — so the kit holds one copy to read, fix and review. An install that copies the plugin into the plugin cache copies what the link points at; one that loads the plugin in place reads through the link (limit 3 of [§4](#g4); decision [dec-0025-shared-gate-code-linked](../docs/decisions/dec-0025-shared-gate-code-linked.md)). This page is the home of every shared text. A module's document writes out its own messages and links here for the rest. Every list and table row carries a handle.*

## 1. What is shared, and why it may be

What may be admitted here, and when a part already admitted may be widened for one module, is [rule 2 of plc-0009-shared-code](../docs/policies/plc-0009-shared-code.md#r2). The table's class says which kind of code each part is: K, it implements a kernel section literally; R, it implements a gate-script rule of [template §6](../module-template/MODULE.md#t6).

| part | class | carries |
|---|---|---|
| `identity` | R | which gate this process is — namespace, gate name, plugin root, any library the module needs beyond the shared ones, the two clauses that close `C2` and `C12.11`, what stands until the failure is fixed, a gate's by default, and, by mode, the skill of the plugin that teaches the rule and its fix — declared once by the entry point, before anything is printed, and with them the mode of the run, hook, scan or act, which the git budget of `repository` and the hook's deadline read (limit 16 of [§4](#g4)). It also carries `hook_seconds`, the seconds one hook run of the gate may take in all: `HOOK_SECONDS`, 25 s, unless the module sets another. In hook mode the declaration starts the run's one deadline, `hook_seconds` from that moment. `remaining` gives a wait the smaller of its cap and what is left of the deadline, the cap where the run has no deadline, and the configuration failure `C12.14` where nothing is left; `ran_out` gives the failure for a wait that ran out; `left_of`, which never raises, serves a wait that no verdict depends on. `LEFT_FOR_THE_REST`, 5 s, is the margin that a handler's timeout keeps over `hook_seconds`. The declaration is one: a second that differs in the identity, `hook_seconds` included, or in the mode is a defect, and a process declared with no mode, as a test runner declares, has no mode to read and no deadline. | `index`, `resolution` | K | the policies found in the root policy's territory, what each claims, and the documents of a scan; which policy governs a document, path first, as a typed result — the policy, or one of the four defects — with no message ([kernel §3](../kernel/CONVENTIONS.md#k3)). ## 2. The interface a module fills

1. **Identity.** The module's `start` builds one `Identity(namespace, gate, plugin_root, libraries, until_installed, until_fixed, skills, hook_seconds)` and calls `cli.run(argv, identity, load_modes)`. That call, and `cli.guarded` below, declare the identity and the mode of the run together, as the one declaration, before anything else (limit 16 of [§4](#g4)). The identity carries the hook's budget, `hook_seconds`, so the declaration of a hook run also starts its deadline. `until_installed` and `until_fixed`, the clauses that close `C2` and `C12.11`, default to a write gate's — writes pass unchecked, the check does not run — which fit a gate whose hook runs on a Markdown write, and `until_fixed`'s fits every gate. Any other gate — a scan alone, a hook on the shell, a hook at a turn's end — names `until_installed` with what its failure leaves unchecked, since no Markdown write passes through it; its entry files carry the same clause in `C1`, `C14` and `C15`, its module's document writes it out, and an item of its runner holds it in `C2` and in the entry files. A second entry point of a module — a generator that changes files, with a command line of its own, never a gate — declares an identity of its own and calls `cli.guarded(identity, Mode.ACT, body, could_not_run)`, whose second argument is the mode it declares: an act, so its git calls have no clock. That is the same single guard, exit codes and log, around a body that parses its own arguments with a parser whose usage error is a configuration failure, runs `preflight.check`, and only then imports what needs the declared libraries; `could_not_run` is its own closing line, since "0 documents examined" is a gate's. Its two clauses say what it leaves undone or what not to do with it — nothing is created, do not move documents with it — true in every state the failure can find, since no write passes through a generator. A session-start printer — an advisory hook that reads the dials and prints to the model's context, blocking nothing — is a third kind. It declares its own identity and calls `cli.guarded(identity, Mode.HOOK, body, could_not_run)`, so that its git calls have the hook's clock and its deadline, around a body that takes no arguments, turning any into the shared misinvocation by hand, runs `preflight.check`, and only then imports the pipeline and its dials. Its closing line says that the gate's state is not said. Its `until_installed` is `until then the gate's state is not said at session start`. Its module's document writes it out, and an item of its runner holds it in `C2` and `C1`. The shared code never imports a module. A library beyond PyYAML goes into `libraries` and `requirements.txt`; S137 holds the two lists equal. `skills` maps a mode to the skill of the plugin that teaches that mode's rule and its fix, by the skill's own name; the pipeline names it in the line after a red verdict of that mode, `F10`, and a mode the map leaves out gets no line. A gate whose module has no skill, a generator and a session-start printer give none.
2. **Two modes.** `load_modes` returns `cli.Modes(hook, scan)`, each returning an exit code. A module whose scan takes flags of its own hands `cli.run` a list of `cli.Argument` and gives `Modes` a `scan_with`, called in `scan`'s place with the values by flag. A flag given without `--scan` is a misinvocation, and the usage line names the flags. `load_modes` is called after the preflight, because the module's code needs the declared libraries. This makes the import inside `load_modes` — and, in an entry point of another kind, the import of a generator's acts or of a printer's pipeline and dials after its preflight — the explicitly necessary exceptions to gate-script rule 16 of [template §6](../module-template/MODULE.md#t6), marked and reasoned where each stands.
3. **The middle of a run is the module's.** A mode calls `pipeline.locate_write` or `locate_scan` and gets a target or a `Skip`, which carries `reason`, the shared text, and `kind` and `where`, the same facts typed; a module that says a skip in its own words switches on `kind` and takes `where` whole, and never parses `reason`. A gate that resolves policies then returns `pipeline.no_root_policy(output)` when `target.dials.root_policy` is absent — the type of `build_index` does not let it forget. A gate that resolves policies only under a dial of its own raises its own `C5` there instead, since a skip would let a write through with nothing examined. A gate that reads only its own dials matches its own territories with the `Matcher` and builds no index. The first kind builds the index by `build_index` inside `with Matcher() as matcher`, with the pending document in hook mode only. Building it raises the shared failure `C12.10` in both modes for a file in the root policy's territory nobody can read — a policy by the kernel's rule whose own territory nobody can know, never a policy with no id. It then examines documents with its own checks, in a scan through `index.documents()`, which raises the same failure. It hands findings and notes to `pipeline.report_hook`, `report_scan`, `green_hook` or `skip`. `report_hook` takes the event's name, which the `warn` channel must repeat, a count line of the module's own where "1 document examined" would not be true, and `ask`, true for a gate whose block is the user's yes at the platform's prompt — the shell gate — all three defaulting to what a gate before the write needs. `WriteTarget.event_name` tells a module wired to both events which one it is answering. `green_hook` takes what the examined document is — `messages.governed_by(policy)`, or the module's own words where no policy is involved — and the event's name, which a run with notes must repeat (`G2`). `skip` takes the event's name in a hook run that has notes to hand on, and none in a scan. A gate wired to an event that names no file — `Stop` — calls `pipeline.locate_event` for an `EventTarget` or a `Skip`. A clean examination ends in `green_event`. Its findings go through `report_hook` with `event_name=STOP` and a `count` of its own, and the warn there is the `systemMessage` alone. Nothing in the pipeline calls back into the module.
4. **Own dials.** `Dials.own` is the module's namespace as YAML read it; the module parses it once into its own dataclass and raises the shared `ConfigurationFailure` with its own `C5` text when it is malformed. It first calls `dials.refuse_unknown_keys(own, known)`, `known` being the keys it reads in the order its failure lists them: the first key outside them, in sorted order, is the shared `C5.10`. A pattern it reads from a dial goes through `dials.refuse_unreadable_patterns(where, patterns)`, `where` being the dial's whole path as a person writes it — `{module}.{dial}`.
5. **Own messages.** A module's findings, skip reasons, notes and dial failures live in the module's `messages`, written like the shared ones. Its finding keys are its own enum. A value a message takes from a document, a dial, the envelope, the command line, the hook payload, the environment or a tool goes through one of two shared functions of `messages` ([§1](#g1)), never raw and never through `shown` alone. `escaped` shows the backslash, the line feed and the carriage return escaped and never cuts. It is for a value the reader must open, copy or type into a fix, or that a later step reads: a repository path, an id or an anchor typed into a fix, the text of a dial that teaches, a tool's one-line diagnosis, a generator's output line. `echoed` is `escaped(shown(value))`: cut at 80 characters, then escaped. It is for a value that only points at something the reader can already see in the file or the command: a dial key, a pattern, a phrase, a command word, a match from a document, an event or tool name. A value is left alone in three cases only. The code or a check has fixed its shape before the message: a name matched whole by a kebab pattern, an integer, a hash, an enum, a code literal. Or the system's own error text already escapes it: an OS error that quotes the path with `repr`. Or it stands inside a command the reader pastes. A pattern that checks an id is applied with `fullmatch`, so that no id ends in a line break. A field read as a string goes through the shared `envelope.string_field`.
6. **The entry files.** The POSIX one prints `C1` and `C11` itself when `python3` is missing. The Python one, parseable by any Python 3, checks the interpreter floor and prints `C14` and `C11`. It imports `constitution_layer_kit.cli` inside a guard that prints `C15` and `C11` — an empty directory fails there too. Then it runs the module's `start`. These two exits, before any package can be imported, are the only ones outside the single guard. A second entry point's files do the same with the closing line of their own in `C11`'s place. Their `C1`, `C14` and `C15` carry their identity's clause, a generator's none. The entry files of a gate that names its own `until_installed` (item 1) carry it in `C1`, `C14` and `C15`, the one its identity gives `C2`.
7. **Links.** `scripts/constitution_layer_kit` and `tests/constitution_layer_kit` → `shared/constitution_layer_kit`; `tests/<name>.py` → `shared/tests/<name>.py` for each `.py` file at the top of `shared/tests/` whose name starts with neither `.` nor `_` (today `harness.py`, `consumer.py`, `acceptance.py`, `test_shared_items.py`); for the tests, `tests/<package>` → the module's own `scripts/<package>` for each folder at the top of its `scripts/`, itself no link, that holds an `__init__.py`, whose name starts with neither `.` nor `_`, save `constitution_layer_kit` (today one per module, named `<x>_gate`); all relative, each straight to its source, never through another link. The kit gate is `scripts/check-shared-links.py`, which reads the list from those folders and fails to run when `shared/constitution_layer_kit/` or one of those four files is gone: red for a missing link, a copy, a plain file, a dangling, absolute or misdirected link, or one that reaches its source through another link, in `scripts/` or in `tests/`, a link to the module's own package included; a finding on that link says why in its own words: the runner must import the code the gate runs. Its `--self-test` is its red→green fixture. A module owes the links by `hooks/hooks.json`, by an import line of the shared code in a `.py` under its `scripts/` — a scan or a generator — or by a link it has; a folder of `modules/` whose name starts with `.` or `_` is no module.
8. **The tests.** A module's `tests/test_<name>.py`, run by pytest, imports the shared package, the module's own packages and the shared test files from its own folder, which pytest puts first on the import path, through the links of item 7. No Python file a module ships edits the import path of its own process, the tests included. The rule binds that process alone: any child process a test starts may be given a path of its own, by `sys.path` in the program it runs or by `PYTHONPATH` in its environment. Today: shared item 112's shim puts the entry's folder first as Python does for a script; a case sets `PYTHONPATH` to a folder that hides or replaces a library for the gate, in the shared items and in the tests of several modules. The list is not closed. The test file declares the module's identity before any expected message is built, builds one `Harness(scripts, wrapper, entry, namespace)` and one `Subject`, which the session fixture `subject` of the module's `tests/conftest.py` returns to the shared items. The `Subject` holds: the harness, a function that runs the gate on a prepared consumer, a patch of its own namespace, a write it passes and one it blocks with the finding that teaches, what the green line says the passed document is, the territory that holds both and the dials patch that declares that territory with other patterns. Its fields `outside`, `long_value`, `pattern_dial`, `noted` and `note` serve the items about a negated pattern, a long echoed value, a path-pattern dial and a note, each described in the `Subject`'s comments; `outside`, the module's skip reason once a negated pattern takes the file out, is typed by hand and required wherever the item about negation runs, so it is never passed on an empty default. It also holds whether the gate resolves policies. Each red→green `Case` names in `green_what`, typed by hand, what its green line says the document is; the case runner holds the exact `RED` lines (the harness's docstring), so a second finding or a stray line fails it. A harness built with `scan_only=True` runs a case the scan's way: each half is written into a fresh consumer and `--scan` run there. The red half's count line is typed by hand in the case's `count`, its `green_what` the whole tail of the green line, the verdict read on stdout and no `RED` line allowed on stderr. A gate on the shell tool gives `event="Bash"`, its `valid` and `red` the commands as the text of a Write, and `ask=True` where its block is the `ask` verdict. For a gate that differs from the first three, the `Subject` also gives what the count line says of a README with no envelope at the repository's top — `0 documents examined` unless the gate covers every Markdown file — and whether the gate judges envelopes. One that does not leaves the items about an envelope out and proves in its own items that an unreadable one is no crash. A module that is only a generator — no hook event, no verdict, no scan — says so with `event_driven=False`, gives its own closing line in `closing` and, in `act_args`, the arguments of a run that completes from inside a fresh consumer. The items about hook input, paths and skips, the warn channel and the scan are then left out with their numbers kept free. Its `gate_on` turns the `Write` the remaining items hand it into the generator's command line, run inside the consumer through the harness's `cwd`, and a refused run counts where a gate's finding would. A gate driven by `Stop` says so with `event="Stop"`: the items about a written file are left out with their numbers kept free, its `gate_on` turns `valid` into a clean tree and `red` into a dirty one, and the items that build a payload use the harness's `stop_json`. A gate whose hook never asks git for the file list says so with `hook_lists_files=False`. A gate without a hook mode — a scan alone, which run as a hook is its own configuration failure — says so with `scan_only=True`: the items about hook input, a written file, the warn channel and a negated pattern's skip are left out with their numbers kept free. Its `gate_on` writes the action's document into the consumer and runs `--scan` there. Its `green` is the whole green line of a scan over the consumer holding `valid` alone, `bare_readme` that line with a README at the top. The items about a red run read stdout, where a scan prints its verdict, the finding and the count line two records of the log, and `F10` a third where the module names a skill. Each test is one item, `@item(<number>, <title>)` of `acceptance`; the module's red→green `Case` records, where it has them, are the rows of one parametrized `test_case`, each marked with its case's number and title. A shared item the `Subject` leaves out is collected and skipped, its reason naming the flag. The conftest's hooks call `acceptance.configure` and `acceptance.collected`, which stops the run before any test on a test without a number or a number two tests carry; the conftest names no plugin in `pytest_plugins`. One run collects one module's folder. `fake_program` starts a fake once before any clock; a gate `run_gate` starts asks git with no clock, save where a test's own `sitecustomize` keeps one. No item depends on the order the items run in, or on another's process: each builds its own consumer and leaves nothing behind, so a module's tests run in any order and side by side, though CI runs them one by one; a run with the collected tests shuffled by a seed, through a `pytest_collection_modifyitems` hook of the run's own, serial and with `-n auto`, three times each, is the proof a change to the fixtures keeps, held by review. The kit's gate list and CI run a module's tests only through `scripts/check-aspects.py`, never pytest itself, so they never select; `scripts/check-gate-lists.py` holds that their code lines, comments aside, name pytest only in an exact pin, pass no `--item` and name no `PYTEST_ADDOPTS`, and that no pytest configuration file at the kit root, in `modules/`, in a module's folder or its `tests/` sets `addopts`.
9. **The envelope's place.** A module that blanks, masks or rewrites the envelope asks `envelope_bounds` where it stands and cuts its lines with `envelope_lines`. It keeps no reading of its own of where the envelope opens or closes, or of where one of the envelope's lines ends.

## 3. Shared messages

Each row is the text of `constitution_layer_kit/messages.py` under that key, word for word — one function per sub-key (`c5_…`, `c12_…`, `g1_skip_…`), the row's handle being the table's, not the function's name. `{module}` is the namespace the entry point declared, other `{…}` are parameters. A configuration failure is one line that stands on its own — in hook mode only the first stderr line reaches the user (Claude Code 2.1.251, read 2026-09-18 to 2026-09-23) — followed by the count line `C11`.

<a id="g3a"></a>
A module's own message table takes a key of this table only to state its part of that message: the keys `G1`, `F9`, `F10`, `C1`, `C2`, `C5`, `C12`, `C14` and `C15`. A key means one thing in every module, so a key of this table never names another message in a module's table. The family of a key is its letters and its first number: the family of C5.a and of C5.10 is C5, the family of C4b is C4. A module's own key has a family that this table does not use. The kit's `scripts/check-handle-forms.py` holds that no other key of this table is taken, sub-keys included: a key of the module's table whose family is a family of this table, and not the family of a key this paragraph names, is a finding. Whether a module's row under an allowed key states that module's part of the message is left to review.

## 4. Shared honest limits

Every module that links this code has these limits and states its own beside them.

1. **Shell writes and other actors.** The gates judge `Write` and `Edit`, the members of `FileTool`. Survey of 2026-10-11, Claude Code 2.1.286: the tools reference lists `NotebookEdit` and the shells `Bash` and `PowerShell` beside them, and `MultiEdit` is in neither page. A matcher of only letters, digits, `_`, `-`, spaces, `,` and `|` is read as an exact string or a list of them, so the matcher `Write|Edit` of a gate that judges writes sends it no other tool. An event for another tool that does reach such a gate is a visible skip, `G1.1`. A shell, `Bash` or `PowerShell`, a heredoc, `sed -i`, a human's editor, a merge, another server's file tool: none is a `Write` or `Edit`, and the hook never sees it. The hooks documentation adds `tool_response.bashEditDiff` to a `PostToolUse` of `Bash` (Claude Code 2.1.269 or later) and calls the list best effort and in public beta. Backstop: the module's scan, on demand and in CI.
2. **A configuration failure, a timeout, and a hook that cannot start are non-blocking in hook mode.** Exit 1 shows the user the first stderr line and the write proceeds. The platform treats a hook past its timeout, or one whose script is missing, the same way (Claude Code 2.1.251, read 2026-09-18 to 2026-09-23). Backstop: the scan exits 1 with the same line, so CI turns red. The line lands in the output log.
3. **The link to this code may be dropped by an install.** Re-read 2026-09-23 against the platform's documentation, Claude Code 2.1.251. A marketplace install that copies the plugin into the plugin cache dereferences a link whose target lies elsewhere within the same marketplace — "the target's content is copied into the cache in its place" — while one leading outside the marketplace is skipped. The marketplace root is the directory holding `.claude-plugin/`, so `.claude-plugin/marketplace.json` at the kit root puts this code inside it. A plugin loaded in place — `--plugin-dir`, or a relative-path entry of a marketplace added from a local directory — is run from its source: its hook processes receive a plugin root that points at the source directory and read through the link there. Observed on Claude Code 2.1.282, 2026-10-01. Installing such an entry writes a copy into the plugin cache all the same, which the session does not run (research [res-0008-const-interaction](../docs/research/res-0008-const-interaction.md), p14). In that copy, on Claude Code 2.1.282, the link to this code arrives as a real directory — file links were recorded dereferenced there on 2026-09-25, this directory link observed 2026-10-01. An install from the marketplace's git remote, the copy a consumer's install writes, carries it the same way. Every run of the kit's CI holds that by `scripts/check-bare-install.py`, which installs each module from the change's GitHub repository and branch and is red on each way a link can fail to arrive (its docstring lists them). The one exception is the fixture runner's link to a package of the module's own (item 7 of [§2](#g2)): the install keeps a link that stays inside the plugin as a link — seen on 2026-10-07 in the kit's CI on Claude Code 2.1.282 and in an install from the working folder on 2.1.286 — and that link must arrive leading to that package in the copy. A project that registers a clone as its marketplace runs that clone in place, as a relative-path entry of a local folder runs above, seen on Claude Code 2.1.286 on 2026-10-07; one registered from the kit's GitHub repository runs the cache copy, which the install guide's check holds on every run of the kit's CI. The documentation's sentence that under `--plugin-dir` only symlinks that resolve within the plugin's own directory are preserved describes what a copy into the cache keeps; the kit reads it as a rule for a component path, and a script's own import through the link is none. On Claude Code 2.1.251 a plugin loaded with `--plugin-dir` resolves it (observed 2026-09-19 and in every live proof since). Backstop: `C15` — loud, exit 1, the same class as a missing library — with an absence fixture in every module; the kit gate on the links; `cp -RL` for a copy of a module's folder. Fallback: when the consumer-live proof, the two-install proof of the marketplace (step 10 of the [rollout plan](../docs/rollout-plan.md)), the kit's install check or a platform update shows the link skipped, kept as a link, or arrived with other files or bytes than its target in an installed copy, the links are replaced by copies and the kit's link gate by a gate on copy equality. No module code changes.
4. **`Edit` is reconstructed, not observed.** The edit is applied to the file on disk and the result judged. An absent `old_string` is a visible skip. An `old_string` occurring twice without `replace_all` is judged on its first occurrence though the tool will refuse the edit. An `Edit` of a missing file with an empty `old_string` is judged on what it creates, and one with an empty `old_string` on a file that exists is a visible skip, since it matches everywhere. Backstop: the tool's own refusal comes after the hook (Claude Code 2.1.251, read 2026-09-18 to 2026-09-23), and the next real write is judged again.
5. **Symbolic links in the consumer.** The written path is resolved before it is matched, so a territory that names only a link does not claim what is written through it. Backstop: territories over real paths; the scan lists files under the paths git records.
6. **A key given twice in an envelope.** YAML keeps the last one. Backstop: review.
7. **Markdown means `.md` — the name's ending, in any case, a file named just `.md` included, in the hook and in the scan alike; git-ignored files are invisible to the scan,** which lists tracked files and untracked ones git does not ignore. A tracked file deleted from the working tree is left out. A path holding a line break is examined, and every message shows the break escaped, `\n`, so each line stays one line. Backstop: the hook still judges such a file when it is written through the file tools. A module whose hook follows its dial skips a new file git ignores before the write too, as [`const-referencing`](../docs/requirements.md#const-referencing) does. A file git lists stays covered, whatever the ignore rules say of it.
8. **The envelope opens when the first line, leading byte-order marks aside, is `---`, and ends at the first later line that is `---`, trailing whitespace ignored on both**; a line ends only at `\n`, `\r\n` or a lone `\r`. Whitespace is what Python's `str.rstrip` strips, so a form feed or another break character after `---` is whitespace, while one before `---`, or one after it with text, makes no delimiter. A block scalar containing such a line truncates it. Backstop: the module reports the truncated envelope as invalid.
9. **Patterns match case-sensitively on every platform,** so one repository gets one verdict everywhere. Backstop: the scan sees a file under the case git records.
10. **The output log is best-effort evidence, not a gate.** A logging failure never changes a verdict, and neither does a failure of an advisory memo a module keeps beside the log: the module swallows that memo's read and write errors the same way, each said so at its place (gate-script rule 12 of [template §6](../module-template/MODULE.md#t6)). A configuration failure is two records — its BROKEN line and the closing line — and an unexpected one three, the traceback last, because the guard prints each apart. Should that trouble a reader, the remedy is a guard that prints once, never another unit of record. `C1`, `C14` and `C15` are printed and not logged, since no shared code runs to log them. Backstop: stdout and stderr remain the record.
11. **No `--help`,** and no abbreviated flags: `argparse`'s own help exits past the guard and the log. Backstop: any unknown argument is a misinvocation whose fix line is the usage.
12. **With two gates installed, the model sees one block message at a time** when both exit 2 (observed on Claude Code 2.1.251, 2026-09-19; the documentation is silent). Backstop: the next write is judged again; both findings are in the output logs.
13. **A negated pattern takes a file out of a territory only where git can re-include it:** not under a directory an earlier pattern excluded. `<dir>/**` followed by `!<dir>/README.md` works, since the file lies directly in the named directory. `!<dir>/sub/README.md` does not, and the file stays inside. Backstop: a territory of file patterns — `<dir>/**/*.md` — from which any file can be taken out. The shared item S148 shows the half that works, and the third module's own fixture shows both.
14. **A hook's text over 10,000 characters is replaced by a preview.** Read 2026-10-03 on the platform's hooks documentation, Claude Code 2.1.286 installed: the `additionalContext`, `systemMessage` and `initialUserMessage` strings of a hook, and its plain stdout, are capped at 10,000 characters, each string measured alone; over it the platform saves the whole text to a file and shows its path and a preview of the first 2,000 characters, and the cap has no setting. The two modules that can print many findings after a write, [`const-language`](../docs/requirements.md#const-language) and [`const-referencing`](../docs/requirements.md#const-referencing), show those that fit in `SHOWN_CHARACTERS`, 8,000, through `pipeline.within_the_cap`, so that the whole text stays under the platform's 10,000 and is not replaced by a preview; the count line and the closing note stand last and would be lost with it. The findings shown fit the 8,000, except the first, which is always shown; the notes and the count line are not counted in the 8,000. A value that only points is cut at 80 characters ([`echoed`](#g1)), but a value escaped whole — a path, an id typed into a fix, the text of a dial that teaches — is bounded by its source, not by 80: a dial's text or a document's text by nothing the gate holds, such as the plain word of [`const-language`](../docs/requirements.md#const-language) kept whole in the fix of its pair rule, or a link's fragment in R6 of [`const-referencing`](../docs/requirements.md#const-referencing). Such values reach `within_the_cap`, which runs after a write only. **Breaks:** one such first finding can alone pass the platform's 10,000, and `within_the_cap` still shows it, since it shows the first; the platform then replaces the whole text with a file path and a preview of its first 2,000 characters, and the count line and the closing note are lost with it. Before a write, [`const-referencing`](../docs/requirements.md#const-referencing) prints its R1 to R4 findings with no cut at all, so many of them, or a lane's `fix` kept whole, can pass the 10,000 there as well. Backstop: the count line says how many findings there are; the scan lists them all; a dial's text stays as short as it teaches, which covers a dial's text and not a link's fragment, whose length is the document's. Fallback: none needed.
15. **A dial's path is read with the platform's separator.** `root_policy`, `log_dir` and the paths a module reads — the `docs` paths of the `coverage` dial of [`const-task-close`](../docs/requirements.md#const-task-close), which trims each first, and the `template` paths of [`const-locations`](../docs/requirements.md#const-locations) — go through `dials.relative_path`: blank, absolute and leaving the repository by `..` are refused, `./` and `//` normalised, and `.` is accepted, the repository itself; a leading or trailing space is kept as part of the name for `root_policy`, `log_dir` and a `template` path of [`const-locations`](../docs/requirements.md#const-locations). A backslash separates only where the platform says so, so `..\x` leaves the repository on Windows and is one file name on macOS and Linux: one dials file, two verdicts on two machines — unlike a pattern, limit 9, which is read the same everywhere. Backstop: a path written with `/` reads alike everywhere.
16. **A hook run has one deadline, and every wait in it takes the smaller of its own cap and what is left.** The identity carries `hook_seconds`, 25 s by default (`HOOK_SECONDS`), which each module's gate, session-start printer or generator declares. In hook mode the guard starts one deadline for the run at that declaration (item 1 of [§2](#g2)). A scan, an act and a process declared with no mode have none. Every shared git call and every wait a module makes takes the smaller of its cap and what is left of the deadline. The shared git calls have a cap of `GIT_SECONDS`, 3 s each: `rev-parse --show-toplevel`, `ls-files`, `check-ignore`, the `Matcher`'s `init` and `check-ignore --no-index`, and every call a module makes through the function. The modules' own caps are the history read of [`const-catalogs`](../docs/requirements.md#const-catalogs), 5 s; the version probe, 5 s, and the run, 10 s, of the prose linter of [`const-language`](../docs/requirements.md#const-language); the version probe, 5 s, and the one budget for the reading, the masking and the run of the link checker of [`const-referencing`](../docs/requirements.md#const-referencing), 20 s. Where nothing is left when a wait is asked, the wait does not start. The run ends in the configuration failure `C12.14`, which names the budget and the wait it ended. It is non-blocking, as limit 2 says, and the count line follows it, so the user reads the gate's line and not the platform's notice for a hook cut at its timeout. A call that runs past its own 3 s is still `C12.12` for a call in the person's repository and `C12.13` for one in the `Matcher`'s scratch repository. A wait that the deadline shortened, given less than its cap, and that then runs out ends in `C12.14` too: a shared git call, the version probe and the run of the prose linter and of the link checker, and the link checker's budget. The tool's own line stands only for a wait given its whole cap. The history read of [`const-catalogs`](../docs/requirements.md#const-catalogs) is the exception: it is a git call outside the function, and an advisory wait, asked only after a verdict. It takes the smaller of its 5 s and what is left, by `left_of`, which never raises, with a clock of its own inside that number. A read that clock cuts ends in the working tree's answer, and so does a read asked when nothing is left, which starts no git, and neither is a failure, so that no verdict falls with its advice. In scan mode and in act mode the function gives git no clock, so a slow scan or a slow move is waited for as long as it takes, and the scan checks the tree a hook gave up on. The version probes of the two tools keep their cap of 5 s in every mode, and their runs have no limit in a scan. A process declared with no mode, as a test runner declares, has no clock and no deadline. **What the deadline does not hold:** the interpreter's start and the reads before the declaration, the reading of the event on standard input, and a wait that takes no number from the clock, of which there is none in hook mode today. A healthy git slower than 3 s in a hook, as on a very large repository, gives the `C12.12` line in place of a late verdict. A process git started, a `core.fsmonitor` hook, may outlive the git the timeout kills. Two ties hold the numbers. Every handler of a module's hooks file — a gate's or a session-start printer's — whose `command` names `python3`, or whose script names it, has a timeout of at least `hook_seconds` plus `LEFT_FOR_THE_REST`, 5 s: the margin for the interpreter's start, which the deadline does not count, and for the reads after the last wait. So a run that spends its deadline ends with the shared line before the platform cuts the hook. S165 holds it, reading the budget the gate declares. A handler's script is each `args` entry that is no option, an option being an entry that starts with `-`, and each word of its `command` that lies under the plugin's folder or is an existing file. A script that cannot be read counts as one that names `python3`. A handler that names no `python3` is not held to the timeout. The other tie: each module's own waits in one hook run fit its `hook_seconds`, held by the module's own item: item 77 of [`const-catalogs`](../docs/requirements.md#const-catalogs), item 16 of [`const-language`](../docs/requirements.md#const-language) and item 70 of [`const-referencing`](../docs/requirements.md#const-referencing). Facts, read 2026-10-08 with git 2.54.0, Python 3.12.4 and Python 3.14.8. A `core.fsmonitor` hook ran on `ls-files`, `check-ignore -q` and `status --porcelain`, never on `rev-parse --show-toplevel` or on the `Matcher`'s `init` and `check-ignore --no-index`. A hung hook of that kind, set in a repository's or a person's configuration, therefore hangs the call that lists the files, and a stalled file system can hang any call. A `subprocess.run` timeout of 1 s raised `TimeoutExpired` at 1.01 s on both interpreters while the hook still ran; the hook ended by itself and no process was left. Backstop: the scan; the lines name the scan, the setting to find and, for `C12.12`, the call to run by hand; S165 and S167.
