# The gate-script rules

**Gate-script rules** *(template rule)* (decision [dec-0020-gate-script-rules](../docs/decisions/dec-0020-gate-script-rules.md)) — every Python script a module ships follows all sixteen; the fresh-context validation checks them:

1. <a id="r1"></a>**Shape.** The entry point is a thin file. Past about 300 lines of logic, or with a second entry point, the code is a package directory beside it, imported with no path manipulation — Python puts the script's directory on the import path. What every gate shares is not written again: it is the Python package `constitution_layer_kit`, which pip installs from the distribution `constitution-layer-kit` and the plugin never carries, the module fills the interface of [kit-shared-gate-code §2](../shared/GATE.md#g2), and the Python entry file states `REQUIRES`, the release of the package it needs, turns a package it cannot import into its designed configuration failure, `C15`, and calls `cli.version_failure` right after it imports `cli` (R5 and R7 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r5)). Never a sibling-script import and never a `sys.path` edit of the script's own process, the fixtures included: the tests import the shared package and the module's own packages through links in `tests/` (item 7 of [kit-shared-gate-code §2](../shared/GATE.md#g2)), and a child process a test starts may be given its own path (item 8 there). A package or shared test file the tests import this way uses `__file__` only as `Path(__file__).resolve()` and derives every path from that, since through a link `__file__` is the link's path, not the file's; the kit's `scripts/check-resolved-paths.py` holds it. Package and module names are snake_case because the language requires identifiers; entry-point files stay kebab-case.
2. <a id="r2"></a>**Messages.** One messages module per package: the shared package's, and the module's own for its findings, skip reasons, notes and dial failures. Each message is a function with typed parameters returning its three parts — what failed, why the rule exists, the exact fix — under the key it carries in [the error-message table of §6 of the module template](MODULE.md#t6).
3. <a id="r3"></a>**One exit.** `main(argv) -> int`, a single `sys.exit`, and one guard that maps the configuration exception to exit 1. The entry file's exits before the module's own package can be imported — the interpreter floor, a shared package that cannot be imported (`C15`) or whose release does not serve the module (`C16` and `C17`, found right after `cli` is imported) — are the only others, each printing its designed line and the count line; a generator's entry file prints its own closing line in the count line's place, and its variants of those lines drop the clause about unchecked writes; a grant's entry file does the same.
4. <a id="r4"></a>**Exit codes.** Named constants: 0 green, 2 finding, 1 configuration failure. Parameters are parsed with `argparse`, whose exit-2 default on bad usage is overridden to 1.
5. <a id="r5"></a>**Separation.** Parsing, checking, and reporting are separate functions; a check is a function of typed inputs.
6. <a id="r6"></a>**Runtime.** Plain `python3` through the POSIX entry point, never `uv run`. Floor: Python 3.12, the value of `FLOOR` in the shared preflight. The interpreter version and every declared library are preflighted on each invocation, before any verdict is printed; a grant is the one exception: it runs the library preflight once a call is its own command, before its answer, and runs it for no other call.
7. <a id="r7"></a>**Dependencies.** Unrestricted, but declared in `requirements.txt` at the plugin root; the configuration-failure message prints the one install command for that file. The shared package is the one exception: it is no entry of that file, and its failure names the module's `INSTALL.md`, which gives the pip command at the tag of `REQUIRES` (R15 and R16 of [dec-0099-shared-code-installed-as-a-pip-package](../docs/decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r15)). `yaml.safe_load` only.
8. <a id="r8"></a>**No fail-open.** An unexpected exception exits 1 with its traceback; unparseable hook input is a configuration failure; nothing exits 0 on error. An advisory script may fail open and says so in its docstring.
9. <a id="r9"></a>**Types.** Every parameter and return is annotated. Untyped data — JSON, YAML — is parsed once into dataclasses; no bare `dict`, `list` or `Any` crosses a function boundary; closed vocabularies are enums. `mypy --strict` is clean.
10. <a id="r10"></a>**Docstring contract.** The entry point's docstring states the hook events, the modes, the input fields read, the exit codes, the output channels, and the dial keys read.
11. <a id="r11"></a>**Hook wiring.** `hooks.json` uses the exec form (`command` plus `args`) wherever a path placeholder appears, with an explicit `timeout`.
12. <a id="r12"></a>**Output log.** Everything a gate prints is also appended to a log, one JSON line per print: timestamp, module, gate, mode, session, path, transcript, stream, text — a text of several lines, a verdict or a traceback, stays one record, never a line apiece, its newlines escaped by JSON. `path` is the file the hook's event names, as the payload gives it, or the shell tool's command, and `transcript` the session's transcript the payload names; a field the run has nothing for stays empty: `path` for a `Stop`, both for a scan (R2 of [dec-0114-module-effect-report-design](../docs/decisions/dec-0114-module-effect-report-design.md#r2)). The records of a run whose log is written, each text followed by a newline, rebuild what was printed on each stream exactly, save a character the stream could not encode, which the stream shows escaped and the record keeps (decision [dec-0038-log-record-per-print](../docs/decisions/dec-0038-log-record-per-print.md)). Location: the fixed dial `log_dir` ([§7 of the module template](MODULE.md#t7)) when set — repository-relative and verified git-ignored, otherwise a configuration failure; else `${CLAUDE_PLUGIN_DATA}`; else nowhere, and stdout is the record. A grant reads no dials file, so its log is `${CLAUDE_PLUGIN_DATA}`, else nowhere. The log rotates at a fixed size, holds only what was printed, and a logging failure never changes the verdict — the one error a gate swallows, and the code says so, save that a gate keeping an advisory memo beside its log, which no verdict reads, swallows that memo's read and write failures the same way, each said so at its place. It is built on the standard library's `logging`, not a hand-made tee (decision [dec-0022-output-log-through-logging](../docs/decisions/dec-0022-output-log-through-logging.md)): a `RotatingFileHandler` behind a `MemoryHandler` that holds records until the location is known, with three cautions — the logger is named and does not propagate, so no other library's line reaches stdout or stderr, which in hook mode are a protocol; the stream is the caller's choice and the level only carries it; `logging.raiseExceptions` is switched off, because its default prints a traceback to stderr, whose first line is what the user sees.
13. <a id="r13"></a>**Paths.** The target path comes from the tool input, resolved against the event's `cwd`; a path escaping the repository is a visible skip.
14. <a id="r14"></a>**Fixtures.** pytest tests in `tests/test_<name>.py`, each an item `@item(<number>, <title>)`, numbered as in [§10 of the module template](MODULE.md#t10), the module's own from 1 and the shared acceptance items, brought into the run by `tests/test_shared_items.py` from `constitution_layer_kit.testing.items` and run through the module's own entry point, from 101, one number per item, a number two tests carry stopping the run before any test. A case record — number, title, red, green, the message red must teach — drives the real entry point with real hook events and fails when red does not fire or does not teach the expected message, or green still fails. A property with no failing half is a plain test. Every message the module's code can print stands, in the fixtures that run it, at least once as a line typed by hand — its fixed text written out, a value the test computes filled in — since an expectation built by the message's own function cannot catch a defect in that function's text; a shared message stands so in the shared items or in the fixtures of a module that runs it. The fresh-context review holds this, with the kit's `scripts/list-message-literals.py`, never shipped in a module, as its aid: it reads the messages modules, where rule 2 puts every message, lists each message function with no piece of its fixed text, 15 characters or more, typed in a fixture that runs it — for a shared message, the shared harness included — and lists apart those whose text is too short to find — a list for the review to judge and never a verdict. YAML fixture documents are rendered by the dumper, never typed as strings, unless malformed text is the point.
15. <a id="r15"></a>**Absence fixtures.** Every external tool or library the gate needs has a fixture simulating its absence; the shared items cover the interpreter, git, PyYAML and the shared package itself, and a module adds one for anything more it needs.
16. <a id="r16"></a>**Imports at the top.** Every import stands at the top of its module, where a reader, the type checker and the preflight see the dependency; none inside a function or a method, unless it is explicitly necessary — and then the reason is written at the import, beside the marker that silences the check, `# noqa: PLC0415`. Today there are three such cases, of one kind: a module's two modes, a generator's acts, and a session-start printer's pipeline and dials, are imported after the preflight, because only then does a missing library become its designed message instead of a traceback. An entry file imports `cli` of the shared package at module level after the floor check, inside the guard that prints `C15`, and the module's own package after the version check that `cli` makes (item 6 of [kit-shared-gate-code §2](../shared/GATE.md#g2)), for the same reason; each of these imports carries the marker `# noqa: E402`. A call of `importlib.import_module` made on purpose — the preflight's own — is one the tool does not see; review holds it. The kit's tooling holds the rule: `ruff` rule `PLC0415` (decision [dec-0026-imports-at-the-top](../docs/decisions/dec-0026-imports-at-the-top.md)).
