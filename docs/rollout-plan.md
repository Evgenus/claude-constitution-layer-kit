# Constitution Rollout — Actionable Plan

*The kit's own write-head ([kernel §2](../kernel/CONVENTIONS.md#k2)): the phases and their sequence, its lifecycle as [rule 1 of plc-0008-rollout-plan](policies/plc-0008-rollout-plan.md#r1) has it. What a module must implement lives in [constitution-requirements](requirements.md), the traceability matrix and module specifications. Nothing here is a requirement or a ruling.*

*Working rule throughout: author against real files, extract when proven, install everywhere else. No module is designed against imagined content.*

<a id="phase-a"></a>
## Phase A — Kit as consumer zero: the document-shaped accumulating modules (~1 week)

*Accumulating failures compound with every unguarded artifact, so their modules exist before the first consumer document does (decision [dec-0006-accumulating-set-first](decisions/dec-0006-accumulating-set-first.md)). Four of the six have their objects in this repository already — envelopes, decision records, cross-references, a numbered kind — and are authored here against real files. The fifth and the sixth, [`const-locations`](requirements.md#const-locations) and [`const-task-close`](requirements.md#const-task-close), followed them here from Phase C. The kit is consumer zero for the kinds it creates and for the code territories its own current-state documents describe (records [dec-0035-locations-module-rulings](decisions/dec-0035-locations-module-rulings.md), [dec-0036-task-close-module-rulings](decisions/dec-0036-task-close-module-rulings.md)).*

<a id="phase-b"></a>
## Phase B — Bootstrap the consumer project (~1 hour)

5. <a id="s5"></a>In the project: copy `kernel/` to `docs/constitution/`. Write a root policy and one policy per document kind under `docs/policies/` — at least a kernel policy for `docs/constitution/**` and a decision-record policy for `docs/decisions/**`. They are written for the project; the kit's policies under `docs/policies/` are examples to read, not to copy — policies are consumer content, never kernel, never module. Write `constitution.yaml` at the root with `root_policy` and each policy's territory under its id, `docs/policies/**` for the root ([kernel §3](../kernel/CONVENTIONS.md#k3)). Load the modules authored in the kit by then — the four of Phase A, [`const-locations`](requirements.md#const-locations), [`const-task-close`](requirements.md#const-task-close), [`const-questions`](requirements.md#const-questions), [`const-interaction`](requirements.md#const-interaction), [`const-styling`](requirements.md#const-styling), [`const-language`](requirements.md#const-language) and [`const-doc-budgets`](requirements.md#const-doc-budgets) — from the kit path from the first commit, so no governed document is ever written unguarded. This is each module's consumer-live proof, the second stage of [CLAUDE.md](../CLAUDE.md) step 5. Run the scan of each module that ships one against the project, its runner on the throwaway repository it builds, and the live item each module's document defers to this step — [`const-meta-types`](../modules/const-meta-types/MODULE.md#t10) T54, [`const-decision-records`](../modules/const-decision-records/MODULE.md#t10) T55, [`const-catalogs`](../modules/const-catalogs/MODULE.md#t10) L5, [`const-locations`](../modules/const-locations/MODULE.md#t10) V3, [`const-referencing`](../modules/const-referencing/MODULE.md#t10) L4, [`const-task-close`](../modules/const-task-close/MODULE.md#t10) L4, [`const-questions`](../modules/const-questions/MODULE.md#t10) L4, [`const-interaction`](../modules/const-interaction/MODULE.md#t10) L4, [`const-styling`](../modules/const-styling/MODULE.md#t10) L4, [`const-language`](../modules/const-language/MODULE.md#t10) L4, [`const-doc-budgets`](../modules/const-doc-budgets/MODULE.md#t10) L4. <a id="phase-e"></a>
## Phase E — Steady state

Friction in a project → commit note → recurring notes on one theme → module authored or amended in the kit → version bump → projects update. That is the principle [p2 of the intent page](../INTENT.md#p2), and, for a document of a kind no policy governs yet, [rule 5 of plc-0001-root-policy](policies/plc-0001-root-policy.md#r5). Onboarding = clone, install, read one page of `CONVENTIONS.md`.
