# A file the gate cannot reach and an interrupt are said, the same on every interpreter

The carry audit of items 9.42 and 9.43 of the rollout plan left two gaps of the shared gate code as stated limits. The decider picked on 2026-11-14, in the orchestrating session's chat, to close both before the release. On 2026-11-16, in the same chat, the decider picked to fix two more of the audit's findings in this wave. They are a working folder the system will not name, and a `.git` nobody can read, past which git's own search goes on upward. Both are the same on main, and the wave's rule would have stated them. All of it is item 9.44.

## 1. A file git lists that the gate cannot reach

The shared listing kept a path git lists only where `Path.is_file` held. Under a folder nobody may search, that call raises on the older interpreters the kit supports and returns False on later ones. So on the older ones a scan printed C12.11, the defect line of the shared code. On the later ones it passed the file over without a word. It could end green on a document it never read. The mention listing of [`const-referencing`](../requirements.md#const-referencing) had the same shape. No real choice existed: the verdict must not hang on the interpreter, and a silent skip is never a verdict.

<a id="r1"></a>**R1.** A path git lists is a file when `os.stat` says so, through any link. As before, what `Path.is_file` reads as absent on every interpreter is absent. That is a path that is gone, a path behind a file, a link that leads nowhere or loops, and a bad file descriptor. Any other error of `os.stat` is the shared C12.10, on every interpreter. That includes a name too long for the system, where the system does not first answer that a folder is missing. The shared functions are `repository.stat_or_none` and `repository.listed_file`, and the shared listing uses them. The dials file is asked the same way. A dials file linked into a folder nobody may search is the shared C12.7, never an absent file. A link that leads nowhere is still no dials file. The shared effect entry asks each plugin's entry the same way. One it cannot reach is the shared U6.4, a note after the headline, and is not run. The shared `repository.reached` makes any error but absent the shared C12.16, which names the path. Modules [`const-catalogs`](../requirements.md#const-catalogs) and [`const-change-cost`](../requirements.md#const-change-cost) ask the same way for the written file, the run's folder, the recorded data folder, and each transcript the count reads. A folder of transcripts the count cannot list is C12.16 too. Each line of this record that carries the system's reason in brackets and teaches a fix has one fix. It is to repair what the brackets name. That reason may lie in a folder above the path, or above the target of a link on it. Those lines are C12.7, C12.10, C12.16 and the mover's refusal of R2. The note U6.4 teaches none, and the mover's line of folders left teaches its own `rmdir`. So the fix is true for every reason the system can give. A reader that keeps no reason prints C12.10 without brackets, and its fix asks the reader to read the file for the reason. The shared walk up to a repository, `repository.stand_in` in `repo_root`, goes up only past a path that is absent or no folder. A folder it cannot search is the shared C12.16 in a scan and a hook alike. That is the path asked about or one above it. So is any other error but absent on the way, a name too long among them. The line names the path as the walk's caller resolved it. So the walk never stands in a repository above it, whose verdict is not this tree's. Before, a hook's write behind such a folder was C12.11 on every interpreter. On the earlier ones the walk's first question raised behind it, and on the later ones git could not run where the walk stopped. A scan's start below such a folder was C12.11 on the earlier ones and C12.6 on the later ones. The scan's own start is asked by `reached` too. Git's own search answers first, as before; the kit makes no search of its own. Where git names a repository above a start spelled as the disk spells it, `repository.ask_passed_over` asks each `.git` git passed over on the way up. It asks a folder's `HEAD`, and opens a regular file; nothing else is opened. One whose `HEAD` the system refuses is C12.16 naming it, never that repository's verdict. Anything else is git's to judge, objects or refs it cannot read among them. The ask is a guard after git's search, and no copy of git's rules. It reads no device number, and asks nothing where `GIT_DIR` or `GIT_WORK_TREE` is set, by their presence alone. Where git names no repository, or the kit cannot tell that git searched, nothing is asked, and the lines are as before. So where a repository lies above an unreadable `.git`, the line is the stated failure. Where none lies above, git's own answer stands as on main, since no other repository's verdict can stand in. That is "not inside a repository" for a `.git` folder, and git's own failure for a gitfile. The orchestrating session shaped this scope after the audit's probe of the first design. No pick on it was asked of the decider beforehand, and it is part of the decider's yes on the change. The shared code asks the working folder in one place, `repository.working_folder`. Where the system will not name it, that is C12.16 naming the working folder. A module's own ask that the system refuses reaches the guard as an unexpected exception. The guard prints C12.16 in place of C12.11 where an OSError names no file and the system refuses that folder with its number. It cannot tell that refusal from another such OSError. The traceback stands after the closing line, or after C12.15 where an interrupt cut the closing line short.

<a id="r2"></a>**R2.** The mention listing of `const-referencing` uses the shared `listed_file`, and keeps no copy of its own. So the module requires the release 2.6.0 of the shared package. The listing asks whether a path is a link before anything else, and a link is never read, wherever it leads. A file it can reach and cannot read is still passed over, as before. The mover asks the paths it was given the same way, by `stat_or_none`. Those are the old path and the new path, and in a move the folders above the new one. That holds for a move and for `--moved`. One it cannot reach is a refusal of its own, V5, that names the path and the system's reason. A Markdown old path that git still lists, behind such a folder, meets the shared listing's C12.10 first. It is never read as absent, so `--moved` never goes on as if the old file were gone.

## 2. An interrupt

The shared guard caught no interrupt. After Ctrl-C an entry printed a traceback and no closing line, and the process ended by the signal. The mover of `const-referencing` then left five states unsaid. An interrupt in the plan moved the file back, but no line said so. If git then refused the move back, no line said where the file was. One during the writes printed no midway line. One while git moved the file, or moved it back, could leave the file moved or the made folders standing.

- **A. The shared guard alone.** It catches the interrupt and prints a line and the entry's closing line.
  - **Pros:** every entry of every module closes the same way; the closing line of the mover already knows the plan and the writes.
  - **Cons:** an interrupt that lands on a `git mv` leaves the move done or not, and no closing line can know which.
- **B. The mover's own entry alone.** The mover catches the interrupt and settles its own state.
  - **Pros:** the one act that changes files says exactly what was done.
  - **Cons:** every other entry still ends in a traceback.
- **C. Both.** The guard gives every entry its line, and the mover says the moments only it knows.
  - **Pros:** every entry closes, and the mover's state is said at each moment.
  - **Cons:** two places to keep; the mover asks git's index and the disk, more calls at each interrupt.

The writing session recommended C, because each layer closes what only it can. It follows the decider's standing lean to ask the thing itself rather than model it. The mover asks git's index and the disk where the file is. The orchestrating session shaped C by the rules it set while it routed the audit's findings. No pick of these options was asked of the decider beforehand. The decider's pick of 2026-11-14, to close both gaps before the release, is why the work came first. C was taken. The choice is the decider's yes on the change, named in the merge commit of the wave's pull request.

<a id="r3"></a>**R3.** The shared guard catches an interrupt raised while the entry's body runs. It prints the new shared line C12.15, whose text stands true with no line below it. The guard makes no claim of its own about what was done by then. It prints an entry's own line after C12.15 only where the entry's closing callable carries `interrupted`, a line made from the entry's own state. An empty line is not printed. The failure closing line is not reused. The guard then flushes, restores the default action of the interrupt and sends it to the process itself. So the process dies by the interrupt, as Python does for one nobody caught, and a shell shows 130. Where the shell got the interrupt too, as a terminal's Ctrl-C sends it to the whole group, its loop over the entry stops. Where the signal does not end the process, the exit is 130.

<a id="r4"></a>**R4.** The mover's closing carries such a line. An interrupt in the plan still moves the file back. Anywhere else the mover settles nothing, since an interrupt can land between any two statements. A failure's line is made the same way, and says git's own move back where the tree agrees. Where git refused the move back, an interrupt's line gives git's words too. Once the closing scan is about to print its verdict, the line says only that the verdict may stand above or be missing. Its line is made from what it observes when the guard asks for it. It asks where git's index and the disk hold the file, by its exact name, and which folders of the move stand. Git reads each path it is given literally, in the mover's own asks and in each command the line teaches. The paths of the move, and the folders it would make, are named to the line before the move begins. No look at the tree can tell whether a document was rewritten. So a flag says it, set before the first write opens. A document that may have been opened for its rewrite is named, as one that may be cut short or empty. The line says how git gives its text back where git's index holds it, and that it may be lost where the index does not. For a document that is a link, git is asked of the file the rewrite went into, and the restore names that file. Where the file stands at the new path and no rewrite can have begun, the line teaches the undo. It does not where git refused the move back. It teaches the finish by `--moved` only where the system says the old path is gone. Where the system refuses to say, it teaches neither. Where a rewrite may have begun, it teaches neither, and names the scan and git status. A command is printed only where each path it gives from where the mover ran prints as itself. Else the line names the path and says why no command is given. The index and the disk can disagree, or an interrupt can land while the line is made. Then the line says the file may stand at either path. It names both, git status and the scan, and teaches no command for the move. A file in a folder that can be searched and not listed is asked by its name alone. That cannot show its case, so the line says the same. An interrupt while a failure's closing line is made reaches the guard. That closing line is not printed. The guard prints C12.15 after the failure's first line, then the mover's line for the interrupt.

<a id="r5"></a>**R5.** An interrupt the guard does not catch ends in the interpreter's own traceback, and the process dies by it. Such an interrupt can come before the guard opens, for example while the entry file imports the shared package. Or it can come while the guard writes its lines or the log. A second interrupt while C12.15 is written is one of them, and the lines printed before it stand above the traceback. An interrupt while the mover makes its line for an interrupt is the mover's, as R4 says. A signal of another kind that ends the process prints no line of the kit. The shared limit 19 and limit 12 of `const-referencing` say so.

<a id="r6"></a>**R6.** R3 and R4 reverse the clause "save after an interrupt" in R6 of [dec-0135-mover-refuses-an-unwritable-document](dec-0135-mover-refuses-an-unwritable-document.md#r6). R4 also narrows two other clauses of that R6. A folder left after a failure's move back is named with the system's reason, and no midway line follows, since nothing else changed. A move back git refuses is said where the tree shows the file at the new path. Where nobody can say, the line says the file may stand at either path. What the mover's line now says is ruled in R4 and R5.

## 3. The end by an interrupt in the entries' texts

The end by an interrupt is the shared guard's, the same for every entry of every module. The item "the docstring as contract" of [dec-0020-gate-script-rules](dec-0020-gate-script-rules.md) has an entry's docstring state its exit codes. Thirty-four entry files and twelve module documents state them.

- **A. One statement.** [rule 4 of the gate-script rules](../../module-template/gate-script-rules.md#r4) states the end by an interrupt, and rule 10 says the entries need not repeat it.
  - **Pros:** one text to keep true, as [law 1 of CLAUDE.md](../../CLAUDE.md#law-1) asks: duplication is a defect.
  - **Cons:** an entry's docstring no longer names every way its process can end.
- **B. A line in every entry.** Each Exit docstring and each module's line of exit codes names the end by an interrupt.
  - **Pros:** each docstring stays a full contract.
  - **Cons:** forty-six copies of one shared fact, each to keep true at every change of the guard.

The orchestrating session recommended A on 2026-11-15, by [law 1 of CLAUDE.md](../../CLAUDE.md#law-1). No pick was asked of the decider beforehand. A was taken. The choice is the decider's yes on the change, named in the merge commit of the wave's pull request.

<a id="r7"></a>**R7.** The end by an interrupt is the shared guard's, the same for every entry file of a module. It is stated for every entry in [rule 4 of the gate-script rules](../../module-template/gate-script-rules.md#r4), which points at the shared page's limit 19. An entry's Exit docstring and its module's line of exit codes state the entry's own exit codes, and need not repeat that end. This narrows, for that one end, the item "the docstring as contract" of [dec-0020-gate-script-rules](dec-0020-gate-script-rules.md). Rule 10 of the gate-script rules spells that item out, the exit codes among it. That item's other demands stand, and so does the rest of that record.
