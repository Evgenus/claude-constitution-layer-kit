## 1. The always-on carrier ([requirement A7.1](../requirements.md#a7-1) to [requirement A7.5](../requirements.md#a7-5), [requirement A10.2](../requirements.md#a10-2))

Six rules that govern every reply, with no trigger — unlike the sibling's asking rules, which a decision triggers (a3 of res-0007-const-questions). Four carriers:

- a1. **A `SessionStart` hook printing the rules.** "For most events, Claude Code writes stdout to the debug log and doesn't show it in the transcript. The exceptions are `UserPromptSubmit`, `UserPromptExpansion`, `SessionStart`, and `PostModelSwitch`, where Claude Code adds plain-text stdout as context that Claude can see and act on." Matchers `startup`, `resume`, `clear`, `compact` ("Auto or manual compaction"), `fork` (was `resume` before v2.1.214). The text is "injected as a system reminder that starts with the hook's name"; "Neither channel produces a visible transcript entry": the model sees it, the user does not. "Plain stdout is measured whole" against a 10,000-character cap, above which the text goes to a file with a 2,000-character preview; "this cap has no setting or environment variable to raise it". At launch the hooks run in the background and "Claude's first response still waits for the hooks to finish". Cost: the rules' characters per session and per compaction.
- a2. **Live, the hook (E2).** A plugin with one `SessionStart` hook, `cat "${CLAUDE_PLUGIN_ROOT}/rules.txt"`, 1,187 characters of six numbered rules; the yes/no prompt "Can we ship the current Unreleased changes as a patch release, 1.4.3? Yes or no." on a repository whose changelog renames a response field. The reply: "No." first, the changelog entries numbered, options lettered a–c, an "Assumptions:" block of two lines — semantic versioning, external clients.
- a3. **Live, the control (E1).** No plugin, the same prompt: "No." first — this model leads with the word unprompted — two unhandled bullets, and the two assumptions of a2 asserted silently. The specification's failure half reproduced: the shape held, the assumption line and the handles did not.
- a4. **Two plugins' lines stack (E6).** Two plugins each with a `SessionStart` hook — the rules, and one line "ix-second: no command is gated — the pattern dial is empty." — in one session: two `hook_response` events, and the model quoted both first lines on request. The visible zero of an off-by-default module, asked for by the audit of 2026-09-22, costs its one line, 61 characters here, and stacks.
- a5. **The three claims of 2026-09-14.** (i) "Claude Code doesn't load a `CLAUDE.md` at the plugin root" ([plugin components](https://code.claude.com/docs/en/plugins/components)); E2's plugin carried one asking for a token, and no reply contains it. (ii) The memory page allows an `@` import "relative and absolute paths" and names no variable; E7, importing `@${CLAUDE_PLUGIN_ROOT}/rules.txt`, answered `IMPORT-NONE`, E7b, importing `@rules.txt`, `IMPORT-OK-9182`. (iii) "A plugin's root path changes with every version" ([plugin loading](https://code.claude.com/docs/en/plugins/loading)). All three stand.
- a6. **An output style shipped by the plugin.** "A plugin can include output styles … Save each output style as `output-styles/<name>.md`" (plugin components). `force-for-plugin`: "Plugin output styles only. Set to `true` to apply this style automatically whenever the plugin is enabled, without requiring users to select it. Overrides the user's `outputStyle` setting. If multiple enabled plugins set this, Claude Code uses the first one loaded" ([output styles](https://code.claude.com/docs/en/output-styles)); `keep-coding-instructions: true` keeps the platform's engineering instructions, default `false`. A style is "fixed at session start" (changelog 2.1.73). Cost: the same order as a1, in a cached position.
- a7. **Live, the style (E3).** The rules as a style with both fields `true`: the reply of E2's shape — "No.", entries 1–2, options a–c, the same two assumption lines. `init` reported `output_style: default` all the same.
- a8. **What the style costs that the hook does not.** One slot: a second plugin's forced style, or the user's own, loses silently; the platform's channel for voice is taken by a governance module. The hook stacks (a4), overrides nothing, and survives compaction by re-running.
- a9. **A skill with a trigger description.** The sibling's carrier: description always in context (cap 1,536 characters), body on invocation. Rules with no trigger would fire on "about to reply", every turn — the description becomes the content and the body is never reached. Cannot carry these rows by construction; not run.
- a10. **The consumer's own copy.** The kit today: five bullets of the "Session conduct" block of [CLAUDE.md](../../CLAUDE.md), corrected in place across sessions; a module ships at most one pointer line in `INSTALL.md`, and a copy drifts on every version bump.
- a11. **What no carrier reaches.** Rules in context do not make every reply match; the friction the module absorbs is the assumption line and the handles (a3), which the carrier produced (a2, a7). [Requirement A7.4](../requirements.md#a7-4) and [requirement A10.2](../requirements.md#a10-2) were not exercised by a run and stay honestly ungateable.

Mechanism class: a1 a hook carrying prose; a6 a system-prompt slot; a9 skill prose; a10 memory. Maturity: all documented, `force-for-plugin` on its page only. Cost: a1 and a6 the same characters; a1 stacks, a6 does not.

**Recommendation: the `SessionStart` hook, no matcher so every source fires, printing the six rules in about 1,200 characters, declared advisory; the output style not shipped, recorded as the stronger single-slot carrier; CONFIRMED as advisory for every row of this section.** Sizes in characters ([law 8 of CLAUDE.md](../../CLAUDE.md#law-8)): 1,187 measured, the visible-zero line 61. For the decider: whether the module also ships the style unforced, selectable under its plugin name at no cost while unselected; and whether `INSTALL.md` offers the copy-into-guide fallback.

## 2. The optional gate-lite of [requirement A7.5](../requirements.md#a7-5)

A script flagging unnumbered multi-item lists in governed documents, priced on the kit's tree (E12):

- b1. **The measurement.** 237 Markdown files at `cc16087`, 215 top-level lists of two or more `- ` items outside fences, read by a counter accepting a leading anchor, a bold marker and a handle of the kit's forms — `1.`, `A.`, `a1.`, `R1`, `S137`, `Q-a` — before the first punctuation: 150 handled, 65 not. Of the 65: 16 are Pro/Con pairs under a lettered option, handled by their parent; 18 open with a bold label ("**Always-on content:**"); 18 open with a link or a code span that is the item's key; 13 are plain.
- b2. **Three examples.** The reading list of [CLAUDE.md](../../CLAUDE.md), eight items keyed by file name; the "Session conduct" block of the same file, thirteen items, the rule's own home, keyed by nothing but a bold lead in some; the `R1`–`R12` items of [dec-0005-reference-forms](../decisions/dec-0005-reference-forms.md), each behind an anchor, which a naive reader counts as unhandled.
- b3. **What a scan can decide.** That an item opens with a token of a closed handle grammar; not that a bold label, a file name or a link is a stable key, which the rule allows. On this tree the honest rate is 13 to 65 in 215, and the kit's own guide would be red at the rule's own list.
- b4. **Shape, should it ship.** A `--scan`-only check on the shared code over an own `territories` dial and a `handles` dial of regular expressions defaulting to the six forms of b1, a finding per list, fences never counted.
- b5. **Friction.** No consumer has cited an item it could not name. R3 of [dec-0041-questions-module-rulings](../decisions/dec-0041-questions-module-rulings.md) shipped its slice at zero measured friction because its claim was narrow; this one's is not (b3).

Mechanism class: a deterministic scan, gate-lite; maturity: trivial on the shared code; cost: a false-positive rate the consumer tunes by a grammar dial.

**Recommendation: not shipped at this version; the rule stays on the carrier — CONFIRMED as advisory, the slice priced and recorded (b4) for the decider, who has twice chosen to ship such a slice when cheap.** For the decider: ship with the grammar of b1 as a dial and the kit's guide exempted by territory, or wait for a consumer's note about an unaddressable item.

## 4. The gate: a `PreToolUse` hook on `Bash` ([requirement A8.3](../requirements.md#a8-3))

- d1. **The input.** `PreToolUse` "Runs after Claude creates tool parameters and before processing the tool call"; the hook receives `tool_name`, `tool_input`, `tool_use_id`, `cwd`, `permission_mode`; for `Bash`, `tool_input` carries `command`, `description`, `timeout`, `run_in_background` (every saved payload of E4–E11).
- d2. **The `if` field.** Added in 2.1.85 ("conditional `if` field for hooks using permission rule syntax (e.g., `Bash(git *)`)"), fixed for compound commands and `VAR=` prefixes in 2.1.89, for `$()` in 2.1.243. "The `if` field holds exactly one permission rule." "Because the `if` filter is best-effort, use the permission system rather than a hook to enforce a hard allow or deny." What a rule does not match ([permissions](https://code.claude.com/docs/en/permissions)): `Bash(git push *)` "Doesn't stop" `git -C . push origin main`, `git -c push.default=current push origin main`, `git 'push' origin main`; `Bash(rm *)` not `/bin/rm` nor `bash -c 'rm -rf build/'`.
- d3. **Live, the filter bypassed (E9).** `if: "Bash(git push *)"` and the prompt to run `git -C . push --force origin main`: no `hook_started` event; the push ran. The same command with the `if` removed (E10): the hook ran. An `if` is a hole the size of the permission grammar's blind spots; the gate runs on every `Bash` call and tokenises the command itself.
- d4. **The decision values.** `hookSpecificOutput.permissionDecision`: `"allow"`, `"deny"`, `"ask"` ("prompts the user to confirm"), `"defer"`; `permissionDecisionReason` "For `"allow"` and `"ask"`, shown to the user but not Claude. For `"deny"`, shown to Claude"; precedence `deny` > `defer` > `ask` > `allow`; deny and ask rules "are still evaluated regardless of what the hook returns" (2.1.101). `updatedInput` "Replaces the entire input object … Combine with `"allow"` to auto-approve, or `"ask"` to show the modified input to the user" — a hook can rewrite `--force` into `--force-with-lease` and show it. The `ask` prompt carries "`[plugin:<name>]` for a plugin's hook", and `ask` "also forces a permission prompt in auto mode" (since 2.1.211).
- d5. **Exit 2.** "A hook that blocks by exiting 2 routes the same way as `"deny"`: Claude sees the stderr message as the denial reason"; "Exit 2's block is the one outcome JSON can't override". Observed (E5): the tool result read "PreToolUse:Bash hook error: […]: RED: … This hook comes from the ix-gate-deny@inline plugin." — and the model, told the alternative, ran it on its own without asking anyone. A deny is a redirect, not a stop.
- d6. **`ask` in headless.** Undocumented. Observed (E4), with `Bash(git push *)` pre-allowed: `permission_denied` with `decision_reason_type: "hook"`, and the model's tool result *is the reason text* — the "not Claude" of d4 does not hold on the headless denial path. The model reported the block, quoted the message, and waited. Under `bypassPermissions` (E11a) and `dontAsk` (E11b) the same. Headless is the unattended case, where a denial is the right "until confirmed"; the interactive prompt was not run and is left to the kit-live proof.
- d7. **Settings rules.** `permissions.ask`/`deny` rules match "any subcommand … including a command nested inside a subshell, a command substitution, or a control-flow body"; but a plugin cannot ship them — the manifest's `settings`: "Only `agent` and `subagentStatusLine` take effect; other keys are dropped at load" ([plugins reference](https://code.claude.com/docs/en/plugins-reference)) — and a rule carries no teaching text. A consumer may add them beside the module.
- d8. **The sandbox, the classifier, `PermissionRequest`.** The sandbox governs files and network, not a git command inside the project; t7's classifier acts in auto mode only; a `PermissionRequest` hook runs "when Claude Code is about to ask you for permission", so a pre-allowed destructive command never reaches it. None replaces the `PreToolUse` gate.
- d9. **Community guards.** t3 and t4 are regular-expression tables, deny only; t4 excludes `--force-with-lease`. t5 is a rule table with deny, ask and warn per rule. t2 parses the command — "Wrapping the command or reordering flags does not hide it. A broken config file never blocks anything" — and answers `deny` or `ask`. t6 is a prefix test on `rm`. None is a plugin dial; only t4's reasons name an alternative.
- d10. **Tokenising.** The permission system's separators are "`&&`, `||`, `;`, `|`, `|&`, `&`, and newlines", `$()` and backticks examined, leading `VAR=value` and the wrappers `timeout`, `time`, `nice`, `nohup`, `stdbuf`, `command`, `builtin`, `noglob`, bare `xargs` stripped. The gate repeats that split on the raw `command`: each subcommand by shell rules (`shlex`, so `'push'` is `push`), `$()`, backticks and the string after `bash -c`/`sh -c` examined, a heredoc body not, a program path reduced to its base name, git's global options before the verb skipped (`-C <p>`, `-c <k=v>`, `--git-dir=…`, `--no-pager`). E10 showed the price of skipping the last: the probe's regex missed `git -C . push --force`.
- d11. **The pattern language, three options.** A: a structured entry — `command` words, a `flags` set, `teach` and `alternative` texts — on the tokens of d10, a flag matched inside a cluster (`-rf` holds `-f`), a long flag by equality so `--force` never matches `--force-with-lease`. B: a regular expression per entry — most expressive, opaque; the survey's own probe caught the alternative it recommended. C: the platform's `Bash(...)` glob — one grammar with `if` and rules, but prefix-shaped ("everything before the first `*` as written"), so "flag anywhere" needs a rule per position and `--force-with-lease` cannot be excluded.
- d12. **The confirmation mechanism, three options.** A: `ask` with the teaching text as the reason — the human's yes at the platform's prompt, labelled with the plugin, a denial where nobody can answer (d6). B: exit 2 and let the user re-run — the model re-runs instead (d5), and the second run is blocked again unless the hook remembers, which needs a marker. C: a marker or prefix word the user tells the model to add — the model can add it alone. Only A puts the yes in a human hand; with `updatedInput` it can also show the rewritten command.
- d13. **A proposed default list,** each with the reversible alternative it teaches; every entry on the tokens of d10, the flag anywhere after the verb: `git push` with `--force`/`-f` → `--force-with-lease`, or a new branch and a pull request; `git reset --hard` → `git stash` first, or `--keep`; `git checkout -- .`, `git restore .`, `git checkout -f` → `git stash`; `git clean` with `-f` → `git clean -n` first; `git branch -D` → `-d`, or a tag on the tip; `git stash drop|clear` → `git stash branch`; `git rebase`, `git filter-branch`, `git filter-repo`, `git reflog expire`, `git gc --prune=now` → a new branch, a tag on the tip; `rm -r` with `-f` → `git rm`, a move to a scratch directory; `DROP TABLE|DATABASE`, `TRUNCATE` → a dump first. Outside the list, said so: `git commit --amend`, a plain push, deletion through a file tool.
- d14. **The rest, and the cost.** [Law 5 of CLAUDE.md](../../CLAUDE.md#law-5): the listed patterns are the gate; the class stays advisory on the carrier, and the gate's document states its holes — an interpreter one-liner, a script file, a shell function, an alias. Cost: a process per `Bash` call, Python's start, tens of milliseconds; the module sets its own timeout.
- d15. **Fixture.** The row's red→green: a listed command blocked, the same passing once confirmed — the "with" half is an `ask` answered yes, which no fixture can answer; the fixture proves the JSON for the listed command and exit 0 for the unlisted one, and the kit-live proof shows the prompt.

Mechanism class: a deterministic hook, a `gate`; maturity: `permissionDecision` with `ask` since 1.0.59, the label and the auto-mode rule since 2.1.211; cost: one process per shell call.

**Recommendation: a `PreToolUse` hook with matcher `Bash` and no `if`, tokenising as d10 says, matching a dial of structured entries (d11 A) whose default is the list of d13, answering `ask` with the three-part teaching text (d12 A) and exit 0 otherwise; CONFIRMED as the gate of the row's enumerated half, and CONFIRMED advisory for the class.** For the decider: the pattern language (A recommended; B if a consumer's patterns need more); the mechanism (A recommended; whether `updatedInput` shows the rewritten alternative); the list of d13, and whether SQL belongs in a shell gate's default; `severity` — whether `warn` stays a third outcome or the gate is fixed on `ask`.

## 5. Fit with the shared gate code

Described, not decided; part names as in [kit-shared-gate-code §1](../../shared/GATE.md#g1). The pipeline is built around a written document; this gate reads no path.

- g1. **What it would use.** `identity`; `cli.run` with `load_modes`; `Dials.own` parsed into the entry list, no root policy (item 3 of [its §2](../../shared/GATE.md#g2)); `output` and `route_log`; own `messages`; the links and the runner; `pipeline.locate_event`, the widening made for `Stop`, whose `EventTarget` carries the repository from `cwd`, its dials and the event's name.
