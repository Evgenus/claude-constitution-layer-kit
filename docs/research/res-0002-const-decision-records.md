# Research comparison — const-decision-records (2026-09-18)

Surveyed 2026-09-18; local `claude --version` prints `2.1.251 (Claude Code)`. Experiments ran with git 2.54.0, Python 3.12.4, PyYAML 6.0.2 on macOS, in a scratch directory outside any repository of the kit.

Scope: the rows of [`const-decision-records`](../requirements.md#const-decision-records) — [requirement A3.4](../requirements.md#a3-4) and [requirement A3.6](../requirements.md#a3-6); [A3.1–A3.3](../requirements.md#a3) are enforced through the first, [A3.5](../requirements.md#a3-5) and [A3.7](../requirements.md#a3-7) are binding-side dials — under [dec-0015-pre-module-audit-rulings](../decisions/dec-0015-pre-module-audit-rulings.md) (Python 3 with PyYAML; a write-time script with a scan mode; `severity` block | warn), [dec-0020-gate-script-rules](../decisions/dec-0020-gate-script-rules.md) and [dec-0023-shared-gate-code-at-module-two](../decisions/dec-0023-shared-gate-code-at-module-two.md). Vocabulary: envelope ([kernel §1](../../kernel/CONVENTIONS.md#k1)), territory and policy ([kernel §3](../../kernel/CONVENTIONS.md#k3)), stakes ([kernel §4](../../kernel/CONVENTIONS.md#k4)), decision record ([kernel §5](../../kernel/CONVENTIONS.md#k5)), dials file ([kernel §6](../../kernel/CONVENTIONS.md#k6)). Sources by authority: official Claude Code documentation, tool documentation, community harnesses, experiments reported here (E1–E12).

## 1. Write-time gate on record frontmatter ([requirement A3.4](../requirements.md#a3-4))

The check is three fields: `type: task-record`, `stakes` in the recorded enum, `decider` a non-empty string.

- **A. `PreToolUse` command hook, matcher `Write|Edit`, exit 2.** Class: platform hook, deterministic. Maturity: documented and re-verified today (section 7): exit 2 "Blocks the tool call", `Write` carries `file_path` + `content`, `Edit` carries `file_path`, `old_string`, `new_string`, `replace_all`, the path "always absolute" ([hooks reference](https://code.claude.com/docs/en/hooks)). Cost: one Python process per matched write — a second one when [`const-meta-types`](../requirements.md#const-meta-types) is installed too (section 7, item e); E11 measured 51 ms for `python3 -c "import yaml, json, argparse, logging"`. The schema is mirrored by PyYAML-only checks, for the reason the [first comparison](res-0001-const-meta-types.md) gives in its section 5: a consumer installs the module without the kit's schema files. Cannot see `Bash` writes or editor edits — scan mode covers them.
- **B. `PostToolUse` hook.** The tool already ran ([hooks reference](https://code.claude.com/docs/en/hooks)); cannot block.
- **C. git `pre-commit` validator.** [check-jsonschema](https://check-jsonschema.readthedocs.io/en/latest/usage.html) detects instance files as JSON or YAML (JSON5 by `--force-filetype`); Markdown front matter is not mentioned as an input. [remark-lint-frontmatter-schema](https://github.com/JulianCataldo/remark-lint-frontmatter-schema) validates front matter against a JSON schema, associated by an in-file `$schema` key or a glob map, and reports enum violations ("Must be equal to one of the allowed values"); Node, ESM. Cost: a runtime and a per-clone install no plugin can perform; fires at commit, not at write.
- **D. CI on pull request.** The `--scan` mode in one consumer workflow line; the backstop the row names, never the teacher.
- **E. Existing decision-record tooling.** Surveyed for one question — does it validate a record's metadata, or only create and list:
  - t1. [adr-tools](https://github.com/npryce/adr-tools/tree/master/src): bash; the source directory holds `adr-init`, `adr-new`, `adr-link`, `adr-list`, `adr-generate`, `adr-upgrade-repository` and helpers — no validating command. Nygard template with a `Date:` line and a `## Status` section ([template](https://github.com/npryce/adr-tools/blob/master/src/template.md)). Latest release 3.0.0, 2018-07-25 ([releases](https://github.com/npryce/adr-tools/releases)).
  - t2. [log4brains](https://github.com/thomvaill/log4brains): `adr new` plus a static site; "ADR metadata automatically guessed from its raw text and git logs"; statuses "Proposed, accepted, deprecated, superseded..."; no lint command documented. Node; v1.1.0, 2024-12-17 ([releases](https://github.com/thomvaill/log4brains/releases)).
  - t3. [MADR 4.0.0](https://adr.github.io/madr/) (2024-09-17): a template, not a tool. Front matter: `status` ("proposed | rejected | accepted | deprecated | … | superseded by ADR-0123"), `date`, `decision-makers` ("list everyone involved in the decision"), `consulted`, `informed` ([template](https://github.com/adr/madr/blob/develop/template/adr-template.md)). Its [markdownlint configuration](https://github.com/adr/madr/blob/develop/template/.markdownlint.yml) only switches MD013 and MD024 off — no metadata rule.
  - t4. [pyadr](https://github.com/opinionated-digital-center/pyadr): `propose`, `accept`, `reject`, and `check-adr-repo` ("performs sanity checks on the ADR repo"); `deprecate` and `supersede` are "not yet implemented". v0.20.0, 2023-04-26 ([releases](https://github.com/opinionated-digital-center/pyadr/releases)).
  - t5. [dotnet-adr](https://github.com/endjin/dotnet-adr): `adr new`, `adr new -i <n>` to supersede, seven templates (MADR default); no validation documented.
  - t6. [ADR Manager](https://github.com/adr/adr-manager), a web editor for MADR files "stored in the folder `docs/adr`", and t7. the [Backstage ADR plugin](https://github.com/backstage/community-plugins/tree/main/workspaces/adr/plugins/adr), display and search over MADR 2.x or 3.x: no validation documented in either.
  - t8. [madr-lint](https://github.com/knktkc/madr-lint): validates — `madr/status-enum`, `madr/date-iso8601`, `madr/required-sections`, `madr/filename-format`, `madr/supersedes-bidirectional`, numbering rules. Node 22+; 2 stars on the survey date.
  - t9. [mdbook-lint ADR rules](https://joshrotenberg.com/mdbook-lint/rules/adr/index.html): ADR001–ADR017 — status defined and recognized, date ISO 8601, sections present, "at least 2 considered options". Rust.
  - t10. [adrkit](https://github.com/mbeacom/adrkit): `adr lint` — "validate records, catch supersession cycles, find decisions that silently contradict each other"; own fields (`reversibility`, `blastRadius`, `affects`); Node 22+, pre-1.0; ships a Claude Code plugin.
  - t11. [agent-decision-record](https://github.com/me2resh/agent-decision-record): a JSON schema, a `validate-agdr.js` script and a GitHub Actions workflow on every pull request; fields `id`, `timestamp`, `agent`, `model`, `trigger`, `status`; a `/decide` skill. CI-time only. 48 stars.
  - t12. [claude-plugin-adr](https://github.com/andronics/claude-plugin-adr): a skill, four commands, a `PostToolUse` sync hook; nothing validates at write time. 0 stars.

  Every validator found (t8–t11) assumes its own status vocabulary — proposed / accepted / deprecated / superseded, or proposed / executed / superseded in t11 — and t8, t9 and t11 a date or timestamp. The kernel excludes both on purpose: `status` is active | inactive, no date field duplicates git, and a reversal is a new record rather than a "superseded by" status ([kernel §5](../../kernel/CONVENTIONS.md#k5)). None knows `stakes`; MADR's `decision-makers` is a list of participants, the kernel's `decider` one accountable string. Adopting one means a Node or Rust runtime plus configuration disabling its vocabulary, for a three-field check.

**Recommendation: A, with D as the consumer's wiring.** B cannot block; C and D are late; E's tools validate a different record.

## 2. How the gate knows a document is a decision record

How the surveyed tools do it — every one by location: adr-tools walks up from the working directory for a `.adr-dir` file or a `doc/adr` directory ([`_adr_dir`](https://github.com/npryce/adr-tools/blob/master/src/_adr_dir)); log4brains reads `adrFolder` from `.log4brains.yml` ([README](https://github.com/thomvaill/log4brains)); dotnet-adr reads `path` from `adr.config.json`, default `docs\adr` ([README](https://github.com/endjin/dotnet-adr)); madr-lint has `adrDir`, default `docs/adr` ([README](https://github.com/knktkc/madr-lint)); Backstage takes the annotation `backstage.io/adr-location` ([plugin README](https://github.com/backstage/community-plugins/tree/main/workspaces/adr/plugins/adr)). Only mdbook-lint mixes in content: front matter present, a numbered title, or a path containing `/adr/` ([ADR rules](https://joshrotenberg.com/mdbook-lint/rules/adr/index.html)). None identifies a record by one metadata key.

The kit's constraint: a module reads its own namespace, the two kernel-owned keys and the policy namespaces, never a sibling's ([kernel §6](../../kernel/CONVENTIONS.md#k6)).

- **A. By location** — a module dial lists the id of each policy that governs decision records; the gate reads those policies' territories. Detects every document in record territory, including one with neither field and one with misspelt keys (`stake`, `deciders`, MADR's `decision-makers`). Misses a record written outside that territory. With the dial absent — the empty-repository default of [law 2 of CLAUDE.md](../../CLAUDE.md#law-2) — the gate is silent: it operates, and enforces nothing until one dial is set (a profile can prewrite it). False positives: none under one kind per policy ([kernel §3](../../kernel/CONVENTIONS.md#k3)); an index file inside record territory is a territory defect, not a false positive. Cost: territory resolution — the generic modules copied verbatim under [dec-0023-shared-gate-code-at-module-two](../decisions/dec-0023-shared-gate-code-at-module-two.md), one `git check-ignore` run per listed policy.
- **B. By content** — a governed document carrying `stakes` or `decider` is a record. Zero configuration; works on an empty repository and outside claimed territory; needs no territory code. Misses exactly the failure the row names: a free-form record with both keys absent or misspelt is invisible. False positives: another kind of `task-record` using a `stakes` key — a collision with kernel vocabulary, arguably worth the finding.
- **C. Both** — territory says "must be a record" (missing keys are a finding); either key anywhere says "is a record" (checked). Detects the union; with no dial it degrades to B, so the default installation still enforces something. Cost: A's.
- **D. By filename or id pattern.** A numbered kind keeps its prefix in the policy namespace ([requirement A13.7](../requirements.md#a13-7)); reading it needs the policy id, which is A plus redundancy. A literal pattern in the module breaches [law 2 of CLAUDE.md](../../CLAUDE.md#law-2); a pattern dial duplicates the territory. In the surveyed tools the `NNNN-title` pattern serves numbering and is itself a lint rule (`madr/filename-format`), not the detector.

**Recommendation: C.** A alone is inert by default; B alone cannot see the record that lacks the fields, the one defect a validity gate exists for; D adds nothing. The human decides: the evidence for A-only is its single meaning of "record" (location, as [kernel §3](../../kernel/CONVENTIONS.md#k3) defines kinds); for C, the working default.

## 3. Deterministic slices of the lifecycle rules

Experiments, in a scratch repository holding `docs/decisions/r1.md` (an `inactive` record) and `r2.md` (`active`):

- E5. `git cat-file -e HEAD:<path>` → exit 0 for a committed record, 128 for a new path; on an unborn `HEAD` also 128, and `git rev-parse --verify -q HEAD` exits 1 — a scan must test for the first commit.
- E6. Fifty runs each: `git show HEAD:<path>` 20.1 ms, `git cat-file -e` 20.2 ms per call.
- E7. Replacing "use tabs" by "use spaces" in the body of `r1.md` → `1 insertion(+), 1 deletion(-)`: a reversed ruling and a typo fix have the same diff shape.
- E8. Flipping `status: active` to `inactive` in `r2.md`, then comparing `yaml.safe_load` of both envelopes and the two bodies → changed keys `['status']`, body unchanged. Envelope and body changes separate cleanly.
- E9. After `git mv r2.md dec-0002-r2.md`, `HEAD:<new path>` → 128: a renamed record looks new unless renames are followed.
- E10. A record written and never committed has no `HEAD` copy; the file on disk is the only "before".

Slices:

- **S1. "Applied in the creating commit → born `inactive`."** At write time a new record with either status is legal, and the commit does not exist yet. At scan time `git log --diff-filter=A` finds the creating commit and its other paths, but "applied" is semantic: a ruling may need no file change, or be recorded after the fact. No surveyed tool has an analogue — acceptance is a human act there (pyadr `accept`; `adr_approve` "gated behind a permission prompt" in [adr-kit](https://github.com/kschlt/adr-kit)). Irreducibly judgment; the skill states the rule.
- **S2. "Reversal is a new record, never an in-place edit."** Only an `inactive` record is frozen; an `active` one is legitimately edited while its ruling is applied.
  - S2a. *Envelope slice, write time, no git:* the old file is on disk when `PreToolUse` fires; old `status: inactive` and a write that changes `stakes`, `decider`, `id` or `type`, or flips `inactive` → `active`, is deterministic (E8). False positives: correcting a misspelt decider; reopening a record closed too early.
  - S2b. *Body slice:* an `inactive` record's body changed. The trigger is deterministic, the verdict is not: [kernel §5](../../kernel/CONVENTIONS.md#k5) permits a reference-form migration in place, and [dec-0017-records-numbered-now](../decisions/dec-0017-records-numbered-now.md) rewrote links across every record; E7 shows a typo fix and a reversal are indistinguishable. As a block it is red on every migration; as `warn` it is a reminder — advisory, to be declared so ([law 5 of CLAUDE.md](../../CLAUDE.md#law-5)).
  - S2c. *Scan time:* edits made through Bash or an editor need the `HEAD` copy — 20 ms per record (E6), an unborn-`HEAD` branch (E5), rename following (E9), and nothing to compare for a never-committed record (E10).
  - Survey: adr-tools `-s` itself edits the old record — "The status of the superceded ADR is changed to record that it has been superceded" ([`adr new` help](https://github.com/npryce/adr-tools/blob/master/src/_adr_help_new)); log4brains states "an ADR is immutable. Only its status can change" ([README](https://github.com/thomvaill/log4brains)) and documents no command that checks it; adr-kit states "the old ADR is superseded — never edited" ([README](https://github.com/kschlt/adr-kit)), enforcement not verified beyond its README and technical notes; `madr/supersedes-bidirectional` checks link symmetry, which has no object here — the kernel has no superseded-by link. **No surveyed tool enforces immutability.** The matrix gives immutability to git: a protected branch ([requirement A3.3](../requirements.md#a3-3)).
- **S3. "`routine` never produces a record."** The enum omits `routine`, so `stakes: routine` is already red under section 1; it earns its own teaching message (a routine call is a commit note — delete the record). Zero added cost. The inverse errors — a routine call recorded as `process`, a recorded-stakes call left as a commit note — are judgment, calibrated by the examples of [requirement A3.5](../requirements.md#a3-5).

**Recommendation: S3 inside the section 1 gate; S1, S2b and S2c as skill prose; S2a not shipped now** — named as the first candidate when a consumer's commit notes report an in-place reversal. The row says "gate on schema" ([law 4 of CLAUDE.md](../../CLAUDE.md#law-4)), and the kit grows by friction. The human decides; the case for S2a now is about fifteen lines over a file the gate has already parsed, against two rare false positives.

## 4. Creation path — a skill that writes records (advisory)

- **A. Plugin skill** (`skills/<name>/SKILL.md`). Frontmatter today: `name`, `description`, `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context`, `agent`, `background`, `hooks`, `paths`, `shell`, `metadata`; `description` plus `when_to_use` "truncated at 1,536 characters in the skill listing"; the listing's budget "scales at 1% of the model's context window" and overflow drops descriptions "starting with the skills you invoke least"; `$ARGUMENTS` and positional placeholders; supporting files sit in the skill directory, referenced by relative link and "loaded when needed"; `${CLAUDE_SKILL_DIR}` is "the skill's subdirectory within the plugin, not the plugin root", and `${CLAUDE_PLUGIN_ROOT}` is substituted in skill content and in `allowed-tools` Bash rules; invoked as `/plugin-name:skill-name`; a loaded body "stays in context across turns" ([skills](https://code.claude.com/docs/en/skills)). So the skill can ship a record template beside `SKILL.md` and name the scan command exactly. It stays model-invocable: a recorded-stakes decision surfaces mid-dialog. `paths` cannot carry a territory, which is a runtime dial. Cost: the description, always on.
- **B. Command file** (`commands/*.md`). "Custom commands have been merged into skills"; a command file supports the same frontmatter "except `name` and `paths`" and has no directory for supporting files ([skills](https://code.claude.com/docs/en/skills)); in a plugin, `commands/` is "Skills as flat Markdown files. Use `skills/` for new plugins" ([plugins reference](https://code.claude.com/docs/en/plugins-reference)). Cannot ship the template beside it.
- **C. Plugin agent.** "Each subagent runs in its own context window"; plugin subagents ignore `hooks`, `mcpServers` and `permissionMode` ([subagents](https://code.claude.com/docs/en/sub-agents)). The record is the residue of a dialog — options argued, the decider's pick — that the agent never saw.
- **D. Third-party scaffolders.** `adr new` writes a numbered file from `templates/template.md` and opens `VISUAL` or `EDITOR` ([`adr new` help](https://github.com/npryce/adr-tools/blob/master/src/_adr_help_new)) — an interactive editor an agent cannot drive; log4brains, dotnet-adr and pyadr scaffold their own metadata (t2, t4, t5), never the envelope.
- **Can anything deterministic detect a record not made via the skill? No** — nothing in the file differs. A session proxy is constructible: a `PreToolUse` hook on the `Skill` tool "fires only when Claude calls the tool, but typing `/skillname` directly bypasses `PreToolUse`", `UserPromptExpansion` covers the typed path, and a skill's frontmatter hooks stay registered "for the rest of the session" ([hooks reference](https://code.claude.com/docs/en/hooks)); a marker keyed by `session_id` in `${CLAUDE_PLUGIN_DATA}` would let the write gate refuse a new record in a session that never invoked the skill. It proves "the skill ran earlier", not "this record came from it"; it is blind to editors and Bash; it is a state machine over three events; whether frontmatter hooks register from a *plugin* skill is not verified. No surveyed tool detects records made outside its `new` command either. The row's split — gate on the result, advisory on the path — is the honest one.

**Recommendation: A**, the template as a supporting file. B cannot carry it, C lacks the dialog, D writes a different record.

## 5. Body shape ([requirement A3.2](../requirements.md#a3-2), advisory part)

- **Formats today.** [Nygard](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions): Title, Context, Decision, Status, Consequences; "If a decision is reversed, we will keep the old one around, but mark it as superseded". [MADR 4.0.0](https://github.com/adr/madr/blob/develop/template/adr-template.md): Context and Problem Statement, Decision Drivers (optional), Considered Options, Decision Outcome with optional Consequences and Confirmation, Pros and Cons of the Options (optional), More Information (optional); four variants — full, minimal, bare, bare-minimal ([template directory](https://github.com/adr/madr/tree/develop/template)). [Y-statement](https://adr.github.io/adr-templates/): one sentence — "In the context of …, facing … we decided for … and neglected …, to achieve …, accepting …". The kernel's choice form is MADR's Considered Options, Pros and Cons, and Decision Outcome plus one element none of the three has — a recommendation distinct from the choice, because the recommender is often not the decider; its no-choice form is Nygard's Context and Decision.
- **A. markdownlint MD043**, required headings: "triggered when the headings in a file do not match the array of headings passed to the rule", wildcards `*`, `+`, `?` ([MD043](https://github.com/DavidAnson/markdownlint/blob/main/doc/md043.md)). Node; MADR's own configuration does not enable it (t3).
- **B. madr-lint `madr/required-sections`** (t8). **C. mdbook-lint** ADR004–ADR006 for sections, ADR014 for "meaningful content", ADR016 for at least two options (t9). **D. agent-decision-record**, whose script checks "Y-statement presence" (t11).
- **E. A heading check inside the module's gate.** Deterministic, yet the kernel names no headings and offers two legal shapes selected by a judgment — "when a real choice existed". The kit's own records vary: [dec-0017-records-numbered-now](../decisions/dec-0017-records-numbered-now.md) has Context, Options, Recommendation, Choice; [dec-0015-pre-module-audit-rulings](../decisions/dec-0015-pre-module-audit-rulings.md) has one section per ruling with the recommendation inline, and would be red. A heading gate passes manufactured options under an "Options" heading.
- **F. The skill's template plus review.**

**Recommendation: F.** A–E check names, not substance — judgment dressed as a check ([law 5 of CLAUDE.md](../../CLAUDE.md#law-5)); the matrix already says advisory.

## 6. Promotion loop ([requirement A3.6](../requirements.md#a3-6))

Experiments, in a scratch repository of five commits: three end in a `Note-Theme:` trailer (one added with `git commit --trailer`, one spelt `note-theme:`, one valued `Naming`); one has the line inside a prose paragraph; one has it followed by a closing paragraph.

- E1. `git log --format='%h|%s|%(trailers:key=Note-Theme,valueonly,separator=%x2C)'` → values for the three real trailers, lower-case key included; empty for the other two — the block must be the last paragraph and all trailers, as [git-interpret-trailers](https://git-scm.com/docs/git-interpret-trailers) states; key matching "is done case-insensitively" ([pretty formats](https://git-scm.com/docs/pretty-formats)).
- E2. The same format piped through `sort | uniq -c` → `2 naming`, `1 Naming`, `1 worktree-location`: values are case-sensitive, so spelling fragments a theme.
- E3. `git shortlog -ns --group=trailer:note-theme HEAD` → the same tally in one git-native command; "commits that do not include the trailer will not be counted" ([git-shortlog](https://git-scm.com/docs/git-shortlog)).
- E4. `git log --grep='(routine)' --fixed-strings --format='%h %s'` → the one commit so marked; extracting Conventional Commits scopes with `sed` → `1 parser`.

Candidates:

- **A. Skill procedure over `git log`** — the agent reads recent subjects and bodies and clusters themes. Class: skill, advisory. Cost: log text in context, bounded by `-n` or `--since`. Cannot count reliably or repeat its own clustering.
- **B. Trailer tally** (E1–E3). Class: git-native. Cost: zero shipped code — one command the skill names; the key is a dial. Cannot see a note written without the trailer: every commit before adoption, every committer who forgets; and choosing the theme word is itself the judgment, moved to commit time.
- **C. Conventional Commits types and scopes.** A scope "MUST consist of a noun describing a section of the codebase" ([Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/)) — a code area, not a decision theme; and it imposes a commit format no row of this module owns. [git-cliff](https://git-cliff.org/docs/configuration/git) groups commits by regex over message, body and footer to render a changelog; it has no counting or threshold.
- **D. git notes.** Notes attach "without touching the objects themselves", under `refs/notes/commits` ([git-notes](https://git-scm.com/docs/git-notes)); whether they travel on a default fetch or push is not verified. The kernel says commit *message* ([kernel §4](../../kernel/CONVENTIONS.md#k4)).
- **E. Marker word in the subject** (E4). Lists routine notes, carries no theme — a candidate list for A. The kit's own history already marks routine commits this way.
- **F. An assist script.** Nothing to add over B's one-liner. No existing tool was found that thresholds recurring commit themes.

**Recommendation: A, naming B's command as the optional assist.** No gate, as the matrix says. The "assist script" shrinks to a git-native command: git already does what a repo script would.

## 7. Hook mechanics and plugin loading — re-verification and discrepancies

Re-verified today and unchanged — facts 1, 2, 3, 5 and 7–12 of the [first module's](../../modules/const-meta-types/MODULE.md) list:

- **exit 2** blocks and stderr is the reason;
- **the `Write` and `Edit` fields** and the "always absolute" path;
- `Write|Edit` as an exact-string list ("Only letters, digits, `_`, `-`, spaces, `,`, and `|`");
- **handlers** "run in the current directory" and "`cwd` follows Claude";
- **the default of 600 seconds**;
- **exec form**, "each `args` element is one argument exactly as written";
- **the three path variables** exported to hook processes ([hooks reference](https://code.claude.com/docs/en/hooks));
- `MultiEdit` absent from the [tools reference](https://code.claude.com/docs/en/tools-reference) and "legacy" in [permissions](https://code.claude.com/docs/en/permissions);
- `hooks/hooks.json`, `${CLAUDE_PLUGIN_DATA}` deleted on uninstall unless `--keep-data`, placeholders resolved "Anywhere the placeholder appears" in skill content ([plugins reference](https://code.claude.com/docs/en/plugins-reference));
- `--plugin-dir` one path per flag, the folder form "requires Claude Code v2.1.265 or later", which local 2.1.251 predates ([CLI reference](https://code.claude.com/docs/en/cli-reference));
- **the 1,536-character cap** and `paths` ([skills](https://code.claude.com/docs/en/skills)).

Fact 8, re-run as E12: `git --git-dir=<fresh-null-repo>/.git --work-tree=<empty-dir> -c core.excludesfile=<file holding docs/decisions/**> -c core.ignorecase=false check-ignore --no-index -v -n -z --stdin` over `docs/decisions/dec-0001-x.md` and `README.md` → the first matched on pattern line 1 though the path does not exist, the second returned empty source, line and pattern fields.

Stale, imprecise or missing (every quotation from the [hooks reference](https://code.claude.com/docs/en/hooks) unless another source is named):

- a. **Fact 4 is imprecise.** "Any exit other than 0 and 2 is non-blocking and shows the first stderr line" holds only with plain-text or empty stdout. With a schema-valid JSON object on stdout, "Claude Code ignores the exit code and the JSON alone decides the outcome". A configuration failure exiting 1 must keep stdout free of JSON — or use that JSON deliberately, to say more than one line through `systemMessage`.
- b. **Missing: a timeout fails open.** "A timed-out `command`, `http`, or `mcp_tool` hook doesn't block the tool call… don't count on a stalled hook to act as a gate." Fact 7 gives the number, not the consequence.
- c. **Missing: a hook that cannot start fails open.** "A hook that can't start lands in the same non-blocking bucket… a mistyped path in `settings.json` leaves the gate silently disabled." It bears on the POSIX entry file of [template §6](../../module-template/MODULE.md#t6).
- d. **Missing: the output cap.** "Hook output strings, including `additionalContext`, `systemMessage`, and plain stdout, are capped at 10,000 characters", the overflow saved to a file with a preview. The `warn` channel is bounded; whether the cap covers exit-2 stderr is not verified.
- e. **Two plugins, each with a `PreToolUse` hook on `Write|Edit`.** "All matching hooks run in parallel. If you define the same handler in more than one settings file, it runs once. A plugin's or skill's copy of the same handler stays separate" — no deduplication across plugins. "Every hook's command runs to completion before Claude Code merges the results. One hook returning `deny` doesn't stop sibling hooks from executing"; "the most restrictive answer applies, in the order `deny`, `defer`, `ask`, `allow`"; `additionalContext` "is kept from every hook and passed to Claude together" ([hooks guide](https://code.claude.com/docs/en/hooks-guide)). "A hook that blocks by exiting 2 routes the same way as `"deny"`" — so any one exit 2 blocks. With several `updatedInput` values "the last one to finish takes effect… the order is non-deterministic" ([hooks guide](https://code.claude.com/docs/en/hooks-guide)). Whether Claude receives both stderr texts when two hooks exit 2 is not stated in the documentation; observed on 2026-09-19 in the module's live proof (Claude Code 2.1.251, both modules loaded through `--plugin-dir`, a record written with no envelope): both hooks exited 2 and logged their findings, and the tool result carried one hook's text only, the first module's. Cost model: one process per plugin per matched write, wall-clock the slowest, about 50 ms of interpreter start each (E11), no ordering between them. Consequence: on a broken envelope both modules would report, so this gate owns the three record fields only — `type: task-record` among them, which keeps kernel plus this module alone a working installation ([law 3 of CLAUDE.md](../../CLAUDE.md#law-3)).
- f. **`if` cannot cheaply spare the spawn.** `"Edit(*.ts)"` "runs only for TypeScript files", but "A single `if` rule matches only one tool's calls" and the filter is "best-effort"; whether a `Write(path)` rule is honoured in `if` is not verified — for file permissions Claude Code accepts a `Write` path rule "but never consults it" ([permissions](https://code.claude.com/docs/en/permissions)). The script exits early on a non-Markdown path itself.
- g. **Fact 6 is imprecise:** the manifest itself is optional — "If you include a manifest, `name` is the only required field" ([plugins reference](https://code.claude.com/docs/en/plugins-reference)).
- h. **New to the kit:** `${CLAUDE_SKILL_DIR}` ([skills](https://code.claude.com/docs/en/skills)) — the stable way to name a template shipped inside the skill directory; plugin `commands/` is the legacy form of `skills/` ([plugins reference](https://code.claude.com/docs/en/plugins-reference)).
- i. **Unchanged, restated:** `bashEditDiff` "Requires Claude Code v2.1.269 or later", "is best effort and in public beta", "not to enforce a policy"; new beside it, a `bashEditDiffEnabled` setting that turns the recording on in every permission mode. Still unfit for a gate.
