## 1. The platform's own split and matching of a shell command ([requirement A8.3](../requirements.md#a8-3))

The module's reading starts from the platform's split ([§5](../../modules/const-interaction/MODULE.md#t5); R6 of [dec-0042-interaction-module-rulings](../decisions/dec-0042-interaction-module-rulings.md)). The [permissions](https://code.claude.com/docs/en/permissions) page, re-read on the survey date, states the split this way:

- a1. **Separators.** The page names `&&`, `||`, `;`, `|`, `|&`, `&` and newlines as separators. A rule must match each subcommand on its own. A deny or an ask rule also applies to a command nested in a subshell, a command substitution or a control-flow body such as a `for` loop. A `&&` or `||` with nothing after it makes the command unparseable, and it is then not split for allow rules.
- a2. **Wrappers.** Before matching, the platform strips `timeout`, `time`, `nice`, `nohup`, `stdbuf`, the builtins `command` and `builtin`, and zsh's `noglob`. It does not strip the query form `command -v` or zsh's `nocorrect`. It strips `xargs` only when `xargs` has no flags. The page says: "This wrapper list is built in and is not configurable." Runners such as `direnv exec`, `devbox run`, `mise exec`, `npx` and `docker exec` are not stripped; the page asks for one rule per runner and inner command.
- a3. **Exec wrappers.** The page names `watch`, `setsid`, `ionice` and `flock`: a prefix rule cannot approve them, so in Manual mode they always prompt; `find` with `-exec` or `-delete` is treated the same way. So in Manual mode the platform prompts for `setsid rm -rf build` with or without this gate, unless a rule allows that exact command. A miss of the gate matters where nothing else prompts: auto mode, `bypassPermissions`, `dontAsk`, or a broad allow rule.
- a4. **Assignments.** A leading assignment of certain known-safe variables is stripped for allow rules; a deny or an ask rule matches past any leading assignment.
- a5. **Options before the subcommand.** The page says the platform "matches everything before the first `*` as written", and its table shows that `Bash(git push *)` does not stop `git -C . push origin main` or `git -c push.default=current push origin main`. By the same rule, `Bash(kubectl delete *)` does not stop `kubectl -n prod delete pod x`; this is read from the rule and was not run. The page says such a rule covers the form Claude usually writes and is no security boundary around the program, and it points to a `PreToolUse` hook for one's own logic.
- a6. **Comments.** The permissions, hooks and permission-modes pages say nothing about shell comments. Elsewhere the permissions page says that a command the analysis cannot parse prompts, and that a command over 10,000 characters always prompts.
- a7. **The `if` field.** The hooks page's table for Bash patterns says the commands inside `$()` and backticks are checked, and that a hook runs whenever the platform cannot tell which commands the input runs. The filter is called best-effort.
- a8. **PowerShell.** The page has a section of its own: rules `PowerShell(...)` of the same shape, common aliases canonicalized, matching case-insensitive, the command parsed as a PowerShell syntax tree and split on `|`, `;` and, on PowerShell 7 and later, `&&` and `||`. Section 5 takes it up.
- a9. **The module's reading beside it.** The module splits on the same separators, reads `$( )`, backticks and bare subshells, and drops heredoc bodies ([`tokens.py`](../../modules/const-interaction/scripts/interaction_gate/tokens.py)). It strips more than the platform — `sudo`, `doas`, `env`, `xargs` with its flags — reads the string after five shells' `-c` and after `env -S`, and skips git's global options. The platform's rules reach none of `bash -c 'rm -rf build/'`, `/bin/rm -rf build/` or `git -C . push`, by the page's own table (a5).

Mechanism class: the platform's split is a built-in parser, not configurable (a2); the module's reading is its own deterministic code on the same split. Maturity: documented, re-read today. Cost: none new.

**Recommendation: keep the module's reading on the platform's split, as R6 rules; CONFIRMED.** The split itself is unchanged since res-0008 in what it names; the page now says more about what it does not strip (a2, a3), and that matters to section 3: in Manual mode the platform covers some of the module's misses, in the other modes nothing does.

## 2. Options between an entry's words ([requirement A8.3](../requirements.md#a8-3))

- b1. **Today.** An entry matches only when its words are the first words of the piece: `_matches` in [`checks.py`](../../modules/const-interaction/scripts/interaction_gate/checks.py) compares the piece's leading words with the entry's words. Options are skipped before the verb for git alone, by `GIT_GLOBAL_WITH_VALUE` in [`tokens.py`](../../modules/const-interaction/scripts/interaction_gate/tokens.py). E1, with four consumer entries `kubectl delete`, `docker rm`, `terraform destroy` and `helm uninstall`: `kubectl delete pod x` asks, and `kubectl -n prod delete pod x`, `kubectl --context=prod delete pod x`, `docker --context x rm c`, `docker -H tcp://h rm c`, `terraform -chdir=infra destroy` and `helm -n x uninstall r` all pass green. `helm uninstall r -n x` asks, since its option follows the verb.
- b2. **How common the form is.** Terraform's [CLI page](https://developer.hashicorp.com/terraform/cli/commands) documents `-chdir=...` as a global option written before the subcommand. In the [kubectl quick reference](https://kubernetes.io/docs/reference/kubectl/quick-reference/) (source at `kubernetes/website` commit `1e0d5c7`, 2026-08-03) and nine pages of the [docker CLI reference](https://github.com/docker/cli/tree/master/docs/reference/commandline) (commit `6239084`, 2026-09-03), 6 of 196 example lines put an option before the verb (E6). The form is a minority in examples. It is the normal form in a team that names the namespace or the context first.
- b3. **t2, read.** A custom rule names a `command` and one `subcommand`. Its matcher, `matchesSubcommandFrom` in [`custom.ts`](https://github.com/kenryu42/cc-safety-net/blob/v2.5.2/src/core/rules/custom.ts), skips every option word before the subcommand. An option without `=` may take the next word as its value: the matcher tries the subcommand both after and at that word. A small table gives the options that take a value for `git` and `docker` only. A second form, `command_path`, takes several words but skips a value only for the options a table lists, for `aws`, `gcloud` and `az`. By this reading `kubectl -n prod delete` meets a rule with `subcommand: delete`, and fails one with `command_path: [delete]`.
- b4. **t3, read.** Each pack writes its own regular expressions: `kubectl\b.*?\bdelete` with lists of kubectl's options, `(?:terraform|tofu|terragrunt)\b.*?\bdestroy(?:-all)?(?=\s|$)`, `helm\b.*?\b(?:uninstall|delete)\b`, docker's `rm` only with a force flag. The verb may stand anywhere after the program. t4 and t5, read: t4 looks for `\brm\s+` anywhere in the command; t5 needs the git verb right after `git`, so `git -C . push -f` passes it.
- b5. **Candidate (i): skip option words between the entry's words.** The first word must be the program. Each later entry word may come after option words; an option without `=` may take one following word as its value; any other word, or `--`, between them means no match. The flags are then looked for after the last entry word, as today. A value that equals the wanted word is read as that word, which errs toward examining more. Built on a copy (E7): every case of b1 asks, `kubectl get pods delete` and `kubectl get pods -n prod` stay green, and the module's own runner stays at 65/65 green. On the corpus of E6 — 1,281 distinct commands from the kit's tracked text and the public pages of b2 — it adds one hit, `kubectl -n my-ns delete pod,svc --all`, a true one. Its known false prompt is a value that equals the verb: `kubectl -n delete get pods`, with a namespace named `delete`. It also lets an entry name a runner the reader does not strip: `[uv, run, rm]` with flag `-r` asks for `uv run --with x rm -rf b`, and `[npx, prisma, migrate, reset]` asks for `npx -y prisma migrate reset` (E7). Class: deterministic code in the module's matcher. Maturity: t2 ships the same idea for one word. Cost: about twenty lines of `checks.py`, the "Matches" sentence of [§5](../../modules/const-interaction/MODULE.md#t5), one fixture item.
- b6. **Candidate (ii): a field per entry listing the program's options that take a value.** Exact: no false prompt. But every consumer entry must carry the list, the list drifts with the program's versions, and a missing option fails open in silence — the failure of b1 again. t2 keeps such tables for five programs in its own code. Class: a dial field. Cost: a field, its validation and its messages, and work for every consumer.
- b7. **Candidate (iii): a dial of wrappers.** It strips a program that runs another; it does nothing for the options of the program itself, so it does not answer b1. Section 3 weighs it.
- b8. **Candidate (iv): match the entry anywhere in the piece.** E6: on the corpus it adds no hit and does not catch `kubectl -n prod delete` alone, since the words are not next to each other. On probes it asks for `git rm -r --cached build`, `echo rm -rf build` and `grep -n rm -r src`, three false prompts, and for `find . -name build -exec rm -rf {} +`, a true one. With (i) it catches the b1 forms, and keeps the false prompts. In a headless run each false prompt is a denial. Class: deterministic, broader. Cost: small code, a false-prompt rate the default `rm` entry pays at once.
- b9. **Candidate (v): declare the limit only.** No code. The [§9](../../modules/const-interaction/MODULE.md#t9) limits do not name the form today: limit 2 is about argument values, limit 4 about wrapper flags. A consumer who checks the entry with the explain on `kubectl delete deploy api` sees it ask, and then meets `kubectl -n prod delete deploy api` in green.

Mechanism class: (i), (iv) and (v) change the matcher or the text; (ii) and (iii) add dial shape. Maturity: (i) and (iv) are both shipped by t2 and t3, for one word and for regular expressions. Cost: (i) the lowest of the candidates that close b1.

**Recommendation: candidate (i), with git's exact skip kept; OVERTURNED against the rule of [§5](../../modules/const-interaction/MODULE.md#t5) that an entry's words are the piece's first words.** It closes b1 for every program without a new dial, it lets an entry name a runner, and on the corpus it adds one hit, a true one. Its one false-prompt shape costs a prompt and errs toward examining more, as the reader's own rule asks. The change narrows the reading R6 of [dec-0042-interaction-module-rulings](../decisions/dec-0042-interaction-module-rulings.md) rules, so it is a `process`-stakes change by [kernel §4](../../kernel/CONVENTIONS.md#k4). For the decider: (i) as recommended; (ii) if no false prompt at all is wanted, at the price of a list per entry that fails open when short; or (v), the floor, if the rule of [§5](../../modules/const-interaction/MODULE.md#t5) is to stay as it is — then the limit must be named in [§9](../../modules/const-interaction/MODULE.md#t9) and in the install note.

## 3. Wrappers and shells ([requirement A8.3](../requirements.md#a8-3))

- c1. **Today.** The reader strips twelve wrappers, `WRAPPERS` in [`tokens.py`](../../modules/const-interaction/scripts/interaction_gate/tokens.py), each with the flags that take a value, and reads the `-c` string of five shells, `SHELLS`: `bash`, `sh`, `zsh`, `dash`, `ksh`. E2: every candidate below passes green today, for example `fish -c 'git push -f'`, `busybox rm -rf build`, `ionice -c3 rm -rf build` and `uv run rm -rf build`; the known forms ask, such as `timeout 5 rm -rf build`, `sudo -u root rm -rf build` and `bash -lc 'git push -f'`. [§5](../../modules/const-interaction/MODULE.md#t5) speaks of "a shell's `-c`" and names no list; the install note says `sudo`, `env`, `nohup`, `timeout`, `nice` "and the like", which claims more than the code does.
- c2. **What the surveyed guards strip.** t3, read: `nohup`, `time`, `nice`, `ionice`, `setsid`, `timeout`, `stdbuf`, `chrt` and `busybox`, besides `sudo`, `env` and `command`, each with a parser of its own options. t2, read: `caffeinate`, `exec`, `nice`, `nohup`, `setsid`, `stdbuf`, `time` and `timeout`, besides `sudo`, `env`, `command` and `builtin`; its shells are `bash`, `sh`, `zsh`, `ksh`, `dash`, `fish`, `csh` and `tcsh`; and a `transparent_wrappers` setting where a user names more, after which any word that names a protected program counts as the child.

The candidate shells, each read and not run unless E3 or E2 names it:

- c3. **fish.** [fish 4.9.3](https://fishshell.com/docs/current/cmds/fish.html): `-c` or `--command=` runs a string; `-C` or `--init-command=` also runs commands; `-d`, `-o`, `-p` and `-f` take a value. Adding `fish` to `SHELLS` reads `-c` and a cluster ending in `c`; it does not read `--command=`, `-C`, or a `-c` after `-d <value>`. Cheap for the usual form; the rest needs fish's own options.
- c4. **ash and BusyBox.** [BusyBox](https://busybox.net/downloads/BusyBox.html) (page served with a date of 2009-10-02) runs `busybox <applet> [arguments...]`, with no flag of its own before the applet. As a wrapper with no flags it is exact, and `busybox sh -c '…'` then reaches `sh`, already in `SHELLS`. The page lists `ash` among its applets; this survey takes its `-c` to be the one of POSIX `sh`, read and not run.
- c5. **mksh.** [mksh R59](https://www.mirbsd.org/htman/i386/man1/mksh.htm): POSIX options, `-o option`, and `-T tty`, which takes a value the reader does not know, so `mksh -T /dev/tty2 -c '…'` would still pass. Cheap for the usual form.
- c6. **yash and posh.** [yash](https://magicant.github.io/yash/doc/invoke.html) runs its first operand as a command string with `-c` or `--cmdline`, POSIX options otherwise. [posh 0.14.1](https://manpages.debian.org/trixie/posh/posh.1.en.html): `posh [+-aCefilnuvx] [+-o option]` and `-c command-string`. Exact for `-c`; yash's long form is not read.
- c7. **csh and tcsh.** [tcsh 6.24.13](https://manpages.debian.org/trixie/tcsh/tcsh.1.en.html) reads its commands from the argument after `-c`. Its grammar is not POSIX, and E3 shows one difference that matters: `tcsh -c 'echo a#b; echo c # d'` prints only `a`, since a `#` begins a comment anywhere when the input is not a terminal. The POSIX reader then examines more than tcsh runs: a false prompt, never a miss. The separators `;`, `&&`, `||` and `|` are the same. Cheap.

The candidate wrappers, each with its flags that take a value and its positional words before the command:

- c8. **setsid.** util-linux 2.43 ([man7.org](https://man7.org/linux/man-pages/man1/setsid.1.html), page of 2026-05-24): `-c`, `-f`, `-w`, none with a value. Exact.
- c9. **ionice.** util-linux 2.43 ([page](https://man7.org/linux/man-pages/man1/ionice.1.html), 2026-05-24): `-c`/`--class` and `-n`/`--classdata` take a value, `-t` does not. With `-p`, `-P` or `-u` there is no command; the words after them are ids, which match no entry. Exact.
- c10. **taskset.** util-linux 2.43 ([page](https://man7.org/linux/man-pages/man1/taskset.1.html), 2026-05-24): `-a`, `-c`, `-p`, none with a value; one positional word, the mask or the CPU list, before the command, as `timeout` has one. With `-p` there is no command. Exact.
- c11. **chrt.** util-linux 2.43 ([page](https://man7.org/linux/man-pages/man1/chrt.1.html), 2026-08-03): `-T`, `-P`, `-D`, `-U` and `-X` with their long forms take a value. The priority before the command is optional for some policies since util-linux 2.42, so the count of positional words is not fixed: the reader would skip one word only when it is a number. Exact with that rule, a little more code.
- c12. **flock.** util-linux 2.43 ([page](https://man7.org/linux/man-pages/man1/flock.1.html), 2026-05-24): `-E`, `-w`/`--wait`/`--timeout`, `--start` and `--length` take a value; one positional word, the lock file, before the command; `-c`/`--command` gives a string that a shell runs, which the reader would have to read as it reads a shell's `-c`. `flock <number>` has no command. Exact for the plain form; the `-c` form is a second step.
- c13. **caffeinate.** macOS 26.6.2's own page (`man caffeinate`, dated 2012-11-09): `-t` and `-w` take a value, `-d`, `-i`, `-m`, `-s` and `-u` do not; the utility follows. Exact.
- c14. **watch.** procps-ng ([page](https://man7.org/linux/man-pages/man1/watch.1.html), 2025-04-16): the words of the command are given to `sh -c` unless `-x` is set; `-n`, `-q` and `-s` take a value, `-d` an attached one only. It would fit as a wrapper whose remaining words are joined and read again, as `env -S` is. But its flags differ between procps versions, and macOS ships none. Guesswork about versions, moderate cost.
- c15. **script.** Two dialects: util-linux ([page](https://man7.org/linux/man-pages/man1/script.1.html), 2026-05-24) runs a command given by `-c` or after `--`, and a plain positional word is the output file; BSD, as macOS 26.6.2's `man script` shows, takes `[file [command ...]]`. A positional word is a file in one dialect and may start the command in the other. Guesswork.
- c16. **uv run, poetry run, npx, pnpm exec.** A program and a subcommand that run a further program, with many options of their own that change between versions; the platform does not strip them either (a2). A wrapper list would have to carry every option. With candidate (i) of section 2, a consumer entry can name the runner — `[uv, run, rm]` — and its options no longer break the match (E7). Not a wrapper.
- c17. **nix-shell --run.** [Nix 2.35.2](https://nix.dev/manual/nix/latest/command-ref/nix-shell.html): `--run cmd` and `--command cmd` run a string in a shell, and `-p` takes several package words. A reader would look for the option and read its value as a shell's `-c`; a special case for one program.

What else the list touches:

- c18. **A wrapper added to the list makes a consumer entry that starts with it unreachable.** The reader strips a listed wrapper before the entry is compared, so an entry `[sudo, rm]` loads and never matches; the same holds for an entry that is a path (E8). If `uv` became a wrapper, the entry of c16 would stop working in silence. Growing the list is safe for the defaults and not for every consumer entry.

Mechanism class: fixed lists in the module's reader, deterministic. Maturity: t2 and t3 ship most of these names. Cost: the cheap and exact set is c3 to c10, c13 and the plain form of c12 — two sets in `tokens.py`, one more count in `WRAPPERS_WITH_VALUE`, a date and a page per wrapper, and E7 shows the runner still green; c11 and the `-c` of c12 need a little code; c14, c15 and c17 are guesswork or special cases; c16 is not a wrapper.

**Recommendation: build the cheap and exact set — `fish`, `ash`, `mksh`, `yash`, `posh`, `csh` and `tcsh` as shells, `busybox`, `setsid`, `ionice`, `taskset`, `caffeinate` and the plain `flock` as wrappers — and name the rest in limit 4 of [§9](../../modules/const-interaction/MODULE.md#t9); no dial of wrappers.** The added names close misses of the default entries themselves — `rm -rf` and `git push -f` behind a wrapper — at no false-prompt cost, since a stripped wrapper only uncovers a command. A dial of wrappers would need each wrapper's valued flags from the consumer, and section 2's candidate (i) already lets an entry name a runner. For the decider: whether `chrt`, the `-c` of `flock`, fish's `-C` and `--command=`, and `nix-shell --run` join now or wait for a signal; and whether an entry the reader cannot produce (c18) is refused at load with a teaching error, which makes growing the list safe for consumers.

## 4. Comments ([requirement A8.3](../requirements.md#a8-3))

- d1. **Today.** The reader has no idea of a comment: it splits the text, then reads each piece's words. E3: `# note; git push -f` asks, since the `;` makes `git push -f` a piece of its own; so does a two-line text whose second line is `# step: git reset --hard && rm -rf build`, for the `rm -rf build` after the `&&`. A comment with no separator in it asks for nothing: `# step 2: git reset --hard` is one piece whose first word is `#`, and `ls # rm -rf build` is a piece whose program is `ls`. So the false prompt needs a comment that holds a separator followed by a listed command.
- d2. **Where `#` begins a comment.** [POSIX.1-2024](https://pubs.opengroup.org/onlinepubs/9799919799/utilities/V3_chap02.html), section 2.3: a `#` that does not continue a word, outside quotes, discards itself and the rest of the line, but not the newline. [Bash 5.3](https://www.gnu.org/software/bash/manual/bash.html#Comments): in a non-interactive shell, or an interactive one with `interactive_comments` set, which is its default, "a word beginning with ‘#’ introduces a comment"; a word begins at the start of a line, after unquoted whitespace, or after an operator. [Zsh 5.9.2](https://zsh.sourceforge.io/Doc/Release/Shell-Grammar.html#Comments): the same in a non-interactive shell, and in an interactive one only with `INTERACTIVE_COMMENTS`, which zsh's own mode leaves off. E3 on zsh 5.9: `zsh -c` honours a comment with the option unset, since `-c` is not interactive.
- d3. **How the platform runs the Bash tool.** The [environment variables](https://code.claude.com/docs/en/env-vars) page: `CLAUDE_CODE_SHELL` accepts a `bash` or a `zsh`; "Other shells such as `fish` are not supported." The [tools reference](https://code.claude.com/docs/en/tools-reference) says the startup file's aliases, functions and shell options are captured once and applied to every command. Whether the shell is interactive is not stated. E4: in this session's Bash tool, `$-` is `hmtBc` — no `i`, and `c` for a `-c` string — and a comment hid the rest of its line. So on both shells the platform allows, a `#` at the start of a word begins a comment.
- d4. **Forms that are not comments.** `$#` and `${#x}`: the `#` is part of an expansion. `a#b`: the `#` continues a word. `'a # b'` and `"a # b"`: quoted. `a\ #b`: the blank before `#` is escaped, so `#b` continues the word. Inside backticks a comment ends at the closing backtick: E3, on bash 3.2.57 and zsh 5.9, `` echo `echo a # b`; echo RAN `` prints `RAN`. Inside an unquoted `$( )` on one line, a comment runs to the end of the line and the substitution never closes: bash reports a syntax error and runs nothing.
- d5. **A drop that only knows quotes fails open.** E6 tried a drop of comments before the split that tracks quotes and backslashes and nothing else. It removed the false prompts of d1. It also hid `git push -f` in `` echo `echo a # b`; git push -f `` and in `echo a\ #b; git push -f`: two commands that run, made green. An exact drop must know backticks, `$( )`, escaped blanks and heredocs — the contexts `_separate` and `_drop_heredocs` in [`tokens.py`](../../modules/const-interaction/scripts/interaction_gate/tokens.py) already track. Placed inside `_separate`, at depth 0, outside any quote or backtick, and only where the scanner itself just passed an unescaped blank, a line start or an operator, the drop would cost some fifteen lines and a fixture case for each form of d4.
- d6. **What the surveyed guards do.** t2, read: its POSIX scanner skips from `#` to the line's end where the `#` stands at the start of the text or after whitespace or one of `;&|()` (`isCommentStart` in [`posix.ts`](https://github.com/kenryu42/cc-safety-net/blob/v2.5.2/src/core/shell/posix.ts)). t3, read: a regression test holds that `ls -la # rm -rf /` is allowed. Both drop comments; neither was run here.
- d7. **The measured cost of keeping.** On the 1,281 distinct commands of E6, a drop changes no verdict: no line of the corpus holds a comment with a separator and a listed command after it. The false prompt of d1 is real and rare; each one costs a prompt, or a denial in a headless run.
- d8. **The reader's own rule.** The docstring of [`tokens.py`](../../modules/const-interaction/scripts/interaction_gate/tokens.py) says that where the reader cannot split a text cleanly it errs toward examining more. A drop examines less; it is safe only when it is exact (d5).

Candidates: keep the reading and declare the false prompt — class: text in [§9](../../modules/const-interaction/MODULE.md#t9), cost nil; or drop comments inside the scanner — class: deterministic code, maturity: shipped by t2, cost: d5, with the risk that a mistake there hides a command.

**Recommendation: keep the reading, and name the false prompt in limit 4 of [§9](../../modules/const-interaction/MODULE.md#t9) — a comment that holds a separator and a listed command prompts; CONFIRMED, the drop not needed at this version.** The measured gain is nil on the corpus, the false prompt costs one prompt, and the only drop that is safe is the exact one of d5, whose mistakes would fail open. For the decider: the exact drop of d5 now, if prompts on comment lines are reported, or after such a report.

## 5. The PowerShell tool ([requirement A8.3](../requirements.md#a8-3))

- e1. **The tool.** The [tools reference](https://code.claude.com/docs/en/tools-reference) lists a tool named `PowerShell` beside `Bash`. On Windows without Git Bash it is on by itself; on Windows with Git Bash it is on by default for claude.ai and Console accounts, and opt-in with `CLAUDE_CODE_USE_POWERSHELL_TOOL=1` for Amazon Bedrock, Google Cloud's Agent Platform and Microsoft Foundry; on Linux, macOS and WSL it is opt-in and needs `pwsh` 7 or later. "When the tool is enabled, Claude treats PowerShell as the primary shell." The changelog dates the parts: Git Bash no longer required, PowerShell the shell tool without it, 2.1.120 of 2026-04-28; PowerShell the primary shell when enabled, 2.1.126 of 2026-05-01.
- e2. **Its hook input.** The [hooks](https://code.claude.com/docs/en/hooks) page gives the PowerShell `tool_input` the Bash tool's fields — `command`, `description`, `timeout`, `run_in_background` — with the command string in `command`. It asks hooks that inspect shell commands to match `Bash|PowerShell`, because on Windows without Git Bash the Bash tool is not registered at all, and "A hook that matches only `Bash` never fires there." A matcher of letters and `|` is a list of exact names. A comma list such as `Bash,PowerShell` never fired before 2.1.191 of 2026-06-24.
- e3. **Its permission rules.** `PowerShell(...)` rules, as a8 states: aliases canonicalized, case-insensitive, split on the syntax tree. On Windows with Git Bash, a deny rule for Bash also turns the PowerShell tool off, since a `Bash` rule does not hold the PowerShell tool; 2.1.287 of 2026-10-01 added a startup warning for it.
- e4. **The module today.** The matcher in [`hooks.json`](../../modules/const-interaction/hooks/hooks.json) is `Bash`. Neither the module document nor its install note names PowerShell or Windows. So wherever the PowerShell tool is the shell, the gate examines nothing and says nothing, while the invariant of [§5](../../modules/const-interaction/MODULE.md#t5) speaks of "the platform's shell tool".
- e5. **PowerShell's syntax, read from its documentation.** [Remove-Item](https://learn.microsoft.com/powershell/module/microsoft.powershell.management/remove-item) (source of 2026-08-10) has the aliases `del`, `erase`, `rd` and `ri` on all platforms, and `rm` and `rmdir` on Windows only. A parameter may be shortened to its shortest unique prefix ([using aliases](https://learn.microsoft.com/powershell/scripting/learn/shell/using-aliases), 2026-01-13), so `-r` is `-Recurse` and `-fo` is `-Force` for `Remove-Item`. Names of commands and parameters are case-insensitive ([about_Case-Sensitivity](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_case-sensitivity), 2026-01-06). [about_Comments](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_comments) (2025-01-10): `#` to the end of the line, `<#` to `#>` across lines, neither inside a string nor inside another token, so `Foo#Bar` is one word. [about_Pipeline_Chain_Operators](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_pipeline_chain_operators): `&&` and `||` from PowerShell 7. [about_Pwsh](https://learn.microsoft.com/powershell/module/microsoft.powershell.core/about/about_pwsh) (2026-01-18): `-Command` or `-c` runs a string and must come last; `-CommandWithArgs` or `-cwa`; `-EncodedCommand`, `-e` or `-ec` takes Base64 text. The backtick is PowerShell's escape character and its line continuation.
- e6. **What the POSIX reader sees in PowerShell text (E5).** It asks for `git push -f`, `& git push -f`, `Test-Path x && git push -f`, `Get-ChildItem; git push -f` and `$(git push -f)`. It asks for the `rm` alias with `-r`, `-Recurse` or `-Rec`, by luck: it reads `-Recurse` and `-Rec` as clusters of short flags that hold an `r` or an `R`. It passes green `Remove-Item -Recurse -Force build`, the aliases `ri`, `del`, `rd`, `rmdir` and `erase` with `-r`, `RM -r build` and `Git push -f` (case), `git.exe push -f` (the suffix), `pwsh -c "git push -f"`, `powershell.exe -Command "git push -f"` and `cmd /c "rd /s /q build"`. It asks for `<# note; git push -f #>` and `# note; git push -f`, two false prompts. And it fails open in two forms: a backtick that ends a line, `` Get-ChildItem ` `` followed by a line `-Path x; git push -f`, and a backtick escape inside a string, `` Write-Host "a`"b"; git push -f ``. The reader takes the backtick for a command substitution, so the `git push -f` after it is never split off. `Git` and `git.exe` pass in Git Bash on Windows too.
- e7. **What the surveyed guards do, read.** t2 has no matcher and reads the `command` of any tool; when the text shows PowerShell signs — a `Remove-Item` head or one of its aliases, `<#`, `$env:` — its PowerShell scanner is tried on it (`shouldUsePowerShellParser` in `powershell.ts`). t3 ships packs for Windows: `Remove-Item -Recurse` with its aliases, `del /s` and `rd /s` of `cmd.exe`, case-insensitive; its README says it works on Windows through WSL or a PowerShell installer.
- e8. **The launcher.** Every hook of the module runs in exec form, `"command": "sh"` with the script as an argument. The hooks page says exec form resolves `command` on `PATH`, and that on Windows it needs a real executable such as an `.exe`; shell form uses PowerShell where Git Bash is not installed. Whether `sh` and then `python3` resolve on a Windows machine was not tried: no Windows machine was at hand. Where they do not, a widened matcher gives a hook that cannot start on every call, and no verdict — the same as the `Bash` matcher already gives wherever the Bash tool runs on such a machine; what the platform then shows was not read on any page.

Candidates:

- e9. **A. Widen the matcher to `Bash|PowerShell` and read PowerShell with the same reader, its limits declared.** It reads the forms of e6 that share POSIX shape — `git`, the `rm` alias with `-r`, `;`, `|`, `&&`, `||`, `$( )` — and never reads less than today, where nothing is read; its new false prompts are those of e6. The limits to name: cmdlets and aliases no entry names; names compared with case and with a suffix such as `.exe`; the backtick, which hides what follows it on PowerShell text (e6); `<# #>` comments read as text; the strings of `pwsh -c`, `powershell -Command` and `-EncodedCommand`; `cmd /c`. Class: deterministic, the same reader. Maturity: the payload is documented (e2). Cost: the shared parts of section 6, the matcher, `modes.py`, one fixture item with a PowerShell payload, and the text of [§5](../../modules/const-interaction/MODULE.md#t5) and [§9](../../modules/const-interaction/MODULE.md#t9).
- e10. **B. Widen with a reader of its own for PowerShell.** Case-insensitive names, an alias table, parameter prefixes, the backtick as an escape, `<# #>`, `-Command` strings; then entries in PowerShell's own terms, such as `Remove-Item` with `-Recurse`. Class: a second parser and a second shape of entry. Maturity: t2 and t3 both ship one. Cost: large — a parser, a dial shape question, and a fixture set as big as the POSIX one.
- e11. **C. Declare the Windows gap only.** [§5](../../modules/const-interaction/MODULE.md#t5) narrows "the platform's shell tool" to `Bash`; [§9](../../modules/const-interaction/MODULE.md#t9) and the install note say that the gate is silent wherever the PowerShell tool runs. Class: text. Cost: nil. It leaves the gate silent on Windows for every account type that has the tool on by default.

**Recommendation: A — widen the matcher to `Bash|PowerShell`, read with the one reader, its PowerShell limits declared, and the Windows run named as a step of the consumer-live proof; OVERTURNED against the matcher `Bash` that [res-0008-const-interaction](res-0008-const-interaction.md) recommended and the matrix's "hook on Bash"; a reader of its own not needed at this version.** A covers the forms PowerShell shares with POSIX shells at the cost of a small widening of the shared code, and it never reads less than today. B waits for a consumer whose destructive act on Windows is a cmdlet. For the decider: A as recommended, or C if the Windows launcher of e8 is not to be proven; and whether `Remove-Item` and its aliases enter the default list, which would need names compared without case — not recommended now.
