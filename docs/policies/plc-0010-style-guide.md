# Style-guide policy

Governs the document kind *style guide*: the one document stating the defaults every governed document of the kit follows. They cover diagrams, drawings, formulas, prose against lists against tables, list and table format, headings, code, emphasis and callouts. Each is defined by its examples (decision [dec-0044-styling-module-rulings](../decisions/dec-0044-styling-module-rulings.md)). Territory under this policy's id in `constitution.yaml`, one path. The guide reaches every other kind's documents through the style rule each kind's policy carries ([rule 9 of plc-0001-root-policy](plc-0001-root-policy.md#r9)), never by resolution.

## Rules

1. <a id="r1"></a>**Type.** `current-state`, superseded in place ([kernel §1](../constitution/CONVENTIONS.md#k1)). It is one document, at the one path the territory names. It is created by hand from the file module [`const-styling`](../requirements.md#const-styling) ships, `skills/style-defaults/style-guide.md` under the plugin root, the module's `plugin/` folder. That file's text is the guide's founding text.
2. <a id="r2"></a>**Shape.** A header paragraph saying what a default is and where a departure and an addition go. Then a section "Defaults", a numbered list in which each entry is one default. An entry is a bold sentence opening the item, with its pairs as nested items reading *departs / follows*. Then a closing section on departures and additions. An entry keeps its number for life, as a rule of a policy does. A withdrawn default keeps its number and its entry says so.
3. <a id="r3"></a>**Change.** A default is added at the first concrete need, as the next numbered entry with its pairs, born with the document that needed it. It is added through a `process`-stakes decision ([kernel §4](../constitution/CONVENTIONS.md#k4)). Amending or withdrawing one is the same. A mechanical edit — a typo, a reference-form migration — is routine. The founding entries are the ten entries d1 to d10 of the guide's section "Defaults". A default is never answered in one document, one template or one commit message alone.
4. <a id="r4"></a>**One guide, no enumeration.** The territory is one path and is never widened to a directory, since a document resolving to two policies is the kernel's defect ([kernel §3](../constitution/CONVENTIONS.md#k3)). The guide names no document and no kind, and lists no departure. A departure is an entry of the dial `departures` of module [`const-styling`](../requirements.md#const-styling) in `constitution.yaml`, per kind by pattern or per document by path, with its reason. Nothing in a document marks it. A second document needing the same one-off departure is the signal that widens the entry to its kind or changes a default here.
5. <a id="r5"></a>**Anchors.** Every default carries an explicit anchor `d<n>` inside its item, before the bold sentence, never renumbered ([requirement A5.5](../requirements.md#a5-5)).
6. <a id="r6"></a>**Style.** The guide follows its own defaults. It is the document that the dial `guides` of module [`const-styling`](../requirements.md#const-styling) names in `constitution.yaml`, the dials file. It departs from one only where that module's dial `departures` names a departure for its path, with the reason ([rule 9 of plc-0001-root-policy](plc-0001-root-policy.md#r9)).
7. <a id="r7"></a>**Enforcement.** The envelope is held by module [`const-meta-types`](../requirements.md#const-meta-types), and links and anchors by module [`const-referencing`](../requirements.md#const-referencing). Module [`const-styling`](../requirements.md#const-styling) holds the twelve traces of the defaults — in the guide and in every covered document — in its scan alone, which runs no hook. The content of a default, whether an example is apt, and whether prose, a list or a table was due, are review. The grade, the sentence length and the constructions of the prose are held by module [`const-language`](../requirements.md#const-language), after a write and in its scan. The length in characters is held by module [`const-doc-budgets`](../requirements.md#const-doc-budgets), after a write and in its scan. The module checks it against the ceiling its dial `ceilings` in `constitution.yaml` sets for documents of this kind.
