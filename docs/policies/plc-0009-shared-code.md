# Shared-code policy

Governs the document kind *shared-code description*: the page beside the kit's shared gate code that states what the code is for, the interface a module fills, every shared message, the shared limits and the shared acceptance items (decision [dec-0025-shared-gate-code-linked](../decisions/dec-0025-shared-gate-code-linked.md)). Territory under this policy's id in `constitution.yaml`.

## Rules

1. <a id="r1"></a>**One home for shared texts.** Every message the shared code prints is written out in this document, word for word as the code returns it; a module's document writes out its own messages and links here for the rest ([law 6 of CLAUDE.md](../../CLAUDE.md#law-6)).
2. <a id="r2"></a>**Admission.** Code is shared only when it implements a kernel section literally or a gate-script rule of [template §6](../../module-template/MODULE.md#t6), and two or more modules need it; the document names the class of each part. A part already shared may be widened for one module where the widening keeps a rule the part carries for all — one guard, one pipeline, one fixture subject — and defaults to what the other modules pass, so they change nothing.
3. <a id="r3"></a>**Portability.** The document and the code carry no project reference ([law 2 of CLAUDE.md](../../CLAUDE.md#law-2)) and no module's name: a module is `{module}` in every text, or, where the document must point at one module's fixture or code, its ordinal in the order of authoring — "the third module" — which the rollout plan resolves and which never changes. A shared message about a module's namespace names the key and never shows an example of that module's dials — an example that replaces the namespace drops the module's own keys; the example is the module's to give.
4. <a id="r4"></a>**Handles.** Every list and table row carries a handle. An acceptance item's number is never reissued: an item a subject leaves out keeps its number free, and a new item takes the next.
5. <a id="r5"></a>**Anchors.** Every section carries an explicit anchor `g<n>`; a new section takes the next number; an anchor is never renumbered.
6. <a id="r6"></a>**Platform facts.** An observed fact about the platform names the platform's version and the date it was observed, its backstop and, where one exists, its fallback; a re-read is dated inline.
7. <a id="r7"></a>**Change.** A change to the shared code updates this page in the same change — the pair `shared-gate-code` of the kit's coverage map — and bumps the version of every published module that requires the package; a draft's need not be bumped (steps 4 and 7 of "Developing a module" in [CLAUDE.md](../../CLAUDE.md)). It also raises the package's `__version__` as rule 11 says.
8. <a id="r8"></a>**Deferred.** A part not built is listed with the signal that would build it, as [template §12](../../module-template/MODULE.md#t12) asks of a module.
9. <a id="r9"></a>**Enforcement.** The envelope by module [`const-meta-types`](../requirements.md#const-meta-types); links and anchors by module [`const-referencing`](../requirements.md#const-referencing); the pairing with the code by module [`const-task-close`](../requirements.md#const-task-close) in its scan alone — the range check, run before a merge and on the trunk after it. Rule 11 by two checks of the kit, never shipped in a module, each an entry of the gate list with `--self-test` as its fixture: `scripts/check-copies.py` holds every version a module requires at or below `__version__`, in the same major, and `scripts/check-shared-package.py` builds the package, installs it into a fresh virtual environment, imports it there and holds the installed version equal to `__version__`. That a change raised `__version__` and that a release is a go-ahead's tag are review — a check on the raise waits for a release that missed it. That the messages table equals the code word for word, and rules 2 and 3, are review — a check on the equality waits for a friction that earns it. The twelve traces of the style defaults are held by module [`const-styling`](../requirements.md#const-styling) in its scan alone, which runs no hook. The grade, the sentence length and the constructions of the prose are held by module [`const-language`](../requirements.md#const-language), after a write and in its scan. The length in characters is held by module [`const-doc-budgets`](../requirements.md#const-doc-budgets), after a write and in its scan, against the ceiling its dial `ceilings` in `constitution.yaml` sets for documents of this kind.
10. <a id="r10"></a>**Style.** Documents of this kind follow the style guides the dial `guides` of module [`const-styling`](../requirements.md#const-styling) names in `constitution.yaml`, and depart from a default only where that module's dial `departures` names a departure for their territory, with its reason ([rule 9 of plc-0001-root-policy](plc-0001-root-policy.md#r9)); the traces of the defaults are held as the enforcement rule says, the rest is review.
11. <a id="r11"></a>**Versions.** The package follows semantic versioning, major.minor.patch, from its first release, `1.0.0`; before that tag nothing is promised. From it on, a release keeps every module written for an earlier release of the same major working, because it only adds: a module, a function, an optional parameter or field whose default keeps the behaviour, a message key. A message's wording may change, its key and its parameters may not, and a name that starts with `_` is no part of the promise. A change that breaks the promise is a new major and a `process`-stakes decision of its own, made only when nothing else serves. A change to the shared code after a release raises `__version__` in the same change, the patch number for a fix and the minor for an addition, unless the version already stands above the last tag. A release is the tag `constitution-layer-kit-v<version>` on a commit of `main` whose `__version__` is that version, pushed only on the decider's go-ahead, since a tag is an outward act. A module requires `1.0.0` until it uses a name that a later release added, and the change that makes it use one raises the version it requires to that release (decision [dec-0099-shared-code-installed-as-a-pip-package](../decisions/dec-0099-shared-code-installed-as-a-pip-package.md)).
