# Requirements policy

Governs the document kind *requirements document*: the traceability matrix and the module specifications beside it. The matrix has one row per requirement part, with its destination and recommended enforcement. Territory under this policy's id in `constitution.yaml`.

## Rules

1. <a id="r1"></a>**Type.** `current-state`, superseded in place ([kernel §1](../constitution/CONVENTIONS.md#k1)). It holds what a module must implement and nothing about when. Phases belong to the rollout plan. A module's entry trigger in its heading, "enters when" (decision [dec-0006-accumulating-set-first](../decisions/dec-0006-accumulating-set-first.md)), names no phase. A condition inside a rule, "until the kit's CI runs it", names none either.
2. <a id="r2"></a>**Change.** Adding, amending, or re-homing a row or a module specification is a `process`-stakes decision ([law 9 of CLAUDE.md](../../CLAUDE.md#law-9)). The row states its rule in full; citing a record beside it is optional provenance.
3. <a id="r3"></a>**Anchors.** Every aspect, row, and module specification carries an explicit anchor — `a<n>`, `a<n>-<m>`, the plugin name (decision [dec-0005-reference-forms](../decisions/dec-0005-reference-forms.md)).
4. <a id="r4"></a>**Aliases.** `M<n>` is a local alias inside this document only. How every other kit document cites a module is the reference rule of [CLAUDE.md](../../CLAUDE.md#references) (decision [dec-0051-module-citation-rule-in-the-guide](../decisions/dec-0051-module-citation-rule-in-the-guide.md)).
5. <a id="r5"></a>**Descriptions.** A module's description moves into its `MODULE.md` when authoring begins. The heading keeps its anchor with a one-line stub linking there (decision [dec-0015-pre-module-audit-rulings](../decisions/dec-0015-pre-module-audit-rulings.md)).
6. <a id="r6"></a>**Rows.** A row keeps its number for life. A new row takes the next number in its aspect and stands in number order. A removed row leaves its number unused. A row's text is its rule in full, whatever its length. The `†` flag marks a row whose destination is under a boundary test, resolved when the module is authored.
7. <a id="r7"></a>**Vocabulary.** The destination classes and the enforcement classes — `gate`, `gate-lite`, `advisory`, `definitional`, `config`, `git-native`, `review` — are closed sets, each defined once in the preamble. A class may carry a qualifier before or after it — "advisory procedure", "review judgment", an assist named. But a Destination cell opens with a destination class, its qualifiers after it. A row waiting for another module says so in words. A row may name the template as its destination or beside another, the template being authoring law. A row's recommended enforcement stays the recommendation. The module's comparison confirms or overturns it, and the module document's enforcement section states what shipped. The row is amended only under rule 2 — when its rule changes, or when the vocabulary it is written in does.
8. <a id="r8"></a>**Structure.** One heading of the first level. The matrix comes first and the module specifications after it, each under its anchor. A moved description leaves the stub "Description moved into the module's document: …; this anchor stays the module's handle". Nothing that is neither a requirement nor a specification. A row carries no implementation status — the kit's `scripts/check-aspects.py` derives it on each run and stores it nowhere. A module's progress stays in the rollout plan.
9. <a id="r9"></a>**Enforcement.** The envelope is held by module [`const-meta-types`](../requirements.md#const-meta-types). Links, anchors and the row and module lanes are held by module [`const-referencing`](../requirements.md#const-referencing). The kit's `scripts/check-module-links.py` holds the module links that the reference rule of [CLAUDE.md](../../CLAUDE.md#references) asks for. It holds them where a module's name stands in a code span after the word "module" or "modules". It does so in the gate list alone, never at write time. A name standing alone, or any name after the first of a plural, is review. Content, vocabulary and structure are review, with two exceptions. The traces of the style defaults are one. The other is held by the kit's `scripts/check-aspects.py` in the gate list alone. The check holds that each Destination cell of the matrix opens with one of the destination classes it types. It holds that the bold names of the preamble's sentence "Destination classes: …" are exactly those. So a class added to the preamble is added to the check in the same change. It holds that each line of this document that holds a row's or an aspect's anchor is in the form its docstring states. And it holds that no two lines open with the same row or aspect anchor. The twelve traces of the style defaults are held by module [`const-styling`](../requirements.md#const-styling) in its scan alone, which runs no hook. The grade, the sentence length and the constructions of the prose are held by module [`const-language`](../requirements.md#const-language), after a write and in its scan. The length in characters is held by module [`const-doc-budgets`](../requirements.md#const-doc-budgets), after a write and in its scan. The module checks it against the ceiling its dial `ceilings` in `constitution.yaml` sets for documents of this kind.
10. <a id="r10"></a>**Style.** Documents of this kind follow the style guides that the dial `guides` of module [`const-styling`](../requirements.md#const-styling) names in `constitution.yaml`, the dials file. They depart from a default only where that module's dial `departures` names one for their territory, with its reason ([rule 9 of plc-0001-root-policy](plc-0001-root-policy.md#r9)). The traces of the defaults are held as the enforcement rule says, and the rest is review.
