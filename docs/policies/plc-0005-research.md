# Research policy

Governs the document kind *research comparison*: one module's dated survey of how its matrix rows are addressed today, ending in one recommendation per mechanism (decision [dec-0010-module-research-per-module](../decisions/dec-0010-module-research-per-module.md)). Territory under this policy's id in `constitution.yaml`.

## Rules

1. <a id="r1"></a>**Type.** `non-authoritative`: a comparison informs a mechanism choice and binds nothing.
2. <a id="r2"></a>**Status.** `active` while it is the module's current comparison; `inactive` once a later survey supersedes it, kept while cited ([kernel §1](../../kernel/CONVENTIONS.md#k1)).
3. <a id="r3"></a>**Provenance.** Every fact names what verified it: a public source; an experiment of the document — numbered `E<n>`, stating what was set up, run and observed and the versions used, so a reader could repeat it; or the kit's own tree at a named commit. A tool read but not run is marked so. An earlier comparison is a starting point and never a source; nothing is copied from earlier design work, and nothing cites an input outside the repository.
4. <a id="r4"></a>**Vocabulary.** Written in kit vocabulary: kernel terms by link, matrix rows by link, modules, comparisons and records by name or id and never by their order of authoring; "the specification" means the module's stub in the requirements document, linked.
5. <a id="r5"></a>**Shape.** Written from `templates/research-comparison.md`, the template named for this kind in `const-locations.templates`: a header paragraph with the survey date, the platform's version, and every tool and library with its version and the platform they ran on; the tools keyed `t<n>`, each with version and date. The body then holds one section per mechanism, its findings lettered per section, each candidate with its mechanism class, maturity and cost, closing with one recommendation and its reasoning; the fit with the shared gate code where the module ships a script; the platform facts re-verified, each with what breaks if it changes; the experiments; a summary with one verdict per row from the closed set CONFIRMED, OVERTURNED, build, not needed. A rule of this policy that changes the shape changes the template in the same change.
6. <a id="r6"></a>**Number.** Comparisons are a numbered kind: id and filename stem are one name, `res-<nnnn>-<slug>`, the slug naming the module surveyed; prefix, width and territory are an entry of `const-catalogs.catalogs` in `constitution.yaml`, its territory this policy's own by a YAML alias. A new comparison takes one more than the highest number the catalog has held, deleted comparisons included, provisional until it lands on main ([requirement A13.1](../requirements.md#a13-1), [A13.3](../requirements.md#a13-3)) — which is how a later survey of the same module gets a name of its own beside the one it supersedes (rule 2). A `res-` name written outside Markdown matches a pattern of the `mentions` dial of module [`const-referencing`](../requirements.md#const-referencing), whose scan reports one that is not an id a document the scan covers carries.
7. <a id="r7"></a>**After the module ships.** A comparison is frozen when the record that accepts its module is accepted: a fact found wrong afterwards is annotated inline with the date, never rewritten, and a finding on the module as built goes into the module document. Beside such an annotation the freeze allows five kinds of edit and no other: the status set `inactive` by a later survey, a link repaired after a move or a renumbering (after a move, by the mover of module [`const-referencing`](../requirements.md#const-referencing) or by hand; after the renumbering that [kernel §1](../../kernel/CONVENTIONS.md#k1) allows, rewritten to the item's new id, a reference-form migration the commit names, with the renumbering), the link to a deleted record becoming that record's title in plain words ([rule 7 of plc-0004-decision-records](plc-0004-decision-records.md#r7)), a typo fix, and a wording edit. A typo fix is of the one kind [rule 14 of plc-0004-decision-records](plc-0004-decision-records.md#r14) defines for a record: a misspelt word, a doubled word, a wrong punctuation mark or a gendered pronoun that stands for a person corrected, the pronoun as that rule says, and no fact, number, link, anchor, code span, handle or word of a quotation changed. The commit names it a typo fix and names the comparisons it edits. A wording edit leaves the comparison's meaning as it stands: it changes no fact and no number, removes or alters no link, anchor, code span or existing handle, and changes no word of a quotation. It is one of these kinds and no other. (a) A sentence split between two independent clauses. It is never made at a colon, at a dash that closes a pair of dashes, or anywhere after a colon that opens a list or an explanation in the same sentence: such a list keeps its lead, and kind (e) serves it. The dash, semicolon or comma there becomes a full stop. The next word takes a capital unless it is code or the text of a link; a handle whose first word is a word, such as "rule 4 of …", takes the capital as any word does. A joining word there — *and*, *but*, *so*, *while* — is dropped. A clause whose subject was shared takes it again, as the same noun or a pronoun for it. (b) A list item that opens with no list handle has its opening words set in bold. At most its words before the first colon, semicolon or full stop that ends a phrase are set so, that mark included; a comma may stand inside them. No word is added, dropped or moved. (c) A word that the `simpler` list of module [`const-language`](../requirements.md#const-language) pairs with a plain word is replaced by that plain word, an article before it made to agree. (d) A quotation, or a word mentioned as a word, that holds a phrase of that module's `forbidden` or `simpler` list or a marker of module [`const-questions`](../requirements.md#const-questions) is put whole in a code span, its words unchanged and its quotation marks outside the span. (e) A list written inside a sentence is set as a bulleted list under its lead. Such a list is items that follow a colon, or the bold lead of a list item, separated by semicolons. Each item becomes one bullet, its words and its closing semicolon or full stop unchanged. The bullets are nested under the list item the list stood in, if it stood in one. The text after the last item becomes a paragraph of its own. A bullet that opens with no list handle takes kind (b). A wording edit is routine. The kit makes it only in a change that has a carry audit, whose readers read each such edit against these kinds; the commit names it a wording edit and names the comparisons it edits. A platform change that breaks a fact, a module revision that reopens a mechanism, or the decider's request earns a new survey of the same module, a new document under rule 6; the older is set `inactive` in the commit that lands it.
8. <a id="r8"></a>**Never a home.** No rule lives in a comparison and no document relies on one: a carry list never links it ([rule 2 of plc-0004-decision-records](plc-0004-decision-records.md#r2)); a module document's research line and a record's context cite it as provenance.
9. <a id="r9"></a>**Author and change.** Written by a subagent, from the template, as a routine act ([kernel §4](../../kernel/CONVENTIONS.md#k4)) of a module's development; the raw material stays in the subagent and only the comparison returns (step 2 of "Developing a module" in [CLAUDE.md](../../CLAUDE.md)). Until the freeze of rule 7 an edit is routine; from it, rule 7.
10. <a id="r10"></a>**Enforcement.** The name, the id and a new item's number, free in the working tree, by module [`const-catalogs`](../requirements.md#const-catalogs) at write time and in its scan, and every collision between items that exist in the tree it scans, in its scan alone; the envelope by module [`const-meta-types`](../requirements.md#const-meta-types), which checks the envelope's validity and not that the type is `non-authoritative`; links, anchors and, in its scan alone, the `res-` mentions outside Markdown by module [`const-referencing`](../requirements.md#const-referencing); `scripts/check-carry-lists.py` refuses a comparison as a home. Provenance, vocabulary, shape and the freeze of rule 7 are review. The six comparisons written before rules 3 to 5 took this form stand as written, under rule 7. The twelve traces of the style defaults are held by module [`const-styling`](../requirements.md#const-styling) in its scan alone, which runs no hook. The grade, the sentence length and the constructions of the prose are held by module [`const-language`](../requirements.md#const-language), after a write and in its scan; a threshold or a list a comparison frozen under rule 7 fails is met by the wording edits of rule 7; what no such edit meets is declared as a departure of that gate's dial in `constitution.yaml` over the comparison's path or a number range that holds it, with its reason, as a trace of a style default is. The length in characters is held by module [`const-doc-budgets`](../requirements.md#const-doc-budgets), after a write and in its scan, against the ceiling its dial `ceilings` in `constitution.yaml` sets for documents of this kind. A frozen comparison over its ceiling is brought under it by the wording edits of rule 7 where they reach it; where they do not, it stays as it is and is declared as a departure of that gate's dial over its path or a number range that holds it, with its reason. The list-handles scan of module [`const-interaction`](../requirements.md#const-interaction) and the marker scan of module [`const-questions`](../requirements.md#const-questions) read documents of this kind too and have no such dial: a plain list item in a frozen comparison takes a bold lead, and a marker it quotes takes a code span. A frozen comparison is never taken out of any gate's territory, save the kit's `scripts/check-module-links.py`, which reads no comparison: a frozen one keeps the form it was frozen with, and in one not yet frozen review holds the module links ([CLAUDE.md](../../CLAUDE.md#references)).
11. <a id="r11"></a>**Style.** Documents of this kind follow the style guides the dial `guides` of module [`const-styling`](../requirements.md#const-styling) names in `constitution.yaml`, and depart from a default only where that module's dial `departures` names a departure for their territory, with its reason ([rule 9 of plc-0001-root-policy](plc-0001-root-policy.md#r9)); the traces of the defaults are held as the enforcement rule says, the rest is review. A trace of a default in a comparison frozen under rule 7 is removed by a wording edit of rule 7 where one removes it; where none does, it is declared by a departure over the comparison's path or a number range that holds it, and never by taking frozen comparisons out of the scan's territory (decisions [dec-0045-frozen-documents-stay-in-the-style-scan](../decisions/dec-0045-frozen-documents-stay-in-the-style-scan.md) and [dec-0048-frozen-documents-take-wording-edits](../decisions/dec-0048-frozen-documents-take-wording-edits.md)).
