# Research policy

Governs the document kind *research comparison*. Each is a dated survey of how one module's matrix rows are addressed today, or of a mechanism of the kit's own tooling. It ends in one recommendation per mechanism (decision [dec-0010-module-research-per-module](../decisions/dec-0010-module-research-per-module.md)). Territory under this policy's id in `constitution.yaml`.

## Rules

1. <a id="r1"></a>**Type.** `non-authoritative`: a comparison informs a mechanism choice and binds nothing.
2. <a id="r2"></a>**Status.** `active` while it is the current comparison of its module or of its tooling mechanism; `inactive` once a later survey supersedes it, kept while cited ([kernel §1](../constitution/CONVENTIONS.md#k1)). A later survey may cover some of the module's mechanisms only. It supersedes the older comparison for those. The module's current comparison is the newest. The older one, `inactive`, stays kept, as the evidence for each mechanism the later survey did not cover. The research line of the module document names which comparison each mechanism cites.
3. <a id="r3"></a>**Provenance.** Every fact names what verified it: a public source, an experiment of the document, or the kit's own tree at a named commit. An experiment is numbered `E<n>`, and states what was set up, run and observed and the versions used, so a reader could repeat it. A tool read but not run is marked so. An earlier comparison is a starting point and never a source. Nothing is copied from earlier design work, and nothing cites an input outside the repository.
4. <a id="r4"></a>**Vocabulary.** Written in kit vocabulary: kernel terms and matrix rows by link, modules, comparisons and records by name or id, never by their order of authoring. "The specification" means the module's stub in the requirements document, linked.
5. <a id="r5"></a>**Shape.** Written from `templates/research-comparison.md`, the template that `const-locations.templates` names for this kind. Its header paragraph gives the survey date, the platform's version, and every tool and library with its version and the platform they ran on. The tools are keyed `t<n>`, each with version and date. The body then holds one section per mechanism, its findings lettered per section. Each candidate has its mechanism class, maturity and cost, and the section closes with one recommendation and its reasoning. The body also holds the fit with the shared gate code where the module ships a script. It holds the platform facts re-verified, each with what breaks if it changes, and the experiments. It holds a summary with one verdict per row, or per mechanism for a survey of the kit's tooling. Each verdict is from the closed set CONFIRMED, OVERTURNED, build, not needed. A rule of this policy that changes the shape changes the template in the same change.
6. <a id="r6"></a>**Number.** Comparisons are a numbered kind. Id and filename stem are one name, `res-<nnnn>-<slug>`, the slug naming the module surveyed or the mechanism of the kit's own tooling. An entry of `const-catalogs.catalogs` in `constitution.yaml` sets prefix, width and territory. Its territory is this policy's own by a YAML alias. A new comparison takes one more than the highest number the catalog has held, deleted comparisons included. The number is provisional until the comparison lands on main ([requirement A13.1](../requirements.md#a13-1), [A13.3](../requirements.md#a13-3)). That is how a later survey of the same module gets a name of its own beside the one it supersedes (rule 2). A `res-` name written outside Markdown matches a pattern of the `mentions` dial of module [`const-referencing`](../requirements.md#const-referencing). Its scan reports one that no covered document carries as an id.
7. <a id="r7"></a>**After the module ships.** A comparison is frozen when the record that accepts its module is accepted. For a survey of the kit's own tooling, it is frozen when the record that accepts the change it informs is accepted. A fact found wrong afterwards is annotated inline with the date, never rewritten. A finding on the module as built goes into the module document. Beside such an annotation the freeze allows five kinds of edit and no other. The first is the status set `inactive` by a later survey. The second is a link repaired after a move, a renumbering or a rename. After a move, it is repaired by the mover of module [`const-referencing`](../requirements.md#const-referencing) or by hand. After a renumbering or a rename that [kernel §1](../constitution/CONVENTIONS.md#k1) allows, it is rewritten to the item's new id. That is a reference-form migration the commit names, with the renumbering or the rename. The third is the link to a deleted record becoming that record's title in plain words ([rule 7 of plc-0004-decision-records](plc-0004-decision-records.md#r7)). The fourth is a typo fix, and the fifth a wording edit. After a document, another file or a folder alike is moved or renamed, a repaired link takes the new path, and only its target changes. The link's text, a code span and the comparison's prose keep the old name or path as written, as history. An item whose id changes, by a renumbering or a rename that [kernel §1](../constitution/CONVENTIONS.md#k1) allows, is outside the two sentences before this one. What its link takes is said by the list above. The second kind covers a bare id too. After a renumbering or a rename, the same migration rewrites each bare id that means the item. Such an id stands outside a link, in prose or in a code span. It is rewritten to the item's new id in the form it stood in: the full id, or the prefix and the number alone. It follows [kernel §1](../constitution/CONVENTIONS.md#k1), which rewrites the references to the item. An id quoted as evidence stays as written: a form shown, the data of a measurement, the words of a quotation. So does any id in a fenced or indented block or an HTML comment. So does an id that means another item, such as the one that kept the number. A typo fix is of the one kind [rule 14 of plc-0004-decision-records](plc-0004-decision-records.md#r14) defines for a record. It corrects a misspelt word, a doubled word, a wrong punctuation mark or a gendered pronoun that stands for a person. The pronoun is corrected as that rule says. It changes no fact, number, link, anchor, code span, handle or word of a quotation. The commit names it a typo fix and names the comparisons it edits. A wording edit leaves the comparison's meaning as it stands. It changes no fact and no number, removes or alters no link, anchor, code span or existing handle, and changes no word of a quotation. It is one of these kinds and no other. (a) A sentence split between two independent clauses. It is never made at a colon or at a dash that closes a pair of dashes. Nor is it made anywhere after a colon that opens a list or an explanation in the same sentence. Such a list keeps its lead, and kind (e) serves it. The dash, semicolon or comma there becomes a full stop. The next word takes a capital unless it is code or the text of a link. A handle whose first word is a word, such as "rule 4 of …", takes the capital as any word does. A joining word there — *and*, *but*, *so*, *while* — is dropped. A clause whose subject was shared takes it again, as the same noun or a pronoun for it. (b) A list item that opens with no list handle has its opening words set in bold. At most its words before the first colon, semicolon or full stop that ends a phrase are set so, that mark included. A comma may stand inside them. No word is added, dropped or moved. (c) A word that the `simpler` list of module [`const-language`](../requirements.md#const-language) pairs with a plain word is replaced by that plain word. An article before it is made to agree. (d) A quotation, or a word mentioned as a word, may hold a phrase of that module's `forbidden` or `simpler` list. Or it may hold a marker of module [`const-questions`](../requirements.md#const-questions) instead. Either way, it is put whole in a code span, its words unchanged and its quotation marks outside the span. (e) A list written inside a sentence is set as a bulleted list under its lead. Such a list is items that follow a colon, or the bold lead of a list item, separated by semicolons. Each item becomes one bullet, its words and its closing semicolon or full stop unchanged. The bullets are nested under the list item the list stood in, if it stood in one. The text after the last item becomes a paragraph of its own. A bullet that opens with no list handle takes kind (b). A wording edit is routine. The kit makes it only in a change that has a carry audit, whose readers read each such edit against these kinds. The commit names it a wording edit and names the comparisons it edits. A platform change that breaks a fact, a module revision that reopens a mechanism, or the decider's request earns a new survey. It surveys the same module or mechanism. It is a new document under rule 6 whose scope is the mechanisms reopened or asked for, under rule 2. The older is set `inactive` in the commit that lands it.
8. <a id="r8"></a>**Never a home.** No rule lives in a comparison and no document relies on one. A carry list never links it ([rule 2 of plc-0004-decision-records](plc-0004-decision-records.md#r2)). A module document's research line and a record's context cite it as provenance.
9. <a id="r9"></a>**Author and change.** Written by a subagent, from the template, as a routine act ([kernel §4](../constitution/CONVENTIONS.md#k4)). The act is part of a module's development, or of a change to the kit's own tooling whose decider asks for one. The raw material stays in the subagent and only the comparison returns (step 2 of [the module-development page](../guide/developing-a-module.md#s2)). Until the freeze of rule 7 an edit is routine; from it, rule 7.
10. <a id="r10"></a>**Enforcement.** Module [`const-catalogs`](../requirements.md#const-catalogs) holds the name, the id and a new item's number, free in the working tree, at write time and in its scan. In its scan alone, it holds every collision between items that exist in the tree it scans. Module [`const-meta-types`](../requirements.md#const-meta-types) holds the envelope. It checks the envelope's validity, not that the type is `non-authoritative`. Links, anchors and, in its scan alone, the `res-` mentions outside Markdown are held by module [`const-referencing`](../requirements.md#const-referencing). `scripts/check-carry-lists.py` refuses a comparison as a home. Provenance, vocabulary, shape and the freeze of rule 7 are review. The six comparisons written before rules 3 to 5 took this form stand as written, under rule 7. The twelve traces of the style defaults are held by module [`const-styling`](../requirements.md#const-styling) in its scan alone, which runs no hook. The grade, the sentence length and the constructions of the prose are held by module [`const-language`](../requirements.md#const-language), after a write and in its scan. A threshold or a list a comparison frozen under rule 7 fails is met by the wording edits of rule 7. What no such edit meets is declared as a departure of that gate's dial in `constitution.yaml`, with its reason. A trace of a style default is declared the same way. The departure is set over the comparison's path or a number range that holds it. The length in characters is held by module [`const-doc-budgets`](../requirements.md#const-doc-budgets), after a write and in its scan. It is held against the ceiling its dial `ceilings` in `constitution.yaml` sets for documents of this kind. A frozen comparison over its ceiling is brought under it by the wording edits of rule 7 where they reach it. Where they do not, it stays as it is. It is declared as a departure of that gate's dial over its path or a number range that holds it, with its reason. The list-handles scan of module [`const-interaction`](../requirements.md#const-interaction) and the marker scan of module [`const-questions`](../requirements.md#const-questions) read documents of this kind too and have no such dial. A plain list item in a frozen comparison takes a bold lead, and a marker it quotes takes a code span. A frozen comparison is never taken out of any gate's territory, save the kit's `scripts/check-module-links.py` and `scripts/check-handle-forms.py`, which read no comparison. A frozen one keeps the form it was frozen with. In one not yet frozen, review holds the module links and the anchors of the rulings it cites ([CLAUDE.md](../../CLAUDE.md#references)).
11. <a id="r11"></a>**Style.** Documents of this kind follow the style guides that the dial `guides` of module [`const-styling`](../requirements.md#const-styling) in `constitution.yaml` names. They depart from a default only where that module's dial `departures` names one for their territory, with its reason ([rule 9 of plc-0001-root-policy](plc-0001-root-policy.md#r9)). The traces of the defaults are held as the enforcement rule says, and the rest is review. A trace of a default in a comparison frozen under rule 7 is removed by a wording edit of rule 7 where one removes it. Where none does, it is declared by a departure over the comparison's path or a number range that holds it. It is never declared by taking frozen comparisons out of the scan's territory. This follows decisions [dec-0045-frozen-documents-stay-in-the-style-scan](../decisions/dec-0045-frozen-documents-stay-in-the-style-scan.md) and [dec-0048-frozen-documents-take-wording-edits](../decisions/dec-0048-frozen-documents-take-wording-edits.md).
