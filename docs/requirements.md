# Constitution Requirements

*What every module must implement, and nothing about when: the phases and sequence live in the rollout plan [constitution-rollout-plan](rollout-plan.md), the kit's write-head. A module implements exactly its rows here ([law 4 of CLAUDE.md](../CLAUDE.md#law-4)).*


**Traceability matrix** — every aspect decomposed into requirement parts, each with exactly one primary destination. Destination classes: **kernel §n** (shared semantics), **Mx** (module, with artifact kind), **binding** (per-project `constitution.yaml` — never module content), **template** (authoring law). An authoring session for module X takes exactly its rows as the requirement set; coverage check = every part homed, every module = exactly its rows.

**Enforcement classes** — the closed set a row's last column is written in: **gate** (deterministic, red means fix, a blocking exit), **gate-lite** (a script that flags, blocking only where a dial turns it on, or checks presence alone), **advisory** (skill prose, judgment shaped and never gated), **definitional** (a kernel definition, enforced through another row's check), **config** (a binding validated at each read, malformed being a configuration failure), **git-native** (held by the repository itself), **review** (human judgment at review). A row whose enforcement waits for another module says so in words.

**"Enters when" has two meanings** (decision [dec-0006-accumulating-set-first](decisions/dec-0006-accumulating-set-first.md)). For an accumulating module it names the first moment an object for the module exists; the module is authored *before* that moment, and for a greenfield consumer the whole accumulating set is the day-one install set. For a self-limiting module it names the friction signal that earns authoring. Dials follow the consumer; modules never wait for calibration.

**Module boundaries remain provisional until authoring** — settled by three tests: *one invariant? one enforcement moment? one lifecycle trigger?* Flagged rows (†) sit on boundaries under test: M7 may dissolve (A8.x → M6). Settled: [A10.2](#a10-2) is M7's, the document half of the language aspect M9's (decision [dec-0046-language-module-rulings](decisions/dec-0046-language-module-rulings.md)). Settled: the M1/M2 boundary — [A2.3](#a2-3) is M1's, so one write-time script guards claimed territory and M2 is advisory creation (decision [dec-0015-pre-module-audit-rulings](decisions/dec-0015-pre-module-audit-rulings.md)).

| <a id="a12"></a>**A12 — Kit portability** | | | |
| <a id="a12-1"></a>A12.1 | No project references in modules; specifics via dials; empty-repo test | [kernel §6](constitution/CONVENTIONS.md#k6) + template | **gate**: kit-repo CI — install on bare repo + project-reference grep. The install is the kit's `scripts/check-bare-install.py`, an entry of each module's own CI job: Claude Code installs the module alone into an empty configuration, which keeps the installed copy, beside a bare repository that holds the kernel and no `constitution.yaml`. A plugin carries no shared code, so every hook and scan runs with the `bin` of a throwaway virtual environment first on `PATH`, whose `.pth` file names the working folder's `shared/` (R7 and R17 of [dec-0099-shared-code-installed-as-a-pip-package](decisions/dec-0099-shared-code-installed-as-a-pip-package.md#r7)). The copy holds the source's hooks file; every hook the module's source declares, run on that repository, exits 0 without blocking, denying, asking or stopping; every scan the module's document declares exits 0 there. Its source is the module's `plugin/` folder, the folder the install copies. No link of the source leads inside that folder, save a fixture runner's link `tests/<package>` → `../scripts/<package>` inside it to a package of the module's own, which arrives as a link leading to that package in the copy; no module's source holds one, since a module's runner's links, as item 7 of [kit-shared-gate-code §2](../shared/GATE.md#g2) derives them, stand in its `tests/`, beside `plugin/`. Every other link arrives in the copy as what its target is, a real file with the same bytes or a real directory with the same files byte for byte, and the copy holds no link the source lacks and nothing at `scripts/constitution_layer_kit`, since what stood there would shadow the installed package; an install Claude Code refuses, its result's `outcome` being `failed`, is a finding. In the kit's CI the module is installed from the GitHub repository and branch of the change — the pull request's head, or `main` on a push to it — cloned over HTTPS with the job's own token, the copy a consumer's install writes; Claude Code needs no account login, and a fork the token cannot read fails. The check runs on the one Claude Code version the kit pins in `scripts/claude-code.version`, a single line, which the kit's CI installs for the jobs that run `claude`: before any other `claude` command it asks `claude --version`. On another version it cannot run, a configuration failure with exit 1, unless the environment sets `CONSTITUTION_KIT_ANY_CLAUDE` to exactly `1`. Then it runs, and each finding's headline, each failure line and the closing line of its report end with a note naming both versions. A version it cannot read (the command fails, prints nothing, or opens with a word that is no version) and a pin file that is missing, empty or not exactly one version are configuration failures whatever the variable says. The check reads what Claude Code installed through its documented `--json` commands: the last standard output line of `claude plugin install <module>@<marketplace> --json`, and the one entry of `claude plugin list --json` whose `id` is that key at the scope the install wrote, its `installPath` an existing folder, which is the copy. Three things are configuration failures, never a finding against the module. A reply it cannot read: no JSON, a result that is no object or whose `outcome` is neither `ok` nor `failed`, a list that is no list. An install that gives no result in its 300 seconds. Replies that disagree: an `ok` result with an exit other than 0 or with no `scope`, a list with no entry or two for that key at that scope, or with an `installPath` that is no folder. The fix of an unreadable reply or of replies that disagree, on the pinned version, is to update the kit's reader that the line names, and on another version, where the opt-out has the check run, to run again on the pinned one; the fix of the timed-out install is to run the check again and check that git can reach the install source. A `claude plugin list --json` that exits other than 0, or gives no result in its time, is a configuration failure too: its fix is to run the check again, and for a non-zero exit first to run the command by hand and read why it fails; on another version, to run again on the pinned one. The copy is compared with the kit's source at the commit the install came from, which Claude Code's install record, `installed_plugins.json` of the configuration, names: the `gitCommitSha` of the entry of `plugins` for that key whose `installPath` is the copy's folder, the one field the check reads that no page of Claude Code's documentation describes and the one place it reads the record, fetched when the clone lacks it. A record that is missing, is no JSON, holds no such entry, names no commit, or names a value that is no git object id (40 or 64 lower-case hexadecimal characters) is a configuration failure with the same fix, and there is no fallback to the working folder; an install from a local folder reads no record and is compared with the module's `plugin/` folder there. Run by hand with no install source named, it is installed from the working folder and compared with the module's `plugin/` folder there; a remote named by hand is compared as in CI, cloned with the machine's own git credentials, and a local folder named by hand is compared as any local folder is, with the module's `plugin/` folder there. The run holds the case of an absent dials file, and a module with neither hook nor scan on its links alone (decision [dec-0059-bare-repo-install-in-ci](decisions/dec-0059-bare-repo-install-in-ci.md)).
